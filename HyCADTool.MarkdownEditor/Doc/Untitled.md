### 差异来源（核心问题）

| 维度     | 编辑器（Vditor）       | 预览器（Markdig）                   | 差异严重度                           |
| :------- | :--------------------- | :---------------------------------- | :----------------------------------- |
| 渲染引擎 | Vditor 内置 (Lute)     | Markdig (C#)                        | 高 -- 两套完全独立的 Markdown 解析器 |
| 字体     | 浏览器默认（未指定）   | Microsoft YaHei（可配置）           | 中                                   |
| 字号     | Vditor 默认（约 16px） | TextSize × PreviewScale（约 2.5px） | 高 -- 单位体系不同                   |
| 行高     | Vditor 默认            | LineSpacingFactor = 1.2             | 中                                   |
| CSS 样式 | Vditor 主题（dark）    | 完全自定义 CSS 模拟 CAD 排版        | 高                                   |
| 分栏     | 无                     | 有（JS 分栏 + 拖拽）                | 高                                   |
| 用途     | 写作体验               | 模拟 AutoCAD 最终输出               | 根本不同                             |

结论：两者差异大是"设计意图"造成的 -- 编辑器负责"写作体验"，预览器负责"模拟 CAD 输出"，它们本来就在做不同的事。

------

## 你可以考虑的 3 条路

### 方案 A: 保持现状，统一字体（最小改动）

只把 Vditor 编辑器的 CSS 字体/字号同步为与预览器一致的微软雅黑，减少视觉跳跃感。不改架构。

- 改动量：仅改 VditorHtmlTemplate.cs 中注入的 CSS

- 优点：最稳定，不破坏任何现有功能

- 缺点：两端 Markdown 解析器仍不同，复杂语法（表格、代码块）的显示差异依然存在

### 方案 B: 用 Vditor 自带的预览替代右侧预览器（中等改动）

Vditor 本身支持 preview 模式和实时预览面板。可以让 Vditor 既当编辑器又当预览器，只保留一个 WebView2 实例。

- 改动量：中等，需要把分栏逻辑和 CAD 参数映射接入 Vditor 的自定义渲染

- 优点：编辑和预览用同一个 Markdown 渲染器（Lute），显示完全一致

- 缺点：Vditor 的预览无法模拟 CAD 分栏/分页，你需要额外写自定义渲染插件

### 方案 C: 去掉 Vditor，换用纯文本编辑器 + 统一 Markdig 渲染（大改动）

用更轻量的编辑器（如 Monaco Editor / CodeMirror）做纯 Markdown 文本编辑，左右两侧都用 Markdig 渲染 HTML，只是左侧简化版（无分栏），右侧完整版（有分栏+CAD参数）。

- 改动量：大，需要替换整个编辑器组件

- 优点：统一渲染引擎，彻底消除解析差异

- 缺点：失去 Vditor 的"所见即所得"即时渲染体验

------

## 我的建议

考虑到你的核心需求是"CAD 输出准确"而非"编辑器和预览器长得一模一样"：

1. 短期：走方案 A，先只统一字体，专注解决"栏宽/换行"这个 CAD 侧的核心问题

1. 中期：可以考虑给 Vditor 注入自定义 CSS（字体、字号、行高与预览器对齐），让视觉差异缩小到可接受范围

1. 长期：如果你觉得 Vditor 的即时渲染模式不够好用，可以换成 Monaco/CodeMirror + Markdig 双端统一渲染
