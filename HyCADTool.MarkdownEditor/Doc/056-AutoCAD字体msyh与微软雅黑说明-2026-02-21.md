# 为什么 AutoCAD 显示 msyh.ttc 而不是微软雅黑？

## 一、结论

**msyh.ttc 就是微软雅黑的字体文件名**。AutoCAD 在文字样式中显示的是**字体文件名**，而不是中文显示名「微软雅黑」。两者是同一字体，只是显示方式不同。

---

## 二、技术背景

### 2.1 字体文件与显示名

| 概念 | 示例 | 说明 |
|------|------|------|
| **字体文件名** | `msyh.ttc` | 磁盘上的实际文件（TrueType Collection） |
| **字体显示名** | 微软雅黑 | 在系统/软件中展示给用户的名称 |
| **字体族名** | Microsoft YaHei | 英文名，常用于 CSS、API |

在 Windows 中，微软雅黑通常对应：
- `msyh.ttc` — 常规
- `msyhbd.ttc` — 粗体

### 2.2 AutoCAD 的 TextStyleTableRecord.FileName

AutoCAD 的 `TextStyleTableRecord.FileName` 保存的是**字体文件名**（如 `msyh.ttc`、`tssdeng.shx`），而不是显示名。因此文字样式对话框会显示 `T msyh.ttc`，其中 `T` 表示 TrueType。

---

## 三、本项目的处理逻辑

在 `DesignSpecService.cs` 中，`ResolveTrueTypeFontFile` 会把多种写法统一为 `msyh.ttc`：

```csharp
// DesignSpecService.cs 约 787-798 行
private static string ResolveTrueTypeFontFile(string fontName)
{
    if (string.IsNullOrWhiteSpace(fontName))
        return "msyh.ttc";

    string value = fontName.Trim();
    if (string.Equals(value, "msyh.ttc", StringComparison.OrdinalIgnoreCase)
        || string.Equals(value, "msyh.ttf", StringComparison.OrdinalIgnoreCase)
        || string.Equals(value, "微软雅黑", StringComparison.OrdinalIgnoreCase)
        || string.Equals(value, "微软雅黑体", StringComparison.OrdinalIgnoreCase)
        || string.Equals(value, "Microsoft YaHei", StringComparison.OrdinalIgnoreCase)
        || string.Equals(value, "Microsoft YaHei UI", StringComparison.OrdinalIgnoreCase))
        return "msyh.ttc";
    // ...
}
```

也就是说，无论配置里写「微软雅黑」还是「Microsoft YaHei」，最终都会写入 `msyh.ttc`，这是 AutoCAD 需要的格式。

---

## 四、黄色警告图标可能的原因

1. **TTC 格式**：`msyh.ttc` 是 TrueType Collection，部分 AutoCAD 版本对 TTC 有特殊处理或提示。
2. **字体路径**：若系统字体目录或路径异常，AutoCAD 可能提示字体替代或未找到。
3. **字体替代**：当系统无法按文件名精确匹配时，会进行替代并显示警告。

若文字能正常显示，通常说明字体已正确加载，警告多为提示性信息。

---

## 五、总结

| 问题 | 答案 |
|------|------|
| msyh.ttc 和 微软雅黑 是否同一字体？ | 是，msyh.ttc 是微软雅黑的字体文件 |
| 为什么 AutoCAD 显示 msyh.ttc？ | 因为 FileName 存的是字体文件名，不是显示名 |
| 是否异常？ | 否，这是 AutoCAD 的常规行为 |
| 黄色图标含义？ | 多为 TTC 或字体路径相关提示，若显示正常可忽略 |
