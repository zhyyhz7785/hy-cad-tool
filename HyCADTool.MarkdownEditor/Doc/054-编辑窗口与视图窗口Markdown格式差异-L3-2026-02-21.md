# 编辑窗口与视图窗口 Markdown 格式差异 — L3 详解

> **目标**：理解编辑窗口与视图窗口 Markdown 显示不一致的根因，支撑「视图窗口显示格式与编辑窗口相同」的修改。

---

## 一、双通道渲染架构概览

| 通道 | 文件 | 职责 |
|------|------|------|
| 编辑窗口 | `VditorHtmlTemplate.cs` | 生成嵌入 Vditor 的 HTML，IR 模式即时渲染 |
| 视图窗口 | `PreviewHtmlRenderer.cs` | 生成分栏预览 HTML，Markdig 解析 + 自定义 CSS |

两者**解析器不同、样式不同**，导致同一 Markdown 在两侧显示不一致。

---

## 二、VditorHtmlTemplate.cs — 编辑窗口

### 类概述

- **类型**：静态类
- **职责**：生成 Vditor 编辑器 HTML 页面（IR 即时渲染 + 暗色主题）
- **依赖**：`VditorCacheManager.CdnFallback`、`Newtonsoft.Json`

### 字段/属性

| 名称 | 类型 | 用途 |
|------|------|------|
| `VDITOR_VERSION` | `const string` | Vditor 版本号（3.10.8） |

### 方法清单

| 方法 | 参数 | 返回 | 职责 |
|------|------|------|------|
| `Generate` | `initialMarkdown`, `cdnBase` | `string` | 主入口：拼接完整 HTML |
| `EscapeForJs` | `text` | `string` | 转义 Markdown 供 JS 使用 |

### 关键方法详解

#### Generate

- **输入**：初始 Markdown、CDN 基础 URL
- **处理**：
  1. 取 CDN 或 fallback
  2. 调用 `EscapeForJs` 转义 Markdown
  3. 拼接 HTML：引入 `index.css`、`index.min.js`
  4. 内嵌 Vditor 初始化配置：`mode: 'ir'`、`theme: 'dark'`、`lang: 'zh_CN'`
  5. **preview 配置**（影响编辑区渲染样式）：
     - `theme: { current: 'dark', path: '{cdn}/dist/css/content-theme' }`
     - `hljs: { style: 'native', lineNumber: true }`
- **输出**：完整 HTML 字符串
- **调用链**：`EditorContentViewModel` → `VditorCacheManager` 或直接调用

### 编辑窗口 Markdown 渲染来源

- **解析器**：Vditor 内置（Lute/JS 实现）
- **样式**：Vditor `content-theme` 系列 CSS（`dark` 主题）
- **代码块**：highlight.js，`style: 'native'`，带行号
- **背景**：`#111418`（暗色）

## 三、PreviewHtmlRenderer.cs — 视图窗口

### 类概述

- **类型**：静态类
- **职责**：Markdown → 交互式分栏 HTML 预览（WebView2 预览控件）
- **依赖**：`Markdig`、`EditorConfig`、`HyCADTool.TextLayout`

### 字段/属性

| 名称 | 类型 | 用途 |
|------|------|------|
| `Pipeline` | `MarkdownPipeline` | Markdig 解析管线（`UseAdvancedExtensions`） |
| `ConsecutiveBlankLines` | `Regex` | 连续空行预处理 |

### 方法清单

| 方法 | 参数 | 返回 | 职责 |
|------|------|------|------|
| `ToInteractiveHtml` | `markdown`, `columnCount`, `previewScale`, `config`, `layoutResult` | `string` | 主入口：完整预览 HTML |
| `RenderBodyHtml` | `markdown` | `string` | 委托给 `RenderFlowBodyHtml` |
| `RenderFlowBodyHtml` | `markdown` | `string` | Flow 模式 body：`PreserveBlankLines` + `Markdown.ToHtml` |
| `ToFlowExperienceHtml` | `markdown`, `columnCount`, `previewScale`, `config` | `string` | 拼接 flowCssTemplate + flowJsTemplate |
| `PreserveBlankLines` | `md` | `string` | 连续空行替换为 WORD JOINER |
| `BuildDynamicCss` | `previewScale`, `cfg` | `string` | 替换 flowCssTemplate 中的占位符 |
| `BuildDynamicJs` | `previewScale`, `cfg`, `columnCount`, `layoutResult` | `string` | 注入 JS 运行参数 |
| `BuildCustomColumnWidthsJson` | `layoutResult`, `previewScale` | `string` | 栏宽数组 JSON |

### 关键方法详解

#### ToFlowExperienceHtml

- **输入**：Markdown、栏数、缩放、配置
- **处理**：
  1. `PreserveBlankLines` 预处理
  2. `Markdown.ToHtml(preprocessed, Pipeline)` 生成 body HTML
  3. 从 `EditorConfig` 解析字体、边距、栏宽等
  4. 替换 `flowCssTemplate` 占位符（`/*FLOW_*`）
  5. 拼接 `flowJsTemplate` 与 body
- **输出**：完整 HTML 字符串
- **调用链**：`PreviewManager.RefreshPreviewAsync` → `FullNavigatePreview` / `IncrementalUpdateFlowAsync`

### 视图窗口 Markdown 渲染来源

- **解析器**：Markdig（`UseAdvancedExtensions`）
- **样式**：内嵌 `flowCssTemplate` 自定义 CSS
- **代码块**：无 highlight.js，无语法高亮、无行号
- **背景**：纸白（`#ffffff`）、栏内 `#f8fafc`

## 四、格式不一致根因对照表

| 维度 | 编辑窗口 (Vditor) | 视图窗口 (PreviewHtmlRenderer) | 是否一致 |
|------|-------------------|--------------------------------|----------|
| **解析器** | Vditor 内置 (Lute) | Markdig | ❌ 不同 |
| **Markdown 扩展** | Vditor 默认 | `UseAdvancedExtensions` | ❌ 可能不同 |
| **标题样式** | content-theme dark | 自定义 h1/h2/h3 | ❌ 不同 |
| **引用块** | content-theme | `border-left:3px solid #6e7781` | ❌ 不同 |
| **行内代码** | content-theme | `background:#f0f3f6` | ❌ 不同 |
| **代码块** | highlight.js + 行号 | 无高亮、无行号 | ❌ 不同 |
| **表格** | content-theme | 自定义 border | ❌ 不同 |
| **主题** | dark (#111418) | 浅色 (#ffffff) | ❌ 不同 |
| **字体** | Vditor 默认 | `PreviewFontFamily`（如 Microsoft YaHei） | ⚠️ 可配置 |

## 五、实现「视图窗口与编辑窗口格式相同」的改造方向

### 方案 A：视图窗口引入 Vditor content-theme CSS

- 在 `PreviewHtmlRenderer` 中引入 Vditor 的 `content-theme/dark.css`
- 替换或覆盖 `flowCssTemplate` 中的 h1/h2/h3/blockquote/code/pre/table 等样式
- **优点**：样式统一，改动相对小
- **缺点**：需处理 CDN/本地资源路径，代码块仍需 highlight.js

### 方案 B：视图窗口引入 highlight.js

- 在 `flowCssTemplate` 后追加 highlight.js 脚本与主题 CSS
- 对 `pre code` 块调用 `hljs.highlightBlock`
- **优点**：代码块与编辑窗口一致
- **缺点**：需与 Vditor 的 `hljs.style: 'native'` 对齐

### 方案 C：统一解析器（不推荐）

- 将视图窗口改为调用 Vditor 的 JS 解析 API，或反向将编辑窗口改为 Markdig
- **缺点**：架构改动大，Vditor 与 C# 通信复杂

### 推荐组合：方案 A + 方案 B

1. 引入 Vditor `content-theme/dark.css` 覆盖 Markdown 元素样式
2. 引入 highlight.js（`native` 主题）并对 `pre code` 执行高亮
3. 保持 Markdig 解析（与 Vditor 的 Lute 在常见语法上差异较小，可后续用回归样本验证）
