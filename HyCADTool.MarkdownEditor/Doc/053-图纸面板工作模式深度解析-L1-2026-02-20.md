## 一、项目定位

MarkdownEditor 是一个 **WPF + WebView2** 的 Markdown 编辑器，内嵌两个 WebView2 实例：

| 面板 | WebView2 实例 | 核心用途 |
|------|--------------|----------|
| **编辑面板** | `EditorWebView` | Vditor 所见即所得编辑器 |
| **图纸面板** | `PreviewWebView` | contenteditable 分栏分页预览（模拟 A0–A4 图纸） |

两个面板共享同一份 `ViewModel.MarkdownText`，通过 **双向消息** 保持同步。

## 四、图纸面板两种模式

`PreviewHtmlRenderer` 内部有一个编译常量：

```csharp
private const bool UseFlowExperiencePaperMode = true;  // 当前固定为 true
```

| 模式 | 开关 | 特征 |
|------|------|------|
| **Flow 模式**（当前） | `UseFlowExperiencePaperMode = true` | C# 侧不做布局，JS 侧自行分栏分页；contenteditable 可直接编辑 |
| Legacy Layout 模式 | `= false` | C# 侧 LayoutEngine 做精确布局，JS 按坐标摆放；contenteditable 受限 |

**当前所有问题都发生在 Flow 模式下**，下文以 Flow 模式为主线。

## 五、核心数据流（全景）

```
用户在编辑面板打字
  │
  ▼  ① Vditor → postMessage({type:"input", value:"..."})
EditorWindow.OnWebMessageReceived
  │
  ├─ ApplyMarkdownFromSource(md, Editor)  ← 更新 ViewModel.MarkdownText
  ├─ SchedulePreviewRefresh(ContentInput)  ← 220ms 防抖
  └─ ScheduleAutoCadSync()                 ← 900ms 防抖
         │
         ▼  ② 防抖到期
  _previewRefreshDebounceTimer.Tick
  → RefreshPreviewAsync(ContentInput)
  → PreviewManager.RefreshPreviewAsync(...)
         │
         ├─ [Flow + ContentInput + 非 configChanged]
         │   → IncrementalUpdateFlowAsync       ← ③ JS: updateSource(body, null, null)
         │     成功？ 直接返回，不销毁 DOM ✅
         │     失败？ fall through ↓
         │
         ├─ [canIncremental && hasInitialRender]
         │   → IncrementalUpdateAsync             ← JS: updateSourceIncremental(...)
         │     失败？ → FullUpdateInPlaceAsync    ← JS: updateSource(body, layout, widths)
         │       失败？ → CaptureCaretAndScroll + FullNavigatePreview（完整 NavigateToString）
         │
         └─ [else：configChanged / InitialLoad / ViewportChanged]
             → CaptureCaretAndScrollAsync         ← ④ 保存光标+滚动
             → FullNavigatePreview                ← ⑤ NavigateToString（销毁+重建 DOM）
               → OnPreviewNavigationCompleted     ← ⑥ 恢复焦点
               → RestoreCaretAfterNavigationAsync ← ⑦ 恢复光标+滚动
```

## 六、用户在图纸面板打字

```
用户在图纸面板 contenteditable 栏内打字
  │
  ▼  ① JS input/keyup 监听
  → updateSourceMirrorFromColumns()        ← 从所有栏合并回 #source
  → debouncedColumnReflow()                ← 重排分栏（400ms 防抖）
  → notifyContentChanged()                 ← 防抖后 postMessage
       │
       ▼  ② postMessage({type:"contentChanged", markdown, version, hash})
  EditorWindow.OnPreviewWebMessageReceived
  → PreviewManager.TryHandlePreviewWebMessage
       │
       ├─ 哈希去重：hash == _lastPreviewContentHash → 丢弃
       ├─ 内容相同：ViewModel.MarkdownText == markdown → 丢弃
       └─ 有变化 → 返回 PreviewContentChange
              │
              ▼
  → ApplyMarkdownFromSource(md, Preview)   ← 更新 ViewModel.MarkdownText
  → SyncEditorFromPreviewAsync(md)         ← setContent() 回写编辑器
  → ScheduleAutoCadSync()
```

## 七、双向同步防环机制

### 7.1 编辑器 → 图纸（正向）

```
编辑器 input → OnWebMessageReceived → ApplyMarkdownFromSource
  → SchedulePreviewRefresh(ContentInput, 220ms)
  → RefreshPreviewAsync → IncrementalUpdateFlowAsync (JS: updateSource)
```

**防环关键**：`SchedulePreviewRefresh` 中检查 `_previewPanel.PreviewWebViewControl.IsKeyboardFocusWithin`，若图纸有焦点则**直接丢弃** ContentInput 刷新请求。

### 7.2 图纸 → 编辑器（反向）

```
图纸 contentChanged → OnPreviewWebMessageReceived → ApplyMarkdownFromSource
  → SyncEditorFromPreviewAsync → EditorWebView.setContent(md)
    → 编辑器触发 input 回声
    → OnWebMessageReceived → _isUpdatingFromPreview == true
      → hash 匹配 → 丢弃回声 ✅
      → hash 不匹配 → 当作真实编辑 ⚠️
```

**防环关键**：
1. `_isUpdatingFromPreview` 标志 + `_pendingPreviewSyncHash` SHA256 哈希
2. 回声的 input.value 哈希匹配 → 丢弃
3. 2秒安全兜底超时清除标志

### 7.3 版本号/哈希去重

```
PreviewManager 内部：
  _markdownVersion       ← 每次 MarkdownText 变更 ++
  _previewVersion        ← 每次预览成功刷新后 = _markdownVersion
  _lastPreviewContentHash ← 图纸 contentChanged 的 hash
  _lastPreviewContentVersion ← 图纸 contentChanged 的 version
```

去重逻辑：`hash == _lastPreviewContentHash && version <= _lastPreviewContentVersion → duplicated → 丢弃`

## 八、刷新管线详解

### 8.1 触发源 → PreviewRefreshReason

| 触发源 | Reason | 优先级 |
|--------|--------|--------|
| 首次加载 | InitialLoad | 40 |
| 用户在编辑器打字 | ContentInput | 10 |
| 配置参数变更（字号/栏数/间距等） | ConfigChanged | 30 |
| 窗口尺寸/面板切换 | ViewportChanged | 20 |
| 增量失败后重建 | FallbackRebuild | 50 |

### 8.2 防抖合并

```
SchedulePreviewRefresh(reason)
  → if reason.priority >= pending.priority: pending = reason
  → restart 220ms timer
  → timer tick → RefreshPreviewAsync(pending)
```

### 8.3 刷新路径决策树

```
RefreshPreviewAsync(reason)
│
├─ Flow 模式 + hasInitialRender + !configChanged + ContentInput
│   → IncrementalUpdateFlowAsync    （最优路径：不销毁 DOM）
│     成功 → return
│     失败 → fall through
│
├─ _incrementalFallbackFuse == true + ContentInput
│   → CaptureCaretAndScroll → FullNavigatePreview
│   → _incrementalFallbackFuse = false
│
├─ canIncremental (hasInitialRender + !configChanged + !forceFullByReason)
│   → IncrementalUpdateAsync
│     成功 → return
│     失败 → FullUpdateInPlaceAsync
│       成功 → return
│       失败 → CaptureCaretAndScroll → FullNavigatePreview
│              _incrementalFallbackFuse = true（下次走 fuse 快速路径）
│
└─ else (configChanged / InitialLoad / ViewportChanged / FallbackRebuild)
    → CaptureCaretAndScroll → FullNavigatePreview
```

## 九、光标与滚动保留机制

### 9.1 保存（CaptureCaretAndScrollAsync）

仅在 **FullNavigatePreview 前** 调用：

```csharp
_pendingCaretBookmarkJson = await ExecuteScriptAsync(
    "JSON.stringify(captureCaretBookmark(getActionTargetColumn()))");
_pendingScrollTop = viewportEl.scrollTop;
_pendingScrollLeft = viewportEl.scrollLeft;
```

JS 侧 `captureCaretBookmark(col)` 的工作：
- 获取 Selection.getRangeAt(0)
- 将 range 转换为 { nodeIndex, textOffset, totalTextOffset } 结构
- nodeIndex = 子节点在父元素中的索引
- textOffset = range 在文本节点中的偏移

### 9.2 恢复（RestoreCaretAfterNavigationAsync）

在 `OnPreviewNavigationCompleted` 事件中调用：

```csharp
await ExecuteScriptAsync($"restoreCaretBookmark({bookmarkJson})");
await ExecuteScriptAsync($"viewportEl.scrollTop={topText};viewportEl.scrollLeft={leftText};");
```

### 9.3 焦点面板记忆

```
SaveCurrentFocusPanel() → 记录 _lastFocusedPanel (Editor/Preview/None)
OnPreviewNavigationCompleted → 根据 _lastFocusedPanel 将焦点交还对应面板
```

## 十、配置变更时的完整链路

以用户修改 TextSize 为例：

```
SettingsPanelControl TextBox 变更
  → ViewModel.TextSize setter
    → SetProperty → OnPropertyChanged("TextSize")

EditorWindow.OnPropChanged
  → case "TextSize":
    → SchedulePreviewRefresh(ConfigChanged)    ← 220ms 防抖
    → UpdateRulerScale()

220ms 后 → RefreshPreviewAsync(ConfigChanged)
  → PreviewManager.RefreshPreviewAsync(ConfigChanged)
    → configJson != _lastRenderedConfigJson → configChanged = true
    → forceFullByReason = true (ConfigChanged)
    → canIncremental = false
    → CaptureCaretAndScrollAsync()              ← ⭐ 保存光标+滚动
    → FullNavigatePreview()                     ← NavigateToString，DOM 全部销毁重建
      → OnPreviewNavigationCompleted            ← 恢复焦点 + RestoreCaretAfterNavigation
```

**问题根因**：FullNavigatePreview 销毁了整个 DOM，恢复光标依赖 `restoreCaretBookmark`，但新 DOM 的节点结构与旧 DOM 不同（分栏/分页可能重排），导致书签无法匹配 → **光标丢失**。

## 十一、增量更新的失败链路

```
ContentInput → IncrementalUpdateFlowAsync
  → JS: updateSource(bodyHtml, null, null)
    → JS 内部：
      1. 创建临时 div，innerHTML = bodyHtml
      2. 逐块比较旧 #source 与新内容
      3. 仅替换变化的块 → 保持未变化块的 DOM 引用
      4. rebuildColumnsFromSource → 重新分栏
      5. restoreCaretBookmark → 恢复光标
    → 返回 true/false

  成功 → return（DOM 保持，光标保持 ✅）
  失败/抛异常 → fall through 到完整刷新
    → CaptureCaretAndScroll
    → FullNavigatePreview → 光标可能丢失 ⚠️
```

## 十二、内容回弹机制分析

"内容回弹"指：用户在图纸面板编辑后，内容被旧版本覆盖回去。

### 发生条件

```
时间线：
  T0  用户在图纸面板打字 → JS notifyContentChanged (防抖中)
  T1  编辑器侧的 SchedulePreviewRefresh(ContentInput) 触发
      → RefreshPreviewAsync → IncrementalUpdateFlowAsync
      → JS updateSource(旧 bodyHtml)  ← 此时用旧 MarkdownText 渲染的 HTML
      → #source 被覆盖为旧内容 → rebuildColumnsFromSource → 用户看到内容"跳回"
  T2  JS notifyContentChanged 终于发出 → postMessage(新内容)
      → 但图纸 DOM 已被旧内容覆盖 → 新 notifyContentChanged 可能发出的还是旧内容
```

### 现有防护

1. **焦点检查**：`SchedulePreviewRefresh` 中，若图纸有焦点 + reason=ContentInput → 丢弃
2. **哈希去重**：`_lastPreviewContentHash` 防止重复处理同一内容
3. **版本号**：`_lastPreviewContentVersion` 防止旧版本覆盖新版本

### 防护不足之处

- 焦点检查仅在 `SchedulePreviewRefresh` 入口，若用户在防抖期间切走焦点，刷新仍会执行
- 编辑器 input 事件与图纸 contentChanged 之间存在时间窗口，可能出现交叉覆盖

## 十三、四大问题根因总结

| 问题 | 根因 | 发生位置 |
|------|------|----------|
| **配置变更光标丢失** | ConfigChanged → 必走 FullNavigatePreview → DOM 全毁 → 书签无法在新 DOM 中定位 | PreviewManager.RefreshPreviewAsync else 分支 |
| **增量失败光标丢失** | IncrementalUpdateFlowAsync 失败 → fall through 到 FullNavigatePreview | PreviewManager.RefreshPreviewAsync catch 分支 |
| **内容回弹** | 编辑器 input 触发的 RefreshPreview 用旧 MarkdownText 覆盖了图纸面板正在编辑的新内容 | SchedulePreviewRefresh → RefreshPreviewAsync → updateSource |
| **滚动位置丢失** | FullNavigatePreview 后 viewportEl 是新 DOM，RestoreCaretAfterNavigation 的 scrollTop 赋值时机可能在 DOM 尚未完成布局前 | OnPreviewNavigationCompleted → RestoreCaretAfterNavigationAsync |
