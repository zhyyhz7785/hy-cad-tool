## 一、当前“图纸模式”结论（先看这个）

当前实现已经固定走 **Flow Experience Paper Mode（图纸主编辑流）**，不是旧版多页分页渲染主路径：

- 模式开关常量：`UseFlowExperiencePaperMode = true`
- `ToInteractiveHtml(...)` 入口直接分流到 `ToFlowExperienceHtml(...)`
- `PreviewManager.RefreshPreviewAsync(...)` 在该模式下跳过 `LayoutEngine` 的分配结果应用（`_latestLayoutResult = null`）

### 2.4 关键方法详解

#### 1) `RefreshPreviewAsync(...)`（图纸模式主控）

输入：
- `EditorViewModel` 当前文本与配置
- 刷新原因（内容输入/配置改变/视口变化等）

处理：
1. 读取 `viewModel.BuildConfig()`，序列化为 `configJson` 用于配置变更比较；
2. 读取 `PreviewHtmlRenderer.IsFlowExperiencePaperMode`；
3. 若图纸模式开启：
   - 清空脏块区间；
   - `_latestLayoutResult = null`（不走旧布局分配链）；
4. 若 WebView 未就绪，先生成 HTML 放入 `_pendingPreviewHtml`；
5. 若就绪，按原因判断是否允许增量：
   - 满足条件走 `IncrementalUpdateAsync(...)`；
   - 失败或不满足则 `FullNavigatePreview(...)`；
6. 刷新 `_renderedPreviewScale`、`_previewVersion`、页状态。

输出：
- 更新后的页面内容与内部版本状态

调用链：
- 被 `EditorWindow.RefreshPreviewAsync(...)` 调用
- 内部调用 `PreviewHtmlRenderer.ToInteractiveHtml(...)`

代码定位：

- `217:314:HyCADTool.MarkdownEditor/Services/PreviewManager.cs`
- `585:590:HyCADTool.MarkdownEditor/Views/EditorWindow.xaml.cs`

#### 2) `TryHandlePreviewWebMessage(...)`（双向同步入口）

输入：
- 预览页面 `postMessage` 的 JSON

处理分支：
- `paperScale`：同步缩放回 ViewModel；
- `wheelZoom`：按滚轮步长调用 `ApplyPreviewScaleStep(...)`；
- `pageState`：更新当前页/总页；
- `paperGeometry`：回写 `PageWidthMm/PageHeightMm`；
- `paperMargins`：回写四边距；
- `contentChanged`：预览编辑后回写 Markdown（含 hash/version 去重）。

输出：
- `markdownChanged != null` 时触发编辑器同步内容

调用链：
- 被 `EditorWindow.OnPreviewWebMessageReceived(...)` 调用

代码定位：

- `79:174:HyCADTool.MarkdownEditor/Services/PreviewManager.cs`
- `472:483:HyCADTool.MarkdownEditor/Views/EditorWindow.xaml.cs`

#### 3) `SyncFromPreviewAsync(...)`（统计口径回流）

输入：
- JS `getPreviewStats()` 返回的序列化对象

处理：
1. 解析为 `PreviewStats`；
2. 更新页状态；
3. 回写 `CharsPerColumn`；
4. 回写 `ColumnParagraphIndices`（优先文本字段，兜底二维数组转文本）。

输出：
- ViewModel 统计字段与页面状态同步

代码定位：

- `421:475:HyCADTool.MarkdownEditor/Services/PreviewManager.cs`

### 2.5 状态管理（图纸模式视角）

`PreviewManager` 维护三层状态：

1. **渲染生命周期状态**：`_previewReady/_hasInitialRender/_pendingPreviewHtml`
2. **内容版本状态**：`_markdownVersion/_previewVersion/_lastMarkdownSnapshot`
3. **交互回写状态**：`_latestPreviewStats/_currentPage/_totalPages`

图纸模式下，布局状态弱化为“页面内 JS 自主重排”，C# 侧主要做配置同步与宿主桥接。

### 3.4 关键方法详解

#### 1) `ToInteractiveHtml(...)`

输入：
- Markdown、栏数、缩放、`EditorConfig`

处理：
1. 判断模式开关；
2. 在当前实现中直接进入 `ToFlowExperienceHtml(...)`；

输出：
- 可执行的交互预览页面

代码定位：

- `30:39:HyCADTool.MarkdownEditor/Html/PreviewHtmlRenderer.cs`

#### 2) `ToFlowExperienceHtml(...)`

输入：
- Markdown + 图纸配置（页宽高、边距、栏数、栏距、字体、缩放）

处理：
1. 计算像素参数：`paperWidthPx/paperHeightPx/margins/gapPx`；
2. 模板替换 CSS token，生成纸张外观与交互控件样式；
3. 模板替换 JS token，注入运行时参数（比例、栏数、几何）；
4. 组装 DOM 骨架：`source + viewport + paper + margin guides + resize handles + footer`；
5. 内联 JS 完成初始化与事件绑定。

输出：
- Flow 图纸交互页面

## 五、状态转换与调用链（图纸模式完整链路）

### 5.1 首次进入排版模式

1. `ApplyWorkspaceMode(Layout)` 切到“图纸主编辑”；
2. `RefreshPreviewAsync(ViewportChanged)` 触发预览刷新；
3. `PreviewManager.RefreshPreviewAsync(...)` 生成 Flow HTML；
4. WebView `init()` 后上报 `pageState/paperScale`；
5. C# 更新页码与缩放状态。

## 六、当前设计的可维护性要点

1. **单开关收敛路径**：`UseFlowExperiencePaperMode=true` 让“当前图纸模式”路径明确，调试成本低。  
2. **协议稳定**：`paperGeometry/paperMargins/contentChanged` 已形成固定消息契约。  
3. **状态回环闭合**：JS 改动 -> C# 回写 -> C# 再下发，最终一致。  
4. **增量策略可保底**：`_incrementalFallbackFuse` 保证失败时可回落全量。  
5. **风险提示**：同文件内仍保留旧模板/旧函数族（非主路径），后续可考虑进一步隔离以降低认知负担。
