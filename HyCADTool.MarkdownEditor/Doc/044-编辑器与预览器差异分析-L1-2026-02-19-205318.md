# 编辑器与预览器差异分析（L1）

## 项目定位
`HyCADTool.MarkdownEditor` 是一个 WPF + WebView2 的 Markdown 编辑组件：  
编辑器负责高效输入与基础格式操作，预览器负责图纸化排版与版面结果反馈，两者共同输出可用于 CAD 文档场景的结构化内容。

## 技术栈
- 框架：`.NET 8 (WPF)`
- 内嵌浏览器：`Microsoft.Web.WebView2`
- Markdown 解析：`Markdig`
- 序列化与消息：`Newtonsoft.Json`
- 版面计算：`HyCADTool.TextLayout`

## 模块关系图（文字版）
`EditorLauncher`（入口）
→ `EditorWindow`（宿主窗口，承接双 WebView）
→ `VditorHtmlTemplate`（编辑器 HTML 生成）
→ `PreviewManager`（预览调度与状态同步）
→ `PreviewHtmlRenderer`（预览 HTML/CSS/JS 生成）
→ `EditorViewModel`（统一状态模型：文本、参数、页面状态）

## 编辑器 vs 预览器：定位差异
| 维度 | 编辑器（Editor） | 预览器（Preview） |
|------|---|---|
| 核心目标 | 快速输入与修改 Markdown | 将内容映射为图纸化可视版面 |
| 页面载体 | `Vditor`（IR 模式） | 自定义 Paper/Column 预览页面 |
| 关注点 | 光标体验、工具栏命令、输入连贯性 | 页尺寸、边距、分栏、缩放、页状态 |
| 状态来源 | 用户实时输入事件 | `EditorConfig` + Markdown + 布局结果 |
| 输出结果 | 最新 Markdown 文本 | 可视排版结果与统计信息 |
| 交互节奏 | 高频、实时、以输入为主 | 中高频、以渲染/同步为主 |

## 数据流（L1）
1. 外部输入 JSON 进入 `EditorViewModel`（初始文本 + 配置）。
2. 编辑器 WebView 加载 Vditor 页面并接收初始 Markdown。
3. 用户输入后，编辑器通过 WebMessage 回传文本到 ViewModel。
4. 预览调度器读取最新文本与配置，生成预览 HTML 并刷新预览 WebView。
5. 预览页面回传页码/统计/版面信息，ViewModel 更新 UI 状态。
6. 最终由宿主导出 EditorResult JSON（文本 + 配置 + 视图状态）。

## 职责边界（一句话）
| 模块 | 一句话职责 |
|------|-----------|
| `Html/VditorHtmlTemplate` | 只负责“编辑器页面”的 HTML 模板与编辑侧 JS 能力注入。 |
| `Services/PreviewManager` | 只负责“何时刷新预览、如何同步状态”的调度决策。 |
| `Html/PreviewHtmlRenderer` | 只负责“预览页面长什么样”的 HTML/CSS/JS 产出。 |
| `ViewModels/EditorViewModel` | 作为编辑器与预览器之间的共享状态中枢。 |
| `Views/EditorWindow` | 作为双 WebView 宿主，连接消息、命令与生命周期。 |

## 当前架构收益
- 输入体验与排版体验解耦，避免“编辑逻辑污染排版逻辑”。
- 预览可独立演进（布局策略、样式、统计）而不破坏编辑输入链路。
- ViewModel 作为单一状态源，便于后续增加导出、打印或只读预览模式。

## L1 结论
- 编辑器是“内容生产层”，预览器是“版面解释层”，二者不是重复功能而是上下游关系。  
- 当前结构已经形成“编辑快路径 + 预览重路径”的双通道，适合继续沿“编辑稳定优先、预览能力增强”方向演进。
