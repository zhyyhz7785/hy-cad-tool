我来仔细审视这份架构文档，从几个维度找出潜在问题。基于这份架构文档，我逐层审视后发现了以下问题，按严重程度排列：

------

## 🔴 严重问题

**[问题 #1] AutoCAD 进程崩溃风险 — WebView2 运行时依赖**

WebView2 需要用户机器上安装对应的运行时（Edge WebView2 Runtime）。AutoCAD 用户的生产环境往往是锁定的企业电脑，不一定有这个运行时，或者版本不匹配。文档里没有任何关于"运行时缺失时怎么处理"的说明。

可能后果：用户点击 AutoCAD 插件功能，直接弹出崩溃报错，整个 AutoCAD 可能跟着不稳定。

Cursor 修改指令：`请在 EditorLauncher.ShowDialog() 入口处添加 WebView2 运行时版本检测，如果检测失败，弹出中文提示框说明需要安装的运行时版本和下载地址，不要让程序崩溃`

------

**[问题 #2] 反射调用没有版本契约保障**

AutoCAD 主项目通过"反射"调用这个类库，意味着它是用函数名字符串去找 `ShowDialog` 方法的。一旦这个方法改名、参数顺序变了、返回值类型变了，反射调用会在运行时静默失败，编译期完全不报错。

可能后果：你改了编辑器代码，在编辑器项目里编译通过，但 AutoCAD 调用时直接抛出异常，而且排查极其困难，因为没有编译警告。

Cursor 修改指令：`请在 EditorLauncher 类上添加一个版本常量字段（如 public const string ContractVersion = "1.0"），并在 Models/ 中补充一份接口契约注释文档，说明 ShowDialog 的参数格式和返回格式不可随意修改`

------

## 🟠 功能缺陷

**[问题 #3] VditorCacheManager 缓存策略不明**

文档提到"CDN 资源本地缓存"，但完全没说明：缓存在哪个目录、缓存失效机制是什么、离线环境能否正常工作、缓存损坏时怎么恢复。

可能后果：用户在没有网络的工厂环境（AutoCAD 常见场景）中打开编辑器，Vditor 编辑器空白无法加载。或者缓存里存了旧版本资源，编辑器行为异常却找不到原因。

Cursor 修改指令：`请在 VditorCacheManager 中添加：1) 缓存目录改为应用本地 AppData 路径而非临时目录；2) 添加缓存完整性校验（文件是否存在+大小校验）；3) 如果缓存失败，显示中文错误提示而不是静默白屏`

------

**[问题 #4] PreviewStats 回传机制不完整**

数据流图里写了"预览JS ──统计──→ PreviewStats 回传"，但 `EditorResult` 里有 `CharsPerColumn` 和 `PreviewStats` 两个字段，这说明统计数据要传回给 AutoCAD 主项目。文档完全没说明：如果用户没有触发预览（直接确认），这两个字段是空值还是默认值，AutoCAD 主项目能否接受空值。

可能后果：AutoCAD 主项目拿到空的 `PreviewStats`，排版计算出错，图纸里的文字块尺寸不对。

------

**[问题 #5] 用户编辑过程中无自动保存**

数据流中的"用户编辑循环"只描述了实时预览刷新，没有提到任何草稿自动保存机制。如果 AutoCAD 突然崩溃（这在 CAD 软件中很常见），编辑器窗口会跟着消失。

可能后果：用户花了半小时编辑的设计说明全部丢失。

Cursor 修改指令：`请在 EditorViewModel 中添加定时自动保存草稿功能，每60秒把当前 Markdown 内容保存到 %TEMP%/HyCADTool_draft.md，下次打开编辑器时检测草稿文件并提示用户是否恢复`

------

## 🔵 维护隐患

**[问题 #6] EditorViewModel 职责过重**

文档描述 EditorViewModel 是"唯一 ViewModel"，管理"所有可调参数、Markdown 文本、状态栏、命令绑定"。这意味着一个类要处理编辑内容、界面状态、底部参数面板、状态栏，几乎整个应用的逻辑都在里面。

可能后果：这个文件很可能已经有几百行甚至上千行代码了，以后要改任何一个小功能都需要在这个大文件里翻找，改了一处容易意外影响另一处。

Cursor 修改指令：`请把 EditorViewModel 拆分为至少三个部分：MarkdownContentViewModel（管理文本内容）、PreviewConfigViewModel（管理预览参数）、UIStateViewModel（管理窗口状态和状态栏），让每个部分只负责一件事`

------

**[问题 #7] 模块命名有歧义**

`Html/` 文件夹下有 `VditorHtmlTemplate`、`VditorJsHelper`、`PreviewHtmlRenderer` 三个模块，但还有一个 `Services/PreviewManager` 也负责"预览刷新调度"。预览相关的逻辑分散在 `Html/` 和 `Services/` 两个地方，没有清晰的边界。

可能后果：以后要修改预览功能，不知道该去改 `PreviewHtmlRenderer` 还是 `PreviewManager`，容易改错地方。

------

**[问题 #8] RegressionSamples 的维护没有保障机制**

文档提到有 10 个测试样本，但没有说明：这些测试是手动跑的还是自动化的？谁负责在代码改动后跑回归测试？没有自动化测试意味着这 10 个样本只是摆设。

------

## 🟡 体验问题

**[问题 #9] 分栏预览和 Vditor 编辑器是两个独立的 WebView2 实例**

从架构来看，`PreviewPanelControl` 负责预览，Vditor 编辑器也在 WebView2 里运行，这很可能是两个独立的 WebView2 进程。每个 WebView2 进程大约消耗 100~200MB 内存。

可能后果：AutoCAD 本身已经是内存大户，再加两个 WebView2，低配工程师电脑可能直接卡死。建议确认是否可以共用一个 WebView2 实例。
