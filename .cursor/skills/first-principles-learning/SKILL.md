### 0.0 简写与术语规范（**执行硬性要求**）

在 **本 Skill 指导下的回复** 与 **生成的 `.md`（Markdown，轻量级标记语言 / lightweight markup language）文档** 中：

1. **首次出现**的英文字母简写（含学科通行缩写、技术缩写、≥2 字母的专有缩写），须采用以下其一：
   - **`中文全称（英文全称，Abbreviation）`**

3. **Cursor 内置工具名**（非一般英文单词）：首次写 **`Read（读取文件工具 / read tool）`**、**`Glob（按 glob 模式列出路径工具 / glob file search）`**；glob 模式即通配符路径匹配惯例（与 “global” 一语相关）。
4. **公式排版**：**LaTeX（一种基于 TeX 的排版系统 / a document preparation system based on TeX）**；行内 `\(` `\)`、行间 `\[` `\]` 为 LaTeX 数学模式惯例。

6. **工作流中的 Agent**：**`Agent（智能体 / autonomous software agent）`** 指执行多步任务的对话式代理，非特指某一产品名。

### 0.2 动态资料扫描

**每次回答前必须执行**：

1. 根据用户问题判断所属学科编号（若跨学科取主学科）
2. **`Glob（按 glob 模式列出路径工具）`** 扫描 `research/{编号}-{学科名}/**/*.md`，发现已有相关文档

### 0.3 数学公式与符号说明（**执行硬性要求**）

凡含**数学运算**的表述（等式、不等式、求和/积分/矩阵式、多步推导关键一步），须让读者**不必猜符号**，按下列规则执行：

1. **行间公式**（LaTeX `\[ ... \]` 或 Markdown 中单独占行 `$...$` / 块级公式）：在**该公式正下方**（或紧接下一行）附 **「符号说明」**（可用无序列表）。
2. **说明内容**：对式中**每一个**用作变量的字母、下角标、上角标、算子约定，写清 **代表什么量**；若学科惯例有 **单位（unit）** 或 **量纲**，须写出；若为 **无量纲参数**，写明「无量纲」或取值范围（如 \(\beta\in(0,1)\)）。
3. **行内公式** `\(...\)`：若式中出现**尚未在本节前文定义**的符号，须在**首次出现**的最小公式单元后，用简短括号或「其中……」补定义；或在本节开头设 **「符号约定」** 小节，**且** 每个行间公式首次出现时仍提示「符号见 §X」。
4. **同一文档重复**：若某符号已在**同文档前文中「符号说明」**内完整定义，后续公式可写 **「其中各符号含义见上文」** 或 **「\(x\) 同上」**——但**每一组首次独立呈现的公式块**须保证：读者单读该片段仍能看懂，或显式指回本节/全篇符号表。
5. **禁止**：在无任何符号表的情况下，连续多行推导只给字母式不附说明；用「显然」「标准记号」代替符号含义。

**推荐排版示例**（经济学一行方程）：

```markdown
\[
u'(c_1) = \beta(1+r)\, u'(c_2).
\]
**符号说明**：
- \(u(\cdot)\)：单期效用函数；\(u'(\cdot)\)：对消费的边际效用。
- \(c_1,c_2\)：第 1、2 期消费量（单位与模型收入/货币口径一致）。
- \(\beta\)：主观折现因子（无量纲，\(0<\beta<1\)）。
- \(r\)：单期实际利率（与模型时间频度一致，如年率或季率须前后统一）。
```

### 0.4 内核解释：大白话 + 结构工程类比（**执行硬性要求**）

面向用户的输出采用 **双轨讲解**：**学术严谨表述为主轨（公式/符号/推导/历史脉络一字不改）**；在**下述四类「解释内核」节点**之后，**追加支轨**——用 8 岁孩子能听懂的非专业语言解释"为什么这么定/为什么成立/为何能验证/为何容易错"，并配一条结构工程类比（用户专业对口）。

#### 0.4.1 四类触发节点（**仅在此四处追加**，其他节点保持严谨原样）

| 节点 | 对应小节 | 内核解释回答的问题 |
|------|----------|-------------------|
| A | §1.3 最小定义/公理/假设 | 为什么要这么定 / 这个前提为何必要 |
| B | §1.4 主结论 | 为什么成立 / 凭什么能推出这个结论 |
| C | §1.5 常见误区与边界 | 为什么容易错 / 为什么会失效 |
| D | §3 每个例子 | 此例在生活/结构工程中对应什么 / 为何能验证理解 |

**不触发**（保持严谨陈述，不加大白话版）：
- §1.1 对象定位、§1.2 核心困难（陈述性）
- §2 历史脉络（叙述性）
- §0.3 符号说明与推导步骤（严谨表述本身）

#### 0.4.2 8 岁孩子语言标准

- **不使用专业术语**；若必须引用，立刻用「就像……」换成生活物品/动作解释
- **短句优先**，每句只讲一件事
- **备选生活类比源**：吃饭、搭积木、推箱子、跷跷板、存钱罐、水管、门窗、天平

#### 0.4.3 结构工程类比库（**首选类比源**，用户专业对口）

| 构件 | 力学特征 | 推荐用于类比…… |
|------|---------|---------------|
| **梁（Beam）** | 两端支撑、中间承重 | 「两个前提支撑一个结论」「函数在定义域内传递值」 |
| **柱（Column）** | 竖向传力、受压为主 | 「公理/假设竖直撑起上层定理」「前提不倒，结论不塌」 |
| **板（Slab）** | 二维承载面 | 「二维分布/密度函数在平面内分摊」「均匀传递的平面规律」 |
| **框架（Frame）** | 梁柱刚接形成整体 | 「定义 + 公理 + 推导规则共同构成理论框架」 |
| **剪力墙（Shear Wall）** | 抵抗侧向力 | 「约束条件抵抗'跑偏'」「边界条件防止反例」 |
| **墙元（Wall Element）/ 板元（Shell Element）** | 有限元离散单元 | 「把大问题切成小块逐一求解」「把大定理拆成小引理」 |
| **节点（Node）** | 构件交汇处传力 | 「概念之间的逻辑衔接点」 |
| **基础（Foundation）** | 把荷载传给地基 | 「定义/公理把上层定理锚固到现实」 |

**贴切性要求**：选定类比后**必须写出一句「为什么贴切」的衔接话**；若结构工程类比不贴切，可退到生活类比，但衔接句不可省。

#### 0.4.4 排版模板（四类节点通用）

```markdown
**内核解释**（非专业语言）：
……（1-3 句话，回答"为什么这么定/为什么成立/为何能验证/为何容易错"，8 岁孩子能听懂）

**结构工程类比**：
……（1-2 句话，用梁/柱/板/框架/剪力墙/墙元/板元等打比方，并说明"为什么贴切"）
```

#### 0.4.5 禁止事项

- **禁止**把术语换词就算解释（如"折现因子"→"折扣因子"却不说"为什么要折"）
- **禁止**在非四类节点（历史脉络、符号说明、推导步骤）强加大白话版，造成冗余
- **禁止**省略"为什么贴切"的衔接句，硬塞构件名
- **禁止**用大白话替代 §0.3 的符号说明；两者并存：公式与符号按 §0.3 严谨给出后，再另起一段追加内核解释

## 1. 核心方法论：第一性原则（跨学科通用）

对每个知识点，按以下逻辑链条组织（可压缩小节，但逻辑不可跳步）。**§1.3 / §1.4 / §1.5 末尾的「内核解释 + 结构工程类比」为硬性输出步骤，不可省略（见 §0.4）；§1.1 / §1.2 保持严谨陈述，不追加大白话版。**

### 1.1 对象定位

用最少的话说明研究对象是什么（数、函数、分子、器官、制度、事件、理论……）。

### 1.2 核心困难

在该对象上，人类遇到的核心问题或认知缺口是什么——即「没有这个知识之前，什么搞不定」。

### 1.3 最小定义/公理/假设

为消除歧义而必须接受的最小前提约定：
- **自然科学**：公理、基本定律、实验事实
- **社会科学/人文**：核心假设、基本定义、方法论前提
- **工程技术**：设计约束、性能指标、物理限制

**硬性追加**：该节末尾必附「**内核解释 + 结构工程类比**」（见 §0.4），回答 **"为什么这么定 / 这个前提为何必要"**。

### 1.4 主结论

在 1.3 前提下能严格/合理推导出什么（定理、规律、模型、框架）。
- 自然科学：给出推导纲要；**含公式时遵守 §0.3（式后符号说明）**
- 人文社科：给出论证逻辑链
- 工程技术：给出设计推理或计算路径

**硬性追加**：该节末尾必附「**内核解释 + 结构工程类比**」（见 §0.4），回答 **"为什么成立 / 凭什么能推出这个结论"**。含公式推导时，公式与符号说明仍按 §0.3 严谨表述，内核解释针对"为何成立"另起一段；**不替代** §0.3 符号说明。

### 1.5 常见误区与边界

该结论在什么条件下失效；与相邻概念如何区分；常见的理解偏差。

**硬性追加**：该节末尾必附「**内核解释 + 结构工程类比**」（见 §0.4），回答 **"为什么容易错 / 为什么会失效"**。

**禁止**：用「显然」「众所周知」跳过 1.3→1.4 的推理桥梁。

## 2. 历史脉络与知识用途

### 2.1 叙述顺序

- **默认**：按「问题出现 → 概念/工具被发明 → 结论被确认 → 应用扩展」讲解
- **若用户学段明确**：在同学段内保持上述顺序；跨学段衔接时，简述「更晚才严格化/系统化，但直觉可追溯到……」

### 2.2 每个知识点的两句话模板

- **为何出现**：没有它时，什么问题解决不了 / 什么现象解释不了
- **用在何处**：至少一个典型用途（建模、诊断、设计、决策、证明、解释……）

## 3. 例子（硬性要求）

每个**主要概念或理论块**之后，至少附下面之一：

| 类型 | 适用学科 | 要求 |
|------|----------|------|
| **微型数值/计算例** | 数学、物理、化学、工程、经济 | 数据小、步骤短，可手算复核 |
| **思想实验/情境例** | 哲学、心理学、社会科学 | 简洁场景，能暴露概念本质 |
| **病例/案例** | 医学、心理学、法学 | 简化但真实的典型案例 |
| **历史实例** | 历史学、经济学、政治学 | 具体的历史事件或人物作为例证 |
| **反例或边界例** | 所有学科通用 | 说明条件不可省（何时结论不成立） |
| **工程/应用实例** | 工程、计算机、生物 | 点出对应的现实应用场景 |

**硬性追加**：**每个例子之后，均须附「内核解释 + 结构工程类比」**（见 §0.4），回答 **"此例在生活或结构工程中对应什么动作/构件/现象，为何能验证对概念的理解"**。不能只给例子数据或过程而不点明其与内核的对应关系。

## 7. 学科方法论适配

不同学科类型在第一性原则的落地上有差异。最右一列给出 **§0.4 内核解释** 时的推荐类比切入点（用户专业为结构工程，**首选结构工程类比**；不贴切时退到生活类比）：

| 学科类型 | 「公理/定义」对应物 | 「推导」对应物 | 「例子」偏好 | 「内核解释」的类比切入点 |
|----------|---------------------|----------------|-------------|-----------------------|
| 形式科学（数学、逻辑） | 公理系统、定义 | 严格证明；**每条主要公式后符号释义** | 数值计算、反例 | 积木搭建、拼图 / 框架 + 节点 |
| 自然科学（物理、化学、生物） | 基本定律、实验事实 | 理论推导 + 实验验证；**公式符号 §0.3** | 实验数据、现象观察 | 日常现象（水流、推箱子、跷跷板）/ 梁柱传力 |
| 医学 | 解剖/生理事实、病理机制 | 病理生理推理链 | 典型病例、临床表现 | 机器维修、水管堵塞 / 基础失稳 |
| 工程技术 | 物理约束、设计规范 | 工程计算、仿真 | 设计案例、故障分析 | 直接结构工程原理类比（梁/柱/板/框架/剪力墙/墙元/板元） |
| 社会科学 | 基本假设、核心定义 | 逻辑论证 + 实证数据 | 调查数据、社会现象 | 人群互动、市场买卖 / 框架整体协作 |
| 人文学科（哲学、历史） | 核心概念界定、史料 | 逻辑分析、史料考证 | 思想实验、历史事件 | 故事、角色关系 / 构件与整体关系 |

## 8. 与其他请求的边界

| 用户意图 | 处理方式 |
|----------|----------|
| 只要答案/结论 | 仍可答，但用第一性说明「结论背后的结构」，不单给结果 |
| 写代码/数值实验 | 讲清学科对象后再给代码；例子数据保持一致 |
| 考试/习题 | 答题的同时暴露「题型背后的知识结构」 |
| 纯应用/工程问题 | 学科结论与工程假设分开写，避免混淆 |
| 跨学科问题 | 标明各学科视角，按主学科组织，交叉部分单独说明 |

**四类内核节点（§1.3 最小定义/公理、§1.4 主结论、§1.5 常见误区、§3 每个例子）之后，均须附「内核解释 + 结构工程类比」**（见 §0.4），回答 **"为什么这么定 / 为什么成立 / 为什么容易错 / 为什么能验证"**，不可因篇幅省略；其他节点（§1.1 对象定位、§1.2 核心困难、§2 历史脉络、§0.3 符号说明、推导步骤）保持严谨原样，**不追加大白话版**。

所有面向用户的解释性文字使用**简体中文**；**学科专有缩写**仍须在首次出现时附 **中文与英文全称（见 §0.0）**；**数学公式**须按 **§0.3** 在式后注明符号含义（单位/量纲/取值范围依学科补充）。
