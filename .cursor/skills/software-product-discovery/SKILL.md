# 软件产品调研 → 实现路径规划

在为某个功能「从零做一款软件」之前，先把**做什么**和**怎么做**想清楚。本 skill 把流程固化为 5 个阶段，最终落盘一份调研报告。

- **范围**：到「最优实现路径 / 技术方案规划」为止，**不写实现代码**。
- **语言**：全程简体中文输出。
- **诚信**：竞品、价格、活跃度等事实**必须来自联网搜索**；查不到的留空并标「待核实」，**禁止编造**。

---

## 工作流总览

复制此清单并逐项推进（一个阶段做完再进下一个）：

```
- [ ] 阶段 0：锁定目标功能、目标用户、平台形态、约束、五维权重
- [ ] 阶段 1：联网搜索竞品（各形态全覆盖），列成竞品清单
- [ ] 阶段 2：五维度逐个列优缺点 + 打分 + 汇总对比表
- [ ] 阶段 3：从分析推导产品定义（空白、定位、MVP、非功能目标、差异化锚点）
- [ ] 阶段 4：最优实现路径（构建方式取舍、技术选型、架构、路线图、风险）
- [ ] 阶段 5：按规范命名落盘到 docs/product-discovery/
```

---

## 阶段 0：锁定目标与约束（搜索前必做）

不先锁定目标就开搜 = 方向跑偏。先和用户对齐下列项；用户没说的，**给出合理默认假设并显式标注「假设」**，让用户一眼可纠正。

| 项 | 要确认什么 |
|---|---|
| 核心功能 | 一句话说清「这款软件帮谁，解决什么问题」 |
| 目标用户 | 谁用、专业度、规模、付费意愿 |
| 平台形态 | 桌面(Win/Mac/Linux) / Web / 移动(iOS/Android) / 浏览器插件 / CLI / 库·SDK / CAD·IDE 插件 |
| 关键约束 | 开源还是商业、预算与人力、时间窗口、技术栈偏好、离线/在线、合规要求 |
| 成功标准 | 怎样算「做成了」（用户数、效率提升、替代某竞品…） |
| 五维权重 | 按目标定权重（工具类→易用性高；金融/医疗→安全高；高频生产→稳定高），用于阶段 2 加权总分 |

**输出**：一段「目标陈述」+ 一张五维权重表（合计 100%）。

---

## 阶段 1：竞品搜索（强制联网）

用 `WebSearch` 系统性搜索，**中英文都搜**，年份用当前年。目标是穷尽「同类 + 可替代 + 邻域参考」，避免只盯一两个知名产品。

**查询模板**（按主题替换关键词）：

- `best {功能/品类} software` / `{品类} 软件 推荐 对比`
- `{品类} open source github` / `{品类} 开源 替代`
- `{已知竞品} alternatives` / `{已知竞品} 替代品`
- `{品类} reddit` / `{品类} 知乎 / V2EX 对比评测`
- `{品类} review G2 / Capterra / Product Hunt / AlternativeTo`

**形态全覆盖清单**（每类至少搜一次，避免遗漏）：

```
- [ ] 商业桌面/客户端软件
- [ ] 开源项目（GitHub / GitLab）
- [ ] SaaS / Web 应用
- [ ] 移动 App（iOS / Android）
- [ ] 浏览器插件 / IDE·CAD 插件
- [ ] CLI 工具 / 库 / SDK
- [ ] 间接替代（用别的方式解决同一痛点，如 Excel、手工流程）
```

**每个竞品记录字段**：

| 名称 | 形态 | 平台 | 商业模式·价格 | 开源? | 活跃度(最近更新) | 链接 | 一句话定位 |
|---|---|---|---|---|---|---|---|

**数量**：主流 5–12 个；额外标注 1–2 个「小众强者/隐形冠军」。**归类**为：直接竞品 / 间接替代 / 邻域参考。

---

## 阶段 2：五维度优缺点分析

对每个**直接竞品 + 关键间接替代**，逐个写 3–5 条优点、3–5 条缺点，并按五维各打 **1–5 分**（1=差，5=优）。证据尽量来自官网/文档/真实用户评价，主观推断要标注。

**五维评估子项（rubric）**：

1. **功能（Functionality）**：核心功能覆盖度、专业深度、高级/边界能力、集成与扩展（API/插件/导入导出/自动化）、平台覆盖广度。
2. **用户体验与易用性（UX & Usability）**：上手成本/学习曲线、界面现代度与信息密度、高频工作流效率（快捷键/批量/模板）、文档与帮助、中文与本地化、无障碍。
3. **可靠与安全（Reliability & Security）**：数据安全（加密/隐私/合规）、认证与权限、备份恢复与防丢失、开源透明度/可审计、漏洞历史与响应速度。
4. **稳定性（Stability）**：崩溃/Bug 频率、大数据量/大文件下的表现、资源占用、维护活跃度与更新节奏、兼容性（OS/依赖版本）。
5. **差异化（Differentiation）**：独特卖点(USP)、护城河/不可替代点、价格与商业模式、生态与社区、数据可迁移性（开放 vs 锁定）、目标人群细分。

> 「差异化」维度评**竞品**时 = 该产品**相对其他产品的独特护城河**；这一列读数将直接喂给阶段 3 找空白。

**汇总对比表**（加权总分 = Σ 各维得分 × 阶段 0 权重）：

| 竞品 | 功能 | 易用 | 可靠安全 | 稳定 | 差异化 | 加权总分 | 一句话总评 |
|---|---|---|---|---|---|---|---|

**关键产出**：一段「行业现状小结」——大家普遍做得好的是什么、普遍的痛点/短板是什么。

---

## 阶段 3：产品定义——该做什么样的软件

从阶段 2 的「普遍短板 + 未满足需求」反推机会，落到一个清晰的产品定义。

1. **机会矩阵**：把「用户高频痛点 / 未满足需求」× 「竞品满足度（高/中/低/空白）」交叉，**圈出空白格与低满足格** = 切入点。
2. **一句话定位**：为【目标用户】提供【核心价值】，区别于【主要竞品】之处在于【差异化锚点】。
3. **目标用户画像**：主要用户 + 次要用户（场景、痛点、当前替代方案）。
4. **MVP 功能集（MoSCoW）**：

| 优先级 | 含义 | 功能 |
|---|---|---|
| Must | 没有它产品不成立 | … |
| Should | 重要但 MVP 后可补 | … |
| Could | 锦上添花 | … |
| Won't(now) | 本期明确不做 | … |

5. **非功能目标**：把性能/可靠/安全/易用写成**可量化目标**，对齐你想超越竞品的那几维（如「打开 100MB 文件 < 2s」「核心流程 ≤ 3 步」）。
6. **差异化锚点**（至少 1 个，明确护城河）：成本 / 体验 / 垂直深耕 / 开放生态 / 数据可迁移 / AI 增强 / 与现有工具链集成 等。
7. **反向清单**：明确「不做什么」，防止做成又一个更差的复制品。

---

## 阶段 4：最优实现路径

「最优」= **以最小风险与成本，最快交付差异化价值**。先决定构建方式，再谈技术细节。

**① 构建方式决策（最关键，避免无脑从零自研）**：

| 方式 | 适用 | 代价 |
|---|---|---|
| 从零自研 | 差异化在核心引擎、现有方案均不可复用 | 最高成本、最高可控 |
| Fork 成熟开源二次开发 | 已有接近的开源底座，差异化在上层 | 省底座，受其架构与许可约束 |
| 套用库/引擎/API 做壳 | 核心能力可被现成库/云 API 覆盖 | 最快，受供应商/依赖锁定 |
| 现成 SaaS/低代码拼装 | 验证期、内部工具、非核心 | 最省力，定制与迁移受限 |

给出**推荐方式 + 理由**，并列 1 个备选。**优先复用，避免重复造轮子**。

**② 技术选型**：对齐平台与团队技能，给「默认 + 备选」，**不要堆砌一长串选项**：语言/运行时、UI 框架、数据存储、关键依赖（按差异化锚点选最关键的几项）。注意**许可证**与商业用途是否兼容。

**③ 架构概要**：模块切分、数据流、对外接口、关键技术风险点（一段话 + 必要时分层列表，不写代码）。

**④ 路线图**：里程碑 MVP → V1 → V2，每阶段「交付物 + 验收点」。**最痛功能先做**（最小可用切口），尽早能给真实用户试。

**⑤ 风险与对策**：

| 风险 | 类型(技术/许可/依赖/市场) | 影响 | 对策 |
|---|---|---|---|

**⑥ 假设验证**：怎样尽早验证产品假设（可点击原型、灰度、用户访谈、关键技术 PoC），把「最危险的假设」排在最前验证。

## 阶段 5：落盘报告

1. **目录**：`docs/product-discovery/`（不存在则创建）。
2. **序号**：用 `Glob` 扫描 `docs/product-discovery/*.md` 取最大序号 +1；首次从 `001` 开始。
3. **时间戳**：PowerShell 取 `Get-Date -Format "yyyy-MM-dd-HHmmss"`。
4. **文件名**：`{序号}-{软件主题}-产品调研-{YYYY-MM-DD-HHMMSS}.md`（对齐项目文档命名规范）。
5. 按下方模板写入；竞品事实附来源链接，存疑处标「待核实」。

## 自检清单

落盘前核对：

```
- [ ] 阶段 0 的目标与五维权重已确认（用户没说的已标「假设」）
- [ ] 竞品 ≥ 3 个且覆盖多种形态（不是清一色同类）
- [ ] 每个直接竞品都有优缺点 + 五维打分
- [ ] 有汇总对比表 + 加权总分 + 行业现状小结
- [ ] 产品定义含「差异化锚点」与「不做清单」（不是更差的复制品）
- [ ] 实现路径先做了「构建方式取舍」（评估过 Fork/复用，不是无脑自研）
- [ ] 技术选型给了默认+备选并核对许可证
- [ ] 路线图最痛功能先做 + 列了最危险假设的验证手段
- [ ] 竞品事实有来源链接，存疑处标「待核实」，无编造
- [ ] 报告已按规范命名写入 docs/product-discovery/
```

## 反模式（不要这样做）

- **跳过阶段 0** 直接搜竞品 → 方向跑偏。
- **只列功能、不打分、不对比** → 看不出差距与机会。
- **竞品只搜一种形态** → 漏掉开源/SaaS/插件里的强者。
- **产品定义没有差异化锚点** → 做出一个更差的复制品。
- **实现路径默认从零自研** → 没评估 Fork 开源/复用库，违背「最优/最省力」。
- **在本 skill 内直接写实现代码** → 越界；本 skill 终点是规划。
- **编造竞品、价格、用户数** → 一律以联网搜索为准，查不到就标「待核实」。
