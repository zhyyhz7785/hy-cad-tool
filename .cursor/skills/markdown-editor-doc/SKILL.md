# MarkdownEditor 渐进式文档生成

## 核心原则

**第一性原理**：先框架后细节，按需展开，不浪费 token。

用户通过 **L1–L4 关键词** 控制文档深度，每级独立输出，不重复上级内容。

---

## 触发关键词

| 关键词 | 深度 | 输出内容 | Token 预算 |
|--------|------|----------|------------|
| `文档L1` / `doc L1` | 架构总览 | 项目定位 + 模块关系图 + 数据流 | 极简，~200行 |
| `文档L2 [模块名]` / `doc L2 [module]` | 模块说明 | 指定模块的职责、类列表、关键接口 | 中等，~150行/模块 |
| `文档L3 [文件名]` / `doc L3 [file]` | 文件细节 | 逐方法说明、参数、调用链、状态管理 | 按需，单文件 |
| `文档L4 [范围]` / `doc L4 [scope]` | 问题诊断 | 代码异味、不合理设计、改进建议 | 按需 |

**不指定级别时**，默认执行 L1。

---

## L1：架构总览

**目标**：让用户 5 分钟理解整个项目是什么、怎么组织的。

**执行步骤**：

1. 读取 `HyCADTool.MarkdownEditor.csproj` 确认依赖和构建配置
2. 列出顶层目录结构（不深入文件）
3. 输出以下内容：

```
### 项目定位
一句话说明项目解决什么问题、谁调用它、输出什么

### 技术栈
框架 + 核心依赖（版本号）

### 模块关系图（文字版）
用缩进或箭头表示模块间依赖方向：
  EditorLauncher（入口）
    → EditorWindow（主窗口）
      → EditorViewModel（数据绑定）
      → Views/Controls/*（UI 控件）
      → Html/*（Vditor + 预览渲染）
      → Services/*（文件树/主题/预览管理）
    → Models/EditorContract（数据契约）

### 数据流
输入 JSON → EditorInput → 编辑 → EditorResult → 输出 JSON

### 模块一句话速查表
| 模块 | 一句话职责 |
|------|-----------|
| Models/ | ... |
| ViewModels/ | ... |
| Views/ | ... |
| Html/ | ... |
| Services/ | ... |
```

**禁止**：不列方法签名、不贴代码、不分析实现细节。

---

## L2：模块说明

**目标**：理解一个模块内部的类分工和交互。

**执行步骤**：

1. 读取指定模块目录下所有文件的类定义（前 50 行即可）
2. 输出以下内容：

```
### [模块名] 模块说明

#### 职责
该模块负责什么

#### 类列表
| 类 | 文件 | 职责 | 行数 |
|----|------|------|------|
| XxxClass | Xxx.cs | 一句话 | ~N |

#### 关键接口/事件
- 对外暴露的 public 方法/事件（签名 + 一句话）

#### 模块内协作
哪个类调用哪个类，用箭头表示

#### 依赖
依赖哪些外部模块/NuGet
```

**禁止**：不贴方法实现体、不逐行解释。

---

## L3：文件细节

**目标**：完全理解一个文件的每个方法在做什么。

**执行步骤**：

1. 读取指定文件的完整内容
2. 输出以下内容：

```
### [文件名] 详细说明

#### 类概述
类的职责、继承关系、实现的接口

#### 字段/属性
| 名称 | 类型 | 用途 |
|------|------|------|

#### 方法清单
| 方法 | 参数 | 返回 | 职责（一句话） |
|------|------|------|----------------|

#### 关键方法详解
对复杂方法（>20行）逐段说明逻辑：
1. 方法名
   - 输入：什么
   - 处理：分步骤描述
   - 输出：什么
   - 调用链：调用了谁、被谁调用

#### 状态管理
该类维护了哪些状态、状态转换条件
```

## L4：问题诊断

**目标**：找出代码中不合理的设计，给出改进建议。

**执行步骤**：

1. 读取指定范围的代码
2. 按以下维度逐项检查：

```
### [范围] 问题诊断

#### 🔴 严重问题（必须修）
- 问题描述 → 影响 → 建议修复方式

#### 🟡 设计改进（建议改）
- 问题描述 → 当前方式 → 更好的方式

#### 🟢 优化建议（可选）
- 描述 → 收益

#### 检查维度
- [ ] 职责单一：一个类是否做了太多事？
- [ ] 耦合度：View 是否直接操作数据？ViewModel 是否包含 UI 逻辑？
- [ ] 异常处理：是否有吞异常、空 catch？
- [ ] 资源管理：WebView2/文件流是否正确释放？
- [ ] 线程安全：UI 线程 vs 后台线程是否正确调度？
- [ ] 命名一致性：同一概念是否用了不同名称？
- [ ] 魔法值：是否有硬编码的数字/字符串应提为常量？
- [ ] 重复代码：是否有可提取的公共逻辑？
```

## 组合用法示例

```
用户: "文档L1"
→ 输出架构总览（~200行）

用户: "文档L2 Html"
→ 输出 Html/ 模块的类分工（~150行）

用户: "文档L3 PreviewHtmlRenderer.cs"
→ 输出该文件的完整方法说明

用户: "文档L4 ViewModels"
→ 诊断 ViewModel 层的设计问题

用户: "文档L2 Views 文档L2 Services"
→ 同时输出两个模块说明（合理，因为模块间有协作）
```

---

## 输出规范

1. **语言**：中文
2. **格式**：Markdown 表格 + 列表，不用散文
3. **禁止冗余**：不重复已输出的上级内容，不输出"让我来看看"等废话
4. **代码引用**：用 `startLine:endLine:filepath` 格式引用已有代码，不复制粘贴
5. **文档保存**：生成后保存到 `HyCADTool.MarkdownEditor/Doc/` 目录
