## 一、核心概念（只需理解这 4 个）

```
┌─────────────────────────────────────────────────────────────┐
│  你的电脑                                                    │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐              │
│  │ 工作目录 │ → │ 暂存区   │ → │ 本地仓库 │              │
│  │ (文件夹) │    │ (Stage)  │    │ (Commits)│              │
│  └──────────┘    └──────────┘    └──────────┘              │
│       ↑              ↑               ↑                      │
│    你在编辑       git add        git commit                 │
└─────────────────────────────────────────────────────────────┘
                                           │
                                           │ git push
                                           ▼
                                  ┌──────────────┐
                                  │ 远程仓库     │
                                  │ (GitHub等)   │
                                  └──────────────┘
```

### 4 个概念，记住就够了

| 概念 | 位置 | 说明 | 比喻 |
|------|------|------|------|
| **工作目录** | 你的文件夹 | 你正在编辑的文件 | 草稿纸 |
| **暂存区** | .git 内部 | 准备提交的文件 | 购物车 |
| **本地仓库** | .git 内部 | 已保存的历史版本 | 相册 |
| **远程仓库** | GitHub | 云端备份 | 云盘 |

## 二、日常操作（5 个命令够用）

### 你 99% 的时间只需要这 5 个命令

```bash
# 1. 查看状态（最常用，随时可以用）
git status

# 2. 添加文件到暂存区
git add .                    # 添加所有修改
git add 文件名               # 添加单个文件

# 3. 提交到本地仓库
git commit -m "描述这次改了什么"

# 4. 推送到远程（备份到 GitHub）
git push

# 5. 拉取远程更新（如果在其他电脑改过）
git pull
```

### 命令速查卡

```
┌────────────────────────────────────────────────────────────┐
│ 日常工作流程：                                              │
│                                                            │
│   写代码 → git status → git add . → git commit → git push  │
│                                                            │
│ 翻译：                                                      │
│   写代码 → 看看改了啥 → 放进购物车 → 结账保存 → 备份云端    │
└────────────────────────────────────────────────────────────┘
```

## 三、Cursor 中的 Git（图形界面操作）

### 3.1 打开源代码管理面板

**快捷键**: `Ctrl + Shift + G`

或者点击左侧边栏的 **分支图标**（第三个图标）

### 3.2 Cursor Git 界面说明

```
┌─────────────────────────────────────────┐
│ 源代码管理                               │
├─────────────────────────────────────────┤
│ Changes (改动的文件)                     │
│   ├── M  file1.cs    (Modified 修改)    │
│   ├── A  file2.cs    (Added 新增)       │
│   ├── D  file3.cs    (Deleted 删除)     │
│   └── U  file4.cs    (Untracked 未跟踪) │
├─────────────────────────────────────────┤
│ Staged Changes (已暂存，准备提交)        │
│   └── M  file5.cs                       │
├─────────────────────────────────────────┤
│ [输入提交信息...]                        │
│ [✓ 提交按钮]                            │
└─────────────────────────────────────────┘
```

### 3.3 Cursor 中的常用操作

| 操作 | 图形界面做法 | 等同命令 |
|------|--------------|----------|
| **查看改动** | 打开源代码管理面板 | `git status` |
| **暂存文件** | 点击文件旁边的 `+` 号 | `git add 文件名` |
| **暂存全部** | 点击 "Changes" 旁边的 `+` | `git add .` |
| **取消暂存** | 点击已暂存文件旁边的 `-` | `git reset 文件名` |
| **提交** | 输入信息，按 `Ctrl+Enter` | `git commit -m "..."` |
| **推送** | 点击 `...` → Push | `git push` |
| **拉取** | 点击 `...` → Pull | `git pull` |
| **查看差异** | 点击文件名 | `git diff 文件名` |

### 3.4 状态栏（左下角）

```
┌─────────────────────────────────────────┐
│  ↻ New ↑2 ↓0                            │
│  │  │   │  └── 远程有 0 个新提交        │
│  │  │   └───── 本地有 2 个待推送        │
│  │  └───────── 当前分支名               │
│  └──────────── 同步按钮                 │
└─────────────────────────────────────────┘
```

**点击 `↻` 按钮** = 同步（相当于 pull + push）

## 五、提交信息规范（简化版）

### 格式

```
类型: 简短描述

类型包括：
- feat:  新功能
- fix:   修复 bug
- docs:  文档
- refactor: 重构
- test:  测试
```

### 好的提交信息示例

```bash
# ✅ 好的
git commit -m "feat: 添加 DCEL 曲线简化功能"
git commit -m "fix: 修复圆弧分割问题"
git commit -m "docs: 添加项目分析报告"
git commit -m "refactor: 优化 OverKill 性能"

# ❌ 不好的
git commit -m "update"
git commit -m "修改"
git commit -m "123"
```

## 六、常见场景处理

### 场景 1：断断续续开发，忘了上次做到哪

```bash
# 查看最近的提交
git log --oneline -5

# 查看当前改动了什么
git status

# 查看具体改动内容
git diff
```

**Cursor 中**: `Ctrl+Shift+G` 打开源代码管理面板，一目了然

### 场景 2：改错了，想撤销

```bash
# 撤销工作目录的改动（还没 add）
git checkout -- 文件名

# 撤销暂存（已经 add，但没 commit）
git reset HEAD 文件名

# 撤销最后一次提交（已经 commit，但没 push）
git reset --soft HEAD~1
```

**Cursor 中**: 右键文件 → "Discard Changes"

### 场景 3：提交信息写错了

```bash
# 修改最后一次提交的信息（还没 push）
git commit --amend -m "新的提交信息"
```

### 场景 4：想看某个文件的历史

```bash
git log --oneline 文件名
```

**Cursor 中**: 右键文件 → "Open Timeline"

### 场景 5：换电脑开发

```bash
# 新电脑上
git clone 仓库地址
cd 项目目录

# 之后正常开发
git pull    # 每次开始前拉取最新
git push    # 每次结束后推送
```

| 功能 | 为什么暂时不需要 |
|------|------------------|
| 分支管理 | 一个人开发，一个分支够用 |

| stash | 不常用 |

| submodule | 复杂项目才需要 |

## 十、常见问题

### Q1: push 失败，提示要先 pull？

```bash
git pull
# 如果没有冲突，会自动合并
git push
```

### Q2: 不小心 add 了不该提交的文件？

```bash
git reset HEAD 文件名
```

### Q3: 想忽略某些文件不被 Git 跟踪？

编辑 `.gitignore` 文件，添加要忽略的文件/目录：

```
# .gitignore 示例
bin/
obj/
*.user
*.suo
```

### Q4: 提交后发现漏了文件？

```bash
git add 漏掉的文件
git commit --amend --no-edit    # 合并到上一次提交
```

### Q5: Cursor 中看不到 Git 图标？

1. 检查项目根目录是否有 `.git` 文件夹
2. 重新打开 Cursor
3. 确认 Git 已安装：终端运行 `git --version`
