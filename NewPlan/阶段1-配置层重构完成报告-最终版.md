## 🐛 问题与解决方案

### 问题 1: 热重启场景下 Assembly.Location 为空

**现象**:
```
Autodesk.AutoCAD.Runtime.Exception: 
An exception was thrown while activating GlobalConfigurationService
```

**根本原因**:
- 通过 `Assembly.Load(File.ReadAllBytes())` 加载的程序集
- 其 `Assembly.Location` 属性返回空字符串
- 配置服务无法确定配置文件路径

**解决方案**:
```csharp
private string FindConfigFile()
{
    var locations = new[]
    {
        // 1. Assembly.Location（正常加载）
        Path.GetDirectoryName(typeof(...).Assembly.Location),
        // 2. 当前工作目录
        Environment.CurrentDirectory,
        // 3. AppDomain 基目录
        AppDomain.CurrentDomain.BaseDirectory,
        // 4. 已知开发路径（热重启场景）
        Path.Combine(AppDomain.CurrentDomain.BaseDirectory, 
                    "..", "..", "..", "HyCADTool.Refactored", "bin", "Debug")
    };

    foreach (var location in locations)
    {
        if (string.IsNullOrEmpty(location)) continue;
        var configPath = Path.Combine(location, "config.json");
        if (File.Exists(configPath))
            return configPath;
    }
    
    return Path.Combine(Environment.CurrentDirectory, "config.json");
}
```

**效果**: ✅ 配置文件成功定位，服务正常初始化

### 问题 2: 构造函数异常导致 DI 失败

**现象**:
- 配置文件不存在时抛出异常
- Autofac 无法创建服务实例
- 整个依赖注入链崩溃

**解决方案**:
```csharp
public GlobalConfigurationService(string configFilePath)
{
    try
    {
        // 初始化逻辑...
    }
    catch (Exception ex)
    {
        // 使用默认配置，避免 DI 失败
        System.Diagnostics.Debug.WriteLine($"初始化失败: {ex.Message}");
        _configFilePath = "config.json";
        _jsonLoader = new JsonConfigurationLoader(_configFilePath);
        _currentConfig = GlobalConfiguration.CreateDefault();
    }
}
```

**效果**: ✅ 即使配置加载失败，服务仍能正常创建并使用默认值

### 问题 3: 配置文件缺失

**现象**:
- `HyCADTool.Refactored` 项目没有 `config.json`
- 运行时找不到配置文件

**解决方案**:
1. 从原项目复制配置文件
2. 更新项目文件自动复制到输出目录

```xml
<None Include="config.json">
  <CopyToOutputDirectory>PreserveNewest</CopyToOutputDirectory>
</None>
```

**效果**: ✅ 配置文件随 DLL 一起部署到 bin/Debug

### 问题 4: 属性名称错误

**现象**:
```
"PileConfiguration"未包含"Diameter"的定义
```

**原因**: 
- `PileConfiguration` 实际属性名为 `DiameterOrEdge`
- 测试代码使用了错误的属性名 `Diameter`

**解决方案**:
```csharp
// 修复前
if (pileConfig == null || pileConfig.Diameter <= 0)

// 修复后
if (pileConfig == null || pileConfig.DiameterOrEdge <= 0)
```

**效果**: ✅ 编译通过，测试正常运行

### 问题 5: 命令重复注册警告

**现象**:
```
无法加载程序集。错误详细信息: 
Autodesk.AutoCAD.Runtime.Exception: eDuplicateKey
```

**原因**:
- 热重启时，新旧命令名称重复
- AutoCAD 保留第一次加载的命令

**状态**: ⚠️ **可忽略**
- 不影响功能
- 测试仍能正常执行
- 是热重启系统的已知特性

## 🎓 经验总结

### 设计模式应用

| 模式 | 应用场景 | 收益 |
|------|----------|------|
| **Value Object** | 配置数据封装 | 不可变性、类型安全 |
| **Service Layer** | 配置管理逻辑 | 分离关注点、可测试 |
| **Dependency Injection** | 服务获取 | 松耦合、可替换 |
| **Factory Method** | 默认配置创建 | 统一创建逻辑 |
| **Strategy Pattern** | 多种加载器 | 灵活切换加载方式 |

### 关键技术决策

| 决策 | 理由 | 影响 |
|------|------|------|
| **双层配置架构** | Global + Modules 分离 | ✅ 清晰、可扩展 |
| **Value Object 不可变** | 数据安全、线程安全 | ✅ 减少 Bug |
| **智能文件查找** | 支持多种部署场景 | ✅ 热重启兼容 |
| **异常保护策略** | 构造函数不抛异常 | ✅ DI 容器稳定 |
| **默认配置机制** | 文件缺失时回退 | ✅ 容错性强 |
| **向后兼容** | 支持旧配置格式 | ✅ 平滑迁移 |

### 最佳实践

1. **配置服务不应在构造函数中抛出异常**
   - 使用异常保护 + 默认配置回退
   - 确保 DI 容器能正常创建服务

2. **Value Object 应提供验证方法**
   - `IsValid(out string error)` 模式
   - 便于在多处使用统一验证逻辑

3. **热重启场景需要特殊处理文件路径**
   - `Assembly.Location` 不可靠
   - 使用多级回退策略

4. **配置文件应随 DLL 一起部署**
   - 使用 `<CopyToOutputDirectory>PreserveNewest</CopyToOutputDirectory>`
   - 确保配置文件可访问
