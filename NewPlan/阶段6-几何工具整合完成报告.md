```csharp
// Domain/ValueObjects/Geometry/Line2D.cs
public bool IsCollinear(Line2D other, double tolerance = 1e-6)
{
    if (!IsParallelTo(other, tolerance)) return false;
    Vector2D v1 = this.Direction;
    Vector2D v2 = this.StartPoint.VectorTo(other.StartPoint);
    double cross = Math.Abs(v1.Cross(v2));
    return cross < tolerance;
}
```

## 五、关键技术决策

### 1. 为什么代数面积在 Extensions 而非 Domain？

**决策**: `GetAlgebraicArea` 作为 Polyline 扩展方法

**原因**:
- 依赖 AutoCAD 的 `Polyline` 类型
- 计算逻辑简单（Shoelace 公式）
- 作为辅助方法供其他扩展使用

**Domain 替代方案**: 如需平台无关，可在 `PolygonAlgorithms` 中实现：
```csharp
public static double CalculateSignedArea(IEnumerable<Point2D> vertices)
```

### 2. 为什么 LineExtensions 不合并到 Line2D？

**决策**: LineExtensions 为 AutoCAD `Line` 扩展，不合并到 Domain 的 `Line2D`

**原因**:
- `Line2D` 是平台无关的值对象
- LineExtensions 依赖 AutoCAD `Line` 类型
- 遵循 Clean Architecture 分层原则

### 3. 为什么删除旧版 GeometryUtils 而非保留兼容？

**决策**: 不保留旧版代码

**原因**:
- 旧版使用部分类（`partial class ZTools`）混乱
- 新版功能更完善且符合架构规范
- 迁移成本低（功能对等或更强）

## 八、性能考虑

### Polyline 操作
- ✅ `RemoveDuplicateVertices`：O(1) 时间复杂度（只检查首尾）
- ✅ `GetAlgebraicArea`：O(n) 时间复杂度（遍历顶点）
- ✅ `EnsureClockwise`：O(n) 计算面积 + O(1) 反转（如需）

### Line 操作
- ✅ `SortByConnectivity`：O(n²) 最坏情况（可优化为 O(n log n) 使用字典）
- ✅ `JoinToPolyline`：O(n²) 排序 + O(n) 构建多段线

### 优化建议
如性能成为瓶颈，可考虑：
- 使用 `Dictionary<Point3d, List<Line>>` 加速线段查找
- 缓存 `GetAlgebraicArea` 结果（如 Polyline 不变）
