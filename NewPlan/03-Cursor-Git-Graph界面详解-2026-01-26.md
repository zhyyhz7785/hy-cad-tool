# Cursor Git Graph 界面详解

> **创建日期**: 2026-01-26  
> **用途**: 理解 Cursor 中 Git 提交历史图的每个功能

---

## 一、界面概览

```
┌─────────────────────────────────────────────────────────────────┐
│  ← 图形                        🎤 自动  ⊙  ※  ✕  ⊙ master ☁   │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ○ test: git  zhy                                              │
│  │                                                              │
│  ● Merge branch 'New'  zhy                                     │
│  │                                                              │
│  ○ commit -m "feat: 保存当前进度"  zhy                          │
│  │                                                              │
│  ...                                                            │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 二、顶部工具栏

### 2.1 左侧

| 元素 | 说明 |
|------|------|
| **← 图形** | 返回按钮 + 当前视图名称，点击返回上一级 |

### 2.2 右侧工具按钮

从左到右：

| 图标 | 名称 | 功能 |
|------|------|------|
| 🎤 **自动** | 自动刷新 | 自动更新提交历史，保持最新状态 |
| ⊙ | 刷新 | 手动刷新提交历史 |
| ※ | 筛选/搜索 | 筛选显示的提交（按作者、消息等） |
| ✕ | 关闭筛选 | 清除当前筛选条件 |
| ⊙ **master** | 当前分支 | 显示当前所在分支名，点击可切换分支 |
| ☁ | 云同步状态 | 显示与远程仓库的同步状态 |

## 三、提交历史图（主区域）

### 3.1 图形元素

```
  ○ ─── 普通提交点
  │
  ● ─── 当前 HEAD 所在的提交（或合并提交）
  │
  ├─┐ ─ 分支分叉点
  │ │
  ├─┘ ─ 分支合并点
```

### 3.2 提交信息格式

```
○ test: git  zhy
│  │          └── 提交作者
│  └────────────── 提交信息（commit message）
└──────────────────── 提交节点
```

### 3.3 颜色含义

| 颜色 | 含义 |
|------|------|
| **蓝色/紫色** | 当前分支的提交线 |
| **绿色** | 其他分支的提交线 |
| **黄色** | 标签（tag）标记的提交 |
| **灰色** | 远程分支的提交 |

## 四、常用操作

### 4.1 查看提交详情

**操作**: 点击任意提交节点

**显示内容**:
- 完整提交信息
- 提交时间
- 作者信息
- 修改的文件列表
- 具体的代码差异

### 4.2 右键菜单（点击提交节点）

| 菜单项 | 功能 | 说明 |
|--------|------|------|
| **Checkout** | 检出 | 切换到这个提交的代码状态 |
| **Create Branch** | 创建分支 | 从这个提交创建新分支 |
| **Create Tag** | 创建标签 | 给这个提交打标签 |
| **Cherry Pick** | 挑选提交 | 把这个提交应用到当前分支 |
| **Revert** | 撤销提交 | 创建一个新提交来撤销这个提交的改动 |
| **Reset** | 重置 | 把当前分支重置到这个提交 |
| **Copy SHA** | 复制哈希 | 复制这个提交的唯一标识符 |

### 4.3 分支操作（点击分支名）

| 操作 | 说明 |
|------|------|
| **Checkout** | 切换到这个分支 |
| **Merge into Current** | 把这个分支合并到当前分支 |
| **Delete** | 删除这个分支 |
| **Rename** | 重命名分支 |

## 五、你的截图解读

根据你的截图：

```
○ test: git  zhy                    ← 最新的测试提交
│
● Merge branch 'New'  zhy           ← 合并提交（把 New 分支合并到 master）
│
○ commit -m "feat: 保存当前进度"     ← 之前的提交
```

**解读**:
1. 你成功把 `New` 分支合并到了 `master`
2. 合并后又做了一个测试提交 "test: git"
3. 现在 `master` 分支是最新的，包含了 `New` 的所有内容

## 六、如何打开 Git Graph

### 方法 1：命令面板

1. 按 `Ctrl+Shift+P`
2. 输入 "Git: View History" 或 "Git Graph"
3. 回车

### 方法 2：源代码管理面板

1. 按 `Ctrl+Shift+G` 打开源代码管理
2. 点击右上角的 `...` 菜单
3. 选择 "View History" 或 "Git Graph"

### 方法 3：状态栏

点击左下角的分支名 → 可能有 "View Git Graph" 选项

## 七、实用技巧

### 7.1 快速定位

- **按作者筛选**: 点击 ※ 图标，输入作者名
- **按消息筛选**: 点击 ※ 图标，输入提交消息关键词
- **按日期筛选**: 点击 ※ 图标，选择日期范围

### 7.2 比较提交

1. 选中一个提交（点击）
2. 按住 `Ctrl` 点击另一个提交
3. 右键 → "Compare"
4. 查看两个提交之间的差异

### 7.3 查看某个文件的历史

1. 在文件上右键
2. 选择 "Open Timeline" 或 "View File History"
3. 查看这个文件的所有修改记录

| 图标 | 名称 | 功能 |
|------|------|------|
| ○ | 空心圆 | 普通提交 |

## 九、常见问题

### Q1: 为什么看到很多分支线？

因为项目有多个分支的历史。整理分支后，图会变得更清晰。

### Q2: 如何只看某个分支的历史？

点击 ※ 筛选图标，选择特定分支。

### Q3: 合并提交（●）和普通提交（○）有什么区别？

- **普通提交**: 只有一个父提交
- **合并提交**: 有两个父提交（把两个分支合并产生的）

### Q4: 如何回退到某个历史版本？

1. 右键点击那个提交
2. 选择 "Reset" → "Soft"（保留改动）或 "Hard"（丢弃改动）

## 十、总结

Git Graph 是可视化理解项目历史的最佳工具：

| 功能 | 用途 |
|------|------|
| **查看历史** | 了解项目的演变过程 |
| **比较版本** | 看两个版本之间的差异 |
| **分支管理** | 可视化分支的分叉和合并 |
| **快速操作** | 右键菜单执行各种 Git 操作 |

**对于你的使用场景**：
- 断断续续开发时，用它快速回顾上次做到哪
- 看到 "Merge branch 'New'" 这样的提交，就知道分支已合并
- 整理分支后，图会变得简洁，一条主线更清晰
