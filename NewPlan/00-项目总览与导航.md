## 🏗️ 架构概览

### Clean Architecture 分层

```
┌─────────────────────────────────────────────────────────────┐
│                    Presentation Layer                        │
│                  (UI, Commands, Controllers)                 │
└────────────────────────────┬────────────────────────────────┘
                             │ 依赖
                             ▼
┌─────────────────────────────────────────────────────────────┐
│                   Application Layer                          │
│              (Use Cases, Application Services)               │
└────────────────────────────┬────────────────────────────────┘
                             │ 依赖
                             ▼
┌─────────────────────────────────────────────────────────────┐
│                      Domain Layer                            │
│         (Entities, Value Objects, Domain Services)           │
│         ✅ 100% 平台无关，可迁移到 Blender                    │

┌─────────────────────────────────────────────────────────────┐
│                  Infrastructure Layer                        │
│          (AutoCAD Services, Repositories, Extensions)        │
└─────────────────────────────────────────────────────────────┘
```

## 🎓 关键技术决策

### 1. Domain 层平台无关

**决策**: Domain 层不依赖任何外部框架（包括 AutoCAD API）

**收益**:
- ✅ 100% 可测试（无需 AutoCAD 环境）
- ✅ 100% 可迁移到 Blender Python
- ✅ 业务逻辑清晰独立

**实现**:
- 使用自定义值对象（Point2D, Line2D, Polygon2D）
- 纯函数算法服务
- 无副作用

### 2. Infrastructure 层作为桥梁

**决策**: Infrastructure 层桥接 Domain 和 AutoCAD

**实现**:
```csharp
// 扩展方法调用 Domain 算法
public static bool ContainsPoint(this Polyline poly, Point3d point)
{
    // 1. 转换 AutoCAD → Domain
    var vertices = poly.GetAllVertices2d()
        .Select(p => new Point2D(p.X, p.Y));
    
    // 2. 调用 Domain 算法
    return PolygonAlgorithms.ContainsPoint(vertices, new Point2D(point.X, point.Y));
}
```

### 3. 测试驱动

**决策**: 每个阶段都有自动化测试

**收益**:
- ✅ 持续验证质量
- ✅ 快速发现问题
- ✅ 重构信心

## 📚 重要概念

### Clean Architecture 原则

1. **依赖规则**: 外层依赖内层，内层不知道外层
2. **业务规则独立**: Domain 层不依赖框架
3. **可测试**: 核心逻辑可独立测试
4. **框架独立**: 可更换技术栈

### DDD 核心概念

| 概念 | 说明 | 示例 |
|------|------|------|
| **Value Objects** | 值对象，不可变 | Point2D, Line2D |
| **Entities** | 实体，有标识 | （未来） |
| **Domain Services** | 领域服务，纯逻辑 | PointAlgorithms |
| **Aggregates** | 聚合根 | （未来） |

### SOLID 原则

- **S** - Single Responsibility（单一职责）
- **O** - Open/Closed（开闭原则）
- **L** - Liskov Substitution（里氏替换）
- **I** - Interface Segregation（接口隔离）
- **D** - Dependency Inversion（依赖倒置）
