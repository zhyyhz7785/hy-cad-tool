## 二、整理步骤

### 步骤 1：确认当前分支内容完整

在 Cursor 终端中运行：

```bash
# 确认当前在 New 分支
git branch

# 查看当前有多少未提交的改动
git status
```

### 步骤 2：先把当前工作保存

```bash
# 如果有未提交的改动，先提交
git add .
git commit -m "feat: 保存当前进度 - 准备整理分支"
git push
```

### 步骤 3：查看各分支的最后提交时间

```bash
# 查看所有分支的最后提交
git branch -v
```

这会显示每个分支的最后一次提交，帮你判断哪个是最新的。

### 步骤 4：决定保留哪些分支

**建议的保留策略**：

| 保留 | 删除 | 原因 |
|------|------|------|
| New | hydev, hydev2, newdev | New 是当前分支，其他可能是旧版本 |
| RefactorDev（可选） | - | 如果有重要内容，暂时保留 |

### 步骤 5：删除不需要的本地分支

```bash
# 删除本地分支（只能删除非当前分支）
git branch -d hydev        # 删除 hydev（如果已合并）
git branch -D hydev        # 强制删除 hydev（如果未合并）

git branch -d hydev2
git branch -d newdev
```

### 步骤 6：删除远程分支（可选）

```bash
# 删除远程分支
git push origin --delete hydev
git push origin --delete newdev
```

### 步骤 7：将 New 重命名为 main（可选）

如果想用更标准的命名：

```bash
# 重命名本地分支
git branch -m New main

# 推送新分支到远程
git push origin main

# 设置远程跟踪
git push origin -u main

# 删除旧的远程分支
git push origin --delete New
```

## 三、推荐的分支策略（个人开发简化版）

### 3.1 只需要 2 个分支

```
main (或 master)     ← 稳定版本，随时可用
  │
  └── dev            ← 日常开发，测试新想法
```

### 3.2 工作流程

```
日常开发：
1. 在 dev 分支开发
2. 测试通过后，合并到 main
3. 删除临时分支（如果有）

测试不同方案：
1. 从 dev 创建临时分支：git checkout -b test-xxx
2. 测试完成后，如果满意，合并回 dev
3. 如果不满意，直接删除：git branch -D test-xxx
```

### 3.3 分支命名规范（简单版）

| 前缀 | 用途 | 示例 |
|------|------|------|
| 无前缀 | 主分支 | `main`, `dev` |
| `test-` | 测试方案 | `test-dcel-v2`, `test-new-algorithm` |
| `fix-` | 修复问题 | `fix-arc-split` |

## 四、快速整理方案（推荐）

### 方案 A：最简单 - 只保留一个分支

如果你不确定其他分支有什么，而且 New 是最新的：

```bash
# 1. 确保在 New 分支
git checkout New

# 2. 提交所有当前改动
git add .
git commit -m "feat: 当前进度保存"
git push

# 3. 删除其他本地分支
git branch -D hydev
git branch -D hydev2
git branch -D newdev
git branch -D RefactorDev

# 4. 完成！以后只用 New 分支
```

### 方案 B：保守整理 - 先备份再删除

```bash
# 1. 创建备份标签（不占空间，只是标记）
git tag backup-hydev hydev
git tag backup-hydev2 hydev2
git tag backup-newdev newdev
git tag backup-RefactorDev RefactorDev

# 2. 推送标签到远程
git push origin --tags

# 3. 删除分支
git branch -D hydev
git branch -D hydev2
git branch -D newdev
git branch -D RefactorDev

# 4. 如果以后需要恢复
git checkout -b 恢复的分支名 backup-xxx
```

### 方案 C：重新开始 - 新的 main 分支

```bash
# 1. 重命名 New 为 main
git branch -m New main

# 2. 推送到远程
git push origin main -u

# 3. 在 Gitee 网页上设置 main 为默认分支

# 4. 删除其他分支
git branch -D hydev hydev2 newdev RefactorDev

# 5. 删除远程旧分支
git push origin --delete New hydev newdev RefactorDev
```

## 五、Cursor 中的分支操作

### 5.1 切换分支

1. 点击左下角状态栏的分支名（如 "New"）
2. 选择要切换的分支

### 5.2 查看所有分支

1. 按 `Ctrl+Shift+P`
2. 输入 "Git: Checkout to"
3. 会显示所有本地和远程分支

### 5.3 删除分支

1. 按 `Ctrl+Shift+P`
2. 输入 "Git: Delete Branch"
3. 选择要删除的分支

## 七、我的建议

对于**一个人断断续续开发**的场景：

### 最简单的方案

1. **只用一个分支**（main 或 New）
2. **每次工作结束都提交推送**
3. **想测试新想法时**，创建临时分支 `test-xxx`
4. **测试完成后**，要么合并，要么删除

### 为什么一个分支够用？

- 一个人开发，不会有冲突
- 断断续续开发，分支多了反而乱
- Git 有历史记录，随时可以回退
- 真的需要时再创建分支

## 八、立即执行（复制粘贴到终端）

### 第一步：保存当前工作

```bash
git add .
git commit -m "feat: 保存当前进度"
git push
```

### 第二步：查看分支情况

```bash
git branch -v
```

### 第三步：删除不需要的分支（确认后执行）

```bash
git branch -D hydev
git branch -D hydev2
git branch -D newdev
git branch -D RefactorDev
```

### 第四步：确认结果

```bash
git branch
```

应该只剩下 `New`（或你选择的主分支）
