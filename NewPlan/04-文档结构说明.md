## 🎯 使用指南

### 新人上手路径

```
1. README.md
   ↓
2. 00-项目总览与导航.md
   ↓
3. 详细计划.md
   ↓
4. 各阶段总览 (阶段1-总览.md, 阶段2-总览.md, 阶段3-总览.md)
   ↓
5. 详细设计/完成报告（按需）
```

### 继续开发路径

```
1. 00-项目总览与导航.md（了解当前进度）
   ↓
2. 下一步行动指南.md（看下一步做什么）
   ↓
3. 详细计划.md（了解下一阶段目标）
   ↓
4. 开始实施
```

### 问题排查路径

```
1. 相应阶段的总览（快速定位）
   ↓
2. 相应阶段的完成报告（了解实现细节）
   ↓
3. 编译错误修复文档（如果是编译问题）
   ↓
4. 架构拆分方案（如果是设计问题）
```

## 🔍 文档命名规范

### 索引/导航文档

- `00-` 前缀 = 最高优先级索引
- `README.md` = 快速开始
- `-指南.md` 后缀 = 操作指南

### 阶段文档

- `阶段N-` 前缀 = 阶段编号
- `-总览.md` 后缀 = 简要概述
- `-详细设计.md` 后缀 = 技术设计
- `-完成报告.md` 后缀 = 成果报告
- `-最终版.md` 后缀 = 最终版本（去重后）

### 专题文档

- `命令详细清单.md` = 功能清单
- `编译错误修复.md` = 问题记录
- `架构拆分方案.md` = 设计决策

## 💡 文档维护原则

### 1. 单一真相源

- 每个主题只有一份权威文档
- 删除过时/重复文档
- 使用 `-最终版` 标识最终文档

### 2. 分层导航

- 一级：索引/导航
- 二级：总览/计划
- 三级：详细设计/报告

### 3. 命名清晰

- 使用描述性名称
- 使用前缀/后缀标识类型
- 使用数字标识优先级

### 4. 保持更新

- 每个阶段完成后更新索引
- 及时删除过时文档
- 维护文档间的链接
