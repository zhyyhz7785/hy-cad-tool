## 1. 当前总体状态

当前分支为 `dev`，主线状态为 `ahead 1`。近期工作重点集中在 Markdown 编辑器的以下三类问题：

1. UI 一体化与布局交互（标题栏、面板、分隔条、开发栏）
2. 图纸预览与标尺联动（缩放、比例、默认适配、拖拽行为）
3. 文本显示与统计一致性（字高、字宽、栏下统计）

整体判断：  
项目已从“功能搭建阶段”进入“精度一致性 + 交互稳定性打磨阶段”。

---

## 2. 本阶段已完成事项

## 2.1 窗口与布局

- 自定义标题栏（替代系统标题栏）已完成，包含最小化/最大化/关闭按钮。
- 顶部菜单、状态栏、面板切换按钮整合进统一标题栏区域。
- 左侧大纲、中央编辑、右侧预览、底部开发栏结构稳定。
- 默认工作区比例（左:中:右 = 1:2:4）与最大化时重排逻辑已接入。

## 2.2 图纸与幅面逻辑

- 幅面统一支持 `A0~A4`。
- 图框边距按标准规则处理：
  - `a = 25`（左装订边）
  - `c = 10`（A0~A3）
  - `c = 5`（A4）
- 横竖切换已改为按钮交互，替代原横/竖下拉模式。
- 默认横向下，X 向为长边，满足“X 向更长”的期望。

## 2.3 预览缩放与标尺

- 缩放触发改为 `Ctrl + 鼠标滚轮`（仅预览区内生效）。
- 标尺与图纸共享 `PreviewScale` 链路，解决缩放不同步问题。
- 初始加载增加“让 A2 图纸约占预览区域 90% 宽度”的自动适配。
- 缩放体验优化：
  - 实时轻量缩放（减少重建）
  - 防抖完整刷新（降低闪烁）
  - 滚轮步进改为指数形式，手感更连续

## 2.4 分栏间距与拖拽

- `ColumnGutter = 0` 时仍保留最小可视/可拖拽宽度，避免“看不到、拖不动”。
- 分隔线增强可见性（中线 + hover 高亮）。
- 页脚分隔宽度与内容区分隔保持同步。

## 2.5 图纸右下角拖拽策略

- 右下角拖拽：默认等比缩放（保持宽高比）。
- 按住 `Ctrl` 右下角拖拽：切换为自由缩放（宽高可独立变化）。

## 2.6 文字显示与统计（本轮重点）

已将文本显示从“固定像素字号”改为“参数驱动”：

- 字高显示与 `TextSize` 关联；
- 字宽统计与 `TextXScale` 关联；
- 图纸缩放时文字与图纸同比例变化；
- 栏下统计不再使用经验采样，改为确定性公式：
  - `字/行 = floor(内容宽(mm) / (TextSize * TextXScale))`
- 栏下信息改为：`字/行 · 段数 · 总字数`。

## 3. 目前仍存在的风险与边界

## 3.1 预览内核限制（关键）

当前预览仍使用 `WebBrowser`（IE 内核路径）。  
这会导致：

- CSS/排版兼容性天花板较低；
- 高频交互下仍可能出现局部闪烁；
- DPI 与 WPF 坐标系需要持续做补偿。

## 3.2 统计“精确度”边界

当前统计已显著优于原逻辑，但在以下场景仍会有偏差：

- 中英混排比例极端变化；
- 字体 fallback（字形替换）；
- 复杂富文本（表格、代码块、脚注）视觉占用与字符占用不完全一致。

## 3.3 参数一致性风险

存在多个相互影响参数：`TextSize`、`TextXScale`、`DrawScale`、`PreviewScale`。  
若后续继续加新参数，需防止“视觉值、导出值、统计值”三套口径分叉。

## 4. 建议（按优先级）

## P0（建议立即执行）

1. 建立 6~10 组固定验收样本（A2/A3、1/2/3栏、字高 2.5/3.5/5.0）。
2. 每次改动后执行同一套快速回归：
   - 图纸尺寸是否正确；
   - 标尺是否同步；
   - 字高变化是否成比例；
   - 栏下统计是否稳定。
3. 对“空文档、超长文档、全中文、混排、代码块文档”各保留一个标准样本。

## P1（建议本周）

1. 推进预览由 `WebBrowser` 向 `WebView2` 统一，减少内核差异。
2. 将统计结果输出结构化（JSON 字段），减少字符串拼接解析依赖。
3. 规范提交信息（避免 `11`、`22` 这类低语义 commit message）。

## P2（建议下阶段）

1. 增加“参数定义文档”：
   - 每个参数单位；
   - 参与计算链路；
   - 与 UI 预览/最终出图的映射关系。
2. 补最小回归脚本（哪怕是人工清单 + 录屏标准），形成可复制验收流程。

## 5. 阶段结论

MarkdownEditor 模块当前已经具备：

- 可持续迭代的 UI 骨架；
- 基本正确的图纸与标尺缩放链路；
- 参数驱动的文字显示与可解释统计；
- 可用的交互行为（面板、分隔、缩放、拖拽）。

下一阶段应从“功能可用”转向“稳定可验收”：

- 先固化验收基线；
- 再做内核统一（WebView2）；
- 最后做精度细化与性能收敛。
