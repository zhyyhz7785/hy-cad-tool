### 1. 【最高优先级】ServiceLocator 是反模式（已造成隐蔽 Bug）
**问题**：几乎所有 Command/ViewModel 都在用 `ServiceLocator.Resolve<T>()`，违背 DIP，破坏可测试性，热重启后偶尔出现「解析失败」。

**优化方案**（3 天内可完成）：
```csharp
// 1. 删除 ServiceLocator.cs（或标记为废弃）
// 2. 把所有 Command 改为构造函数注入
public class DrawPilesCommand : ICommand
{
    private readonly IPileLayoutService _pileService;
    private readonly IDrawingService _drawingService;

    public DrawPilesCommand(IPileLayoutService pileService, IDrawingService drawingService)
    {
        _pileService = pileService;
        _drawingService = drawingService;
    }

    public void Execute() { ... }
}
```
- 在 `PluginInitializer.cs` 或 `AutofacModule` 里注册：
  ```csharp
  builder.RegisterType<DrawPilesCommand>().As<ICommand>();
  ```
- 面板命令统一走 `ICommandFactory`（后面第 3 点）。

### 2. 【高优先级】命令系统绕过 [CommandMethod] 带来的痛点
**问题**：不能用原生命令名（HYOV、HYBC…），只能靠 `ShowPanelCommand` 转调，热重启后老用户经常「找不到命令」。

**推荐方案**（最优雅）：
采用 **动态注册 + 命令代理**（很多成熟 AutoCAD 重构项目都在用）：
```csharp
// Infrastructure/AutoCAD/Commands/DynamicCommandRegistrar.cs
public static void RegisterAllCommands()
{
    foreach (var cmd in ServiceLocator.Resolve<IEnumerable<ICommand>>()) // 临时过渡
    {
        var attr = cmd.GetType().GetCustomAttribute<CommandMethodAttribute>();
        if (attr != null)
            Application.DocumentManager.MdiActiveDocument.CommandWillStart += ... // 动态注册
    }
}
```
或者直接升级到 .NET 6+ + AutoCAD 2025+ 的新加载方式（长期解法）。

### 3. 【高优先级】命令实例化方式混乱（new XXXCommand()）
**问题**：`TestCommand.cs` 里 `new XXXCommand().Execute()`，完全绕过了 DI，依赖注入形同虚设。

**立即优化**：
建立 `ICommandFactory` + `CommandFactory`：
```csharp
public interface ICommandFactory
{
    T Create<T>() where T : ICommand;
    ICommand Create(string commandName);
}
```
然后 `TestCommand.cs` 改成：
```csharp
new TestCommand(factory).Run(); // factory.Create<OverKillCommand>().Execute()
```

### 4. 【中优先级】配置访问方式太多（3 种路径）
**问题**：`SettingsPanelViewModel.Current`、`IConfigurationService`、`GlobalConfigurationService` 三种方式并存，容易出现「改了面板没生效」或「重启后恢复默认」。

**统一方案**：
- 保留 `IConfigurationService` 作为唯一入口（注入）。
- `SettingsPanelViewModel` 也注入 `IConfigurationService`，不再暴露静态 `.Current`。
- `GlobalConfiguration` 改为 immutable ValueObject，只在启动时加载一次。

### 5. 【中优先级】Domain 层「看起来」平台无关，但实际有隐患
**问题**：
- `ValueObjects/Geometry` 里很多类有 `ToPoint3d()`、`ToPolyline()` 扩展（其实是 Infrastructure 的职责）。
- `DCELRenderer`、`PolygonAdapter` 等类在 Domain 引用了 `Autodesk.AutoCAD.Geometry`。

**快速修复**：
把所有带 AutoCAD 类型的成员/方法移到 `Infrastructure/AutoCAD/Converters` 里，Domain 只保留纯数学方法。

### 6. 【中优先级】测试体系几乎为 0
**问题**：目前只有「手动跑命令 + 看图形」，Domain 算法完全没单元测试。

**3 天建立最小可用测试项目**：
```bash
dotnet new xunit -o HyCADTool.Refactored.Tests
```
重点测：
- 所有 `XXXAlgorithmService`（纯函数，最容易测）
- `Polygon2D.Offset()`、`DCELBuilderService.BuildFromLines()`
- 用 `NetTopologySuite` 的 `GeometryFactory` 做断言

### 7. 【中优先级】扩展方法爆炸（50+ 个）
**问题**：`EntityExtensions`、`PolylineExtensions`、`Point3dExtensions`… 以后会变成「万能垃圾桶」。

**建议**：
- 把通用扩展拆成 `GeometryExtensions`、`EntityExtensions`、`SelectionExtensions` 三类。
- 复杂逻辑（如 `pline.Simplify()`）改为 `ISimplificationService` 接口实现。

### 8. 【低-中】WPF + WinForms 混合
**问题**：部分旧面板还在用 Windows Forms（HyovSettings.cs），与 WPF 面板混用，样式/焦点/热重启表现不一致。

**建议**：全部迁移到 WPF（已经有了 `HyovSettingsWindow.xaml`，直接换掉）。

### 9. 【低】Autofac 注册阶段太多（0~14）
**问题**：改一个服务要跳 14 个阶段，容易漏。

**优化**：
改成模块化注册：
```csharp
builder.RegisterModule<GeometryModule>();
builder.RegisterModule<ReinforcementModule>();
builder.RegisterModule<PileModule>();
```

### 10. 【低】热重启机制依赖文件复制 + 手动卸载
**问题**：偶尔出现「DLL 被占用」「旧版本残留」。

**长期方案**：
升级到 AutoCAD 2022+ 的 `PluginManager` + `AssemblyLoadContext`（.NET 6+），或直接用第三方热加载框架（如 `Prism` + `AutoCAD` 插件模板）。

### 11. 【低】缺少全局异常捕获与日志
**问题**：命令崩溃后只看到「Command failed」，无法定位。

**立即加**：
```csharp
// PluginInitializer.cs
Application.DocumentManager.DocumentLockModeChanged += (s,e) => { ... };
AppDomain.CurrentDomain.UnhandledException += (s,e) => SimpleLogger.LogError(e.ExceptionObject);
```

### 12. 【低】命名空间与文件夹不完全一致
例如：
- `Presentation.Commands.rode/` → 应该是 `Presentation.Commands.Rode`
- `Infrastructure/AutoCAD/Cluster/` → 应该和 `Domain/Services/Cluster` 对应

小问题，但长期会影响 IDE 导航和代码搜索。
