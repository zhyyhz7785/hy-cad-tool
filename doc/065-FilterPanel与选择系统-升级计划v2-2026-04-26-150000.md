## 3.1 ArcGIS Pro 的参照：Python、查询与「LINQ 式」能力

> 目的：为熟悉 **ArcGIS Pro** 的用户提供**心智对照**，并把可借鉴的能力映射到本计划的 `ISelectionQueryEngine` / `SelectionPredicate`；**不**在 v1 引入完整 ArcPy 运行时。

### 3.1.1 Pro 里三类常见做法（概括）

| 做法 | 在 ArcGIS Pro 中的典型形态 | 能力本质 |
|------|---------------------------|----------|
| **Python (arcpy)** | Notebook/脚本：`arcpy.management.SelectLayerByAttribute` / `arcpy.analysis.Select`；`arcpy.da.SearchCursor` + **SQL `WHERE` 子句**；或模型构建器导出 Python | **命令式脚本**：字符串化 WHERE、几何/表 API、可批处理、可进自动化工作流。 |
| **定义查询 (Definition query)** | 图层的持久化 **WHERE**（与属性表/视图绑定），改变地图显示子集，常配合符号系统 | **声明式、可持久、可重开工程即生效**；对标本计划的**命名预设 + 可选「变更后重算」**（对应 065 的 `AutoRefresh` 远期项）。 |
| **「LINQ 式」** | **C# only**：ArcGIS Pro **SDK for .NET** 在内存中对 **已获取的行/要素包装对象** 使用 **LINQ to Objects**（`Where` / `Select`）；**不是** 像 Entity Framework 那样把 IQueryable 直接翻译成 GDB SQL。Python 中无 C# LINQ，习惯上常类比为 `SearchCursor` + 条件或 **先 SQL 子集再 Python 精筛** 的链式脚本。 | **链式、强类型/可读**；在 HyCAD 侧应对 **同一套 Predicate AST/表达式 的「语法糖」或「可导出脚本」**，避免两套求值语义。 |

### 3.1.2 映射到 HyCAD（本仓库）

| Pro / SDK 侧概念 | 本计划中的落点 | 备注 |
|------------------|----------------|------|
| `WHERE` / 定义查询 字符串 | **M2** `SelectionPredicate` 的**文本序列化**；可选子集用 **类 SQL 单行** 表达仅含属性/等式的筛选，**编译为同一 AST** 再交引擎执行 | 与 **DynamicExpresso** 双轨：**一种** 用户可编辑的「类 SQL/类 FILTER 行」；**一种** 完整表达式/可视化条件树 |
| arcpy 脚本化选择 | **远期** `ISelectionQueryScriptHost`：由宿主在**受控**环境下执行脚本/片段，**输入**当前 `ObjectId[]`/`Handle` 与只读 `Database` 访问，**输出**目标 id（须定义事务、安全与撤销策略） | **v1 不实现**；可先提供 **「导出当前 Predicate 为 C# 片段 / 伪代码」** 降低迁移成本 |
| C# 链式 `.Where().OfType<>` | **M2+（可选，称 M2.1）**：在 **编译时** 将强类型 `Query` DSL（若引入）**降为** 与 M2 相同的 `SelectionPredicate` / 可执行树 | **禁止** 在运行时维护「LINQ 直跑」与「引擎」两条不一致的语义；LINQ 仅为糖 |

### 3.1.3 与 §六 技术决策的衔接

- **DynamicExpresso** 已覆盖「类脚本」的组合表达式；若增加 **类 LINQ 的 C# 写法**，应 **仅** 经 Roslyn 或手写解析 **翻译为同一 `SelectionPredicate`**，与 **GDB/AutoCAD 真值**（ByLayer 等）仍由 `EntityAppearanceResolver` 与引擎统一处理。
- 可选小项 **WhereClauseAdapter（命名仅示意）**：将 Predicate 的**纯属性**部分导出为**可读 WHERE 行**或对照表，便于与 **Pro 定义查询** 文档/培训材料对齐；**不** 保证与 ArcGIS 字段名 1:1，仅**心智与文档**用途。

### 3.1.4 与阶段计划的挂钩

| 项 | 建议阶段 |
|----|----------|
| Python 真在进程内选实体 | 独立「脚本宿主」子项，**不绑定** M1~M3 交付；安全评审后再排期 |
| 类 SQL 单行 + AST | **M2 或 M2.1**（在 M2 Predicate 与 DynamicExpresso 之后增量） |
| 导出 C#/伪代码/「WHERE 对照行」 | **M2.5 或 M3**（与预设、历史同面板「高级导出」区） |

## 3.2 规则查询编辑器：快速输入 + 代码提示（重点）

> 对应面板里的 **「6. 规则查询」**。这里不是简单 TextBox，而是一个轻量 Query Editor：**可视化条件树 / 表达式输入 / 类 SQL 单行** 三种入口，最终全部编译为同一个 `SelectionPredicate` AST。

### 3.2.1 设计目标

| 目标 | 说明 |
|------|------|
| **快** | 常用筛选不打字：点击「同图层」「长度 >」「文字包含」「图层通配」即可插入表达式片段。 |
| **准** | 字段名、操作符、函数、枚举值由 `EntityPropertyDescriptorService` 和当前样例对象动态提供，避免用户输错属性名。 |
| **可解释** | 输入后同步显示「将执行的 Predicate 树」和「预估筛选范围」，让用户知道表达式如何被理解。 |
| **一套语义** | 快速按钮、表达式、类 SQL、未来 LINQ 糖都必须编译到同一 `SelectionPredicate`，不能各自实现一套筛选。 |
| **渐进增强** | M2 先用普通 WPF 控件实现；如果体验不够，再升级为 `AvalonEdit`（`ICSharpCode.AvalonEdit`）做语法高亮与补全窗口。 |

### 3.2.2 UI 分区建议

规则查询区从上到下分 5 层：

| 层 | UI | 作用 |
|----|----|------|
| **模式行** | `ComboBox`：条件树 / 表达式 / 类 SQL | 切换输入心智；内部仍同 AST。 |
| **快速输入条** | 一排紧凑按钮或 Pill：`同图层`、`同类型`、`同真色`、`长度 >`、`文字包含`、`图层通配`、`块名 =`、`半径区间` | 点击后向编辑器插入完整片段，并把光标放到待填值。 |
| **编辑器** | MVP：`TextBox + Popup`；增强：`AvalonEdit + CompletionWindow` | 支持输入、补全、错误下划线、快捷键。 |
| **提示/校验行** | 一行状态：`字段 Length: Double · 支持 > < between` / `错误：TextStyleName 只支持 contains/==` | 实时解释当前 token。 |
| **预览行** | `AST 预览` + `试算数量` + `导出 C#/WHERE` | 连接 M2.5 预设与 Pro 对照。 |

### 3.2.3 快速输入片段（首批）

| 按钮 | 插入片段（表达式模式） | 类 SQL 模式等价 | 备注 |
|------|------------------------|-----------------|------|
| `同图层` | `Layer == "当前图层"` | `Layer = '当前图层'` | 当前样例对象提供默认值。 |
| `同类型` | `DxfType == "LWPOLYLINE"` | `DxfType = 'LWPOLYLINE'` | 类型族另由 M3 处理。 |
| `同真色` | `TrueColor == sample.TrueColor` | 不建议直接暴露 | 真色由 `EntityAppearanceResolver` 处理，不让用户拼 RGB 细节。 |
| `长度 >` | `Length > 100` | `Length > 100` | 仅当前类型有 `Length` 时显示。 |
| `半径区间` | `Radius between 100 and 300` | `Radius BETWEEN 100 AND 300` | `between` 编译为 `>= && <=`。 |
| `文字包含` | `TextString contains "说明"` | `TextString LIKE '%说明%'` | 仅文字类显示。 |
| `图层通配` | `Layer like "*-road-*"` | `Layer LIKE '*-road-*'` | AutoCAD wildcard 与 SQL `%` 需做模式转换。 |
| `块名 =` | `BlockName == "A1"` | `BlockName = 'A1'` | 仅块参照显示。 |
| `有 XData` | `HasXData("HYROAD")` | 不建议映射 | 属于关系/扩展数据函数。 |

### 3.2.4 代码提示内容

补全源分 5 类，统一为 `RuleCompletionItem`：

| 类型 | 示例 | 来源 |
|------|------|------|
| **字段 Field** | `Layer`、`DxfType`、`Length`、`Radius`、`TextString`、`TrueLineWeight` | `EntityPropertyDescriptorService` + 公共字段字典。 |
| **操作符 Operator** | `==`、`!=`、`>`、`<`、`between`、`contains`、`like`、`regex`、`in` | 根据字段类型过滤。 |
| **函数 Function** | `HasXData(app)`、`IsClosed()`、`InLayer(pattern)`、`OfType(type)` | `RuleFunctionRegistry`。 |
| **值 Value** | 当前图层名、图层列表、线型名、颜色名、块名、文字样式名 | 从当前图纸表读取；只读事务。 |
| **片段 Snippet** | `Layer == "${layer}"`、`Length between ${min} and ${max}` | 固定模板 + 当前样例值。 |

补全触发规则：

| 触发 | 行为 |
|------|------|
| `Ctrl + Space` | 强制打开补全列表。 |
| 输入字段首字母 | 显示字段候选。 |
| 字段后空格 | 只显示该字段支持的操作符。 |
| 操作符后空格 | 显示当前字段可用值，例如图层名/块名/线型名。 |
| 输入 `/` | 打开快速命令：`/layer`、`/text`、`/length`、`/where`、`/preset`。 |
| 输入 `.` | 若左侧是对象/函数结果，显示可链式成员；MVP 可先不实现。 |

### 3.2.5 表达式语言（MVP）

MVP 只支持**够用且可解释**的子集，避免一开始做成通用编程语言：

```text
// 属性比较
Layer == "0-road"
Length > 100
Radius between 100 and 300

// 文本
TextString contains "说明"
Layer like "*-road-*"
TextStyleName in ("Standard", "宋体")

// 组合
(Layer == "0-road" && Length > 100) || TrueColor == sample.TrueColor

// 函数
HasXData("HYROAD")
IsClosed()
OfType("LWPOLYLINE")
```

禁止项（MVP）：

- 禁止任意方法调用（除白名单函数）。
- 禁止反射、文件、进程、网络等副作用能力。
- 禁止让 DynamicExpresso 直接访问 AutoCAD 对象；表达式只访问**已投影的只读 DTO**。

### 3.2.7 WPF 控件选型

MVP 推荐：`TextBox + Popup + ListBox`。

- 优点：无新增依赖，最快落地。
- 缺点：语法高亮弱，补全体验一般。

增强版推荐：`AvalonEdit`。

- 优点：成熟的 WPF 文本编辑器，支持语法高亮、补全窗口、行列定位、错误标记。
- 风险：新增 NuGet 依赖；加入前需确认不引入 AutoCAD 宿主程序集，不影响 ReCall C2 热重载。

结论：**M2.1 先 MVP；若使用频率高，再升级 AvalonEdit**。

### 3.2.10 规则查询属性白名单（待用户确认）

> 规则查询的属性**不能直接暴露 AutoCAD .NET 的所有 public property**。必须先经过筛选，只保留能帮助用户区分图形、语义稳定、读取成本可控、不会误导的字段。下面是首版候选白名单，确认后再进入 `EntityPropertyDescriptorService` / `RuleCompletionProvider`。

#### 属性筛选原则

| 原则 | 说明 |
|------|------|
| **可区分** | 能明显区分对象，例如图层、类型、长度、半径、块名、文字内容。 |
| **可理解** | 面向 CAD 用户，而不是 .NET API 用户；字段名可显示中文名。 |
| **稳定** | 不依赖瞬时状态、不容易跨版本变化。 |
| **低成本** | 读取不应触发复杂重算；复杂几何可延后到高级字段。 |
| **真值优先** | 颜色、线宽、线型、透明度默认用 `EntityAppearanceResolver` 解析后的真值字段。 |
| **少而精** | 每类图形默认 5~10 个高价值字段；其余放入「高级属性」折叠区。 |

#### 所有实体通用属性

|--------|----------|------|

#### 用户已确认的属性白名单决策（2026-04-26）

| 编号 | 决策 | 结论 |
|------|------|------|
| 1 | 默认补全是否只显示 **P0 + P1 + P2**，把 P3/P4 放到「高级」？ | **是**。默认只显示 P0/P1/P2；P3/P4 进入高级属性/高级函数。 |
| 2 | 块属性是否第一版就支持 `Attribute["tag"]`？ | **是**。第一版支持块属性查询语法 `Attribute["编号"] == "A-01"`。 |
| 3 | 表格 `CellText(row,col)` 是否进入第一版？ | **是**。第一版支持表格单元格查询函数 `CellText(row,col)`。 |
| 4 | `3DSolid` / `Region` 是否放入首版？ | **进入首版**。默认字段按白名单暴露，复杂 BRep/集合仍只放高级模式。 |
| 5 | 颜色字段是否统一显示为 `TrueColor` /「真颜色」？ | **是**。默认展示「真颜色 `TrueColor`」，避免与实体 `ColorIndex` 混淆。 |

由此得到的实现约束：

- `RuleCompletionProvider` 默认补全只返回 **P0 + P1 + P2**。
- UI 需要提供「显示高级属性」开关，打开后追加 **P3 + P4**。
- `BlockReference` 第一版必须支持 `Attribute["tag"]` 读取与补全。
- `Table` 第一版必须支持 `CellText(row,col)` 与 `TextContains`。
- `Region` / `3DSolid` 进入首版字段目录，但只暴露面积、体积、边界盒等白名单字段，不暴露内部 BRep。
- 所有颜色相关默认走 `TrueColor`，`ColorIndex` 只作为高级/调试字段。

## 六、关键技术决策（与 064 一致，补充一条）

1. 仍采用 **DynamicExpresso** 作为可编译表达式后端（`SelectionPredicate` 可编可序列化显示字符串）。
2. **SelectionFilter**：仅用于**已和 DXF 一致**的条件，或**先按图层/类型缩小**再迭代真值。
3. **BatchModify** 与选择引擎**解耦**（HyTool 第 7 节）。
4. **ArcGIS Pro 系「Python + WHERE + LINQ 心智」**：产品侧按 **§3.1** 做**分层**——**引擎语义唯一**（`SelectionPredicate` AST）；**Python** 与 **类 SQL 单行** 均为**可选项/导出/宿主**，不并行维护第二套真值与求值规则。
5. **规则查询编辑器** 按 **§3.2** 渐进实现：MVP 使用 `TextBox + Popup`；补全/快速输入/诊断全部只产生或解释 `SelectionPredicate`，不绕过查询引擎。
6. **规则查询字段只走白名单**：默认补全不使用 AutoCAD .NET public property 全量反射结果，只使用 **§3.2.10** 中经确认的字段目录；反射仅作为白名单字段取值的实现手段。
