# Markdown 专项测试回归与排障

## 1. 目标

提供可直接执行的专项测试清单、回归样例说明和常见故障排查路径，保证 Markdown 导入/编辑链路可持续验证。

## 2. 测试前准备

## 2.1 开发循环

1. 修改代码
2. Visual Studio 编译
3. AutoCAD 执行 `C2`
4. AutoCAD 执行 `C1`

## 2.2 测试入口

文件：`HyCADTool.Refactored/Test/TestCommand.cs`

- 导入测试：`new DesignSpecCommand().Execute();`
- 编辑测试：`new DesignSpecEditCommand().Execute();`

## 2.3 样例文件

- `HyCADTool.MarkdownEditor/RegressionSamples/04-code-block.md`
- `HyCADTool.MarkdownEditor/RegressionSamples/05-table-heavy.md`
- `HyCADTool.MarkdownEditor/RegressionSamples/06-long-doc.md`
- 索引：`HyCADTool.MarkdownEditor/RegressionSamples/manifest.json`

## 3. 回归用例清单

## 3.1 代码块样例（04）

- 关注点：
  - 代码块不被拆断
  - 代码块等宽字体显示
  - 代码块缩进合理

## 3.2 表格样例（05）

- 关注点：
  - 顶层表格转 `Table` 实体
  - MText 中不重复渲染该表格文本
  - 表格与正文相对位置稳定

## 3.3 长文档样例（06）

- 关注点：
  - 分栏稳定，不随机错栏
  - 引用、列表、段落间距一致
  - 更新后实体组可完整替换

## 4. 验证矩阵

| 场景 | 入口 | 预期 |
|---|---|---|
| 新建导入 | `DesignSpecCommand` | 插入 MText/Table，写入元数据 |
| 二次编辑-选正确对象 | `DesignSpecEditCommand` | 能加载源码并更新重建 |
| 二次编辑-先选错误对象 | `DesignSpecEditCommand` | 提示重选，不应直接中断 |
| 二次编辑-同组回溯 | `DesignSpecEditCommand` | 可通过组内实体找到源码 |

## 5. 元数据检查点

扩展字典键：

- `HyDesignSpec_MD`
- `HyDesignSpec_CFG`
- `HyDesignSpec_Group`

若二次编辑异常，优先确认这三项是否存在且组内一致。

## 6. 常见问题与排障

## 6.1 未知命令 `hymdE`

现象：命令行提示未知命令。  
原因：Refactored 不依赖直接 `[CommandMethod]` 注册。  
处理：通过 `C2 -> C1` 与 `TestCommand` 入口切换执行。

## 6.2 提示“此 MText 不含 Markdown 源码”

原因常见于：

- 选中的不是本功能生成实体；
- 实体无 `HyDesignSpec_MD`；
- 组内元数据不完整。

处理：

1. 重新选择同组对象；
2. 检查组 ID 与 XRecord 键；
3. 必要时重新插入后再测编辑。

## 6.3 表格未显示

排查路径：

1. 样例是否含顶层 Markdown 表格；
2. 该栏是否为空（`ColumnParagraphIndices` 空组）；
3. 是否已执行 `C2` 加载最新版本；
4. 锚点附近是否存在被遮挡/超视窗的表格。

## 6.4 更新后残留旧对象

排查路径：

1. 组 ID 是否一致；
2. `Update` 是否删除同组所有实体；
3. 是否误改了组键名常量。

## 7. 冒烟测试建议（发布前）

1. `04` 导入一次 + 编辑一次；
2. `05` 导入一次 + 编辑一次；
3. `06` 导入一次 + 编辑一次；
4. 抽查至少一次“错误对象后重选”路径；
5. 检查模型空间实体数量变化是否符合预期。

## 8. 测试记录模板

建议记录：

- 样例文件

- 定位结论与修复提交
