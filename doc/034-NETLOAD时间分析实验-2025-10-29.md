# NETLOAD 时间分析实验

**目的**: 确定 WPF 框架是在 NETLOAD 时加载，还是在首次创建窗口时加载

---

## 🧪 实验步骤

### 步骤 1：完全重启 AutoCAD
```
1. 关闭所有 AutoCAD 实例
2. 重新启动 AutoCAD
3. 不要加载任何插件
```

### 步骤 2：记录 NETLOAD 时间
```
1. 准备秒表（或看命令行时间戳）
2. 执行命令: NETLOAD
3. 选择: HyCADTool.Refactored.dll
4. 观察命令行输出
5. 记录以下时间：
   - T1: 从执行 NETLOAD 到看到"插件初始化中..."
   - T2: 从"插件初始化中..."到"插件初始化完成"
   - T3: NETLOAD 命令总时间
```

### 步骤 3：记录首次命令执行时间
```
1. NETLOAD 完成后，立即执行: HYOVSET
2. 观察命令行输出
3. 记录：
   - InitializeComponent 时间
   - 总时间
```

## 📊 预期结果

### 预期 A：WPF 在 NETLOAD 时加载

```
NETLOAD 命令:
  [插件初始化中...] 
  [加载 WPF 程序集...] ← 耗时 ~5秒（隐藏在这里）
  [依赖注入容器已初始化]
  [插件初始化完成]
  NETLOAD 总时间: ~5-10秒

首次执行 HYOVSET:
  [InitializeComponent] ~8ms ← 很快，因为 WPF 已加载
  总时间: ~50ms
```

### 预期 B：WPF 在首次创建窗口时加载

```
NETLOAD 命令:
  [插件初始化中...] 
  [依赖注入容器已初始化]
  [插件初始化完成]
  NETLOAD 总时间: ~0.5秒 ← 很快

首次执行 HYOVSET:
  [InitializeComponent] ~5000ms ← 很慢，需要加载 WPF
  总时间: ~5500ms
```

## 💡 可能的真相

### 真相 1：WPF 程序集已被 AutoCAD 加载

**AutoCAD 2024 可能内部使用了 WPF：**
- AutoCAD 的某些界面组件（如属性面板）使用 WPF
- 所以 PresentationCore.dll 等已经在内存中
- 你的 NETLOAD 只需要加载自己的代码，不需要加载 WPF
- 这解释了为什么 NETLOAD"很快"，而 InitializeComponent 也很快

**验证方法：**
```powershell
# 在 AutoCAD 启动后（加载任何插件之前）
# 打开 Process Explorer 或 Process Hacker
# 查看 acad.exe 进程加载的模块
# 搜索：PresentationCore.dll, PresentationFramework.dll
```

### 真相 2：NETLOAD 时间被低估

**可能用户对"快"的感知不同：**
- 5 秒对于 NETLOAD 命令来说可能算"快"？
- 因为 AutoCAD 的其他操作（如打开大图纸）可能需要更长时间
- 用户习惯了等待，所以 5 秒感觉"很快"

### 真相 3：.NET Framework 的程序集缓存

**.NET Framework 的 NGEN 缓存：**
- .NET Framework 会预编译常用程序集
- WPF 程序集可能已经被 NGEN 缓存
- 所以 JIT 编译时间大幅减少

**验证方法：**
```cmd
# 检查 WPF 程序集是否已被 NGEN 缓存
ngen display PresentationCore
ngen display PresentationFramework
```
