## 一、两条启动路径，一份业务初始化

HyCADTool 进 AutoCAD 的方式只有两条，**业务初始化代码完全共用同一个** `PluginInitializer.Initialize()`：

```
路径 A（开发模式）：AutoCAD ─NETLOAD─▶ ReCall.dll ─反射加载─▶ HyCADTool.dll ─调用─▶ PluginInitializer.Initialize()
路径 B（生产模式）：AutoCAD ─NETLOAD─▶ HyCADTool.dll ──────────────────────────▶ PluginInitializer.Initialize()
```

| 路径 | 何时用 | 编译配置 | NETLOAD 谁 | 是否需要 ReCall |
|------|--------|----------|------------|----------------|
| **A 开发** | 日常调试，C2 热重载 | `Debug` / `Release` | `ReCall.dll` | 必须 |
| **B 生产** | 客户安装包、性能基线 | `Production`（`HYCAD_PRODUCTION` 常量） | `HyCADTool.dll` | 不需要 |

**关键事实**：两条路径在进入 `PluginInitializer.Initialize()` 那一刻起，后面 11 个子阶段（WpfStub / WpfTraps / Warmup / Autofac / LoadCfg / Linetypes / StylesLayers / DocEvents / Road / RibbonMenus / Operators）**字节级一致**。

## 二、路径 A · 开发模式的完整调用链（最常用）

### 阶段 1 · AutoCAD 启动加载 ReCall.dll

```
用户操作
    │
    ▼
AutoCAD 命令行：NETLOAD ReCall.dll  （或预先放进 startup suite，自动加载）
    │
    ▼
[ReCall.dll]  程序集级 Attribute 触发：
    [assembly: ExtensionApplication(typeof(ReCallExtension))]
    [assembly: CommandClass(typeof(ReCallClass))]
    │
    ▼
AutoCAD 调用：ReCallExtension.Initialize()       ◀── src/ReCall/Recall.cs:54
    │
    ├─ Application.Idle += OnIdleAutoReload      ◀── 仅订阅一帧空闲事件，本身啥都不做
    │                                                 (受 HYCAD_RECALL_NO_AUTO_RELOAD 控制)
    │
    ▼  (此时 AutoCAD 启动套件还在加载，MdiActiveDocument 可能为 null)
... AutoCAD 完成自检 / 加载其它插件 / 显示初始 Drawing1.dwg ...
    │
    ▼  (UI 线程进入第一个空闲帧)
ReCallExtension.OnIdleAutoReload(...)            ◀── src/ReCall/Recall.cs:72
    │
    ├─ Application.Idle -= OnIdleAutoReload      ◀── 立即解绑，避免重复触发
    ├─ ed.WriteMessage("ReCall: 自动加载 HyCADTool …")
    │
    ▼
new ReCallClass().Reload()                       ◀── 等价用户在命令行手输 C2
```

**为什么要走 `Application.Idle` 这一帧延迟？**
AutoCAD 调 `IExtensionApplication.Initialize()` 时，文档管理器 / 命令行 / Ribbon 不一定就绪。延迟到 idle tick 再做实事，可拿到稳定的 `MdiActiveDocument` 与 `Editor`，所有日志能正常打印。

### 阶段 2 · C2（`ReCallClass.Reload`）—— 把 HyCADTool.dll 拉起来

`src/ReCall/Recall.cs::Reload`（`[CommandMethod("C2")]`）按顺序做 11 件事，每一步都打耗时：

```
1.  定位 bin\Debug 路径与 .nuget 缓存目录
        └─ 解析出 HyCADTool/bin/Debug/HyCADTool.dll 与依赖根

2.  CleanupOldTempCopies(retain = 15)
        └─ 清理 %TEMP%/HyCADTool/<ticks>/ 旧副本，只留最近 15 个

3.  CopyToTempAndGetLoadPath
        └─ bin\Debug 整个目录拷贝到新建的 %TEMP%/HyCADTool/<ticks>/
           （核心：源文件不锁，业务 DLL 可随便重编译）

4.  注册 AppDomain.UnhandledException + AssemblyResolve（首次 C2）
        └─ AssemblyResolve 内含【宿主程序集黑名单】
           AdWindows / AcMr / AcCoreMgd / PresentationFramework 等
           一律走 AppDomain 已加载查表，杜绝双载入（B11 真根因修复）

5.  PreloadCompanionAssemblies(loadDepsPath)
        └─ 副本目录里所有 HyCAD*.dll 在 Refactored 之前先 Load(byte[])
           （WPF 跨程序集 pack URI 不会触发 AssemblyResolve，必须预载）

6.  File.ReadAllBytes(loadPath) → byte[] mainBytes

7.  Assembly.Load(mainBytes)                            ◀── 关键一步
        └─ 得到一个全新的 HyCADTool 程序集实例
           缓存到 _refactoredAssembly

8.  InvokeLegacyTerminate(ed)                           ◀── 仅第二次起的 C2 生效
        └─ 反射调【上一个】PluginInitializer 实例的 Terminate()
           解绑文档事件、Reset ServiceLocator、保存面板设置
           （CLR 不能卸载程序集，但事件订阅必须解绑，否则跨 C2 累积）

9.  InvokePluginInitialize(asm)                         ◀── 进入业务初始化
        └─ Activator.CreateInstance(PluginInitializer 类型)
        └─ 反射调用 .Initialize()  ← 见【阶段 3】
        └─ 把新实例存到 _lastPluginInitInstance

10. CreateStaticMethodDelegate → _c1Action
        └─ 把 HyCADTool.App.Test.TestCommand.Run 反射封装成 Action
           供 C1 命令使用

11. CommandTable.ForceReload + ValidateAll
        └─ 重新解析 commands.json
        └─ 反射验证每条命令的 type / method 真实存在
        └─ 输出 "命令表：X 条已配置 + Y 条占位符，解析失败 N 条"
```

**输出形如**：

```
C2 #1 完成 1234ms  (复制80 + 读盘15+CLR.Load60 + 预载40 + Terminate0 + Initialize980 + 绑C12 + 表57)
  命令表：85 条已配置 + 50 条占位符，解析失败 0 条
```

### 阶段 4 · 用户输业务命令的调用链（C2 之后的日常）

以输 `gj`（绘制钢筋）为例：

```
AutoCAD 命令行：gj
    │
    ▼
[ReCall.dll]  CommandFacade.gj()                    ◀── src/ReCall/CommandFacade.cs
                 [CommandMethod("gj")]
                 public void Gj() => ReCallClass.Invoke("gj");
    │
    ▼
ReCallClass.Invoke("gj")                            ◀── src/ReCall/Recall.cs:554
    │
    ├─ 1) 取 _refactoredAssembly（C2 时缓存的 HyCADTool 程序集）
    │     若为 null → 提示先 C2，return
    │
    ├─ 2) 命令表查找：CommandTable.Get("gj")
    │     得到 entry = { Type = "HyCADTool.Features.Reinforcement.DrawReinforcementCommand",
    │                     Method = "Execute", ... }
    │
    ├─ 3) InvokePreHooks(refactored)                ◀── 反射执行三件套：
    │       SettingsPanelViewModel.CommitFocusedTextBoxValue()  ← TextBox 失焦提交
    │       SettingsPanelViewModel.Current.LoadSettings()       ← 同步最新参数
    │       SettingsPanelViewModel.Current.EnsureStylesApplied()← 同步样式/图层
    │
    ├─ 4) 反射创建实例 + 调用方法：
    │       var t = refactored.GetType("HyCADTool.Features.Reinforcement.DrawReinforcementCommand");
    │       var instance = Activator.CreateInstance(t, ctorArgs);
    │       var m = t.GetMethod("Execute");
    │       m.Invoke(instance, null);
    │
    ▼
[HyCADTool.dll]  DrawReinforcementCommand.Execute()
    │
    ├─ 用户在 AutoCAD 中拾取点 / 选择实体
    ├─ 调用 ReinService 等 Infrastructure 服务画线
    ├─ tr.Commit() 落盘
    │
    ▼
返回到 AutoCAD 命令行，等下一条命令
```

**关键点**：业务代码本身没有任何 `[CommandMethod]`。命令名 `gj` 由 `ReCall/CommandFacade.cs` 注册，业务类只是普通 C# 类，靠 `commands.json` 把命令名映射到类型 + 方法。

```

    │
    ▼
[VS] Ctrl+Shift+B 编译
    │   产物：src/HyCADTool/bin/Debug/HyCADTool.dll （新版本）
    │
    ▼
[AutoCAD] 命令行输 C2
    │
    ▼  跳回【阶段 2】，但有差异：

          → 旧实例还在 AppDomain（CLR 不卸载），但所有反射查 _refactoredAssembly 都用新的
       9. 全新的 PluginInitializer.Initialize() 跑一遍
    │

```

**唯一需要关 CAD 重新 NETLOAD 的场景**：改了 `src/ReCall/*.cs`（含 `Recall.cs` / `CommandFacade.cs` / `CommandTable.cs`）—— ReCall 自己不热重载自己。

## 三、路径 B · 生产模式调用链

```
[VS] dotnet build src\HyCADTool\HyCADTool.csproj -c Production
    │
    ├─ HYCAD_PRODUCTION 编译常量被定义
    ├─ src/HyCADTool/App/Production/ProductionEntry.cs 内 #if HYCAD_PRODUCTION 段被编译
    ├─ HyCADTool.dll 程序集 manifest 里出现：
    │     [assembly: ExtensionApplication(typeof(ProductionExtension))]
    │     [assembly: CommandClass(typeof(ProductionCommandFacade))]
    │
    ▼
[发布客户机]  AutoCAD 命令行：NETLOAD HyCADTool.dll
    │
    ▼
AutoCAD 调用：ProductionExtension.Initialize()      ◀── src/HyCADTool/App/Production/ProductionEntry.cs:43
    │
    ├─ _initializer = new PluginInitializer();
    ├─ _initializer.Initialize();                   ◀── 进入【阶段 3】完全相同的初始化
    │
    ▼
所有命令立即可用（[CommandMethod] 由 ProductionCommandFacade 注册，与 ReCall.CommandFacade 一一对应）
```

**生产模式与开发模式唯一的运行时差异**：
- 没有 `Assembly.Load(byte[])`，HyCADTool.dll 由 AutoCAD 直接 LoadFrom 加载（`.Location` 非空）。
- 没有 ReCall 这层壳，命令调用不经 `ReCallClass.Invoke`，而是 `ProductionCommandFacade.Gj() → DrawReinforcementCommand.Execute()` 直调（无反射）。
- 不能 C2 / C1，不能改 `commands.json` 即时生效（生产环境通常也不允许）。

## 六、读完这篇之后，你应该知道：

1. **谁是 AutoCAD 真正第一眼看到的 dll**——开发模式是 `ReCall.dll`，生产模式是 `HyCADTool.dll`，两者**绝不同时存在于同一份发布**。
2. **业务初始化的统一入口**——`PluginInitializer.Initialize()`，11 子阶段顺序固定，每段耗时都打日志（`⏱ PluginInitializer 阶段耗时(ms)`）。
3. **C2 = 反射调一次 `PluginInitializer`**——不是"重启 AutoCAD"，而是"把新版 HyCADTool.dll 加载进来再走一遍业务初始化"。
4. **命令名怎么变成业务类的 `Execute`**——`CommandFacade.cs`（被 NETLOAD 扫到）→ `ReCallClass.Invoke(key)`（命令表反射）→ 业务类 `Execute`。
5. **`commands.json` 改了立即生效**——`CommandTable` 按 `mtime` 自动重载，不用 C2、不用关 CAD。
6. **唯一需要关 CAD 的修改**：`ReCall/*.cs` / `App/Bootstrap/AutofacModule.cs` 的 DI 规则 / 升级托管 NuGet 版本 / 加新 `[CommandMethod]` 想直接输命令名（用 N1~N50 占位则不需要关）。

## 七、定位问题的最快路径

| 现象 | 第一刀切到哪 |
|------|-------------|
| AutoCAD 启动后没有任何 HyCAD 入口 | 命令行输 `hyRecallSelfCheck`；看 `_refactoredAssembly` 是否未加载 |
| C2 报"未找到 HyCADTool.dll" | 检查 VS 编译是否成功（`src/HyCADTool/bin/Debug/HyCADTool.dll` 存在性） |
| 输业务命令报"占位符未分配" | 编辑 `src/ReCall/commands.json`，把 N1~N50 占位符指向真实 `type/method` |
| 输业务命令报"类型未找到" | C2 时 `ValidateAll` 也会报；说明 `commands.json` 里的全限定名拼错或类未编译进 dll |
| Ribbon 选项卡不见 | 看 `_ribbonReady` 日志；输 `_RIBBON` 打开 Ribbon UI 后会自动重挂 |
| Badge / 0xE0434352 / "调度程序处理已暂停" | 直接读 `.cursor/rules/05-AdWindows-WPF-PaletteSet宿主.mdc`，**禁止**走"加 ResourceAssembly / WarmupBadge"老路 |
| 改了业务代码 C2 后还是旧行为 | VS 是否真的编译成功？`bin/Debug/HyCADTool.dll` 的 mtime 是否新于上次 C2？ |
