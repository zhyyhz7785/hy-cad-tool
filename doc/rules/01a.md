## 一、项目配置

### 1.1 目录结构

```
hy-cad-tool/
├── HyCADtool/                    # 旧项目（不要修改）
├── HyCADTool.Refactored/         # 重构项目（主要工作区）
│   ├── Domain/                   # 领域层（平台无关）
│   ├── Infrastructure/           # 基础设施层（AutoCAD 相关）
│   ├── Presentation/             # 表示层（命令）
│   └── Test/TestRunner.cs        # 可选，Refactored 内自测用
├── ReCall/                       # 热重启（仅改配置区）
│   └── Recall.cs                 # C2 重载 / C1 测一个命令
└── NewPlan1/                     # 文档目录（精简版）
```

### 1.2 关键文件

| 文件                                           | 用途               | 是否可修改                                   |
| ---------------------------------------------- | ------------------ | -------------------------------------------- |
| `ReCall/Recall.cs`                             | 热重启；C1 测谁由此配置 | ✅ 仅修改顶部配置区（C1_CLASS_NAME、C1_METHOD_NAME） |
| `HyCADTool.Refactored/Test/TestRunner.cs`      | 可选测试入口       | ✅ 需要时改；日常单命令测试以 C1 为主         |
| `HyCADTool.Refactored/Presentation/Commands/*` | 命令实现           | ✅ 主要工作区                                 |

## 二、标准工作流程

### 2.1 开发循环（核心）

```
修改代码 → VS 编译 → C2 重载 → C1 测试 → 重复
```

### 2.2 命令说明

- **C2**：重新加载 `HyCADTool.Refactored.dll`（热重启）
- **C1**：执行**当前配置的一个测试命令**（要测谁在 Recall.cs 顶部配置）

### 2.3 用户习惯

1. **不需要重启 AutoCAD**：用 C2 热重启即可
2. **换测哪个命令**：改 Recall.cs 的 `C1_CLASS_NAME`、`C1_METHOD_NAME`，保存后 C2 再 C1
3. **Visual Studio 编译后反馈**：用户会告知编译结果

## 三、代码规则（必须遵循）

### 3.1 输出规则 ⚠️ 极其重要

#### ✅ 必须遵循

**常用命令输出原则：极简 = 1-3 行**

```csharp
// ✅ 正确：简洁摘要（一行）
ed.WriteMessage($"\n处理完成：{inputCount} → {outputCount} 曲线");
ed.WriteMessage("\nINFO: 操作 耗时 1234 毫秒");  // LogElapsedTime 输出

// ✅ 正确：只在错误时输出
if (selRes.Status != PromptStatus.OK)
{
    ed.WriteMessage("\n未选择任何对象。");
    return;
}
```

#### ❌ 严格禁止

**性能杀手：循环内输出 = 绝对不要**

```csharp
// ❌ 错误：循环内详细输出（影响性能 50-90%）
foreach (var item in items)  // 如果有 1000 个对象
{
    ed.WriteMessage($"\n处理 {item.Name}...");        // ❌ 输出 1000 次
    ed.WriteMessage($"\n  属性: {item.Property}");     // ❌ 输出 1000 次
    ed.WriteMessage($"\n  尝试处理...");               // ❌ 输出 1000 次
}

// ❌ 错误：详细调试信息
ed.WriteMessage($"\n尝试分割 Line: [{start:F4}, {end:F4}]");
ed.WriteMessage($"\n  起点: ({pt.X:F2}, {pt.Y:F2})");
ed.WriteMessage($"\n  终点: ({pt2.X:F2}, {pt2.Y:F2})");
```

### 3.2 时间测量规则

**使用 LogElapsedTime（完全按照 SimpleLogger 风格）**

```csharp
// TestRunner.cs 中
private void LogElapsedTime(string operation, Action action)
{
    var stopwatch = Stopwatch.StartNew();
    action?.Invoke();
    stopwatch.Stop();
    _editor?.WriteMessage($"\nINFO: {operation} 耗时 {stopwatch.ElapsedMilliseconds} 毫秒");
}

// 使用
LogElapsedTime("测试执行", () =>
{
    var cmd = new YourCommand();
    cmd.Execute();
});
```

**输出格式（简洁一行）：**

```
INFO: 测试执行 耗时 1234 毫秒
```

### 3.3 单命令测试（推荐）与 TestRunner（可选）

**日常单命令测试**：在 Recall.cs 配置 `C1_CLASS_NAME`、`C1_METHOD_NAME`，C2 后 C1 即测该命令，无需改 TestRunner。

**若在 Refactored 内跑多组测试**，可用 TestRunner，异常捕获请用 `System.Exception`（见规则 06）：

```csharp
catch (System.Exception ex)
{
    _editor.WriteMessage($"\n错误：{ex.Message}");
}
```

## 四、架构原则（快速参考）

### 4.1 Clean Architecture 分层

```
Presentation (Commands)
    ↓ 依赖
Application (Use Cases) [可选，简单场景省略]
    ↓ 依赖
Domain (算法、实体、值对象) ← 平台无关，可迁移 Blender
    ↑ 实现
Infrastructure (AutoCAD 适配器)
```

### 4.2 职责分配

| 层级               | 职责                   | 依赖规则                       |
| ------------------ | ---------------------- | ------------------------------ |
| **Domain**         | 算法、业务逻辑、值对象 | ✅ 零依赖（可迁移）             |
| **Infrastructure** | AutoCAD API 封装       | ➜ 依赖 Domain                  |
| **Presentation**   | 命令、用户交互         | ➜ 依赖 Domain + Infrastructure |

## 五、用户偏好（重要）

### 5.1 回应风格

- **语言**：优先中文，除非特别指定英文
- **语气**：正式、专业
- **风格**：第一性原理思维，详细解释

### 5.2 工作方式

1. **不要直接做工作总结**：等用户测试完成后再做
2. **编译工作让用户用 Visual Studio 进行**：完成后用户会反馈结果
3. **遵循 Clean Architecture**：按职责分层，不要简单迁移

### 5.3 不要修改的项目

- ❌ **ReCall 项目**：仅可改顶部配置区（C1_CLASS_NAME、C1_METHOD_NAME 等），其余勿动
- ❌ **HyCADtool 旧项目**：完全不要修改

---

## 六、🔥 最重要的 3 条规则

1. **极简输出**：常用命令 = 1-3 行输出
2. **循环内禁止输出**：性能杀手，绝对不要
3. **只修改 Refactored 项目**：ReCall 仅改配置区，其余勿动

## 七、常见场景处理

### 场景 1：用户说"还有很多输出"

**原因**：使用了旧版本的 DLL

**回应**：

```
当前代码已优化，只有 X 行输出。
您看到的是旧版 DLL，请：
1. Visual Studio 重新生成（Rebuild）
2. AutoCAD 执行 C2 命令
3. 再次测试
```

### 场景 2：用户要求优化性能

**步骤**：

1. 删除所有循环内输出（最重要）
2. 删除详细调试信息
3. 异常处理用空 `catch`
4. 只保留关键信息（错误、警告、结果）

### 场景 3：换测另一个命令

**做法**：修改 `ReCall/Recall.cs` 顶部配置后 C2 再 C1。

```csharp
private const string C1_CLASS_NAME = "HyCADTool.Refactored.Presentation.Commands.新命令类名";
private const string C1_METHOD_NAME = "Execute";
```
