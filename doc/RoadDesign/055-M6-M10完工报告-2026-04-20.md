### 2.4 历史目录约定

对 DWG `C:\prj\abc.dwg`，历史目录为 `C:\prj\abc.roaddesign.history\`：

```text
abc.roaddesign.history/
├── history-index.json               # HistoryIndex（Entries + NextSeqNo）
├── snap-0001-20260420-143015.json   # 全量 RoadDesign 快照
├── snap-0002-20260420-150248.json
└── ...
```

- 每个条目带 **SHA-256 Checksum**；`Restore` 前校验，失败抛 `InvalidDataException`。
- 索引损坏（JSON 解析失败）时 `LoadIndex` 返回空 `HistoryIndex`，不丢旧快照文件。
- `CreateSnapshot` 采用"临时文件 + `File.Replace`"原子写入。

### 5.2 默认优先级表

| 条带类型 | 优先级 |
|---------|:------:|
| `GreenStrip`（绿化带） | 1 |
| `Sidewalk`（人行道） | 2 |
| `NonMotorized`（非机动车道） | 3 |
| `MedianStrip`（中央分隔带） | 4 |
| `Pavement`（机动车道） | 5 |

同类相遇：机动车道 / 中央分隔带 → `BlendByLength`；其他同类 → `ConnectWithArc`。
异类相遇：高优先级 `KeepSelf`，低优先级 `KeepOpposite`；同优先级不同类型 → `ConnectWithArc`。

### 5.3 MVP 决策

考虑到 WPF DataGrid 矩阵编辑 + XAML 中文特殊字符编码反复踩坑成本（详见 §9.1），本轮 **M9.2 做命令行 UX 而非 WPF 窗口**。规则 override 持久化到 `RoadDesign.IntersectionBandMergeRules`（进入 `.roaddesign.json` 而非 `hy-settings.json`）。WPF DataGrid 版可在后续需要时基于已有 `IntersectionBandMergeRuleTable` 直接搭建。

### 5.4 M9.3 集成范围

`IntersectionBandMergeRuleTable.ResolvePairs()` 方法给命令层提供"按相邻臂条带类型查表得策略"的查询入口。当前 `Intersection.Legs` 没有 `BandKind` 字段，所以 **几何层面的真实合并（裁剪 / 延伸 / 圆角）留给 M10+ 的 `CorridorSweepService` 再扩展**。本轮实现至规则表 + 查询 + 持久化，真实几何集成标记为"深化留给下一轮"。

### 6.3 扫掠算法要点

- 采样：`SampleAlignmentUniformly(polyline, stepM)` 按弧长均匀采样，默认 5 m 一点，首尾必保证端点在结果里；bulge 忽略（v1 按直线段近似，真实弧段采样留给下一轮）。
- 法向：切向顺时针旋 90°（`nx=-ty, ny=tx`），左右一致使 "左半 -n / 右半 +n" 符号稳定。
- 展开：从中心线起，先算中分带半宽，再按 `LeftBands` / `RightBands` 宽度累加；每条条带边都产出一条分界线 Polyline3D，最外一条是红线。

### 6.4 双模式落图

## 9. 经验与踩坑记录

### 9.1 XAML 中文编码陷阱

在构建 `StructureLayerWindow.xaml` 时，曾两次遇到 `MC3000: Invalid character in the given encoding.` 错误。

**症状**：Write 工具写入 UTF-8 无 BOM 的 XAML 含某些中文（如"×"、标题"结构层定义"）时，MSBuild 的 XAML 预处理器在 line N 报不可识别字符，文件 offset 3499 处出现 U+FFFD 替换字符。

**规避**：
1. 参照既有 `AlignmentTableWindow.xaml`（同样 UTF-8 无 BOM），XAML 中文属性值一般可用，但 `×` / `↑↓` 等非基本 CJK 字符有较高概率触发问题。
2. 本次 `StructureLayerWindow.xaml` 最终改为**纯英文字符串**（按钮 Content / Expander Header / PropertyRow Label 均用 `Name` / `Thickness cm` / `Add Scheme` 等），完全绕开编码问题。中文界面文本的升级留给后续"单独用 UTF-8 BOM 重写 XAML"或"把字符串抽到 `.resx` 资源"时再做。

### 9.2 PowerShell 重定向语法陷阱

`dotnet build ... 2>&1 | Select-Object -Last 50` 在 PowerShell 里会被解析为 "`2` 输出流到 `&amp;1`"，MSBuild 报 `MissingFileSpecification`。**解决**：直接用 `dotnet build ... /verbosity:minimal /consoleloggerparameters:NoSummary`，不再做 `2>&1`。

### 9.3 ReCall.dll 构建锁定

AutoCAD 打开时 `ReCall.dll` 被锁定，如果走 `ProjectReference` 从 `HyCADTool.Refactored` 触发 `ReCall` 链式构建会 `MSB3027/MSB3021` 整个解决方案失败。这一规律已在既有 [`HyCADTool.Refactored.csproj`](../../HyCADTool.Refactored/HyCADTool.Refactored.csproj) 的 Reference+HintPath 机制中解决，本轮无需再改。开发时**只构建 `HyCADTool.Refactored.csproj` 与 `.Tests.csproj`**，`ReCall` 自身不需要每次重建。

### 9.4 RelayCommand 没有 `RaiseCanExecuteChanged`

项目的 [`RelayCommand`](../../HyCADTool.Refactored/Presentation/ViewModels/RelayCommand.cs) `CanExecuteChanged` 是 noop（不跟 `CommandManager` 绑定）。所以 ViewModel 里按钮 `IsEnabled` 的响应式刷新得依赖额外的 `INotifyPropertyChanged` 属性（如本轮 `RoadHistoryViewModel.CanRestore`）供 XAML 绑定，**不能调用 `((RelayCommand)x).RaiseCanExecuteChanged()`**。

### 9.5 Newtonsoft 多态反序列化

`List<IHyControl>` 的多态解析必须在属性上同时显式标：

```csharp
[JsonProperty(ItemConverterType = typeof(HyControlJsonConverter),
              ObjectCreationHandling = ObjectCreationHandling.Replace)]
public List<IHyControl> Controls { get; set; } = new List<IHyControl>();
```

- `ItemConverterType`：每个元素走多态 converter
- `ObjectCreationHandling = Replace`：强制每次反序列化新建 List（避免旧实例残留）
