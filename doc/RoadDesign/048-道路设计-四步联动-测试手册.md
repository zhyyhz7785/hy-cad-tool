# 048 · 道路设计 · 四步联动 — 测试手册

> 适用范围：**道路四步联动**（新建命名路线 → 桩号区段挂横断模板 → 出平面图 → 自动平交检测）。  
> 技术背景见 [047-道路设计-四步联动-2026-04-25.md](./047-道路设计-四步联动-2026-04-25.md)；索引见 [041-道路设计-AI上下文索引.md](./041-道路设计-AI上下文索引.md)。

---

## 一、测试环境

| 项 | 说明 |
|----|------|
| 平台 | 已加载 HyCAD 道路插件的 AutoCAD，完成 **C2 热重载**（或冷启动后首次加载与 `commands.json` 一致） |
| 图档 | 含道路设计 JSON（`hyRoad` 体系），至少一个 **RoadDesign** 下已有 **标准横断面模板**（`Design.Templates` 非空） |
| 图层 | 与 `HyRoadLayers` 一致；若层被锁，用既有 **LayerLockScope** 或先解锁，避免“静默落 0 层” |

**命令全名与短别名（命令行可输）**

| 全名 | 短别名 | 作用（一句话） |
|------|--------|----------------|
| `hyRoadAName` | `rAn` | 拾取多段线登记路线并命名 |
| `hyRoadAlnAssign` | `rAsg` | 为路线指定桩号区段 + 模板 |
| `hyRoadAlnPlan` | `rPlp` | 按区段（或首模板）出平面 |
| `hyRoadAutoIntersection` | `rIa` | 多路线两两求交、聚类、批量生成交叉口 |
| `hyRoadPlan` | （面板/JSON） | 与 `hyRoadAlnPlan` 行为一致（转发） |

---

## 二、前置数据准备（通用）

1. 打开或新建可保存道路 JSON 的图档，确保 **当前设计** 中至少有 **1 个横断面模板**（在道路面板/横断设计器里建过并写入设计即可）。
2. 在模型空间用 **LWPOLYLINE** 或道路认可的 **多段线** 画 1～2 条在平面**相交**或**不相交**的线，用于登记路线与相交测试。
3. 调用 **`hyRoadTree`**（或统一面板）打开 **项目树**，确认根节点/设计节点可展开。

**通过标准（本节）**：项目树能列出当前设计；命令行能输入 `rAn` 等不报错 “未知命令”。

---

## 三、用例 A — 步骤 1：新建路线并命名（`hyRoadAName` / `rAn`）

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| A1 | 命令行输入 `rAn` 或 `hyRoadAName` | 进入拾取/命名流程，命令行有道路提示语 |
| A2 | 按提示拾取一条多段线；输入**合法名称**（非空，按提示结束） | 该线登记为 `Alignment`，名称写入，JSON/项目树**刷新**后出现对应路线节点 |
| A3 | 对第二条多段线重复（若需两条线测相交） | 设计内 `Alignments` 条数 +1，项目树**两条**路线 |

**通过标准**：项目树中路线节点显示名与输入一致；图元带 `HY_ROAD` 等既有规则（以代码/Road 文档为准）。

**负例 / 注意**

- 取消拾取 / 不输入名称：不应对已有数据做部分写入，或回显“已取消”（以实际提示为准）。

---

## 四、用例 B — 步骤 2：配置横断面区段（`hyRoadAlnAssign` / `rAsg`）

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| B1 | 输入 `rAsg` | 提示拾取**路线**线位（HY_ROAD 对应实体） |
| B2 | 拾取**一条**已登记路线；在列表/编号中选 **一个**已有模板 | 提示输入**起、终桩号**（米，沿中心线） |
| B3 | 输入**覆盖整线**的区间，例如 `0` 与路线总长（或默认若提供） | 写入 `CrossSectionAssignments` 一条，**无与已有区段重叠** |
| B4 | 再执行一次，换另一模板、**相邻或衔接**的下一区段 | 可形成多段；若区间重叠，应**拒绝**并提示，不落库 |

**通过标准**

- 项目树 **“横断面”** 相关节点下：优先以 **K…～K… → 模板名** 形式展示区段；无区段时仍为“可引用全量模板”的既有行为。

**负例**

- 桩号上 **End ≤ Start** 或越出路线总长：应校验失败或提示，不写脏数据。  
- 无模板时：应有明确提示，无法强写区段。

---

## 五、用例 C — 步骤 3：按区段出平面图（`hyRoadAlnPlan` / `rPlp` 与 `hyRoadPlan`）

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| C1 | 对**已配置区段**的路线执行 `rPlp` | 调 `SweepWithAssignments`；命令行/日志可带**分段数、顶点**等汇总（若有实现回显） |
| C2 | 删除或清空区段，仅余模板池时按提示执行 | 可回退为**首模板**逻辑并**提示**先配置区段（与 047 描述一致） |
| C3 | 执行 `hyRoadPlan` | 行为与 `hyRoadAlnPlan` **一致**（转发），脚本可兼容 |

**通过标准**

- 平面线位/红线/板块（在条带一致时）与既有 `RoadPlanDrawService` 图层、XData 规则一致。  
- **多模板条带数不一致**时：允许仅**中心线 + 左右红线**（`UsedBandDividers = false`），不崩溃。

---

## 六、用例 D — 步骤 4：自动平交（`hyRoadAutoIntersection` / `rIa`）

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| D1 | 仅 **1 条**路线时执行 `rIa` | 提示至少需要 **2 条**路线，不进入生成 |
| D2 | **2 条及以上**、中心线在平面有**真交**时执行 | 命令行列出 **候选交叉口**（序号、中心近似坐标、参与路线名） |
| D3 | 输入 **单个序号** 或 **逗号分隔多序号** | 对选中簇调用既有交叉口生成+写块，有成功/失败计数或汇总 |
| D4 | 输入 **A** 或 **全部** | 对全部候选批量处理（以提示为准） |
| D5 | 中心线**平行无交** 或 交点在容差外 | 提示未发现或候选为空（与实现一致） |

**通过标准**

- JSON/领域对象中出现新增或更新的 `Intersection`（以既有 `RoadIntersectionService` 为准），图面有预期实体。  
- 端点-端点/纯 T 接若被排除，应无“假交叉口”误报或文档说明排除策略。

**（若实现含）交互** 在提示中若出现 **R/W/V** 等，按命令行帮助逐项验证。

## 七、用例 E — 项目树面板与右键

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| E1 | 打开 `RoadProjectTreePanel`，看**第一行** | 四按钮依次为：**新建路线**、**配置横断面**、**生成平面图**、**检测相交**；第二行仍为搜索+刷新 |
| E2 | 点 **新建路线** | 等效发送 `hyRoadAName`（`rAn`） |
| E3 | 选中**路线**节点，点 **配置横断面** | 发 `hyRoadAlnAssign`，尽量带该路线上下文（若有） |
| E4 | 点 **生成平面图** | 发 `hyRoadAlnPlan` 类命令；若有选中路线则与节点绑定 |
| E5 | 点 **检测相交** | 发 `hyRoadAutoIntersection`（`rIa`） |
| E6 | 根项目节点 **右键 → 重命名** | 可改**项目**名，落盘+树更新 |
| E7 | 路线节点 **右键 → 重命名** | 可改**路线**名，落盘+树更新 |

**通过标准**

- 无 WPF 资源解析异常、无 `AddVisual` 后崩溃；按钮可用性与是否有项目/节点逻辑合理。

## 八、用例 F — 持久化与兼容

| 步骤 | 操作 | 预期结果 |
|------|------|----------|

## 九、研发侧 — 自动化测试（`HyCADTool.Refactored.Tests`）

在仓库根目录执行（仅道路四步相关）：

```text
dotnet test HyCADTool.Refactored.Tests\HyCADTool.Refactored.Tests.csproj --filter "FullyQualifiedName~CrossSectionAssignmentTests|FullyQualifiedName~CorridorSweepServiceAssignmentTests|FullyQualifiedName~IntersectionDetectorTests|FullyQualifiedName~RoadProjectTreeViewModelToolbarCommandsTests"
```

| 类 | 覆盖点 |
|----|--------|
| `CrossSectionAssignmentTests` | 桩号区间校验、JSON 往返 |
| `CorridorSweepServiceAssignmentTests` | 单区段全路径 `SweepWithAssignments`、左右红线 |
| `IntersectionDetectorTests` | 两两交点、聚类、容差边界 |
| `RoadProjectTreeViewModelToolbarCommandsTests` | 四按钮在空 handler 下可执行 |

> 全量 `HyCADTool.Refactored.Tests` 可能包含依赖 AutoCAD 宿主的用例，在纯 `dotnet test` 环境下部分会失败，属已知现象；**发版/回归**以本节的筛选集 + 第二节～第八节**手工**清单为准更稳妥。
