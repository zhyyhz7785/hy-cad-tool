# 058 · C2 热重载耗时观测与原因（2026-04-21）

> 与 [041-道路设计-AI上下文索引](./041-道路设计-AI上下文索引.md) 配套：说明为何近期 **`C2` 明显变快**，以及如何自己对照命令行分段确认。

---

## 1. 先看命令行：C2 把时间拆成五段

`ReCall` 的 `C2` 在完成后会打印类似：

```text
C2 #n 完成 XXXms (复制A + 加载B + TerminateC + InitializeD + 表E)
```

| 分段 | 含义 |
|------|------|
| **复制** | 把整个 `HyCADTool.Refactored\bin\<配置>\` **递归复制**到 `%TEMP%\HyCADToolRefactored\<ticks>\`（每次新目录，避免覆盖已映射文件）。 |
| **加载** | `Assembly.Load(File.ReadAllBytes(…))` 加载**新的** `HyCADTool.Refactored.dll`。 |
| **Terminate** | 反射调用上一版 `PluginInitializer.Terminate`（解绑、清容器等）。 |
| **Initialize** | 反射创建新版 `PluginInitializer` 并 `Initialize`（Autofac、道路子系统、文档事件等）。 |
| **表** | `CommandTable.ForceReload()` + `ValidateAll`（`commands.json` 校验）。 |

**提速时优先看**：是 **「复制」** 变短、**「加载」** 变短，还是 **「Initialize」** 变短——对应原因不同（见下文）。

---

## 2. 代码层面：与「变快」直接相关的改动

### 2.1 宿主程序集 `AssemblyResolve` 黑名单（2026-04 落地）

**位置**：`ReCall/Recall.cs` → `ResolveAssembly`，常量 `AutoCadHostAssemblyNames`。

**作用**：对 `AdWindows`、`AcMgd`、`AcDbMgd`、`PresentationFramework` 等 **AutoCAD / WPF 宿主已加载**的程序集，解析时 **直接返回 `AppDomain` 里已有那份**，而 **不再** 从临时目录 `ReadAllBytes` + `Assembly.Load` 再载入一份旧版（例如 NuGet 传递的 `AdWindows 5.0.1.2`）。

**为何会感觉更快**：

- 绑定阶段 **减少大量磁盘读** 与 **重复加载/JIT** 尝试；
- 避免「错误路径」上反复探测 `deps` / `.nuget`（黑名单在路径拼接之前就短路）。

**关联文档**：`doc/RoadDesign/00.md`（B11 / Badge 类型身份割裂）；技能 `hycad-project-pitfalls` 中 **B11 / AdWindows 双载入** 条目。

**Git**：`ReCall/Recall.cs` 在提交 `1c731dd`（2026-04-20）引入该黑名单逻辑。

### 2.2 伙伴程序集预加载的幂等（第二次及以后的 C2）

**位置**：`ReCall/Recall.cs` → `PreloadCompanionAssemblies`。

**行为**：枚举临时目录下 `HyCAD*.dll`，若 `AppDomain` 里 **已有同短名**，则 **跳过** `Assembly.Load(byte[])`。

**现象**：首次 `C2` 常见 `预加载伙伴: +N / 已存在 0`；**同一会话内再次 `C2`** 常见 `+0 / 已存在 M`，**「加载」分段往往明显变短**（少读、少载入多个 HyCAD 卫星程序集）。

**注意**：**「复制」** 仍每次都是全量拷贝 `bin`——若只有「复制」变短，更可能是输出目录变小或本机 I/O 环境变化，而不是这段逻辑。

### 2.3 `PluginInitializer` 不再作为 `IExtensionApplication`（避免双初始化）

**背景**：`Assembly.Load(byte[])` 加载的 `HyCADTool.Refactored` 仍会被 AutoCAD 扫描到 **`IExtensionApplication`**，导致 **AutoCAD 自动 `Initialize` 一次 + ReCall 反射再 `Initialize` 一次**。

**现状**：`PluginInitializer` **不继承** `IExtensionApplication`，仅由 `C2` 反射调用（见 `ReCall/Doc/Recall-陷阱与问题.md` **§4**）。

**对耗时的影响**：**「Initialize」** 不再做两套几乎相同的 DI/订阅/子系统初始化，**同一次 C2 下该分段应显著低于双初始化时期**。

## 3. 环境与构建（辅助因素，需自行对照）

| 因素 | 说明 |
|------|------|
| **`bin\Debug` 文件数量与体积** | `CopyDirectoryRecursive` 会拷贝目录下**所有文件**；若某次构建后输出目录变小（依赖复制策略、清理了多余 DLL），**「复制」** 会更快。 |
| **磁盘与杀毒** | `%TEMP%` 与工程盘若为 SSD、或对开发目录排除实时扫描，复制阶段波动大。 |
| **首次 vs 重复 C2** | 首次冷启动通常慢于同会话内第二次（见 2.2）。 |

---

## 4. 建议的「以后参考」用法

1. 每次觉得 C2 变慢/变快，**先抄一行完整分段计时**（含五次分项）。
2. 若 **「Initialize」** 异常大：查是否又回到双初始化、或 `PluginInitializer` 里新增重逻辑。
3. 若 **「加载」** 在**第二次 C2** 仍很大：查伙伴预加载是否失败、或 `bin` 是否异常膨胀。
4. 若 **「复制」** 很大：查 `bin` 体积、临时目录磁盘、是否误把无关大文件放进输出目录。
