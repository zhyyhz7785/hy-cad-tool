# 056 · 当前文件系统说明（2026-04-20）

> 目标：把 **hy-cad-tool 现在这套文件系统** 讲清楚，明确“哪类文件该改、哪类文件别改、功能链路从哪里进哪里出”。
> 适用对象：继续做道路设计（RoadDesign）功能、查问题、补文档、清理仓库噪音时的快速导航。

---

## 0. 一句话结论

当前仓库是一个 **AutoCAD 插件主工程 + WPF UI 组件库 + 热重载壳 + 文档体系** 的组合体。  
你日常 90% 的开发应集中在 `HyCADTool.Refactored`，其余目录大多是 UI 复用、测试、热加载、文档和构建产物。

---

## 1. 仓库根目录分区（你现在看到的“文件系统”）

按职责分成 5 层最清晰：

### 1.1 产品源码层（主要改这里）

- `HyCADTool.Refactored`：主插件工程（命令、ViewModel、Domain、Infrastructure 都在这里）
- `HyCADTool.Refactored.Tests`：主工程测试（Domain/Presentation 等单元测试）
- `HyCAD.BlenderUI`：WPF 主题与控件库（Blender 风格窗口、控件模板）
- `HyCADTool.TextLayout`：文字/排版相关基础库
- `HyCADTool.MarkdownEditor`：独立 Markdown 编辑器工程（与 RoadDesign 主链路相对独立）
- `HyCADTool.MarkdownEditor.TestHost`：MarkdownEditor 的测试宿主
- `ReCall`：AutoCAD 侧热重载与命令入口壳（`commands.json`、`CommandFacade.cs` 等）

### 1.2 文档与计划层（查设计和历史）

- `doc`：项目文档总目录（其中 `doc/RoadDesign` 是道路设计主文档线）
- `Plan`、`NewPlan`：阶段性计划、方案记录
- `research`：调研/学习型输出

### 1.3 开发工具与配置层

- `.cursor`：Cursor 规则、skills、计划缓存
- `.vscode`：VSCode/Cursor 工作区配置
- `agent-tools`：辅助脚本/工具文件
- `NuGet.Config`：NuGet 源配置
- `HyCADtoolGpt.sln`：解决方案入口

### 1.4 构建与索引产物层（通常不手改）

- 各项目下的 `bin/`、`obj/`：编译输出与中间产物
- `.vs/`：Visual Studio 索引与会话缓存（如 `.suo`、索引数据库）
- 根目录 `debug-*.log`：调试日志

### 1.5 临时与杂项层

- `temp.md`、`Untitled 11.assets`、零散临时文件：临时调试或编辑痕迹，按需清理

## 2. RoadDesign 功能主链路（最关键）

如果你在做道路设计，文件系统里应该按这条链找代码：

1. **命令入口（Presentation）**  
   `HyCADTool.Refactored/Presentation/Commands/Road/*Command.cs`
2. **窗口/面板与交互（Presentation）**  
   `HyCADTool.Refactored/Presentation/Views/Road/*`  
   `HyCADTool.Refactored/Presentation/ViewModels/Road/*`
3. **业务模型与算法（Domain）**  
   `HyCADTool.Refactored/Domain/Models/Road/*`  
   `HyCADTool.Refactored/Domain/Services/Road/*`
4. **AutoCAD 落地（Infrastructure）**  
   `HyCADTool.Refactored/Infrastructure/AutoCAD/Services/Road/*`  
   `HyCADTool.Refactored/Infrastructure/AutoCAD/Xdata/*`
5. **热加载命令映射（ReCall）**  
   `ReCall/commands.json`（面板命令映射）  
   `ReCall/CommandFacade.cs`（顶级命令入口，按需改）

这条链对应“用户点命令 -> Domain 计算 -> AutoCAD 画图/写 Xdata -> 可重建/可导出”的完整回路。

## 3. 数据落盘与运行时“外部文件系统”

除了仓库内代码，RoadDesign 还有一套运行时文件落地：

- **DWG 旁路设计数据**：`*.roaddesign.json`（RoadDesign 结构化数据）
- **DWG 历史快照目录**：`<dwg名>.roaddesign.history/`
  - `history-index.json`
  - `snap-xxxx-时间戳.json`

这意味着：  
RoadDesign 的“真实业务状态”不只在 CAD 图元里，也在 DWG 同目录的数据文件里；排错时需要同时看图形与 JSON 快照。

## 4. 现在最容易混淆的目录边界

### 4.1 该改 vs 不该改

- 该改：`HyCADTool.Refactored/**`（功能逻辑首选）
- 谨慎改：`ReCall/**`（仅命令入口与热重载配置）
- 一般不改：`.vs/**`、`**/bin/**`、`**/obj/**`、`debug-*.log`

### 4.2 为什么 `git status` 会很“脏”

当前大量未跟踪文件主要来自：

- Visual Studio 索引缓存（`.vs`）
- 编译输出（`bin`、`obj`）
- 调试日志与临时文件

它们是“环境产物”，不是业务功能增量。  
看变更时要优先盯：`HyCADTool.Refactored`、`ReCall`、`doc/RoadDesign`。
