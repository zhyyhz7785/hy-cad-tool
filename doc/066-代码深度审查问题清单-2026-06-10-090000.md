## P0 - 计算错误 / 历史致命链复发

### P0-1 ✅ AnchorBoltCalcCommand:M_y 漏乘 1000,单根螺栓受力计算结果错误

`src/HyCADTool/Features/AnchorBolt/AnchorBoltCalcCommand.cs:53-59, 85`

```53:59:src/HyCADTool/Features/AnchorBolt/AnchorBoltCalcCommand.cs
                var mxRes = ed.GetDouble("\n请输入绕X轴的力矩 M_x (kNm)：");
                if (mxRes.Status != PromptStatus.OK) return;
                double Mx = mxRes.Value * 1000;

                var myOpt = new PromptDoubleOptions("\n请输入绕Y轴的力矩 M_y (kNm) [默认0]：") { AllowNone = true, DefaultValue = 0.0 };
                var myRes = ed.GetDouble(myOpt);
                double My = myRes.Status == PromptStatus.OK ? myRes.Value : 0;
```

- `Mx` 做了 kN·m → kN·mm 换算(×1000),`My` 没有。
- 第 85 行 `force = (N / n) + (Mx * RelY / sumY2) + (My * RelX / sumX2)`,坐标单位 mm:M_y 项的贡献被**缩小 1000 倍**。
- **影响**:双向弯矩工况下输出的螺栓受力偏小 → 工程安全隐患。这是结果正确性问题,优先级最高。
- **修复**:`double My = (myRes.Status == PromptStatus.OK ? myRes.Value : 0) * 1000;`
- 顺带:第 61-62 行剪力 `V` 读取后未参与任何计算(只验状态),确认是未完成功能还是应删除提示。

### P0-2 ✅ B11 复发链:bin\Debug 混入 AutoCAD 宿主 DLL + ReCall 黑名单缺口

两处叠加,正是规则 05 / 陷阱 B11 的「Badge XamlParseException → 0xE0434352」前置条件:

1. **`src/HyCADTool/HyCADTool.csproj`**:`<CopyLocalLockFileAssemblies>true</CopyLocalLockFileAssemblies>` 且 `AutoCAD.NET` 包引用**没有** `<ExcludeAssets>runtime</ExcludeAssets>`。实测 `bin\Debug` 中存在 `AdWindows.dll`、`AcCoreMgd.dll`、`AcDbMgd.dll`、`AcMgd.dll`、`acdbmgdbrep.dll`、`AcDx.dll`、`AcTcMgd.dll` 等宿主程序集 → C2 全量复制进 ReCall 临时目录。
2. **`src/ReCall/Recall.cs::AutoCadHostAssemblyNames`**:黑名单含 `AdWindows/AcMr/AcCoreMgd/AcDbMgd/AcMgd/AcCui/AcWindows/...`,但**缺** `acdbmgdbrep`、`AcDx`、`AcTcMgd` —— 这三个恰好在 bin\Debug 实测在列。一旦任何代码路径触发对它们的 AssemblyResolve,旧版 byte[] 加载 → 类型身份割裂(同 B11 机理)。

**修复**(两层都做,规则 05 §5.3 强制):

- csproj:`AutoCAD.NET` 加 `<ExcludeAssets>runtime</ExcludeAssets>`,从源头阻止宿主 dll 进 bin\Debug;
- Recall.cs:黑名单补 `acdbmgdbrep`、`AcDx`、`AcTcMgd`(以及前缀匹配 `Ac*` 可考虑,但需排除自家程序集)。

## P1 - 功能性缺陷

### P1-1 ✅ HyBlenderPanelViewModel.SpongeCityVm:getter 每次访问可能 new 新 VM,状态丢失

`src/HyCADTool/Shell/BlenderPanel/HyBlenderPanelViewModel.cs`

- `SpongeCityVm` 的 getter 在 `SpongeCityPanelViewModel.Current == null` 时直接 `new` 并返回——**不缓存**。WPF 绑定引擎每次求值都可能拿到不同实例:用户在面板里输入的参数写进实例 A,命令执行时读到的是实例 B 的默认值。
- **修复**:getter 改为「取 `Current`,为 null 时创建一次并登记到文档级缓存再返回」,与 `SettingsPanelViewModel.GetOrCreate` 同模式。

### P1-2 ✅ 模式面板 VM 文档切换不刷新:ReinVm / PileVm / ClusterVm 等无变更通知

`HyBlenderPanelViewModel.cs` + `Features/Reinforcement/Views/ReinToolPanel.xaml` 等

- `ReinVm`、`PileVm` 等属性在 VM 构造时取一次文档级实例,`DocumentActivated` 后**不触发 `OnPropertyChanged`** → 切换 DWG 后面板仍绑定旧文档的 VM,参数读写错文档(陷阱 A 类「单例缓存跨文档」的 UI 版)。
- `ClusterPanelViewModel` 更进一步:静态 `Current` 全局单例,根本无文档维度。
- **修复**:`PanelManager.OnDocumentActivated` 里统一对所有 `XxxVm` 属性 `OnPropertyChanged`,VM 获取一律走 per-doc `GetOrCreate`。
