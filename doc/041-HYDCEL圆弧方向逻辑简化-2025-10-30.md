# HYDCEL 圆弧方向逻辑简化

> **完成日期**: 2025-10-30  
> **问题**: 圆弧方向处理逻辑过于复杂  
> **解决方案**: 简化为"原样复现 + 根据面类型调整"

---

## 核心逻辑

### 用户需求

1. **原始圆弧是顺时针（bulge < 0）**：
   - `dcelInner` 和它同向（顺时针），**不用处理**
   - `dcelOuter` 需要反向（变成逆时针），**bulge 取反**

2. **原始圆弧是逆时针（bulge > 0）**：
   - `dcelOuter` 和它同向（逆时针），**不用处理**
   - `dcelInner` 需要反向（变成顺时针），**bulge 取反**

### 代码实现

```csharp
// 计算 bulge
double bulge = CalculateBulge(arc);

// 关键逻辑：根据面类型和原始 bulge 符号决定是否反向
// 原始圆弧是顺时针（bulge < 0）：
//   - dcelInner 同向（不变）
//   - dcelOuter 反向（取反）
// 原始圆弧是逆时针（bulge > 0）：
//   - dcelOuter 同向（不变）
//   - dcelInner 反向（取反）
bool needReverse = (bulge < 0 && face.IsOuter) || (bulge > 0 && !face.IsOuter);
if (needReverse)
{
    bulge = -bulge;
}
```

## 测试场景

### 场景 1：完整圆（Circle）被分割

**输入**：Circle (完整圆，半径 R)

**DCEL 处理**：
- 外部面（dcelOuter，红色）
- 内部面（dcelInner，黄色）

**预期结果**：
- Circle 默认为逆时针（0° → 360°，bulge > 0）
- dcelOuter：逆时针圆弧（bulge > 0）✅ 不变
- dcelInner：顺时针圆弧（bulge < 0）✅ 反向

## 简化说明

之前的逻辑过于复杂，尝试在匹配阶段就处理方向，导致逻辑混乱。

新逻辑：
1. 匹配阶段：只负责找到对应的圆弧段
2. 渲染阶段：根据 `face.IsOuter` 决定是否反向 bulge

这样更清晰，更容易理解和维护。
