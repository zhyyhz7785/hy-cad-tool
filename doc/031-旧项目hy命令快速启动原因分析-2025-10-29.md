
## 🔍 三个关键机制

### 1️⃣ LibraryResources.xaml 共享机制

**旧项目的所有面板都引用同一个资源字典：**

```xml
<!-- ReinPanel.xaml, BaseReinPanel.xaml, FilterPanel.xaml 都有 -->
<UserControl.Resources>
    <ResourceDictionary>
        <ResourceDictionary.MergedDictionaries>
            <ResourceDictionary Source="pack://application:,,,/HyCADTool;component/Resources/LibraryResources.xaml" />
        </ResourceDictionary.MergedDictionaries>
    </ResourceDictionary>
</UserControl.Resources>
```

**WPF 资源字典缓存原理：**

| 步骤                  | 第一个面板 (ReinPanel) | 第二个面板 (BaseReinPanel) | 第三个面板 (FilterPanel) |
| --------------------- | ---------------------- | -------------------------- | ------------------------ |
| **解析 XAML**         | 5000ms (首次 JIT)      | 50ms (已 JIT)              | 50ms (已 JIT)            |
| **加载资源字典**      | 200ms (首次解析)       | **0ms (直接复用)**         | **0ms (直接复用)**       |
| **创建控件树**        | 100ms                  | 100ms                      | 100ms                    |
| **InitializeComponent总时间** | 5300ms            | **150ms**                  | **150ms**                |

**资源字典复用的核心：**
```csharp
// WPF 内部缓存机制（伪代码）
static Dictionary<Uri, ResourceDictionary> _resourceCache = new();

ResourceDictionary LoadResourceDictionary(Uri uri)
{
    if (_resourceCache.ContainsKey(uri))
    {
        return _resourceCache[uri];  // ✅ 直接返回缓存
    }
    
    var dict = ParseXaml(uri);  // ❌ 需要 200ms 解析
    _resourceCache[uri] = dict;
    return dict;
}
```

## 💡 为什么 C2 预热无效？

### WPF 预热的局限性

```csharp
// ReCall/Recall.cs - WarmupWPF()
string xaml = @"
<UserControl xmlns='...'>
    <StackPanel>
        <TextBlock Text='预热' />
        <ComboBox />
        <Button Content='预热' />
    </StackPanel>
</UserControl>";

XamlReader.Load(xmlReader);  // ✅ 这会预热 XAML 解析管线
```

**预热的内容：**
- ✅ WPF 框架初始化 (PresentationCore, PresentationFramework)
- ✅ XAML 解析器 (System.Xaml)
- ✅ 基本控件 JIT 编译 (TextBlock, ComboBox, Button, Grid, StackPanel)
- ✅ 布局引擎初始化

**未预热的内容：**
- ❌ 特定的 XAML 文件 (HyovSettingsPanel.xaml)
- ❌ 特定的控件组合
- ❌ 特定的资源字典 (LibraryResources.xaml)
- ❌ 特定的样式和模板

**关键原理：**
```
每个 .xaml 文件首次 InitializeComponent() 时，WPF 都会：
1. 解析 XAML 语法树 (300-500ms)
2. 创建对象图 (200-300ms)
3. 应用样式和模板 (100-200ms)
4. 设置属性和绑定 (50-100ms)
5. 触发 Loaded 事件 (10-50ms)

总计: 660-1150ms (复杂 XAML 可达 5000ms+)
```

## 🎯 解决方案建议

### 方案 1：模仿旧项目 - 使用共享资源字典

**优点：**
- ✅ 立即见效，后续面板都快
- ✅ 统一样式，维护方便
- ✅ 符合 WPF 最佳实践

**实现：**
```xml
<!-- HyovSettingsPanel.xaml -->
<UserControl.Resources>
    <ResourceDictionary>
        <ResourceDictionary.MergedDictionaries>
            <!-- 引用共享资源字典 -->
            <ResourceDictionary Source="pack://application:,,,/HyCADTool.Refactored;component/Resources/LibraryResources.xaml" />
        </ResourceDictionary.MergedDictionaries>
    </ResourceDictionary>
</UserControl.Resources>
```

### 方案 2：在 C2 预热时加载实际使用的 XAML

**优点：**
- ✅ 真正预热目标 XAML
- ✅ 首次打开面板时快速

**实现：**
```csharp
// ReCall/Recall.cs - WarmupWPF()

{

    {
```

## 📝 总结

### 旧项目快的三大核心

1. **LibraryResources.xaml 复用** → 后续面板 0ms 资源加载
2. **无依赖注入开销** → 直接 `new ReinPanel()`，无 ServiceLocator
3. **事件驱动** → 无 ViewModel 初始化和绑定引擎开销

### 新项目慢的根本原因

1. **HyovSettingsPanel.xaml 是独立的** → 无资源字典复用
2. **OverKillCommand 有依赖注入** → ServiceLocator.Resolve 开销
3. **C2 预热的 XAML 不同** → 未预热实际使用的控件组合

### 最佳实践建议

**短期方案（立即见效）：**
- ✅ 创建共享的 LibraryResources.xaml
- ✅ 让所有面板引用同一个资源字典

**长期方案（架构优化）：**
- ✅ 保持 MVVM 架构（可测试、可维护）
- ✅ 使用静态构造函数预加载
- ✅ 在 C2 命令中预热实际使用的 XAML

**关键原则：**
> "第一个面板慢，后续面板快" - WPF 资源字典复用机制
