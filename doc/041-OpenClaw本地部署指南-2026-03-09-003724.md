# OpenClaw 本地部署指南（Win11 + WSL2 + Ollama + qwen2.5:14b）

## 1. 适用环境

- 操作系统：Windows 11
- CPU：i9-12900KF
- 内存：64GB
- 显卡：RTX 3080 10GB
- 本地模型：`qwen2.5:14b`
- 目标：以**稳定优先**方式部署 `OpenClaw`，本地模型主要供 `OpenClaw` 调用

本文采用的部署拓扑：

- `Ollama` 安装在 **Windows 原生**
- `qwen2.5:14b` 模型由 **Windows 版 Ollama** 管理
- `OpenClaw` 安装在 **WSL2 Ubuntu**
- `OpenClaw` 通过 `http://127.0.0.1:11434` 访问 Ollama

这样做的原因：

- `OpenClaw` 官方对 Windows 更推荐 `WSL2`
- `Ollama` 在 Windows 原生下安装和显卡调用更直接
- 后续升级、迁移、排错都更容易

## 2. 先说结论

对你这台机器，`qwen2.5:14b` 是一个偏稳的选择，但它仍然属于中等体量本地模型。用于 `OpenClaw` 时，适合：

- 中文问答
- 常规代理任务
- 结构化输出
- 轻中度代码与命令生成

不建议期待它完全替代云端大模型，尤其是在：

- 超长上下文
- 极复杂多步推理
- 高强度工具调用链

如果后续发现本地模型偶尔不稳，建议保留“云端兜底模型”作为 fallback，而不是继续一味追求更小更快。

## 3. 容量需求与磁盘规划

## 3.1 核心容量估算

以下是比较实用的容量预算，不是理论最小值。

| 项目 | 预计占用 | 说明 |
|---|---:|---|
| Ollama 程序本体 | 1GB 以内 | Windows 安装程序和运行文件 |
| `qwen2.5:14b` 模型文件 | 9GB | Ollama 官方页面显示约 `9.0GB` |
| 模型下载/解压缓冲 | 5GB~10GB | 下载、更新、临时缓存建议预留 |
| 后续第二个模型 | 7GB~12GB | 例如再加一个 `7b` 或同级模型 |
| WSL2 Ubuntu 系统 | 8GB~15GB | 初装后较小，后续会增长 |
| OpenClaw 运行环境 | 3GB~8GB | Node、缓存、依赖、日志、状态文件 |
| 日志/工作区/会话数据 | 2GB~10GB | 视使用强度增长 |

建议按下面三档准备空间：

- 最低可用：`35GB`
- 推荐舒适：`60GB`
- 长期折腾：`80GB~120GB`

如果你未来可能再装：

- `deepseek-r1:7b`
- `qwen2.5-coder:7b`
- 其他 14B/32B 模型

那就建议直接给 AI 相关目录预留 `100GB+`。

## 3.2 你的双 SSD 规划建议

你有两块 2TB NVMe，最稳妥的规划如下：

### 方案 A：快速部署，改动最少

- `C:`：系统、WSL2、OpenClaw 配置
- `D:`：Ollama 模型目录

适合：

- 想尽快装起来
- 当前系统盘空间还比较充裕

建议空闲空间：

- `C:` 至少保留 `80GB`
- `D:` 至少保留 `100GB`

### 方案 B：长期使用，结构最清晰

- `C:`：仅系统与常规软件
- `D:`：集中放 AI 相关
  - Ollama 模型目录
  - WSL2 虚拟磁盘（如迁移到 D 盘）
  - AI 备份与工作目录

适合：

- 打算长期跑本地 AI
- 后续还会继续下载模型
- 希望系统盘尽量干净

推荐目录结构：

```text
D:\AI\Ollama\models
D:\WSL\Ubuntu-24.04
D:\AI\Backup
```

我更推荐你用 **方案 B**。

## 3.3 推荐的空间分配

如果你采用方案 B，建议这样预留：

- `D:\AI\Ollama\models`：先预留 `50GB`
- `D:\WSL\Ubuntu-24.04`：先预留 `40GB`
- `D:\AI\Backup`：预留 `20GB`

总计先按 `110GB` 心理预算规划，后面几乎不会因为空间问题频繁调整。

## 4. 安装前准备

### 4.1 建议先做的事

1. 更新显卡驱动到较新稳定版本
2. 确认 BIOS 和 Windows 已正常启用虚拟化
3. 确认 Windows Terminal / PowerShell 可正常以管理员身份运行
4. 确认磁盘剩余空间满足上面的建议

### 4.2 建议先创建的目录

在 Windows 中先创建：

```powershell
mkdir D:\AI
mkdir D:\AI\Ollama
mkdir D:\AI\Ollama\models
mkdir D:\WSL
mkdir D:\AI\Backup
```

如果你想先简化流程，也可以只先建：

```powershell
mkdir D:\AI\Ollama\models
```

## 5. 第一步：在 Windows 安装 Ollama

### 5.1 安装

到 Ollama 官网下载安装 Windows 版本：

- 官网：<https://ollama.com>

安装完成后，先不要急着拉模型，先规划模型目录。

### 5.2 把模型目录迁移到 D 盘

Windows 下常见默认目录是：

```text
%USERPROFILE%\.ollama\models
```

为了避免模型把系统盘慢慢吃满，建议把模型目录改到：

```text
D:\AI\Ollama\models
```

方法一：在“系统环境变量”中新增：

- 变量名：`OLLAMA_MODELS`
- 变量值：`D:\AI\Ollama\models`

方法二：PowerShell 设置当前用户环境变量：

```powershell
[System.Environment]::SetEnvironmentVariable("OLLAMA_MODELS", "D:\AI\Ollama\models", "User")
```

设置后：

1. 退出所有终端
2. 重新打开 PowerShell
3. 再启动 Ollama

### 5.3 验证 Ollama

PowerShell 中执行：

```powershell
ollama --version
ollama list
```

如果能正常输出版本号，说明安装成功。

## 6. 第二步：下载并测试 `qwen2.5:14b`

### 6.1 下载模型

```powershell
ollama pull qwen2.5:14b
```

说明：

- 该模型在 Ollama 页面显示约 `9.0GB`
- 下载期间建议保证额外 `10GB` 左右可用空间

### 6.2 直接本地测试

```powershell
ollama run qwen2.5:14b
```

建议先问三类问题：

1. 中文总结
2. JSON 结构化输出
3. PowerShell 或 Bash 命令生成

例如：

```text
请只输出 JSON：{"status":"ok","steps":["a","b","c"]}
```

如果它能稳定按要求输出，说明模型本身适合拿来接 `OpenClaw`。

### 6.3 API 自检

在 PowerShell 中测试：

```powershell
curl.exe http://127.0.0.1:11434/api/tags
```

能拿到模型列表 JSON，说明本机 Ollama API 正常。若用 `curl`（PowerShell 里是 `Invoke-WebRequest` 的别名）会弹出“脚本执行风险”提示，改用 `curl.exe` 或 `Invoke-WebRequest -Uri "http://127.0.0.1:11434/api/tags" -UseBasicParsing` 即可。

## 7. 第三步：安装 WSL2 与 Ubuntu

`OpenClaw` 在 Windows 上更推荐跑在 `WSL2` 内。

### 7.1 安装 WSL2

管理员 PowerShell：

```powershell
wsl --install -d Ubuntu-24.04
```

如果系统要求重启，按提示重启。

安装完成后，首次打开 Ubuntu，设置：

- Linux 用户名
- Linux 密码

### 7.2 启用 systemd

进入 Ubuntu 终端后执行：

```bash
sudo tee /etc/wsl.conf >/dev/null <<'EOF'
[boot]
systemd=true
EOF
```

然后回到 PowerShell：

```powershell
wsl --shutdown
```

重新打开 Ubuntu，再验证：

```bash
systemctl --user status
```

如果不再报明显的 systemd 不可用错误，就可以继续。

## 8. 第四步：把 WSL2 放到 D 盘（可选但推荐）

如果你想长期使用，建议把 Ubuntu 虚拟磁盘也放到 `D:`。

如果你只是先快速试用，可以先跳过本节，后面跑通了再迁移。

### 8.1 查看当前发行版

```powershell
wsl --list --verbose
```

若你用的是 `wsl --install` 默认安装，发行版名可能是 `Ubuntu`；若用 `wsl --install -d Ubuntu-24.04` 则为 `Ubuntu-24.04`。下面 8.2～8.4 中的名称需与这里一致。

### 8.2 导出发行版

```powershell
wsl --export Ubuntu-24.04 D:\WSL\ubuntu-24.04.tar
```

### 8.3 注销旧发行版

```powershell
wsl --unregister Ubuntu-24.04
```

### 8.4 从 D 盘重新导入

```powershell
wsl --import Ubuntu-24.04 D:\WSL\Ubuntu-24.04 D:\WSL\ubuntu-24.04.tar --version 2
```

### 8.5 重新进入系统

```powershell
wsl -d Ubuntu-24.04
```

备注：

- 这一步适合追求磁盘规划整洁的人
- 如果你不熟悉 WSL，建议先不迁移，先安装跑通再说

## 9. 第五步：在 WSL2 中安装 OpenClaw

官方推荐安装方式是安装脚本。

在 Ubuntu 中执行：

```bash
curl -fsSL https://openclaw.ai/install.sh | bash
```

该脚本会处理：

- Node 检测
- OpenClaw 安装
- Onboarding 流程

安装完成后，建议执行：

```bash
openclaw doctor
openclaw status
```

如果你希望安装时不立刻进入 onboarding，可用：

```bash
curl -fsSL https://openclaw.ai/install.sh | bash -s -- --no-onboard
```

## 10. 第六步：在 WSL2 中配置 OpenClaw 使用 Ollama

## 10.1 最重要的连接原则

`OpenClaw` 连接 `Ollama` 时：

- `baseUrl` 用 `http://127.0.0.1:11434`
- **不要带 `/v1`**

这一点很重要，因为 `OpenClaw` 官方文档明确提示：对 Ollama 应优先使用原生 API，而不是 OpenAI 兼容的 `/v1` 路径。

## 10.2 先验证 WSL 能访问 Windows 中的 Ollama

进入 Ubuntu：

```bash
curl http://127.0.0.1:11434/api/tags
```

如果能返回模型信息，说明 WSL 到 Windows 的连通是正常的。

如果访问失败，优先检查：

1. Windows 里的 Ollama 是否正在运行
2. Windows 防火墙是否拦截
3. 是否重启过终端但 Ollama 没有重新启动

## 10.3 最简配置方式

如果你想让 OpenClaw 自动发现本地 Ollama 模型，在 Ubuntu 中设置：

```bash
echo 'export OLLAMA_API_KEY="ollama-local"' >> ~/.bashrc
source ~/.bashrc
```

然后查看：

```bash
openclaw models list
```

如果自动发现正常，后续只需要把主模型设为：

```text
ollama/qwen2.5:14b
```

## 10.4 建议配置示例

OpenClaw 配置文件通常位于：

```text
~/.openclaw/openclaw.json
```

可以参考下面这份最小本地模型配置：

```json
{
  "agents": {
    "defaults": {
      "workspace": "~/.openclaw/workspace",
      "model": {
        "primary": "ollama/qwen2.5:14b"
      }
    }
  }
}
```

如果你需要显式写入 Ollama provider，可参考：

```json
{
  "agents": {
    "defaults": {
      "workspace": "~/.openclaw/workspace",
      "model": {
        "primary": "ollama/qwen2.5:14b"
      }
    }
  },
  "models": {
    "providers": {
      "ollama": {
        "baseUrl": "http://127.0.0.1:11434",
        "apiKey": "ollama-local",
        "api": "ollama",
        "models": [
          {
            "id": "qwen2.5:14b",
            "name": "Qwen2.5 14B",
            "reasoning": false,
            "input": ["text"],
            "cost": {
              "input": 0,
              "output": 0,
              "cacheRead": 0,
              "cacheWrite": 0
            },
            "contextWindow": 32768,
            "maxTokens": 8192
          }
        ]
      }
    }
  }
}
```

说明：

- 如果自动发现可用，优先用自动发现，配置更省心
- 如果自动发现不稳定，再改成显式 provider

## 11. 第七步：安装并启动 Gateway

在 Ubuntu 中执行：

```bash
openclaw onboard --install-daemon
```

然后检查状态：

```bash
openclaw gateway status
openclaw doctor
```

如需前台运行测试：

```bash
openclaw gateway --port 18789
```

打开浏览器访问：

```text
http://127.0.0.1:18789/
```

或者使用：

```bash
openclaw dashboard
```

## 12. 第八步：稳定性验证

完成安装后，不要急着做复杂任务，先做 5 分钟稳定性检查。

### 12.1 模型连通性

在 Ubuntu 中：

```bash
curl http://127.0.0.1:11434/api/tags
openclaw models list
```

在 Windows PowerShell 中测 Ollama API 时请用 `curl.exe` 或 `Invoke-WebRequest -UseBasicParsing`，避免 `curl` 别名触发的安全提示。

### 12.2 Gateway 健康检查

```bash
openclaw doctor
openclaw health
openclaw gateway status
```

### 12.3 用同一组问题压测模型风格

建议连续问下面 4 类提示词：

1. 中文步骤整理
2. JSON 结构化输出
3. 命令生成
4. 信息不足时先提问

重点观察：

- 会不会跑题
- 会不会过度啰嗦
- JSON 会不会失真
- 响应速度是否可接受
- 长一点的回答是否容易中途发散

## 13. 维护建议

### 13.1 模型侧

- 常用模型不要装太多
- 保留 1 个主模型 + 1 个备选模型即可
- 不要频繁切换量化版本，否则不利于稳定评估

### 13.2 OpenClaw 侧

升级建议用官方安装脚本重新跑一遍：

```bash
curl -fsSL https://openclaw.ai/install.sh | bash
```

升级后执行：

```bash
openclaw doctor
openclaw gateway restart
openclaw health
```

### 13.3 备份建议

建议定期备份：

- `~/.openclaw/openclaw.json`
- `~/.openclaw/workspace`
- `~/.openclaw/credentials`
- `D:\AI\Ollama\models` 的目录清单

## 14. 常见问题

### 14.1 明明装好了，WSL 里连不上 Ollama

先检查：

- Windows 中 `ollama list` 是否正常
- `curl http://127.0.0.1:11434/api/tags` 在 Windows 是否正常
- WSL 中是否也能访问同一个地址

多数情况下是：

- Ollama 没启动
- 环境变量改完没重开终端
- 防火墙限制

### 14.2 系统盘空间被慢慢吃掉

常见原因：

- 模型还在默认目录
- WSL 虚拟磁盘仍然在 `C:` 盘
- 日志和缓存长期没清理

### 14.3 `qwen2.5:14b` 速度没有想象中快

这是正常现象。你当前选择的是“稳定优先”，不是“极限速度优先”。

如果你后面觉得速度稍慢但仍可接受，建议先保持不动，至少连续使用几天再决定是否换成 `7b`。

### 14.4 PowerShell 里执行 curl 报“安全警告：脚本执行风险”

PowerShell 的 `curl` 是 `Invoke-WebRequest` 的别名，会解析页面并可能触发安全提示。改用系统自带的 curl 或加参数即可：

```powershell
curl.exe http://127.0.0.1:11434/api/tags
# 或
Invoke-WebRequest -Uri "http://127.0.0.1:11434/api/tags" -UseBasicParsing
```

## 15. 最终建议

对你这台机器，推荐的最终落地方式是：

- Windows 原生安装 `Ollama`
- 模型目录放 `D:\AI\Ollama\models`
- `OpenClaw` 跑在 `WSL2 Ubuntu`
- 主模型使用 `qwen2.5:14b`
- 后续如需备选，再增加一个 `7b` 模型

这是当前兼顾：

- 稳定性
- 维护成本
- 磁盘可控
- 后续扩展性

的最平衡方案。
