# WSL 基础使用手册（Win11 实用版）

## 1. 这份手册适合谁

适用于：

- Windows 11 用户
- 已安装或准备安装 `WSL2`
- 想在本机使用 `Ubuntu`
- 主要需求是开发、命令行工具、本地 AI、`OpenClaw`、`Docker` 或脚本环境

本文尽量只讲实用内容，不讲太多底层原理。

## 2. WSL 到底是什么

`WSL` 是 `Windows Subsystem for Linux`，可以理解成：

- 让你在 Windows 里运行 Linux 环境
- 常见做法是安装一个 Linux 发行版，例如 `Ubuntu`

要分清两个概念：

- `WSL`：Windows 提供的 Linux 运行平台
- `Ubuntu`：运行在 `WSL` 里的 Linux 系统

所以平时你真正打开来用的，通常是：

- `Ubuntu`
- 或者 `wsl -d Ubuntu`

而不是专门去点 `Windows Subsystem for Linux` 那个图标。

## 3. 先记住最重要的 5 条

### 3.1 打开 Ubuntu

PowerShell 中执行：

```powershell
wsl -d Ubuntu
```

或者开始菜单搜索：

```text
Ubuntu
```

### 3.2 查看已安装发行版

```powershell
wsl --list --verbose
```

### 3.3 彻底关闭 WSL

```powershell
wsl --shutdown
```

### 3.4 进入 Linux 后更新软件列表

```bash
sudo apt update
```

### 3.5 退出 Linux 终端

```bash
exit
```

## 4. 平时怎么打开 WSL

## 4.1 推荐打开方式

### 方法 1：开始菜单

按 `Win` 键，搜索：

- `Ubuntu`
- `Ubuntu-24.04`

点开即可。

### 方法 2：PowerShell

```powershell
wsl -d Ubuntu
```

如果只有一个发行版，也可以直接：

```powershell
wsl
```

### 方法 3：Windows Terminal

打开 `Windows Terminal`，在下拉菜单里选择：

- `Ubuntu`

这是最舒服的日常使用方式。

## 4.2 不推荐的打开方式

不要把 `Windows Subsystem for Linux` 图标当成平时入口。

原因：

- 它更像 `WSL` 本体或更新/修复入口
- 有时会触发安装、修复、升级流程
- 如果旧安装包丢失，可能会弹出 MSI 报错

平时进入 Linux，请优先用：

- `Ubuntu`
- `wsl -d Ubuntu`

## 6. Windows 和 Ubuntu 的路径关系

这是 WSL 最容易让新手迷糊的地方。

## 6.1 在 Ubuntu 里访问 Windows 盘符

Windows 的盘符会映射到：

```text
/mnt/c
/mnt/d
/mnt/e
```

例如：

- `C:\Users\ZHY` 对应 ` /mnt/c/Users/ZHY`
- `D:\AI` 对应 ` /mnt/d/AI`

示例：

```bash
cd /mnt/c/Users/ZHY
cd /mnt/d/AI
```

## 6.2 在 Windows 里访问 Ubuntu 文件

Ubuntu 文件可以通过资源管理器访问：

```text
\\wsl$\Ubuntu
```

你可以在资源管理器地址栏输入这一路径。

## 6.3 哪边存文件更合适

建议：

- Linux 工具链的项目尽量放在 Ubuntu 自己的文件系统里
- Windows 文档、下载包、普通资料放在 Windows 盘里

如果是开发工具链项目，通常：

- 放在 Linux 内部性能更稳定
- 文件权限问题更少

## 7. 发行版、版本、默认项

## 7.1 查看当前安装的发行版

```powershell
wsl --list --verbose
```

常见输出信息：

- 名称：如 `Ubuntu`
- 状态：`Running` 或 `Stopped`
- 版本：`1` 或 `2`

## 7.2 设置默认发行版

```powershell
wsl --set-default Ubuntu
```

这样之后直接执行：

```powershell
wsl
```

就会默认进入 `Ubuntu`。

## 8. 安装与更新

## 8.1 安装 WSL

管理员 PowerShell：

```powershell
wsl --install
```

或指定安装 Ubuntu：

```powershell
wsl --install -d Ubuntu
```

## 8.2 更新 WSL 本体

```powershell
wsl --update --web-download
```

如果 `WSL` 更新出现 MSI 缺失、找不到旧安装包等错误，优先尝试：

```powershell
winget install --id Microsoft.WSL --source winget --force
```

这通常比去找旧版 MSI 包更省事。

## 8.3 更新 Ubuntu 里的软件

进入 Ubuntu 后：

```bash
sudo apt update
sudo apt upgrade -y
```

## 9. systemd 是什么，需不需要开

如果你只是普通使用终端，不一定立即需要。

但如果你要做这些事，建议启用：

- `OpenClaw`
- Linux 服务常驻
- 某些 daemon / 后台服务
- 更接近完整 Linux 体验

启用方式：

在 Ubuntu 中执行：

```bash
sudo tee /etc/wsl.conf >/dev/null <<'EOF'
[boot]
systemd=true
EOF
```

然后回到 PowerShell：

```powershell
wsl --shutdown
```

重新打开 Ubuntu 即可。

## 10. 如何备份 Ubuntu

这是非常重要的基础操作。

## 10.1 导出备份

PowerShell：

```powershell
wsl --shutdown
wsl --export Ubuntu D:\WSL\Backup\Ubuntu-backup.tar
```

这会把整个 Ubuntu 导出为一个 `tar` 文件。

## 10.2 什么情况下要先备份

以下场景都建议先导出：

- 打算删除发行版
- 打算重装到别的盘
- 准备做重大调整
- 不确定里面有没有重要数据

## 11. 如何删除 Ubuntu

警告：

下面这条命令会删除当前发行版的数据：

```powershell
wsl --unregister Ubuntu
```

执行前务必确认：

- 已经备份
- 或者里面没有你要的数据

## 12. 如何迁移到 D 盘

如果你只是想把 `Ubuntu` 从 `C:` 盘移到 `D:` 盘，推荐优先用 **移动**，不一定要删掉重装。

## 12.1 推荐：直接移动

```powershell
wsl --shutdown
mkdir D:\WSL
wsl --manage Ubuntu --move D:\WSL\Ubuntu
```

优点：

- 不用重装
- 数据保留
- 风险更低

## 12.2 迁移式重装：导出再导入

```powershell
wsl --shutdown
wsl --export Ubuntu D:\WSL\Backup\Ubuntu-backup.tar
wsl --unregister Ubuntu
wsl --import Ubuntu D:\WSL\Ubuntu D:\WSL\Backup\Ubuntu-backup.tar --version 2
```

适合：

- 你想保留数据
- 但又想彻底重新注册发行版

## 12.3 真正重装到 D 盘

如果你就是想删掉后重装：

```powershell
wsl --unregister Ubuntu
wsl --install -d Ubuntu --location D:\WSL\Ubuntu --name Ubuntu
```

注意：

- 删除前仍建议先备份
- 不同 Windows / WSL 版本支持参数略有区别
- 如果 `--location` 不可用，就改用导出/导入方案

## 13. 常见问题

## 13.1 点了 WSL 图标却弹出安装/修复窗口

这是常见误区。

原因：

- 你点的是 `Windows Subsystem for Linux`
- 它不是你平时该进入的 Ubuntu 终端

正确做法：

- 打开 `Ubuntu`
- 或 `wsl -d Ubuntu`

## 13.2 提示找不到 `wsl.x.x.x.x64.msi`

这通常表示：

- Windows 正在修复或更新 `WSL`
- 但旧版 MSI 缓存文件丢了

优先处理方式：

```powershell
wsl --shutdown
wsl --update --web-download
```

如果还不行：

```powershell
winget install --id Microsoft.WSL --source winget --force
```

## 13.3 `wsl` 能用，但那个 WSL 图标报错

只要下面命令能正常进入：

```powershell
wsl -d Ubuntu
```

通常说明：

- Ubuntu 发行版基本还是好的
- 报错更多是 `WSL` 本体更新链问题

## 13.4 我不知道自己现在是在 Windows 还是 Ubuntu

判断方法很简单：

- PowerShell/CMD 通常路径像：`C:\Users\...`
- Ubuntu 通常提示符像：`user@machine:~$`

也可以执行：

```bash
pwd
uname -a
```

如果能输出 Linux 内核信息，那你就在 Ubuntu 里。

## 14. 对你当前场景的建议

如果你的目标是：

- 用 `Ollama`
- 准备跑 `OpenClaw`
- 追求稳定

推荐结构是：

- Windows：装 `Ollama`
- `D:` 盘：放模型目录
- `WSL2 Ubuntu`：跑 Linux 工具链和 `OpenClaw`

这样比较稳，也方便维护。
