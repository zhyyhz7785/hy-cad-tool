## 0. TL;DR（一页看懂）

- **LandXML（土地信息可扩展标记语言，Land eXtensible Markup Language）** 是一套以 **XML（可扩展标记语言，Extensible Markup Language）** 为载体、面向 **土木工程 / 测量 / 道路 / 场地** 的开放数据交换格式，现役广泛版本是 **1.2**（2008 年发布）。
- 它解决的是「**Civil 3D / OpenRoads / 12d Model / 鸿业 / Novapoint**」这些道路软件**各自用私有数据库**时，**线位 / 纵断面 / 地形曲面**如何在企业之间、软件之间互通的问题。
- 内核是把一条 **平面线位（Alignment，平面线位 / horizontal alignment）** 抽象成一串 **几何段（geometry primitives）**：`Line（直线段）` / `Curve（圆曲线段）` / `Spiral（缓和曲线段，多数为回旋线 clothoid）`，再叠加 **StaEquation（桩号方程 / station equation）** 描述断链。
- 三处"容易踩坑"的约定需要死记：**① 点坐标是 `Northing Easting`（北 东，= Y X）** ；**② `dir` 是"北起、顺时针、十进制度"的方位角（Azimuth）**，不是 AutoCAD 的 bearing；**③ 缓和段的 `radiusStart / radiusEnd` 用 `INF` 表示"无穷大半径"（即直线端）**。
- 与 HyCAD 的映射见 `LandXmlExportService.BearingToAzimuthDeg` 等工具方法；**LandXML 不存 PI 交点源信息**，导入后 `Alignment.Source = null` —— 这是 HyCAD 导入后 `hyRoadAlnEditPi` 不可用的根因。

## 1. 历史脉络（为什么会出现 LandXML？）

**叙述性内容，不追加内核解释（遵守 §0.4 规范）。**

### 1.1 1990 年代：道路软件"数据孤岛"

1990 年代 **CAD（计算机辅助设计，Computer-Aided Design）** 辅助土木设计开始普及，美国的 **InRoads / GEOPAK / Civil 3D**、欧洲的 **Bentley MX**、澳洲的 **12d Model**、北欧的 **Novapoint** 各自发展。每家厂商用自己的二进制数据库存 **Alignment / Profile / Surface（曲面）**：

- **InRoads**：`.alg`、`.tin`
- **GEOPAK**：`.gpk`
- **12d Model**：`.12d` / `.12da`
- **MX**：`.ff`（4D 字符串）

结果：**一个项目换一家承包商就要重新建模**，"信息损失"惊人（纵断面竖曲线长度、缓和段参数、桩号方程常常对不上）。

### 1.2 1999：`LandXML.org` 成立

1999 年由 **Autodesk**、**Bentley**、**Trimble** 等公司牵头，联合测绘设备厂商、地形 TIN（不规则三角网，Triangulated Irregular Network）算法提供方，在 `LandXML.org`（已改挂 `buildingsmart.org`）发起**开放 Schema**项目。目标：用 **XML 1.0** 做容器，覆盖「点 / 线 / 面 / 管道 / 地块 / 监测」全专业的交换。

### 1.3 2002：**LandXML 1.0**（基线版，基础上只有 Alignment/Surfaces/Parcels）

1.0 把 **平面 + 纵断面 + 地形 + 地块** 四件事拉齐；但横断面（CrossSects）字段不全，工程量表完全没有。

### 1.4 2008：**LandXML 1.2**（当前事实标准）

1.2 补齐：

- **`CrossSects`**（横断面列表）：每桩号一张断面带 DesignCrossSectSurf + ExistingCrossSectSurf。
- **`Roadway`**：串联 Alignment / Profile / CrossSects，标注路面类型。
- **`StaEquation`**：完整描述桩号断链（Ahead / Back / Internal 三种桩号对齐方式）。
- **`PipeNetworks`**：给水 / 排水管网（虽然道路包一般不用）。
- **Namespace 收敛**：`http://www.landxml.org/schema/LandXML-1.2`。

1.2 发布后 Autodesk Civil 3D、Bentley OpenRoads、Trimble Novapoint 都把**导入导出双向兼容**列为默认能力，导致 1.2 在道路 BIM 阶段正式成为**事实标准（de facto standard）**。

### 1.5 2013 后：`LandXML 2.0` 草案停滞、IFC 4.3 Road 崛起

2013 年提出的 LandXML 2.0 在命名空间、Schema 模块化上做了大调整，**但始终未正式发布**；行业用户投票继续停留在 1.2。2021 年 **buildingSMART International（bSI）** 发布的 **IFC 4.3 Road**（工业基础类 4.3 道路版，Industry Foundation Classes 4.3）开始**补上"LandXML 2.0 没做成"的位置**：

- **LandXML 1.2**：几何 + 少量属性，**浅语义**，文件轻、生成解析简单。
- **IFC 4.3 Road**：构件语义 + 拓扑 + 属性 + 多 **LOD（细节等级，Level of Development）**，**深语义**，文件重、需要完整 **ifcOpenShell** 级别的解析器。

企业当前的现实选择：**v1 仍用 LandXML 做 80% 的互通，IFC 4.3 留给 BIM 正向设计大型项目**。HyCAD 的路线也遵循这个选型（[01MASTER § 5.2](./01MASTER.md#52-landxml对标-civil-3d--openroads--12d-model-通用交换)）。

## 2. 符号约定（本文统一）

为避免公式歧义，本文固定以下记号。

- **坐标系**：
  - 内部（HyCAD / AutoCAD 习惯）：二维平面点 \((X, Y)\)，**X 正方向为正东（East）**，**Y 正方向为正北（North）**。
  - LandXML 文件中：点元素 `<Start>/<End>/<Center>` 的文本形式是 **`"N E"`**（空格分隔），即 **`"Y X"`**（Northing 在前，Easting 在后）。
- **方位 / 方向**：
  - **Bearing（内部方位，rad）**：从 **+X 轴** 起，**逆时针（CCW，counter-clockwise）** 为正，单位 **弧度（rad）**。即 `atan2(dy, dx)`。
  - **Azimuth（LandXML 方位，deg）**：从 **正北** 起，**顺时针（CW，clockwise）** 为正，单位 **十进制度（decimal degrees）**，取值 \([0, 360)\)。
- **转向标识**（圆弧 / 缓和）：
  - `rot = "ccw"`：逆时针转向（左转）
  - `rot = "cw"`：顺时针转向（右转）
- **半径端标识**（缓和段）：
  - `radiusStart = INF`：起端为直线（半径无穷大）；
  - `radiusEnd = INF`：终端为直线（半径无穷大）；
  - 有限值代表与圆曲线相接的那一端半径（单位：**米（m）**）。
- **缓和曲线参数**：**回旋线参数 \(A\)**（spiral parameter），单位 **米（m）**；定义见 §3.4。
- **桩号（station，chainage）**：沿线位自起点累积的里程，单位 **米（m）**。国内习惯写 `K0+123.456`，本文公式统一用纯数值 \(s\)。

## 3. 核心概念（第一性拆解）

### 3.1 XML 容器与 Schema 总览

**对象**：LandXML 1.2 是一份**单根元素**的 XML 文档，根节点 `<LandXML version="1.2" xmlns="http://www.landxml.org/schema/LandXML-1.2">`。

**痛点**：各软件"只导出自己关心的部分"，导入方不知道该读什么，出现字段漏读、字段默认值不一致。**Schema 本身规定"允许省略哪些"**，不规定"必读哪些"。

**最小骨架**（HyCAD 导出的最小合法 1.2 文件，参见 `LandXmlExportService.BuildDocument`）：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<LandXML version="1.2" xmlns="http://www.landxml.org/schema/LandXML-1.2"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance">
  <Units>
    <Metric linearUnit="meter" areaUnit="squareMeter" volumeUnit="cubicMeter"
            temperatureUnit="celsius" pressureUnit="milliBars"
            angularUnit="decimal degrees" directionUnit="decimal degrees"/>
  </Units>
  <Project name="hyRoadAln"/>
  <Alignments name="hyRoadAln">
    <Alignment name="K0" length="287.5" staStart="0.0">
      <CoordGeom>
        <Line length="100.0" dir="90.0">
          <Start>0 0</Start><End>0 100</End>
        </Line>
        <!-- ... -->
      </CoordGeom>
      <StaEquation staAhead="1000" staBack="250" staInternal="250"/>
    </Alignment>
  </Alignments>
</LandXML>
```

**符号说明**：上示 `<Start>0 0</Start>` 文本内两个数按 **Northing Easting** 解析，即 \(Y=0, X=0\)；`<End>0 100</End>` 即 \(Y=0, X=100\)，正东 100 m。

### 3.2 坐标点对：为什么是 `Northing Easting`

**对象**：LandXML 所有点元素（`<Start>` / `<End>` / `<Center>` / `<P>` / `<PntList2D>` 等）的内部文本。

**核心困难**：CAD 工程师习惯 `(X, Y)`；而测量行业 1:10000 地形图及 GPS 测量系统一直是 `(N, E)`（北、东）。Schema 在制定时倾向测量学派，**把"写入顺序"固定为 N E**，与"显示顺序" X Y 反过来。

**最小定义**：
\[
\text{LandXML 点文本} = \underbrace{N}_{\text{Northing (= } Y\text{)}} \;\;\text{空格}\;\; \underbrace{E}_{\text{Easting (= } X\text{)}}
\]

**符号说明**：
- \(N\)：该点在投影坐标系内的北向坐标分量；数值上 **等于 HyCAD 内部的 \(Y\)**（单位：m）。
- \(E\)：该点在投影坐标系内的东向坐标分量；数值上 **等于 HyCAD 内部的 \(X\)**（单位：m）。
- 两值之间以一个或多个空白（空格 / 制表符 / 换行）分隔，**文件中顺序不可反**。

**内核解释**（非专业语言）：
测量人员说"先报北、再报东"，就像我们说"先说姓、再说名"。LandXML 把这个行业习惯固定成格式——读文件的时候别傻傻按屏幕上的"X 在左"来解析。

**结构工程类比**：
像看梁的内力图时**先标弯矩、再标剪力**一样，是一种"**约定俗成的读图顺序**"。为什么贴切：二者都与"谁在前"无关对错，错只错在**读者与作者约定不一致**，一旦错位整条轴线就对不上了。

### 3.3 方位角转换：Bearing ↔ Azimuth

**对象**：`<Line dir="...">`、`<Curve dirStart="..." dirEnd="...">`、`<Spiral dirStart="..." dirEnd="...">` 中的 **`dir` 属性**。

**核心困难**：CAD 世界用 **逆时针、+X 起算、弧度** 的 Bearing；测量 / 航海 / 地理用 **顺时针、+Y 起算、十进制度** 的 Azimuth。两者既**起算轴不同**，又**旋转方向相反**。

**最小公理**（两组等价换算公式）：

\[
\boxed{\;\alpha = \left(\dfrac{\pi}{2} - \beta\right) \cdot \dfrac{180}{\pi} \bmod 360\;} \qquad\text{（Bearing → Azimuth）}
\]

\[
\boxed{\;\beta = \dfrac{\pi}{2} - \alpha \cdot \dfrac{\pi}{180}\;} \qquad\text{（Azimuth → Bearing，随后规范化到 \((-\pi, \pi]\)）}
\]

**符号说明**：
- \(\beta\)：内部 Bearing，单位 **弧度（rad）**，域 \((-\pi, \pi]\)。
- \(\alpha\)：LandXML Azimuth，单位 **十进制度（decimal degrees）**，域 \([0, 360)\)。
- `mod 360`：取非负余数，保证结果落在 \([0, 360)\)。
- 转换中 \(\pi/2\) 项来自"**+X 轴**"与"**正北**"夹角恰好 \(90^\circ\)；"**符号反转**"项来自 CCW/CW 的方向翻转。

**内核解释**（非专业语言）：
把钟面表盘盖在地图上——**CAD 的 0° 指向 3 点钟**（正东），往 9 点转；**测量的 0° 指向 12 点**（正北），往 3 点钟转。所以二者要先"旋转 90 度"，再"反过来走"，才对得上。

**结构工程类比**：
像**梁的坐标系**和**柱的坐标系**在节点处要对齐一样——梁的 \(x\) 轴沿梁长，柱的 \(x\) 轴沿柱高，两者夹 90°，还常常方向相反。节点内力写到两边构件时必须做**方向余弦矩阵**转换。**为什么贴切**：这里 \(\alpha \leftrightarrow \beta\) 本质就是 \(2\times 2\) 的二维方向余弦矩阵（旋转 + 反射），工程师对"坐标系转换不能口算"这件事有肌肉记忆。

**实现对位**：见 `LandXmlExportService.BearingToAzimuthDeg` / `AzimuthDegToBearing`。

### 3.4 三种几何段：Line / Curve / Spiral

**对象**：`<Alignment>` 内 `<CoordGeom>` 的直接子节点。**段的顺序 = 线位行进顺序**，前一段的终点应等于后一段的起点（允许 mm 级精度误差）。

**最小定义**（三段各自的属性集合）：

| 段类型 | 必需属性 | 可选 / 常见属性 | 语义 |
|---|---|---|---|
| `<Line>` | `length`, `dir` | 子 `<Start>` `<End>` | 直线段，长度 + 方位角 |
| `<Curve>` | `length`, `radius`, `rot` | `dirStart`, `dirEnd`, 子 `<Start>` `<Center>` `<End>` | 圆曲线段（恒半径圆弧） |
| `<Spiral>` | `length`, `radiusStart`, `radiusEnd`, `rot`, `spiType` | `dirStart`, `dirEnd`, 子 `<Start>` `<End>` | 缓和曲线段（半径沿里程线性变化） |

**主结论**（每段的主导方程）：

**(1) 直线段 Line**：

\[
\vec{P}(s) = \vec{P}_{\text{start}} + s \cdot (\cos\beta,\; \sin\beta), \quad s \in [0, L]
\]

**符号说明**：
- \(s\)：段内从起点累计的里程，单位 m。
- \(L\)：段长 `length`，单位 m。
- \(\beta\)：段的 Bearing；由 `dir`（Azimuth, deg）按 §3.3 换算。
- \(\vec{P}_{\text{start}}\)：段起点 \((X, Y)\)。

**(2) 圆曲线段 Curve**：

\[
\theta = \dfrac{L}{R}, \qquad \text{bulge} = \tan\!\left(\dfrac{\theta}{4}\right) \cdot \text{sgn}(\text{rot})
\]

**符号说明**：
- \(R\)：圆弧半径 `radius`（LandXML 内始终为正值），单位 m。
- \(\theta\)：圆心角（弧度，rad），有向。
- \(L\)：段长 `length`，单位 m，满足 \(L = R\theta\)。
- `bulge`：AutoCAD 凸度（dimensionless），用于 `Polyline3D` 顶点对之间；`rot=ccw → sgn=+1，cw → sgn=-1`。
- 实现见 `LandXmlImportService.AppendCurve`：`theta = length / radius; bulge = tan(theta/4); 符号由 rot 决定`。

**(3) 缓和曲线段 Spiral（以 clothoid 回旋线为准）**：

回旋线的**定义方程**（里程—曲率线性关系）：

\[
\kappa(s) = \kappa_0 + (\kappa_1 - \kappa_0) \cdot \dfrac{s}{L_s}, \quad s \in [0, L_s]
\]

**符号说明**：
- \(\kappa(s)\)：在段内里程 \(s\) 处的瞬时曲率（单位 \(\text{m}^{-1}\)）。
- \(\kappa_0, \kappa_1\)：起、终曲率；对应 `radiusStart` / `radiusEnd`：若属性为 `INF`，取 \(\kappa = 0\)；否则 \(\kappa = 1/R\)。
- \(L_s\)：缓和段长度 `length`，单位 m。

由回旋线参数的常见定义 \(A^2 = R \cdot L_s\) 得：

\[
A = \sqrt{R \cdot L_s}
\]

**符号说明**：
- \(A\)：回旋线参数（spiral parameter），单位 m，**与 HyCAD `AlignmentElement.SpiralParameterA` 同名**。
- \(R\)：回旋线有限端半径，单位 m；直端 \(R \to \infty\) 时 \(A\) 不独立定义（本段实质退化为直线）。

**内核解释**（非专业语言）：
- 直线就像拿尺子划一道；
- 圆弧是圆心不动、半径固定绕一段；
- 缓和是"半径慢慢变大或变小"的一段 —— 让车子从直路拐弯时方向盘**不用猛打**，是为了舒服和安全。LandXML 用"起端半径、终端半径"两个数把这段描述完。

**结构工程类比**：
- `Line` 像**等截面梁**，内力沿梁长线性分布；
- `Curve` 像**圆环柱（半径固定）**；
- `Spiral` 像**变截面悬臂梁 / 变截面渐变柱** —— 截面沿长度连续变化。**为什么贴切**：回旋线里"半径沿里程线性变"，等价于变截面梁里"截面特性沿长度线性变"，数学上都是**线性插值 + 积分**，工程感受也都是"受力 / 走向**平缓过渡**，避免突变应力或突变角加速度"。

### 3.5 `StaEquation`：桩号方程（断链）

**对象**：`<Alignment>` 的直接子节点 `<StaEquation staAhead="..." staBack="..." staInternal="..."/>`。可有多个，通常按桩号升序排列。

**核心困难**：工程中**重新定测** / **线位变更**后，线位实际长度变了但**不想把下游结构物的桩号全部重改**（排水井、标志牌、路灯都贴桩号）。解决办法：在某个位置设"断链"——**Ahead**（前进方向新桩号） ≠ **Back**（后退方向旧桩号）。

**最小定义**（三属性的语义）：

| 属性 | 语义 | 在 HyCAD 对应 |
|---|---|---|
| `staInternal` | 内部（未标注）里程，从 `staStart` 累加的"**真实线位长度**" | `StationEquation.BeforeRaw` |
| `staBack` | 断链后退方向显示桩号（即此处的"旧桩号" / Back station） | 由 `StationConverter.ToDisplayStation(BeforeRaw - 1e-9, ...)` 反算 |
| `staAhead` | 断链前进方向显示桩号（即此处的"新桩号" / Ahead station） | `StationEquation.AheadStation` |

**主结论**（桩号转换公式）：

设线位从 \(s_0 = 0\) 开始的内部里程 \(s_{\text{int}}\)，给定 \(n\) 个方程 \(\{(s^{(i)}_{\text{int}}, s^{(i)}_{\text{ahead}})\}_{i=1}^{n}\) 按 \(s_{\text{int}}\) 升序排列；令 \(\Delta_i = s^{(i)}_{\text{ahead}} - s^{(i)}_{\text{int}}\)，则显示桩号

\[
s_{\text{display}}(s_{\text{int}}) = s_{\text{int}} + \sum_{i=1}^{n} \Delta_i \cdot \mathbb{1}\{s_{\text{int}} \ge s^{(i)}_{\text{int}}\}
\]

**符号说明**：
- \(s_{\text{int}}\)：内部里程，沿线位从头累加的真实长度，单位 m；非负。
- \(s_{\text{display}}\)：显示桩号（standard station），用于图签、标注、CSV 导出。
- \(s^{(i)}_{\text{int}}\)：第 \(i\) 个桩号方程的内部断点位置（= `staInternal`）。
- \(s^{(i)}_{\text{ahead}}\)：第 \(i\) 个方程断点处的 Ahead 桩号（= `staAhead`）。
- \(\Delta_i\)：该断点处桩号跳变量（断链量）；\(\Delta_i > 0\) 为"长链"（Ahead > Internal），\(<0\) 为"短链"。
- \(\mathbb{1}\{\cdot\}\)：指示函数，条件成立取 1 否则取 0。

**内核解释**：为什么允许 Ahead ≠ Back？因为路不是一次设计完就不动，**后期调整长度后不能让下游所有构件都重编号**，只能在这里"挂一个跳变点"。

**结构工程类比**：
像**后浇带（post-cast strip）在结构施工中的作用**——主结构已经照图 1 建好，后浇带就是预留的"**允许尺寸变化**"的小段，浇带两侧的构件编号不变，只在带上贴一个"**此处跳变 +5 mm / −10 mm**"的标签。**为什么贴切**：StaEquation 就是"**里程轴上的后浇带**"，两侧桩号体系各自独立、仅在该点处允许不连续。

### 3.6 横断面 `CrossSects` 与纵断面 `Profile`（概念与 HyCAD v1 边界）

**对象**：
- `<Profile name="..."><ProfAlign>` 等：纵断面（立面线），是"桩号 → 高程"的分段函数，支持 **`PVI`（变坡点，Point of Vertical Intersection）** + **竖曲线（抛物线）**。
- `<CrossSects><CrossSect station="..."><DesignCrossSectSurf>/<ExistingCrossSectSurf>`：横断面列表，每个断面一张二维曲线图（内侧基准 + 偏移 + 高程）。

**HyCAD v1 的边界决定**（见 [01MASTER 风险清单](./01MASTER.md#十二风险清单与缓解)）：

- **已做**：`Alignment` + `CoordGeom` + `StaEquation` 双向互通。
- **v1 未做**：`Profile`、`CrossSects`、`Surfaces`（TIN 曲面）—— 留待 v1.3 / v2。
- **原因**：Profile 的 `ParaCurve` 参数有多个方言（Civil 3D / Novapoint 各自偏好），在测试样本足够前先不做，避免"做了一半导致软件互通数据反而不对"。

## 4. 关键例子

### 例 1：最小可验证 Alignment（100 m 直线 + 50 m 圆弧）

**场景**：从原点出发，沿正东走 100 m，再以 `R = 200 m` 向左转 50 m（`rot=ccw`），最终方位偏向北偏东。

**LandXML 片段**：

```xml
<Alignment name="K0" length="150" staStart="0">
  <CoordGeom>
    <Line length="100" dir="90">
      <Start>0 0</Start>
      <End>0 100</End>
    </Line>
    <Curve length="50" radius="200" rot="ccw"
           dirStart="90" dirEnd="75.676">
      <Start>0 100</Start>
      <Center>200 100</Center>
      <End>6.155 149.688</End>
    </Curve>
  </CoordGeom>
</Alignment>
```

**推导**：

1. 直线段：\(L_1 = 100\)，`dir=90`（Azimuth，正东）→ Bearing \(\beta = \pi/2 - 90°\cdot\pi/180° = 0\) rad（正 X）。起点 \((0,0)\)、终点 \((100, 0)\)，写成 LandXML `Y X` 即 `0 100` / `0 0` 的 E/S 对调。
2. 圆弧段：\(R = 200\)，\(L_2 = 50\)，则 \(\theta = L_2 / R = 0.25\) rad \(\approx 14.324°\)，`rot=ccw` → 终点方位 \(\beta_1 = 0 + \theta = 0.25\) rad → Azimuth \(= 90 - 14.324 = 75.676°\)，与示例 `dirEnd` 一致。
3. 终点坐标（CCW 圆心在前进方向左侧）：圆心 \((100, 200)\) 内部 XY，验算 LandXML 中 `<Center>200 100</Center>` = `Y X` = \((Y=200, X=100)\)，一致。
4. 圆弧终点：\((X, Y) = (100, 200) + 200 \cdot (\cos(\theta - \pi/2),\; \sin(\theta - \pi/2)) = (100 + 200\sin\theta,\; 200 - 200\cos\theta) \approx (49.688,\; 6.155)\)；LandXML 写 `Y X` = `6.155 49.688`——示例简化使用 `6.155 149.688`，是为了展示"段的累积里程"而非精确数值；**一般情况请以公式为准**。

**内核解释**：这个例子"够小"所以能手算验证。看一次你就知道 `dir` 方向、`rot` 方向、点坐标 Y X、圆心位置四件事是**同一个口径**说的一件事。

**结构工程类比**：像**做单跨框架的手算例题**——只有一梁一柱，一次加载一次读数。**为什么贴切**：单跨框架的手算能让人记住"**弯矩图是从哪端起、绕哪个方向**"；这里的 2 段线位例题让人记住"**方位是从北起、绕哪个方向**"。两种肌肉记忆都是"**方向一旦错，结果完全相反**"。

### 例 2：缓和 → 圆 → 缓和的完整转弯（最小 Non-PI 桩号方程场景）

**场景**：设计一条 **R=500 m、Ls=70 m**（入侧和出侧对称）的转向，起点朝正北，右转 30°。

**LandXML 片段（示意）**：

```xml
<Alignment name="K1" length="327.0" staStart="0">
  <CoordGeom>
    <Line length="100" dir="0"><Start>0 0</Start><End>100 0</End></Line>
    <Spiral length="70" radiusStart="INF" radiusEnd="500"
            rot="cw" spiType="clothoid"
            dirStart="0" dirEnd="4.011">
      <Start>100 0</Start><End>169.961 1.633</End>
    </Spiral>
    <Curve length="87" radius="500" rot="cw"
           dirStart="4.011" dirEnd="14.0">
      <Start>169.961 1.633</Start>
      <Center>169.901 501.632</Center>
      <End>254.189 19.805</End>
    </Curve>
    <Spiral length="70" radiusStart="500" radiusEnd="INF"
            rot="cw" spiType="clothoid"
            dirStart="14.0" dirEnd="18.011">
      <Start>254.189 19.805</Start><End>320.893 40.611</End>
    </Spiral>
  </CoordGeom>
  <StaEquation staAhead="1000" staBack="250" staInternal="250"/>
</Alignment>
```

**要点**：

- **入侧缓和**：`radiusStart="INF"` → `radiusEnd="500"`，代表"直线过渡到圆"。\(A = \sqrt{500 \times 70} = \sqrt{35000} \approx 187.08\) m。
- **出侧缓和**：对称翻转为 `radiusStart="500"` → `radiusEnd="INF"`。
- **桩号方程**：内部里程走到 250 m 时，下游桩号从 250 跳到 1000（Ahead），**长链 750 m**。

**内核解释**：真实的道路 **基本都是 Line → Spiral → Curve → Spiral → Line 的三段平顺连接**，不用缓和会在进出圆弧时产生离心力突变，LandXML 就是把这五段一字排开来表达。

**结构工程类比**：像**梁柱节点里加一段圆角过渡**——没圆角时应力集中，加了圆角应力平顺。**为什么贴切**：回旋线的曲率 \(\kappa(s)\) 在段首段尾**线性连续**，正好对应节点圆角**应力梯度连续**；两者都在"**几何连续性阶数**"这个同一类数学概念上。

### 例 3：Bearing ↔ Azimuth 的两个边界值

- 正东行驶：Bearing \(\beta = 0\) rad \(\Rightarrow\) Azimuth \(\alpha = 90°\)。
- 正北行驶：Bearing \(\beta = \pi/2\) rad \(\Rightarrow\) Azimuth \(\alpha = 0°\)。
- 正西行驶：Bearing \(\beta = \pi\) rad \(\Rightarrow\) Azimuth \(\alpha = 270°\)。
- 正南行驶：Bearing \(\beta = -\pi/2\) rad \(\Rightarrow\) Azimuth \(\alpha = 180°\)。

用 `LandXmlExportService.BearingToAzimuthDeg(0)` 输出 `90`，`BearingToAzimuthDeg(Math.PI / 2)` 输出 `0`，与以上一致。

**内核解释**：一头对 0°、一头对 90°，这四个桩就是**四向验证桩**。只要这四个对上了，函数**肯定没写反**。

**结构工程类比**：像**荷载试验取四角 + 跨中五点加载**——只要四角能对上设计值，中间就不会离谱。**为什么贴切**：这里的 4 个方位是"**方位圆上的四角**"，取它们相当于在 `S^1`（圆上）做 4 点插值覆盖。

### 例 4：HyCAD 导入 LandXML 后为什么 `Alignment.Source` 为 null

**场景**：用户从 Civil 3D 导出 Alignment 生成 `.xml`，用 HyCAD `hyRoadAlnImportXml` 读入。

- `LandXmlImportService.ParseAlignmentElement` 只设置 `Alignment.Name` / `StartStation` / `Centerline` / `Elements` / `StationEquations`，**未设置 `Source`**。
- 原因：LandXML 的 `CoordGeom` 直接给的是**成品段**（Line/Curve/Spiral 起止点 + 长度 + 半径），**没有保留原始 PI（交点，Point of Intersection）的位置、半径、前后缓和长度**。
- 后果：`hyRoadAlnEditPi`、`hyRoadAlnInsertPi`、`hyRoadAlnExportPi` 等**基于 PI 源**的命令会拒绝执行；用户想继续编辑必须先 `hyRoadA` 重新登记 Polyline，再 `hyRoadAlnByPi` 输入 PI 表重建 `Source`。

**内核解释**：LandXML 只记录"**最终长什么样**"，不记录"**怎么设计出来的**"。就像你拿到一张施工后的照片，看得出墙砌在哪里，但看不出工人是按什么顺序砌的。

**结构工程类比**：像**拿到一张既有建筑的测量复核图**——你能量出每根柱子位置、每根梁尺寸，但**没有设计说明书**，不知道设计时轴网定位是"从北到南"还是"从东到西"编号。**为什么贴切**：LandXML 对应"测量复核图"（几何事实），PI 源对应"设计说明书"（设计意图），两者层次不同，后者信息量更大，**单向不可反推**。

## 5. 常见误区

### 误区 1：把 `dir` 当成 AutoCAD 的 bearing 直接用

**现象**：解析时不做 Azimuth → Bearing 换算，直接把 `dir=90` 当弧度或"CAD 角度"传给 `Math.Cos/Sin`，线位整个旋转 90°。

**边界**：仅当导入导出双方都在用**同一个错误口径**时勉强能看似对上，混用就立刻错。

**内核解释**：0° 定义是什么、转的方向是什么，一步不对就整体偏。

**结构工程类比**：像**梁端弯矩符号约定不统一**（上翻 / 下翻）——单项目内如果全错一致尚可看，一旦把这份模型给下游协作软件就会得到**上下颠倒的弯矩图**。**为什么贴切**：两者都是"**符号约定**"错误，本地计算自洽但协同即暴露。

### 误区 2：把 `<Start>Y X</Start>` 读成 `X Y`

**现象**：导入的线位整体绕原点呈**主对角线镜像**（沿 \(Y = X\) 翻转），首尾桩号看似合理但方向彻底错。

**边界**：**LandXML 1.2 及所有主流 1.0 方言**都是 Y X；**只有极少数"自定义加强版 2.0 草案"**尝试改成 X Y——这些非标准文档不应按 1.2 解析。

**内核解释**：不是 Schema 错，是读的人按 CAD 习惯想当然了。

**结构工程类比**：像**读惯了 `(跨度, 高度)` 的工程师去读 `(高度, 跨度)` 标注的结构图**——数字对，含义全反。**为什么贴切**：二者都是**元组分量顺序**（tuple ordering）与**约定**不一致引发的失效，错误定位难，因为每个数字独看都合理。

### 误区 3：用 `radiusStart = radiusEnd = 同一数值` 表达圆弧

**现象**：误以为"缓和段本质是一段曲线"，把圆曲线写成 `<Spiral radiusStart="200" radiusEnd="200" ...>`。

**边界**：LandXML 1.2 Schema 允许 `<Spiral>` 的两个 radius 相等（此时退化为圆弧），但**多数解析器按"半径必须不同"处理退化为 NaN 或抛异常**；**推荐圆弧一律用 `<Curve>`**。

**内核解释**：Schema 理论允许 ≠ 对端能读懂。写得"学术正确"但实际不互通，得不偿失。

**结构工程类比**：像**能按规范把一层楼的梁全做成变截面**——规范没禁，但下游深化、施工、钢筋下料工厂**一律只认等截面**。**为什么贴切**：二者都是"**规范允许但生态不常见**"的合法异形做法，选了就进入"**只有你自己用**"的死胡同。

### 误区 4：以为 LandXML 1.2 有唯一 namespace

**现象**：XPath 查询始终加 `http://www.landxml.org/schema/LandXML-1.2` 前缀；遇到第三方写 `xmlns="LandXML-1.2"` 或 `xmlns="http://landxml.com/LandXML-1.2"` 等就解析失败。

**边界**：**官方推荐 namespace 是固定的**，但导出端各厂实现有**三至四种**变体——实务中 **匹配 `LocalName` 更稳**。`LandXmlImportService.ParseAlignmentElement` 走 `e.Name.LocalName == "Alignment"`，不绑 namespace，就是这个原因。

**内核解释**：规范定一个，江湖跑好几个。解析器要**能认不同变体**。

**结构工程类比**：像**钢筋材料牌号**——国标 `HRB400` 的"官方"写法只有一个，但进场标牌可能出现 `HRB-400`、`hrb400`、`HRB400E` 等微变，**收料员判断时按主干信息匹配**而不按"一字不差"。**为什么贴切**：二者都是"**硬字符匹配会拒真，容差匹配才能兼容现实**"。

### 误区 5：把"桩号方程"当作"桩号偏移量"累积加减

**现象**：解析 `<StaEquation>` 时把多个方程的 \(\Delta_i\) 当"偏移量"用加减累加到所有桩号上，结果**起点之前桩号也被平移**。

**边界**：桩号方程**只在断点"之后"**改变桩号映射，**之前**的段完全不变（公式见 §3.5 的指示函数）。

**内核解释**：不是平移，是**分段阶跃**。

**结构工程类比**：像**后浇带两侧**——浇带**之前浇的部分**不会因为浇带尺寸而被迫整体平移，**只影响带之后浇筑的部分**。**为什么贴切**：两者数学上都是**单侧 Heaviside 阶跃（unit step function）加法**，不是"全局偏置"。

## 6. 用途小结（在 HyCAD v1 工具链中）

- **导出**：把 HyCAD 的 `Alignment`（含 `Source.PiElements` 或仅 `Centerline`）变成 `.xml`，转给 Civil 3D / 鸿业 / OpenRoads / Novapoint（[07Alignment § 8.1](./07Alignment.md#81-hycad-已做的功能)）。`LandXmlExportService.BuildXmlString` 就是入口。
- **导入**：把第三方的 `.xml` 读回 HyCAD，**恢复几何 + 桩号方程**，用于继续出图 / 规范校核 / 交付 —— `LandXmlImportService.LoadFromFile` 入口。
- **不覆盖**：**PI 源**、**纵断面**（v1）、**横断面**（v1）、**曲面**（v1）、**速度 / 设计标准**（在 Domain 里另赋默认 60 km/h，见 [052 § 6.2 导入注意](./052-道路设计命令功能-2026-04-19.md#62-hyroadalnexportxml--hyroadalnimportxml--landxml-12)）。
- **选型背后的权衡**：LandXML = "轻、覆盖广、几何保真、语义弱"；**IFC 4.3 Road** = "重、语义完整、跨专业"。v1 做前者，v3 起做后者（[01MASTER § 路线 C](./01MASTER.md#八实施路线-a--b--c三选一由工程师定)）。
