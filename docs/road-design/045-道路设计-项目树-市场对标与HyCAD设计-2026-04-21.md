## 一、文档目的与结论摘要

### 1.1 目的

回答三个产品与工程问题：

1. **UX**：道路设计软件需不需要一棵"项目树"？用户图（20260421 草案）的专业分组是否可取？
2. **数据**：HyCAD 当前 `RoadDesign` 是扁平多 `List<>` 聚合根，如何以最小代价支撑树视图？
3. **架构**：跨 DWG、跨子项目的多方案比选能力（Civil 3D 的 Data Shortcut、纬地的数据文件联动）如何嵌入现有 `.roaddesign.json`？

### 1.2 结论摘要（一句话）

**做**。以 **`RoadProject` 根聚合** 包住现有 `RoadDesign`（每个 DWG 一个 `RoadDesign`，多 DWG 共一个 `RoadProject`），UI 层新增 `RoadProjectTreePanel`（独立 `PaletteSet`），节点按 **专业分组 + Civil 3D Toolspace 子项嵌套** 混合排布；Schema 升 v2.0，向下兼容 v1.x 自动迁移 + `.bak` 备份。

## 二、市场软件项目树速览

### 2.1 Autodesk Civil 3D — Toolspace Prospector

- **一级分类（按数据类型）**：Projects（Vault 安装时显示）/ Drawing Templates / Data Shortcuts / Open Drawings
- **Open Drawings 下**：Points / Point Groups / Surfaces / Alignments / Feature Lines / Sites / Pipe Networks / Pressure Networks / Corridors / Assemblies / Intersections / Survey / View Frame Groups
- **Alignment 下嵌套**：Profiles / Profile Views / Sample Lines / Superelevation / Widenings / Offset Alignments / Station Control
- **视图切换**：`Active Drawing View` 与 `Master View`（多 DWG / 项目模板）
- **右键标配**：Properties / Edit / Zoom To / Pan To / Create Folder / Export LandXML / Refresh

> 参考：Autodesk Civil 3D 2026 *About The Toolspace Window* / *About the Toolspace Prospector Tab*。

### 2.2 Bentley OpenRoads Designer — Explorer 面板

- 按 **Feature Definition（语义标签）** 组织：`Alignment_Main` / `Alignment_Ramp` / `Terrain_EG` / `Corridor_Mainline` / `Mesh_Earthwork` 等
- 好处：跨文件共用语义；一条路线可按 Feature Definition 聚合 Corridor + Template Drop + Target Alias
- 坏处：概念抽象，初学者需要数周培训

> 参考：OpenRoads Designer Help — *Corridor Modeling Overview*；FHWA ORD User Manual 第 13 / 17 章。

### 2.3 鸿业市政道路 9.0 — 工程树（文件型）

- 按 **工程 → 数据文件 → 桩号** 排布（9.0 新增"桩号"一级）
- 右键提供：`核查` / `管理当前数据文件` / `置为当前`
- 支持类型：`hjd`、`zddata`、`zdmj`、`dl` 等
- 特点：**偏项目管理**，与设计对象的图形状态弱耦合；适合"一个工程多个阶段"的评审场景

### 2.4 纬地路立得 BIM — 专业/构筑物分组（最接近用户草案图）

- 一级分类（按专业）：**路线 / 立交 / 平交 / 构筑物 / 交通工程 / 地形 / 地质**
- 路线下嵌套：**几何（平纵横）+ 构筑物与附属（桥/隧/涵/交通设施）**
- 立交独立为一级（不挤进某条路线下），匹配"主线+多匝道+接线"的组合形态
- 配景（过街设施/铁路/水域）与地质各自独立，国内市政协同常见

### 2.5 Autodesk InfraWorks — 方案场景分组

- 按 **场景/方案** 组织：`Terrains` / `Roads` / `Bridges` / `Railways` / `Buildings` / `Coverage` / `Water Areas`
- 概念设计阶段使用；详细设计交给 Civil 3D
- 启示：**两档模型**（概念 vs 施工图）可共享一棵树的骨架，但数据精度不同

### 2.6 小结对照

| 维度 | Civil 3D | OpenRoads | 鸿业 9.0 | 纬地路立得 | InfraWorks |
|------|----------|-----------|----------|------------|------------|
| 分组逻辑 | 数据类型 | Feature Definition | 文件+桩号 | 专业+构筑物 | 场景/方案 |
| 路线下是否嵌套 | 是（Profile/SampleLine） | 是（VGeom/Corridor） | 弱（按桩号） | 是（几何+附属分家） | 否 |
| 立交位置 | Intersections 并列 | Corridor + Target | 独立 | **独立一级** | 独立一级 |
| 跨 DWG 引用 | Data Shortcut | 强（Ref + iModel） | 工程文件包 | 数据文件同步 | 自带 IMX |
| 中国市政契合 | 弱 | 弱 | **强** | **强** | 弱 |

## 三、用户草案图（20260421）分析

**输入**：用户在 2026-04-21 画了一张树图（`中华大街南延` 根 → 曲面 / 路线 / 道路平交 / 立交 / 配景 / 其他 / 地质，路线下又分两级）。

### 3.1 优点（建议保留）

1. **专业优先**，术语中文化，国内设计师一打开就是"我要做路线/立交/平交"，比 Civil 3D "Alignments / Corridors / Assemblies" 的术语负担低。
2. **路线下双模块**（`几何` + `构造物/附属`）是精华——避免一条路线展开一屏都是子节点。
3. **立交独立大类**（不挤进路线下）——立交涉及主线+多匝道+接线，挂在某一条路线下会割裂。
4. **纵断分幅节点化**（`0~175 / 175~350 / …`）—— 国内市政"大段纵断拆幅出图"的刚需，Civil 3D Profile View 整图方式做不到。
5. **`曲面` 与 `地质` 独立**，契合"先有地形图推路线"的国内工作流。
6. **`配景`（过街设施/铁路/水域）**单独大类——参照物不混进设计对象，国外软件稀有，但国内很实用。

### 3.2 可优化点（10 条）

| # | 问题 | 市场最佳实践 | 建议 |
|---|------|-------------|------|
| 1 | **根节点缺"项目元信息"** | Civil 3D 有 Drawing Settings / Data Shortcuts；鸿业 9.0 有"工程属性" | 根节点下加 **项目信息 / 坐标基准 / 规范设置**（对齐 `RoadDesign.ProjectName/CrsEpsg/Schema`） |
| 2 | **路线下两个"中华大街A"同名** | 路立得用 `路线几何` vs `路线构造物` 区分 | 改名为 `几何设计` / `构造物与附属`（或加图标区分） |
| 3 | **缺 `横断面模板 Template` 顶层节点** | Civil 3D 有 Assemblies / Subassemblies 独立根 | 新增一级 `标准断面` 或 `模板`，让多条路线引用（对齐 `RoadDesign.Templates`） |
| 4 | **缺 `走廊 Corridor` 可视化节点** | Civil 3D Corridors 是一等公民 | 路线下加 `走廊` 子节点（对齐 `RoadDesign.Corridors` + `AlignmentId`） |
| 5 | **`道路平交` 节点不可展开到实例** | Civil 3D / 纬地平交口可点击跳到具体路口 | 让 `道路平交` 展开成 `交叉口 1 / 交叉口 2`（对齐 `RoadDesign.Intersections`） |
| 6 | **缺"规范校核/审核报告"节点** | 纬地 120 项审核、Civil 3D Design Criteria | 加一级 `设计审核`（对齐 `*CodeChecker` 输出） |
| 7 | **交通设施在两处出现**（路线下 `入库标线` + 大类 `其他→交通设施`） | 路立得明确"路内附属 vs 路外交通工程" | 统一：路内（入库/停止线/斑马线）挂路线；路外（标志/电子警察）挂 `其他→交通设施` |
| 8 | **缺桩号管理一级** | 鸿业 9.0 新增的"桩号"一级正是痛点回应 | 路线下增加 `桩号体系` 节点（桩号断链/主桩/控制桩），对齐现有 `StationEquation` |
| 9 | **缺管线/排水** | 市政道路配套必备 | v2 规划位，先占树位 `管线`（空） |
| 10 | **`构筑物定义` 独立于桥/隧/涵** | 纬地 BIM 里构筑物即桥/隧/涵，定义在其上 | 把"构筑物定义"下移成 `桥梁/隧道/涵洞` 的父节点，或明确它是"类型库" |

## 四、HyCAD 优化版树结构（UI 与数据基准）

```text
RoadProject「中华大街南延」 (根 · 新聚合)
├─ [新] 项目信息 ProjectMeta            → RoadProject.Name + RoadDesign.ProjectName/Schema/CrsEpsg + 规范 + 图纸模板
├─     曲面 Surfaces                    → 新增 RoadDesign.Surfaces（占位，EG/FG/TIN 统一容器）
├─ [新] 标准断面 Templates              → 已有 RoadDesign.Templates（提到顶层展示）
├─     路线 Alignments
│   └─ 中华大街A  (Alignment 节点)
│       ├─ 几何设计 (AlignmentGeometryGroupNode，原"中华大街A"改名)
│       │   ├─ [新] 桩号体系             → 已有 Alignment.StationEquations 展开
│       │   ├─     纵断面 Profiles       → 已有 Alignment.Profiles（EG/FG）
│       │   ├─ [新] 纵断设计图 ProfileViews + 分幅 ProfileSheets
│       │   ├─     横断面 CrossSections  → 已有 Template 引用（按 AlignmentId 过滤）
│       │   └─ [新] 走廊 Corridors       → 已有 RoadDesign.Corridors（按 AlignmentId 归属）
│       └─ 构造物与附属 (AlignmentAssetsGroupNode，原第二个"中华大街A"改名)
│           ├─ 工程量 / 桥梁 / 隧道 / 涵洞 (占位空列表)
│           └─ 路内交通附属              → 已有 LaneMarking/StopLine/Crosswalk 分类（按 AlignmentId）
├─     道路平交 Intersections (可展开实例) → 已有 RoadDesign.Intersections（草案未展开，补可点击）
├─     立交 Interchanges               → 新增 RoadDesign.Interchanges
├─     配景 Landscapes                 → 新增 RoadDesign.Landscapes（过街/铁路/水域）
├─     其他 Others (路外交通设施)      → 新增 RoadDesign.ExternalTrafficFacilities
├─     地质 Geologies                  → 新增 RoadDesign.Geologies
├─     管线 Pipes  [v2 占位]           → 预留空节点，不含数据
└─ [新] 设计审核 CodeAudit             → 已有 *CodeChecker 输出聚合呈现
```

**节点命名**：显示为中文（用户习惯），代码内部字段走英文，与 041 / 053 / 057 保持一致。

### 5.1 现有字段（v1.2）直接复用

| 树节点 | `RoadDesign` 现有字段 | 无需改动 |
|--------|----------------------|---------|
| `路线` | `Alignments` | ✓ |
| `纵断面 Profiles` | `Alignment.Profiles` | ✓ |
| `标准断面 Templates` | `Templates` | ✓ |
| `走廊 Corridors` | `Corridors`（按 `AlignmentId` 过滤） | ✓ |
| `道路平交` | `Intersections` | ✓ |
| `控制体 Controls` | `Controls`（若 UI 需要） | ✓ |
| `结构层方案` | `StructureLayerSchemes`（选配） | ✓ |
| `桩号体系` | `Alignment.StationEquations` | ✓ |
| `路内交通附属` | `LaneMarking` / `StopLine` / `Crosswalk`（通过 Xdata 查） | ✓ |
| `设计审核` | `*CodeChecker.Check()` 现场调用 | ✓（派生视图，不落盘） |

### 5.2 新增字段（v2.0 Schema 引入，均为空列表占位）

| 树节点 | 新增字段 | 类型 | 最小字段 |
|--------|---------|------|---------|
| `项目元信息` | `RoadProject` 聚合根 | class | `Id / Name / CreatedAtUtc / LastModifiedUtc / Schema / Designs[] / Shortcuts[]` |
| `曲面` | `RoadDesign.Surfaces` | `List<Surface>` | `Id / Name / Kind(EG|FG|TIN)` |
| `纵断设计图分幅` | `Profile.Sheets` | `List<ProfileSheet>` | `Id / Name / StartStation / EndStation / Scale` |
| `立交` | `RoadDesign.Interchanges` | `List<Interchange>` | `Id / Name / Kind(MainRamp|UnderPass|OverPass) / AlignmentIds[]` |
| `配景` | `RoadDesign.Landscapes` | `List<Landscape>` | `Id / Name / Kind(Crossing|Railway|Water)` |
| `其他 / 路外交通设施` | `RoadDesign.ExternalTrafficFacilities` | `List<TrafficFacility>` | `Id / Name / Kind(Sign|Signal|Camera)` |
| `地质` | `RoadDesign.Geologies` | `List<Geology>` | `Id / Name / Kind(BoreHole|Stratum)` |
| `桥梁 / 隧道 / 涵洞` | `RoadDesign.Bridges / Tunnels / Culverts` | 分三类 `List<>` | `Id / Name / OwnerAlignmentId? / StartStation / EndStation` |
| `管线` | 占位 | — | v2 议题，不入 v2.0 schema |

**占位策略**：所有新增字段都是 `List<T>`，空集合默认值，`JsonProperty(NullValueHandling = Ignore)` + `[JsonIgnore] IsEmpty` 规则保持兼容（读取旧 JSON 时字段为 null → 构造函数补空集合）。

### 5.3 IsEmpty 新判据

```text
RoadDesign.IsEmpty 继续约束：现有 8 项集合 + 新增 8 项集合（Surfaces/Bridges/Tunnels/Culverts/Interchanges/Landscapes/ExternalTrafficFacilities/Geologies）全部空时才为空。
RoadProject.IsEmpty：Designs 全部 IsEmpty 且 Shortcuts 空。
```

## 七、JSON Schema v2.0 与迁移策略

### 7.1 版本号规则

- `SchemaVersion.Current` bump：`"1.2"` → `"2.0.0"`
- `SchemaVersion.MinimumSupported` 保持 `"1.0"`（读取 v1.0 / v1.1 / v1.2 均可）
- `RoadProject.Schema` 字段与 `RoadDesign.Schema` 独立；嵌入的每个 `RoadDesign` 仍可能是 v1.x 读入后升级到 v2.0

### 7.2 文件布局

```
<dwg 所在目录>/
├─ 某项目.dwg
├─ 某项目.roaddesign.json          ← v1.x 文件（单 DWG 模式，向后兼容）
├─ 某项目.roadproject.json         ← v2.0 新文件（项目根，含 Shortcut 列表）
└─ 备份/                            ← 迁移时自动产生的 .bak
    └─ 某项目.roaddesign.json.bak
```

### 7.3 迁移算法（`Migration.From1_x`）

1. 读入 `某项目.roaddesign.json` → 反序列化为 `RoadDesign`（若 `Schema < "2.0"`）
2. 为其新增字段填空 `List<>`（不修改已有字段值）
3. 创建 `RoadProject`：`Name = RoadDesign.ProjectName`，`Designs = [ design ]`，`Shortcuts = []`，`Schema = "2.0.0"`
4. 把旧文件重命名为 `.roaddesign.json.bak`（保留一份）
5. 落盘两个文件：
   - `某项目.roaddesign.json`（新字段空列表，`Schema = "2.0.0"`）
   - `某项目.roadproject.json`（项目根）

### 7.4 读取路径自动识别

```text
RoadJsonExportService.Load(path):
  若 path 以 .roadproject.json 结尾 → 反序列化为 RoadProject（新接口 LoadProject）
  若 path 以 .roaddesign.json 结尾：
    - 反序列化为 RoadDesign
    - 若 Schema < "2.0" → 走 Migration.From1_x → 返回包装过的 RoadProject（含单 RoadDesign）
```

### 7.5 保存路径约束

- `SaveForDocument` 保持语义（写 `.roaddesign.json`）；新增 `SaveProjectForDocument` 写 `.roadproject.json`
- 两者独立原子替换，不强制耦合（单 DWG 项目可以只保留 `.roaddesign.json`）

## 八、Data Shortcut 设计

### 8.1 值对象

```csharp
public enum DataShortcutKind
{
    Alignment = 0,
    Profile   = 1,
    Template  = 2,
    Corridor  = 3,
    Surface   = 4,
    Intersection = 5
}

public sealed class DataShortcut
{
    public Guid   Id            { get; set; } = Guid.NewGuid();
    public DataShortcutKind Kind { get; set; }
    public string SourcePath    { get; set; }   // 绝对路径或相对项目根
    public Guid   SourceId      { get; set; }   // 目标对象在远端 RoadDesign 的 Id
    public string LocalAlias    { get; set; }   // 本项目树显示名
}
```

### 8.2 注册表（`RoadProjectRegistry` 包裹现有 `RoadDesignRegistry`）

- 维持现有 `RoadDesignRegistry` API（`GetOrCreate(docName)` / `TryGet` / `Replace` / `Remove` / `Rekey`）
- 新增 `GetProjectOrCreate(rootPath)` / `TryGetProject(rootPath, out RoadProject)` / `ResolveShortcut(DataShortcut)` 
- 跨 DWG 引用：解析 `DataShortcut.SourcePath` → 懒加载目标 `.roaddesign.json`，按 `SourceId` 查

### 8.3 UI 约束

- 项目树节点带 **来源 DWG 徽标**（本地 vs 引用 vs 断链）
- 引用节点只读（右键菜单去掉 "删除"，保留 "打开源文件" / "解除链接"）
- 断链节点红字提示，保留 Shortcut 记录

### 8.4 与 Civil 3D 的差异

| 维度 | Civil 3D Data Shortcut | HyCAD v2.0 |
|------|------------------------|------------|
| 宿主 | Project Folder（固定目录结构） | 项目根目录（相对路径） |
| 绑定 | XML + DWG 引用 | JSON + DWG 引用（同文件格式） |
| 同步 | 手动 Synchronize | 打开项目树时懒加载 |
| 版本控制 | Vault 集成 | 暂不做（v3 议题） |

## 十、避坑清单（交叉引用）

### 10.1 `.cursor/skills/hycad-project-pitfalls/SKILL.md`
