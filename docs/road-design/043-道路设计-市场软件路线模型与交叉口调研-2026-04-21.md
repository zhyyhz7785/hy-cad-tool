## 2. 共性抽象：从「线」到「路体」的数据流

不同厂商术语不同，但 **可显示道路模型** 的构造在工程上普遍可归纳为同一条流水线（可与仓库 [10Corridor.md](./10Corridor.md) 中 Civil 3D 叙述对照）：

| 层级 | 常见对象 / 概念 | 作用 |
|------|-----------------|------|
| **平面** | Alignment / 导线 / 中心线 | 定义水平线位与桩号体系 |
| **纵断面** | Profile / 设计高程线 | 沿桩号给出路面或结构顶面标高 |
| **横断面规则** | Assembly + Subassembly（Civil 3D）；Template / Template Drop（OpenRoads）；横断面模板（国内习惯） | 定义半幅宽度、结构层、边坡、路缘等 **扫掠截面** |
| **三维扫掠** | Corridor（走廊） | 沿基准线按频率放置截面，生成 **连续三维道路体**（逻辑上多为参数化对象，可重建） |
| **贴地与目标** | Surface Target、Feature Line、Offset Alignment、Secondary Alignment 等 | 使边坡、加宽、交叉口缘石线等 **随外部几何变化**，而非固定截面 |
| **可视化与交付** | Corridor Surface、Mesh、Solid、IFC、FBX、渲染引擎 | 用于屏幕显示、碰撞检查、出图与下游 BIM / GIS |

**结论（给产品讨论用）**：「有路线」只是第一步；**可显示的道路模型** 几乎总是 **平面 + 纵断 + 横断规则 + 沿路线扫掠** 的合成物；交叉口处要么 **拆走廊 Region / 换模板**，要么 **专用交叉口对象生成附加线位与竖向** 再并入走廊。

## 3. 国际主流：Autodesk 系

### 3.1 Autodesk Civil 3D

**路线到模型**

- **Baseline** = Alignment +（通常）Finished Ground 的 Profile；**Assembly** 提供标准横断面；**Corridor** 沿桩号扫掠生成道路模型。
- **Frequency（频率）** 控制截面采样密度；曲线段常用「按曲率」加密以避免弯道折线感（培训与社区文章常见建议）。
- **Target（目标）** 将宽度、高程等绑定到曲面、路线、纵断或特征线，实现动态加宽与边坡。

**交叉口**

- **Intersection** 为独立对象：在两条（或多条）路线相交处创建，向导可生成 **Offset Alignments（偏移路线）**、**Curb Return（缘石回头线）** 及相关 **Profile**，以便在交叉口范围内用 **不同 Region / Assembly** 重建走廊（参见 Autodesk 帮助 *About Intersections*、教程 *Creating a Peer Road Intersection*）。
- **环岛**：除基础交叉口工具外，业界培训常强调 **Connected Alignments** 与走廊配合，用于环岛环道与辐射道路的整体衔接（如 Autodesk University 课程 *Connected Roundabouts* 类材料）。
- **环岛编辑**：帮助文档提供环岛专用设置、夹点编辑与样式，用于控制曲面、走廊与标线等显示（版本间菜单位置可能调整，以当前版本帮助为准）。

**可借鉴点**：把交叉口当成 **「附加线位 + 竖向 + 走廊分段」** 的打包对象，而不是单条 Polyline 上硬扫。

### 3.2 Autodesk InfraWorks

**定位差异（与 Civil 3D 对比）**

- 更偏 **方案 / 概念阶段**：地形、道路、桥梁在城市模型中快速摆放，强调 **可视化与比选**。
- 详细设计常 **下沉到 Civil 3D**（或其它详细 BIM 工具）做走廊级参数化；InfraWorks 侧多为 **简化的道路样式与地形适配**，而非全量 Subassembly 级控制。

**可借鉴点**：**两档模型**——概念「快显」与详细「可施工走廊」分离，接口通常是 **IMX / 路线导出** 等数据交换（具体格式以厂商文档为准）。

## 4. 国际主流：Bentley OpenRoads Designer

**路线到模型**

- **Corridor** 为核心：沿 **Baseline** 应用 **Template（模板）**；在匝道、交叉口、加宽处使用 **Template Drop（模板放置）** 与 **Transition（过渡）** 实现截面渐变（OpenRoads 帮助 *Corridor Modeling Overview*）。
- **Target Aliasing（目标别名）** 用于多条路走廊 **互相引用目标**，使相交道路在三维上 **闭合与衔接**（培训材料与州 DOT 自学课件中常见表述）。

**交叉口**

- 通常不单独起一个与 Civil 3D 完全同构的「Intersection 向导」名称，而是通过 **多模板、多 Baseline、点控制、次路线** 等机制，在交叉口范围 **拆分走廊逻辑段** 并绑定目标；大型项目常配合 **Civil Cell** 做标准段复用（详见仓库 [OpenRoads.md](./OpenRoads.md) 若有展开）。

**可借鉴点**：**目标别名 + 模板分段** 是处理 **多走廊互联** 的关键思想。

## 5. Trimble 与其它

### 5.1 Novapoint + Quadri（Trimble）

- 强调 **多专业模型服务器** 与 **Quadri** 中轴线一：道路几何在 Novapoint 中生成，模型对象进入协同环境，适合 **长线性工程企业流程**（总览见 [02Software_Overview_INDEX.md](./02Software_Overview_INDEX.md)）。
- 「路线 → 模型」仍遵循模板化走廊类逻辑，差异在 **数据托管与专业协同**，而非单句 UI 流程。

### 5.2 12d Model

- 以 **字符串（Strings）**、**超模型（Super Alignment）**、**函数式纵断** 等为特色，走廊类能力完整，学习路径与 AutoCAD 系不同（见 [12dModel.md](./12dModel.md)）。

## 6. 国内主流：鸿业、纬地、EICAD 等

### 6.1 鸿业（市政道路 + RoadLeader 等）

- **鸿业市政道路**：覆盖 **平纵横** 与 **交叉口竖向**、标准横断面与出图习惯，在国内市政单位渗透率高（详见 [HongYeRoad.md](./HongYeRoad.md)、[08Intersection.md](./08Intersection.md)）。
- **RoadLeader 路立得**（公开宣传）：强调 **BIM 理念** 下的三维道路、 **交叉口及立交出入口三维生成**、横断面与边坡自动化、 **参数联动**（修改参数后交叉口与标注联动）、三维漫游等（百科与厂商介绍类页面；细节以厂商手册为准）。

**可借鉴点**：**市政项目** 更关心 **交叉口竖向 + 规范图框**；三维展示常与 **专用三维模块** 绑定。

### 6.2 纬地（HintCAD / BIM 2.0）

- 公路行业常见：**平纵横一体化**、互通立交 **智能布线 / 模板化**、数模与三维集成。
- 公开资料常见表述：**BIM 三维交互式** 环境可与 CAD 端 **同步**，支持模型查询与标志物布置等（厂商解决方案与百科类摘要）。
- 互通立交：**主线 + 匝道 + 接线曲线** 一体化，强调 **起终点接线** 与 **纬地数据文件** 流转（社区与秘笈类文章描述较多，工程实施以软件版本为准）。

**可借鉴点**：**公路互通** 与 **市政平交** 往往是两条产品线能力侧重不同；立交更重 **匝道线位与接线约束**。

### 6.3 EICAD 等

- 在 [02Software_Overview_INDEX.md](./02Software_Overview_INDEX.md) 中，**交叉口 / 立交专业深度** 标注靠前；公开材料常强调 **渠化、待行区、复杂路口** 的参数化能力（详见 [EICAD.md](./EICAD.md)）。

## 7. 交叉口处理方式的类型学归纳

便于与 [08Intersection.md](./08Intersection.md) 中 Civil 3D / 鸿业 / HyCAD 三方对照阅读：

| 类型 | 代表思路 | 典型手段 | 优点 | 代价 |
|------|----------|----------|------|------|
| **A. 交叉口对象 + 自动生成附加线位** | Civil 3D Intersection | 偏移路线、缘石回头、竖向、再建走廊 Region | 平交路口 **流程闭合**，易复用标准 | 学习曲线陡，环岛 / 畸形路口需叠加其它工具 |
| **B. 纯走廊分段 + 目标互联** | OpenRoads 类 | Template Drop、Target Aliasing、多 Baseline | **灵活**，适合枢纽 / 变异大 | 对团队 **规程与模板库** 要求高 |
| **C. 国内「平交口模块 + 竖向」** | 鸿业、纬地市政模块 | 参数化路口 + 竖向设计 + 图面联动 | **贴合国标图框与审图习惯** | 与通用 IFC 走廊 **语义对齐** 需额外工作 |
| **D. 立交专用线位 + 横断模板** | 纬地互通、EICAD | 匝道线位、超高、护栏、结构分段 | **公路立交** 表达强 | 与市政 **慢行系统**（缘石坡道、盲道）组合时需扩展 |
| **E. 概念模型快速摆放** | InfraWorks | 城市尺度道路样式 | **方案沟通快** | 不宜直接当施工图走廊 |
