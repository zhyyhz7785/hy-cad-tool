# AutoCAD 转 SVG 产品调研与实现路径

> 调研日期：2026-09-21
> 目标形态：AutoCAD 插件命令（假设）+ 可选离线批处理
> 一句话目标：帮已经打开 AutoCAD 的人，把当前图纸变成浏览器能打开的矢量图

## 总论

**结论（建议）**：市场上「DWG 转 SVG」软件已经很多，不要再做通用文件转换器；值得做的是 HyCAD 里一条不离开 AutoCAD 的导出命令——用当前图面数据库写 SVG（Scalable Vector Graphics，可缩放矢量图形，作用是把线、弧、字存成可缩放的 XML 图），并带图层分组与实体 ID。

纸上可画成这条链：AutoCAD 当前图 → 遍历实体 → 写出 `.svg` → 浏览器打开。Autodesk 官方写明 AutoCAD **不能**把 DWG（Drawing，AutoCAD 原生图纸文件）转成 SVG；浩辰、中望、BricsCAD 等竞品 CAD 已有 `EXPORT` 出 SVG；桌面/在线/开源转换器也成批存在。空白不在「会不会转」，而在「AutoCAD 用户少一个按钮」以及「转完还认得出哪条线是哪个实体」。

证据：Autodesk 支持文 [已验证](https://www.autodesk.com/support/technical/article/caas/sfdcarticles/sfdcarticles/Convert-DWG-files-to-SVG-format.html)；浩辰 2023 官方博客 [已验证](https://blog.gstarcad.net/now-you-can-import-export-svg-file-in-gstarcad-2023/)；BricsCAD `EXPORT` 帮助 [已验证](https://help.bricsys.com/en-us/document/command-reference/e/export-command)。本仓 `docs/DataExchange` 已把 SVG 定为 JSON（JavaScript Object Notation，一种文本数据格式）快照的可视旁路，与本结论同向 [已验证]。

## 0. 目标与约束

**结论（假设）**：用户要的是「AutoCAD 图变成 SVG」；本仓场景默认做成 HyCAD 插件命令，而不是再做一个 AnyDWG 类批处理软件。

- 核心功能：当前图纸 / 选择集 / 布局 → SVG，浏览器打开后线型、图层、文字大体像 AutoCAD 出图。
- 目标用户：已在 AutoCAD 里画结构/土木图的 HyCAD 用户（假设）。次要：要网页展示、说明书插图、AI 看图的人。
- 平台形态：Windows + AutoCAD 插件（假设，因本仓是 HyCADTool）。离线批处理只作备选，不作为产品主形态。
- 关键约束：本地、不上传图纸；中文 SHX（Shape，AutoCAD 形字体文件，作用是存线划字型）与 TTF（TrueType Font，轮廓字体）要可读；不从零解析 DWG 二进制。
- 成功标准（假设）：同一张二维图，浏览器里的 SVG 与 AutoCAD 当前视口/布局在图层开关、颜色、线宽上可对照；选择集导出只含所选实体。
- 五维权重：功能 30% / 易用 20% / 可靠安全 15% / 稳定 15% / 差异化 20%（合计 100%）。工具类本应抬易用；本市场同质转换器已多，抬差异化以免做成更差的复制品。

### 头部竞品要点

#### 浩辰 / 中望 / BricsCAD 原生导出
- 优点：人不用离开 CAD；BricsCAD 还能用 `SVGSCALEFACTOR` 把 1 图面单位对到毫米。
- 缺点：AutoCAD 没有对等按钮；换宿主成本远高于加一条 HyCAD 命令。
- 评分：功能 4/5 · 易用 5/5 · 可靠安全 4/5 · 稳定 4/5 · 差异化 3/5

#### QCAD Professional `dwg2svg`
- 优点：$48；CLI 可进脚本；默认「看起来一样」，`-g` 尽量保留圆/弧几何给 Inkscape 再编辑。
- 缺点：不是 AutoCAD 渲染，复杂标注/动态块/中文 SHX **待验证**；要另装一套 CAD。
- 评分：功能 4/5 · 易用 4/5 · 可靠安全 4/5 · 稳定 4/5 · 差异化 3/5

#### ODA Drawings SDK
- 优点：读 DWG 的工业底座，带 `OdSvgExportEx` 样例；会员价按公司不计开发者席位。
- 缺点：Commercial 首年 $3,000，且不可 Web/SaaS；SVG 导出线程安全官方未保证。
- 评分：功能 5/5 · 易用 2/5 · 可靠安全 4/5 · 稳定 5/5 · 差异化 3/5

#### AutoDWG 类转换器
- 优点：不装 AutoCAD、批量、布局/字体路径/SVGZ（压缩 SVG）。
- 缺点：同质产品多；无法带上 AutoCAD 当前选择集与 HyCAD 业务 ID；保真靠厂商自述。
- 评分：功能 4/5 · 易用 4/5 · 可靠安全 3/5 · 稳定 4/5 · 差异化 2/5

#### Aspose.CAD
- 优点：.NET 几行 API；可选图层、文字转图形。
- 缺点：Small Business 不能对外分发；嵌进 HyCAD 发给客户要 OEM（Original Equipment Manufacturer，允许把库打进卖给别人的软件）/ SDK 档，价远高于 $799。
- 评分：功能 4/5 · 易用 3/5 · 可靠安全 4/5 · 稳定 4/5 · 差异化 2/5

### 行业现状小结

- 普遍做得好：不装 AutoCAD 也能批量出一张能在浏览器打开的图；CAD 替代品已经把 SVG 放进 `EXPORT`。
- 普遍短板：AutoCAD 官方缺口一直在；转换器把块/标注/填充打散后无法反向认实体；中文形字体与出图线宽各家自说自话；走 PDF 中转会把圆切成碎线（Autodesk 论坛案例，已验证现象描述、未在本机复现）。
- 本仓已有判断：`docs/DataExchange/01-AutoCAD几何数据传递给AI的方案对比与推荐-2026-04-27-022600.md` 把 SVG 定为可视旁路、JSON 为主路——说明 HyCAD 要的不是「又一个转换器」，是「能对上实体 ID 的预览」。

## 3. 我应当做的产品

**结论（建议）**：不要做「第 N 个 DWG 转 SVG 软件」；做 HyCAD 命令：当前图面 → 语义 SVG（图层成组、Handle 当 `id`），专补 AutoCAD 缺的那个按钮。

- 机会矩阵：
  - 「把 DWG 文件批量变成网页图」→ 竞品满足度 **高**，不要进。
  - 「AutoCAD 里一键导出当前视口/选择集」→ **低**（官方没有）。
  - 「SVG 里还能指回 CAD 实体 / 给 AI 当缩略图」→ **空白**。
- 一句话定位：为【AutoCAD + HyCAD 用户】提供【当前图面的矢量副本】，区别于【AutoDWG / QCAD】在于【不解析 DWG 文件、用 AutoCAD 自己的数据库、带实体 ID】。
- 目标用户画像：
  - 主：正在 AutoCAD 里改图，要把图贴进网页、Markdown、说明书或给 AI 看。
  - 次：无 AutoCAD、只要文件夹批量转——请买 QCAD $48 或现成转换器，不作为本产品 MVP。
- MVP 功能集（MoSCoW：Must / Should / Could / Won't，按优先级切范围；MVP 是 Minimum Viable Product，最小可行产品）：

| 优先级 | 含义 | 功能 |
|---|---|---|
| Must | 没有它产品不成立 | 当前选择集或当前空间全部；直线 / 多段线 / 圆 / 弧 / 椭圆 / 样条采样 / 单行文字；`Explode()` 递归展开块参照、标注、引线、表格、多行文字、图案填充（深度 8）；实体填充写 `<path fill>`；图层 → `<g>`；Handle 当 `id`；Y 轴翻转后浏览器正立；本地写文件 |
| Should | 重要但可后补 | SHX 描轮廓（MVP 用微软雅黑回退）；线型虚线 `stroke-dasharray`（本仓 `LinetypeTableExporter` 已能读 dash）；布局视口裁剪 |
| Could | 锦上添花 | 与 `.hycad-snapshot.json` 同 id；背景色/纸色开关；命令行批当前打开的图 |
| Won't(now) | 本期明确不做 | 无 AutoCAD 的 DWG 文件解析器；云上传转换；三维投影成 SVG；反向 SVG→DWG；和 AutoDWG 比拼文件夹批量 |

- 非功能目标（可量化，验收前均为 **待验证**）：A3 量级二维图导出 < 5 s；输出可被 Chrome / Edge 直接打开；关闭图层的实体不出现；不把图纸传到网络。
- 差异化锚点：AutoCAD 进程内 + 实体 Handle（句柄，图中每个对象的稳定编号，作用是让 SVG 里的图形能指回 CAD 里的同一条线）进 SVG `id` + 中文工程字（微软雅黑 / TSSD / SHX）走 AutoCAD 已加载字体，而不是再猜一份字体表。
- 不做清单：不做独立安装的「CAD 转换器」产品；不 Fork LibreDWG；不把 Aspose/ODA 仅为「出一张图」而引入（宿主已是 AutoCAD 时它们是多余的 DWG 阅读器）。

## 4. 最优实现路径

**结论（建议）**：构建方式选「套用 AutoCAD .NET API 做壳」——DWG 已经在内存里，再买 ODA/Aspose 是重复买阅读器；高风险是填充、标注、形字体的视觉差，要用对照样张先做 PoC（Proof of Concept，概念验证），不要先铺架构。

- 构建方式：
  - **推荐**：套用库/引擎做壳 = AutoCAD 图形数据库当引擎，自写 SVG 写出器。理由：零 DWG 解析、字体与显示样式跟当前会话一致、能拿选择集。
  - **备选 A**：无 AutoCAD 的批处理需求 → 买 QCAD Professional（$48）调 `dwg2svg`，或试用 AutoDWG。
  - **备选 B**：必须独立读 DWG 且要嵌进自有软件 → 评估 Aspose（对内 $799）或 ODA（公司 $3,000/年）；不要用 LibreDWG（GPLv3+）。
  - **不推荐**：从零自研 DWG 解析；Fork ACadSvg 当生产引擎（覆盖与维护都不够）。

- 技术选型（默认 + 备选；版本已核对处已写来源，否则 **待验证**）：
  - 语言/宿主：C# + AutoCAD .NET API（与 HyCADTool 一致）。
  - 写出：自写最小 SVG 1.1（`<g>` / `<line>` / `<path>` / `<text>` / `<circle>`），不引入 Skia / Svg.NET。
  - 文字：MVP 用 `<text>`——TTF（TrueType Font，轮廓字体）保留 `Font.TypeFace`；SHX 回退 `"Microsoft YaHei", sans-serif`。描轮廓留 V1，标 **待验证**。
  - 本仓可复用：`EntityToHyobConverter` 已覆盖 Line / Circle / Arc / Polyline / BlockReference / MText / DBText / Dimension / Hatch 九类（几何字段对照，不直接调用）；`LinetypeTableExporter` 已读线型 dash，V1 可接 `stroke-dasharray`。
  - 无 AutoCAD 备选读库：ezdxf（MIT，仅 DXF）或 ACadSharp（MIT）+ 自写写出器；**不要** LibreDWG。
  - 许可证：HyCAD 闭源插件可调用 AutoCAD API；ACadSvg 的 LGPL-3.0 动态链接可用但实体不全；GPLv3 不可嵌入。

- 架构概要：命令入口 → 收集选择集或当前空间 → `Explode()` 递归到基元 → 世界坐标转 SVG 视口（Y 翻转、按范围 `viewBox`（视口框，规定图在画布里占哪一块））→ 图层/颜色/线宽写入属性 → 落盘。风险点：Hatch 边界、标注分解后碎线、SHX 在浏览器里不是原字形、超大图 SVG 体积。

- 路线图：
  - **MVP**：`hysvg` / 占位符 `N42`；选择集或当前空间；基元 + Explode 复合实体；Chrome/Edge 打开对照。验收见 §6，未跑标 **待验证**。
  - **V1**：SHX 描轮廓、线型虚线、布局视口裁剪。验收：与 AutoCAD 打印预览并排看。**待验证**。
  - **V2**：`id` 对齐 JSON 快照；可选给 AI / 网页。不把批量转文件当目标。

- 风险与对策：

| 风险 | 类型 | 影响 | 对策 |
|---|---|---|---|
| 填充/标注/形字体看起来不像 AutoCAD | 技术 | MVP 被判失败 | 先做 3 张金标准对照（纯线、带字、带填充）；差则改「分解后描轮廓」而不是猜算法 |
| 超大施工图 SVG 几十 MB | 技术 | 浏览器卡 | 选择集默认；超出阈值改写 PNG 旁路或分层导出 |
| 第三方转换器「已经够用」导致无人用插件 | 市场 | 白做 | 只做 AutoCAD 内一键 + 实体 ID；不宣传成通用转换器 |
| 误嵌 GPLv3 LibreDWG | 许可 | 整仓传染 | 禁止；独立批处理用买来的 QCAD/AutoDWG |
| Aspose OEM 条款不够对外分发 | 许可 | 发版违规 | 宿主已是 AutoCAD 时不引入 Aspose |

- 假设验证（最危险的先做）：
  1. 「AutoCAD API 描出来的字/填充，浏览器里能被结构工程师认成同一张图」→ 1 周 PoC，3 张对照。失败则改用「打印 PDF 再转」并接受碎线，或直接买 QCAD 对比同一张图。
  2. 「用户要的是当前图，不是文件夹批量」→ 问一句或看 HyCAD 使用场景即可否决通用转换器。
  3. 「实体 ID 是否马上需要」→ 不需要就把 V2 放下，Must 只做出能看的图。

## 5. 结论

**结论（建议）**：市场有对应软件，而且不少；缺的是 AutoCAD 里那一键，以及带实体身份的 SVG。HyCAD 应做进程内导出命令，不要做转换器产品。第一步：`N42` / `hysvg` 把当前图写出 `.svg`，和 AutoCAD 并排看；不过关就停，不要先写独立 DWG 引擎。

## 6. 快速实现路径

**结论（已验证编译 / 图面待验证）**：`hysvg` 先弹出打印式对话框，再按纸张毫米写出 SVG；根因是旧写出器把图形范围当成纸张（建筑平面变成十几万毫米宽，Edge 首屏只见白纸一角）。

纸上可画：`N42` → 对话框（纸张 / 窗口 / 比例 / 单色）→ 展平线圆字 → `y_svg = -y_dwg` → `<svg width="纸张mm">` + `viewBox`（视口框）= 打印窗口 → DWG 同级 `.svg`。预览用系统默认浏览器打开临时文件。

| 项 | 做法 |
|---|---|
| 对话框 | `SvgExportWindow`（Blender 深色主题，`ShowModalWindow`）；本会话静态记住，不落盘 |
| 纸张 | ISO A0–A4、ANSI A–D、自定义宽×高 mm；方向 纵 / 横 / 上下颠倒 |
| 打印区域 | 窗口（按钮「窗口 <」拾两点）/ 图形范围 / 当前显示 / 选择集；与矩形相交才展平 |
| 比例 | 默认布满图纸：`scale = min((纸宽-2·边距)/窗宽, (纸高-2·边距)/窗高)`；自定义「1 mm = N 图形单位」 |
| 样式表 | 默认 `monochrome`（单色，全黑；近白填充仍白）；按对象颜色；灰度 |
| 线宽 | 记 mm；写出时 `mm × 单位/mm` 换成图形单位；去掉 `vector-effect="non-scaling-stroke"`（屏幕放大线变粗） |
| 裁切与边框 | 忽略空白 = 窗口内实体包围盒；`clipPath`（裁切路径）裁窗口；边距 mm；可选边框线 |
| 输出 | 已保存图：DWG 同级同名 `.svg`；未保存 / 预览：`%TEMP%\hysvg-*.svg` |
| 展平 | 基元直出；`BlockReference` / `Dimension` / `MLeader` / `Leader` / `Table` / `MText` / 非 SOLID `Hatch` 递归 `Explode()`，深度 8 |
| 注册 | `commands.json` 的 `N42` + `hysvg` |

代码落点：`SvgExportCommand.cs`、`Views/SvgExportWindow.xaml`、`Services/Svg/SvgPlotSettings.cs`、`SvgExportRunner.cs`、`SvgEntityFlattener.cs`、`SvgDocumentWriter.cs`。
