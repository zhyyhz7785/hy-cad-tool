# AutoCAD 表格工具 产品调研与实现路径

> 调研日期：2026-06-24
> 目标形态：AutoCAD 插件（.NET，跑在 AutoCAD 进程内，HyCADTool 体系）
> 一句话目标：帮工程绘图人员在 CAD 里像用 Excel 一样顺手地建/改/联动表格，替代难用的原生 TABLE

---

## 0. 目标与约束

- **核心功能**：通用数据表格的创建与编辑（替代原生 `TABLE` 命令），并打通与 Excel 的数据流。
- **目标用户**：结构/市政/机电等专业绘图人员；高频画材料表、设备表、说明表、统计表；多数会用 Excel 但不喜欢 CAD 原生表格。
- **平台形态**：AutoCAD 插件（融入现有 HyCADTool + HyCAD.BlenderUI 面板体系）。
- **关键约束**：
  - 自用/内部工具优先，非对外卖货（**假设**：先服务自己团队，故成本敏感度高、可不做授权加密）。
  - 技术栈锁定 .NET Framework 4.8 + AutoCAD.NET API + WPF（项目既有栈）。
  - 必须兼容 ReCall C2 热重载、PaletteSet 宿主约束（见项目规则）。
  - 中文字体/`%%c`→Φ 等本地符号必须正确。
- **成功标准**：常用建表/改表流程比原生快一半以上、比 Excel 导入少踩格式坑；自己团队愿意长期用它而不是原生 TABLE。
- **五维权重（合计 100%）**：**易用 40% / 功能 30% / 稳定 15% / 可靠安全 8% / 差异化 7%**（易用性优先，符合"原生太难用"的初衷）。

> 用户已确认：用途=通用数据表格；痛点=编辑体验差 + 与图形数据脱节 + Excel 互通差 + 样式排版难统一（四项全选）；权重=易用性优先。

## 2. 五维度优缺点分析

> 评分 1–5（5=优）。"差异化"列评的是该竞品**相对其他产品的护城河**。

### AutoTable (Cadig)
- **优点**：所见即所得（Excel 格式 1:1 落地）、导入即原生实体可打印、保留条件格式/多字体/合并单元格、跨多 CAD 平台、更新及时（已支持 2027）。
- **缺点**：单向偏重 Excel→CAD（回写弱）、商业收费、本地化偏英文、不解决"在 CAD 里直接顺手编辑"的核心诉求（仍以 Excel 为主战场）。
- 评分：功能 5 · 易用 4 · 可靠安全 3 · 稳定 4 · 差异化 4

### TableTransformer (TRTT，中望)
- **优点**：功能最全（16 场景）、**真双向同步**（强制拉取/反向写回/仅同步变化单元格）、相对路径绑定项目迁移不丢链、假表→真表一键转、保留公式/颜色、Ribbon+侧边栏、覆盖国产 CAD。
- **缺点**：偏中望生态、命令繁多学习成本高、商业闭源、深度绑定其工作流（迁移成本/锁定）、对"原生编辑卡顿"本身无能为力。
- 评分：功能 5 · 易用 4 · 可靠安全 3 · 稳定 4 · 差异化 5

### 真实表格 TrueTable
- **优点**：老牌稳定、CAD↔Excel/WPS 互导成熟、自带工程统计（型钢重量/螺栓球/面积/文本统计）、`%%c→Φ` 等中文符号处理到位、表格倒置/分片/表头表尾等细节多。
- **缺点**：更新慢（官网最高列到 AutoCAD 2022）、UI 偏老、加密狗/淘宝注册体验差、专业版按行业拆分售卖、闭源。
- 评分：功能 4 · 易用 3 · 可靠安全 3 · 稳定 4 · 差异化 4

### JTB Excel2TextField
- **优点**：字段级精细绑定（文字/属性/表格单元格均可）、源 Excel 改则图改、批量改源路径方便、兼容 2012–2026 全系与各 vertical。
- **缺点**：定位偏"字段联动"而非"建表/排版"、不解决建表与编辑体验、需要先有图元再绑、闭源收费。
- 评分：功能 3 · 易用 3 · 可靠安全 3 · 稳定 4 · 差异化 3

### AutoCAD 原生 TABLE / Data Link（基线，要被替代的对象）
- **优点**：免费内置、Data Link 能连 Excel/CSV 并手动更新、生成原生实体。
- **缺点（用户痛点实锤，均有来源）**：
  - **编辑卡顿**：大表（400+ 单元格）越编越慢，须关图重开；[Autodesk 论坛](https://forums.autodesk.com/t5/autocad-forum/autocad-2022-table-cells-very-slow-to-work-with-reason/td-p/11500910)。
  - **字体被改**：单击直接输入会触发格式覆盖，单元格字体外观不一致且 match cell 无效；[Autodesk 论坛](https://forums.autodesk.com/t5/autocad-mep-forum/autocad-table-cell-font-changes-depending-on-how-it-gets-edited/td-p/9212318)。
  - **中文问号**：TEXT/属性不支持多语言，跨系统打开变 `?`，需大字体或转 MTEXT；[Autodesk 支持](https://www.autodesk.com/support/technical/article/caas/sfdcarticles/sfdcarticles/Chinese-text-shows-as-a-question-mark-in-AutoCAD.html)。
  - Data Link 来源表导入后样式覆盖难清、回写能力弱。
- 评分：功能 3 · 易用 2 · 可靠安全 3 · 稳定 2 · 差异化 1

### 汇总对比（加权：易用0.40 / 功能0.30 / 稳定0.15 / 可靠安全0.08 / 差异化0.07）

| 竞品 | 功能 | 易用 | 可靠安全 | 稳定 | 差异化 | 加权总分 | 总评 |
|---|---|---|---|---|---|---|---|
| AutoTable | 5 | 4 | 3 | 4 | 4 | **4.22** | Excel→CAD 标杆，回写与"原地编辑"弱 |
| TableTransformer | 5 | 4 | 3 | 4 | 5 | **4.29** | 功能最全的双向同步旗舰，重、绑生态 |
| TrueTable | 4 | 3 | 3 | 4 | 4 | **3.52** | 老牌统计强，更新慢 UI 旧 |
| JTB Excel2TextField | 3 | 3 | 3 | 4 | 3 | **3.18** | 字段联动专精，非建表工具 |
| 原生 TABLE/DataLink | 3 | 2 | 3 | 2 | 1 | **2.31** | 免费但难用，正是要超越的基线 |

> 加权总分≈ Σ(维度分×权重)。易用权重最高，故"原地编辑顺手度"对排名影响最大。

### 行业现状小结

- **普遍做得好**：Excel→CAD 导入并保持原生实体可打印；双向/字段联动同步；保留样式、公式、合并单元格；批量导入导出；假表转真表。
- **普遍短板/未满足**：
  1. **没有人真正解决"在 CAD 里直接编辑表格的体验"**——大家都把战场搬到 Excel，绕开而非修复原生编辑卡顿/字体跳变。
  2. 原生大表性能差、字体覆盖、中文问号是长期痛点，第三方多靠"用 Excel 替你编"回避。
  3. 强者多为闭源商业 + 生态锁定，**自用/可定制/与既有插件深度集成**是空白。
  4. 与**图形数据联动**（从图里选实体自动统计进表）多停留在 TrueTable 的统计工具层，少有和自家业务命令打通的。

## 3. 我应当做的产品

### 机会矩阵（痛点 × 竞品满足度）

| 用户痛点 | 竞品满足度 | 机会 |
|---|---|---|
| 在 CAD 里**原地顺手编辑**（不切 Excel） | **低/空白**（大家靠 Excel 回避） | **★ 主切入点** |
| 样式一键统一（中文字体/行高/边框/Φ符号） | 中 | ★ 体验切入点 |
| Excel 双向导入导出 | 高（AutoTable/TRTT 很强） | 做到"够用"即可，不硬拼 |
| 从图形选实体自动统计进表 | 低 | ★ 差异化（结合 HyCADTool 业务） |
| 项目迁移不丢链 | 高（TRTT 已解决） | 借鉴相对路径方案 |

→ **切入空白 = 原地编辑体验 + 样式一键统一 + 与自家图形/业务数据联动**，而非再造一个 Excel 导入器。

### 一句话定位

> 为【HyCADTool 体系下的工程绘图人员】提供【一个像 Excel 般顺手、能从图里直接取数、样式一键规整的 CAD 内嵌表格面板】，区别于【AutoTable / TableTransformer 等"以 Excel 为主战场的导入同步器"】之处在于【把编辑体验和图形数据联动直接做进 CAD 面板，自用、可定制、与既有命令深度集成】。

### 目标用户画像

- **主**：本团队结构/市政绘图工程师——天天画材料表/设备表/说明表，受够原生编辑卡顿与字体跳变。
- **次**：偶尔需要把图中统计（数量、长度、面积、型号）汇成表的人。

### MVP 功能集（MoSCoW）

| 优先级 | 功能 |
|---|---|
| **Must** | ① WPF 面板内类 Excel 网格编辑（输入/Tab 跳格/插删行列/合并单元格）→ 生成/回写 CAD 原生 Table；② 样式一键统一（中文大字体、行高列宽、对齐、边框、`%%c→Φ`）；③ 表格样式模板（材料表/设备表预设）一键套用 |
| **Should** | ④ Excel/CSV 导入导出（用 NPOI，无需装 Excel）；⑤ 从图中选实体统计（计数/长度/面积/块属性）填入表；⑥ 选中已有 CAD 表→拉回面板编辑 |
| **Could** | ⑦ 假表（直线+文字）一键转真表；⑧ 公式/小计；⑨ 与 Excel 相对路径联动更新 |
| **Won't(now)** | 授权加密/对外售卖；跨 ZWCAD/GstarCAD 移植；条件格式高级渲染 |

### 非功能目标（可量化，对齐"易用+稳定"高权重）

- 新建一张 10×6 表 ≤ 3 步、≤ 20 秒。
- 面板内编辑 300+ 单元格无明显卡顿（不复现原生"越编越慢"）。
- 中文字体零问号；样式统一一键完成，不出现单击/双击字体跳变。
- 生成的全部是 CAD 原生实体，可正常打印。

### 差异化锚点

1. **原地编辑体验**——把编辑放进自家 WPF 面板（数据在内存网格里跑，避开原生 Table 逐格刷新的性能坑），定稿一次性写图。
2. **图形数据联动**——复用 HyCADTool 既有选择集/统计能力，从图直接取数进表。
3. **自用可定制 + 深度集成**——和现有 Ribbon/面板/样式体系一体，模板贴合本团队图纸规范。

### 不做清单

- 不做又一个"Excel 导入器"去硬拼 AutoTable/TRTT 的 16 场景。
- 不做授权/加密/多 CAD 平台移植（自用阶段纯负担）。
- 不在原生 Table 上做编辑（直接继承它的性能/字体坑）。

## 4. 最优实现路径

### ① 构建方式决策

| 方式 | 是否采用 | 理由 |
|---|---|---|
| 从零自研整套 | 部分 | 仅"WPF 网格编辑面板"这层值得自研（差异化所在） |
| **Fork/复用开源库** | **✔ 推荐** | 表生成与 Excel 读写用 NetCad/Linq2Acad/NPOI 现成能力，不重复造轮子 |
| 套用现成商业插件 | 否 | 闭源、收费、生态锁定，且不解决原地编辑诉求 |
| 现成 SaaS/低代码 | 否 | CAD 进程内插件，不适用 |

**推荐**：**复用既有 + 局部自研**——底层表生成/写图复用 HyCADTool 自有 `*TableBuilder` 与 AutoCAD Table API；Excel 读写引入 NPOI；**自研重点放在 WPF 类 Excel 编辑面板 + 样式统一引擎 + 图形取数**。
**备选**：若编辑体验要求极高，编辑网格可引入成熟 WPF DataGrid 三方控件，但需核对许可证与 PaletteSet 宿主兼容性。

### ② 技术选型（默认 + 备选）

- **语言/运行时**：C# / .NET Framework 4.8（项目锁定）。
- **UI**：WPF + HyCAD.BlenderUI 主题；编辑网格默认用原生 `DataGrid`，备选三方网格控件（需查 License）。
- **CAD 写图**：AutoCAD.NET `Table` 实体 API + 项目既有 `EntityExtensions`。
- **Excel 读写**：**NPOI**（无需安装 Excel，MIT/Apache，**注意按项目规则核对是否传递引用 AutoCAD 宿主程序集，必要时 `<ExcludeAssets>runtime</ExcludeAssets>`**）。备选 Open XML SDK。
- **持久化**：表样式模板存入 `SettingsPanelViewModel` 体系。
- **许可证核对**：NPOI(Apache-2.0)/NetCad(MIT)/Linq2Acad(MIT) 均可商用，自用无忧。

### ③ 架构概要（分层，遵循项目 Domain→Infra→Presentation）

- **Domain**（平台无关）：`TableModel`（行列/单元格/合并/对齐/样式），样式统一规则、Excel↔Model 映射、图形取数统计算法（纯逻辑）。
- **Infrastructure**（AutoCAD 侧）：`TableWriter`（Model→原生 Table 实体，含中文大字体/Φ 替换）、`TableReader`（选中 Table→Model）、`ExcelIO`（NPOI 读写）、选择集统计封装。
- **Presentation**：WPF 表格编辑面板（PaletteSet/Blender 主题）+ `ShowPanelCommand` 入口 + `TestCommand` 联调钩子，命令走 `commands.json` 注册。
- **关键风险点**：PaletteSet 宿主下 WPF 资源字典/主题坑（见项目 skill）；NPOI 依赖复制进 bin\Debug 的宿主程序集冲突；大表写图的事务/锁文档处理。

### ④ 路线图（最痛功能先做）

| 里程碑 | 交付物 | 验收点 |
|---|---|---|
| **MVP** | 面板网格编辑 → 生成原生表 + 样式一键统一 + 2 个模板 | 建 10×6 表 ≤3 步；中文零问号；编辑 300 格不卡 |
| **V1** | Excel/CSV 导入导出 + 选中表回拉编辑 + 图形选实体统计填表 | Excel 往返不丢格式；从图统计数量/长度入表正确 |
| **V2** | 假表转真表 + 公式小计 + 相对路径联动更新 | 旧图假表一键规整；源改表更新不丢链 |

### ⑤ 风险与对策

| 风险 | 类型 | 影响 | 对策 |
|---|---|---|---|
| NPOI 等依赖把旧版 AutoCAD 宿主 dll 复制进 bin\Debug | 依赖 | Badge/双载入崩溃 | 按项目规则加 `<ExcludeAssets>runtime</ExcludeAssets>`，核对传递引用 |
| PaletteSet 宿主 WPF 资源/主题崩 | 技术 | 面板打不开 | 遵循 `wpf-paletteset-resource-pitfalls` skill，仅局部 merge 主题 |
| 大表写图性能/事务异常 | 技术 | 卡顿/写图失败 | 内存编辑+一次性 GenerateLayout 写图；分片处理超大表 |
| 自研网格编辑体验不及 Excel | 市场/体验 | 用户仍回 Excel | 先做可点击原型验证关键交互（Tab/批量/合并） |

### ⑥ 假设验证（最危险假设排最前）

1. **最危险假设**：自研 WPF 网格能否给出"接近 Excel"的编辑手感且不卡 → 先做**可交互原型**（仅网格+生成表），让本团队试用打分，再决定是否投入完整开发。
2. 图形取数统计是否真省时 → 拿一张真实材料表跑端到端对比计时。
3. NPOI 在 AutoCAD 进程内稳定读写 → 早期做技术 PoC。

## 5. 结论

- **做什么**：做一个 **CAD 内嵌的"类 Excel 表格编辑面板"**，融入 HyCADTool 体系；不做又一个 Excel 导入器。
- **靠什么差异化**：①原地顺手编辑（避开原生 Table 性能/字体坑）②从图直接取数联动 ③自用可定制、与既有命令/样式深度集成。
- **第一步先做**：WPF 网格编辑面板原型 + 生成原生表 + 样式一键统一（含中文大字体/Φ 替换），先让团队试用验证"手感"这个最危险假设，再按 V1/V2 扩展。
- **工作方式范式决策**（面板式 vs 画布命令式）：见 [017 对比调研](./017-表格制作工作方式对比-产品调研-2026-06-25-220420.md)——**主范式 = 面板 Excel 式（方式 A）**。
