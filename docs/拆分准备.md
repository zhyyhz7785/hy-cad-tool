# 拆分准备

单仓库先按 7 个模块画界：画图动作留在 base，有限元、设计说明、图纸交换各自独立；本阶段不移动目录、不新建仓库。**已验证**（对照 `src/HyCADTool/Modules/*/commands.json`、命名空间与 `whitelist-module-deps.txt`）。

下文模块名：base（底座，公共宿主与画图）、road（道路）、sponge-city（海绵城市）、structure（结构）、fea（finite element analysis，有限元分析）、design-spec（设计说明）、hyob（图纸交换）。fea 是独立求解内核加 CAD 面板，不是画图命令的一部分。

## 2. 剩余跨模块依赖

循环已拆。下面是单向剩余，白名单在 `src/HyCADTool.LinuxTests/Architecture/whitelist-module-deps.txt`，只减不增（硬编码上限，禁止加行）。粒度是「文件 × (from→to)」，同一文件再多几个跨模块类型不会抬计数。**已验证**。

Tables→SpongeCity 已消除（`OpenXmlSheetHelper` 下沉 Shared）。

Features→Shell 的 C# 直连已清零；横断出图两处 XAML 的 `clr-namespace:HyCADTool.Shell` 已改到 `Features.Road.CrossSection.Behaviors`，架构扫描会拦 Features/Shared 里再写 Shell xmlns。

Features→`App.Bootstrap`（约 77 处 `ServiceLocator`）仍允许：架构测试把 App 标成 host，不算模块互依。拆仓后业务仓还会碰到 ServiceLocator 具体实现，下一阶段收成 CadHost 工厂。**待消**。

shared（公共代码）→ road：`Shared/AutoCAD/Services/Road/*`、`RoadGeometryBridge`、两个 LayerKind 画刷转换器。这些文件名字就带 Road，拆仓时应整夹进 road，不要留在 base。

shared → structure：`ElevationSymbolJig`、`PolygonAdapter`、`ExtensionDictionaryService`、`HyComponentXdata`。标高夹具和构件 Xdata（扩展字典里的业务标记）仍调 Features 类型。

base 画图 → design-spec：`Features/Export/DesignSpec*.cs` 与 `HymdCad*.cs`。命令清单已登记在 design-spec，源文件命名空间还是 Export。

structure → design-spec：`SettlementPanelViewModel` 引用 `DesignSpec.Domain` 的 `MarkdownTableParser` 做报告表解析。Settlement 应改为只依赖 Shared 的 `SoilLayer` 与本模块报告生成器。

host（Shell/App）组合各业务模块是允许的：设置面板、Ribbon、Autofac 注册在拆仓后由 base 用模块注册接口装载，不算违规。

## 3. Directory.Packages.props

Directory.Packages.props 是中央包版本管理（Central Package Management，把 NuGet 版本写在仓库根、各 csproj 只写包名）文件，用来避免同一包在多个项目里各写各的版本。

**建议**：单仓库继续共用根上这一份。拆成 7 个仓库之后，每个仓库自带一份，先复制当前版本，再各自演进。**建议**。

理由：现在 Newtonsoft.Json 13.0.3、AutoCAD.NET 24.3.0、xunit 2.9.2 已经对齐；共用能挡住漂移。拆仓后 road 不该被 fea 的 CSparse 升级拖着走，fea 也不该被 WPF 包拖着走。公共包（Newtonsoft、xunit、System.Text.Json）在各仓 props 里先锁同一版本，升级时按仓单独 PR。

不要在拆仓当天改用“各模块立刻不同版本”——那会让 LinuxTests / HYFEA.Tests 的对测失去基线。
