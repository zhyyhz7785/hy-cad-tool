## 几何内核决策分析

你的项目当前已经有一套相当完整的几何体系，我先梳理现状，再给出三个选项的利弊。

------

### 当前项目几何现状

Domain 层（平台无关）： 已有 Point2D/3D、Vector2D/3D、Line2D、Circle2D、Arc2D、Polygon2D、Polyline2D、BoundingBox 等基础类型，以及 ConvexHull、Intersection、PolygonOffset、PolygonBoolean、Voronoi 等算法服务。

已引入的外部库：

- Clipper2 v1.4.0 — 用于高性能多边形布尔/偏移

- NetTopologySuite v2.5.0 — 用于 Voronoi 图、Delaunay 三角剖分

Infrastructure 层： 有完整的 Domain ↔ AutoCAD 双向转换器（GeometryConverter），布尔/偏移的实际实现委托给 Clipper2。

------

### 三个选项对比

|              | 选项A：自建几何内核                      | 选项B：继续用外部库组合                                      | 选项C：切换到单一大库 (如 CGALDotNet)      |
| :----------- | :--------------------------------------- | :----------------------------------------------------------- | :----------------------------------------- |
| 你已有的基础 | 基础类型已齐全，算法层框架已搭好         | 已在用 NTS + Clipper2，架构成熟                              | 需要重写 Infrastructure 适配层             |
| 维护成本     | 高：每个算法要自己写/调/验证健壮性       | 低：核心算法由成熟库提供                                     | 中：依赖单一大库，受其更新/License 制约    |
| 性能         | 可针对场景深度优化                       | NTS 中等，Clipper2 极快                                      | CGAL 算法层面最优，但有 native 调用开销    |
| 健壮性       | 边界情况需要大量测试（退化、共线、容差） | NTS/Clipper2 经过产线验证                                    | CGAL 业界最健壮                            |
| 跨平台迁移   | 完全可控，无外部依赖                     | NTS/Clipper2 均为纯 C#，跨平台无障碍                         | GPL-3 license + native DLL，Blender 侧复杂 |
| License      | 无风险                                   | BSD-3 + BSL-1.0，无风险                                      | GPL-3，商业使用有风险                      |

------

### 关于 Blender 的几何能力

- BMesh：Blender 自有的网格内核（非流形 B-rep），仅在 Blender 内可用，无法独立使用

- mathutils：可通过 pip install mathutils 独立安装，提供 Vector/Matrix/基础几何运算，GPLv2+

- mathutils.geometry：射线-三角、线-线交点等基础函数

- Geometry Nodes：与 Blender 的 depsgraph 深度耦合，无法独立使用

- Manifold：独立的 C++ 库（Apache-2.0），专做 mesh boolean，有 Python 绑定

- 结论：Blender 没有可直接复用的独立几何库，迁移时需要在 Python 侧重建 Infrastructure 层

------

### 建议：选项 B（继续当前组合策略）

理由：

1. 你的 Domain 层已经做对了 — 基础几何类型（Point2D、Polygon2D 等）是自建的纯值对象，算法接口（IGeometryService、IPolygonOffsetService）通过接口抽象，实际实现在 Infrastructure 层委托给 Clipper2/NTS。这正是最佳架构。

1. 没有必要自建底层算法 — 多边形布尔运算、Voronoi、Delaunay 这些算法的健壮实现（处理退化、容差、自相交）需要数年的打磨。Clipper2 和 NTS 已经是产线级别。

1. 跨平台迁移路径清晰 — 迁移到 Blender 时：

- Domain 层：Point2D/Polygon2D 等值对象 → Python dataclass 1:1 对应

- Infrastructure 层：Clipper2 → pyclipper (Python 绑定)，NTS Voronoi → scipy.spatial.Voronoi

- 只需重写 Infrastructure 层的适配器，Domain 层逻辑不变

1. 补强方向 — 如果未来需要更多算法（如 straight skeleton、constrained Delaunay），优先看 NTS 是否已支持，其次考虑引入单一功能小库，而非自己写。

一句话总结：自建几何类型 + 外部库做算法引擎 + 接口隔离，是你当前架构已经在走的路线，也是最务实的选择。不需要重建内核，也不需要换大库。
