## 一、问题清单（已通读源码确认）

### A. ByLayer / ByBlock 真实属性判定（4 个真 Bug）

| 编号 | 位置 | 现象 | 根因 |
|---|---|---|---|
| **A1 颜色跨体系误判** | `Filters/ColorFilter.Apply` 直接 `color.ColorValue == targetColor.ColorValue` | ACI 索引 1（红）≠ TrueColor RGB(255,0,0)，互判不等 | AutoCAD 颜色三套体系（`ColorMethod.ByAci` / `ByColor` / `ByLayer/ByBlock`）`ColorValue` 内部表示不一致，必须先按 `ColorMethod` 分桶再比 |
| **A2 ByBlock 永远走不到** | `FilterExtensions.GetTrueColor` / `GetTrueLineWeight` / `GetTrueLinetype` / `GetTrueTransparency` 仅在 `ent is BlockReference && ent.Color.IsByBlock` 才返 `br.Color` | BlockRef 在 ModelSpace 不可能是 ByBlock，分支永远 dead | 真正的 ByBlock 场景在**块内嵌套实体**——`BlockTableRecord` 内的 entity 颜色 ByBlock 时应该向外继承所在 BlockRef 的颜色。当前实现完全没考虑块内→外层 BlockRef→layer 的多层溯源 |
| **A3 线宽筛选用 SelectionFilter 注定失败** | `Filters/LineWeightFilter.Apply` 把 ByLayer 解出来的真实线宽（如 50）当 `TypedValue((int)DxfCode.LineWeight, 50)` | DXF code 70 在 ByLayer 实体里存的是 `-1`，filter 比 50 永不匹配，**ByLayer 同伴一个都筛不到** | SelectionFilter 不会自动解 ByLayer，必须改全实体迭代 |
| **A4 透明度同 A3** | `Filters/TransparencyFilter` 走 transaction 迭代，但比较 `int alpha` 时没区分 `IsByAlpha / IsByLayer / IsByBlock` 三种 | 跨体系判等错误 | 同 A1 思路：先按 `TransparencyMethod` 分桶 |

### B. 属性值过滤器（6 处不足）

| 编号 | 位置 | 不足 |
|---|---|---|
| **B1 元数据硬编码 270 行** | `FilterablePropertyMetadataProvider.GetMetadataList()` | 新增类型要手写几十条；没覆盖 XData / Dictionary / 块属性参照 (Attribute) |
| **B2 操作符固定 6 个不分类型** | `FilterPanelViewModel.Operators = { "==","!=", ">","<", ">=","<=" }` | 字符串属性给 `>` `<` 无意义；缺 `contains` / `startsWith` / `endsWith` / `regex` / `between` / `in` / `isNull` |
| **B3 表达式解析脆弱** | `FilterPanelViewModel.SelectWithFilters` 用 `exp.Split(' ')` 三段切 | 字符串值带空格、中文、引号、转义全部崩；如 `TextStyleName == "黑体 标准"` 解析后变 4 段 |
| **B4 不支持 OR / NOT / 括号** | 多条件全部 `Intersect` | 无法表达 `(图层 == "A" AND 半径 < 100) OR 颜色 == 红` |
| **B5 Point3d 列出来不可用** | `FilterExtensions.GetFilterableProperties` 仅接受 `int / double` | 元数据里 Point3d 全部点了无效；Point3d 应拆 X/Y/Z 三轴 |
| **B6 不能保存命名过滤器** | 无持久化 | AutoCAD FILTER 命令的 .nfl 都有；常用过滤器复用为 0 |

### C. 架构耦合

| 编号 | 现象 | 影响 |
|---|---|---|
| **C1 两套 Filter 体系** | `FilterExtensions`（静态扩展，VM 用）+ `FilterManagerService` + `Filters/*`（已注册 Autofac，**0 引用**） | 死代码 6 个类 |
| **C2 ByLayer 解析 4 处重复** | `FilterExtensions.GetTrueColor / GetTrueLineWeight / GetTrueLinetype / GetTrueTransparency` 与 `Filters/ColorFilter.GetTrueColor` 等 4 个类内部各写一遍 | 改一个忘三个 |
| **C3 没有"类型族"概念** | 选 1 个 Polyline 只能筛所有 Polyline | 业内（Civil3D / Bricscad）支持"曲线类"族（Line + Arc + Polyline + Spline + Ellipse） |

## 三、升级方案（三阶段，逐阶段编译）

### 阶段 M1：核心 Bug 修复 + 架构清零（1-2 天）

**目标**：用户立刻能用对的"按 ByLayer 真实颜色 / 真实线宽选择"

**任务清单**：

1. 新建 `Shared/AutoCAD/Entities/EntityAppearanceResolver`（**单一 Domain Service**）：
   - 一处实现：颜色 / 线宽 / 线型 / 透明度 4 个属性的 ByLayer / ByBlock / ByColor 三层溯源
   - **颜色比较算法**：先按 `ColorMethod` 分桶（ByAci / ByColor / ByPenIndex），同桶才比 ColorIndex / RGB
   - **块内嵌套 ByBlock 溯源**：`ent → 所在 BlockTableRecord → 所有 BlockReference → 取 BlockRef 颜色`（多重引用时取第一个的颜色，UI 给出提示）
   - **图层冻结 / 锁定不影响真实属性**（仅影响选择能力，独立处理）

2. 删除死代码：
   - `Shared/AutoCAD/Selection/FilterManagerService.cs`
   - `Shared/AutoCAD/Selection/Filters/IEntityFilter.cs`
   - `Shared/AutoCAD/Selection/Filters/ColorFilter.cs` 等 6 个 Filter 类
   - `AutofacModule` 内对 `IFilterManagerService` 的注册（确认 grep 无引用）

3. 改写 `FilterExtensions`：
   - 删 `GetTrueColor / GetTrueLineWeight / GetTrueLinetype / GetTrueTransparency`
   - 删 `FilterByColor / FilterByLineWeight / FilterByLinetype / FilterByTransparency`
   - 全员转调 `EntityAppearanceResolver`
   - **线宽 / 透明度筛选放弃 SelectionFilter**（DXF code 70 走不通 ByLayer），改为 `FilterEntitiesBy(predicate, ids)` 全实体迭代
   - **类型 / 图层 / 显式颜色保留 SelectionFilter**（性能 100x）

4. `FilterPanelViewModel.GetColorFilteredIds / GetLineWeightFilteredIds / GetLineTypeFilteredIds / GetTransparencyFilteredIds` 全部转调 `EntityAppearanceResolver`

**验收用例**：

- 样图画 5 条 Line，所在图层颜色 = 红，Line 自身颜色 = ByLayer。选 1 条 → 勾"颜色"过滤器 → 应选中全部 5 条
- 同上，图层线宽 = 0.5mm → 勾"线宽"过滤器 → 应选中 5 条
- 块内 entity 颜色 = ByBlock + 块本体颜色 = 蓝 → 选块内某 entity → 勾"颜色" → 同色块全选
- 旋转 ACI 索引 1（红）和 RGB(255,0,0) 同时存在的图层，选索引 1 红 → 不应误选 RGB 红

### 阶段 M2：属性值过滤器升级（2-3 天）

**目标**：从"垃圾文本拼接"升级到"业内标配的可视化条件构建器"

**任务清单**：

1. 新建 `Shared/AutoCAD/Metadata/EntityPropertyDescriptorService`：
   - 反射 `Entity.GetType().GetProperties()`，过滤可读 + 简单类型 + 加可本地化 DisplayName
   - **Point3d 自动拆 X / Y / Z 三轴**
   - 过滤 ObjectId / 内部 Handle 等无意义字段
   - 第一次反射后缓存到 `ConcurrentDictionary<Type, IReadOnlyList<PropertyDescriptor>>`，进程级
   - 旧 `FilterablePropertyMetadataProvider` 退化为"中文 DisplayName 字典"（保留 270 行的中文映射），元数据来源换成反射

2. 属性类型分类 + 操作符按类型联动：
   - `Numeric`：`==` `!=` `>` `<` `>=` `<=` `between`
   - `String`：`==` `!=` `contains` `startsWith` `endsWith` `regex` `in (a,b,c)`
   - `Boolean`：`is true` / `is false`
   - `Point3d`：拆 X / Y / Z 后走 Numeric
   - `ObjectId`：`==` `!=`（用于关联实体如 LinetypeId、BlockTableRecordId）
   - UI 端 ComboBox 根据选中属性类型动态切换可选操作符

3. 引入 `DynamicExpresso.Core` 表达式引擎：
   - csproj 加 NuGet 包（不传递 AutoCAD 宿主程序集，无需 `<ExcludeAssets>runtime</ExcludeAssets>`）
   - 替换 `FilterEntitiesByExpression` 与 `Compare<T>`：拼接成 `e.Radius >= 100 && e.Layer == "0-road-edge"` 形式交给 `Interpreter.Eval`
   - 字符串值带空格 / 引号 / 转义 / 优先级全部交给引擎

4. 复合条件树：
   - Domain 加 `FilterCondition` / `FilterConditionGroup`（含 `LogicalOperator: And / Or / Not`）
   - UI 加"分组"按钮，可视化构建 `(A and B) or (not C)`
   - 内部转换为 DynamicExpresso 表达式

5. 过滤器命名保存：
   - 新建 `Shared/Settings/FilterPresetService`
   - 序列化为 JSON，存到 `%AppData%/HyCAD/filter-presets.json`（与 `hy-settings.json` 同套机制）
   - UI 加"保存为预设" / "加载预设"下拉

**验收用例**：

- 选 1 个 Polyline → 在属性值过滤器输入 `Length between 100 200 and Layer == "0-road-edge"` → 一键筛
- 表达式 `TextStyleName contains "黑体"` 能筛出所有黑体文字
- 表达式 `TextString regex "^说明.*"` 能筛出所有以"说明"开头的文字
- 表达式 `Radius in (100, 200, 300)` 能筛出 3 个特定半径的圆
- 保存预设"主干道边线"，下次打开直接加载

## 六、关键技术决策

1. **DynamicExpresso vs LINQ Dynamic Core**：选 **DynamicExpresso**（更轻、文档好、支持本地化语法、活跃维护）
2. **是否走 SelectionFilter / 是否全实体迭代**：
   - 类型 / 图层 / 显式颜色 → SelectionFilter（性能 100x）
   - ByLayer 真实颜色 / 线宽 / 线型 / 透明度 → 必须全实体迭代（无办法）
   - 折中策略：先 SelectionFilter 缩范围（"图层 == X"），再全实体迭代细筛
3. **属性元数据反射缓存策略**：按 Type 缓存到 `ConcurrentDictionary<Type, IReadOnlyList<PropertyDescriptor>>`，进程级
4. **预设文件格式**：JSON（System.Text.Json，与 `hy-settings.json` 一致）
5. **DI 注册**：3 个新 Service 全部走 Autofac 单例（无状态 / 缓存级）
