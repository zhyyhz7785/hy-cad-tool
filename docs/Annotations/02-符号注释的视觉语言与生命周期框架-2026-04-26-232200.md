## 1. 重新定义问题：注释为什么必须存在

客观世界由「**形状 + 物质 + 状态 + 行为 + 关系**」构成。计算机能精确记录前两者（几何 + 物理量），但人脑无法直接消化原始数据——

- 一份 1 GB 的点云
- 一组 100 万个有限元单元
- 一份 80 字段的 IFC 属性集
- 一张满是构件的施工图

对工程师都没有任何意义，**除非有人帮他翻译**。注释，就是这种翻译。

注释不是装饰，而是从「**数据**」到「**意图**」的语义信道。世界上不存在没有注释的工程交付物。

---

## 2. 三层本体：物理 / 几何 / 表达

| 层级 | 例子 | 计算机表达 | 人类感知 |
|---|---|---|---|
| 物理层 | 一根钢筋：⌀14、HRB400、抗拉强度 540 MPa | 数值 + 单位 + 标准代号 | 不可视，需读出 |
| 几何层 | 它在三维空间中是一段折线 | 点列 + 线宽 + 图层 | 可见但不可懂 |
| 表达层 | 标注「上排负筋 ⌀14@200」 | 引线 + 文字 + 编号 | 可懂、可决策、可施工 |

注释的作用：**把不可视的物理层和不可懂的几何层，翻译成可决策的表达层**。

---

## 3. 符号学的三元结构（C.S. Peirce）

任何符号都包含三层（注释也是符号）：

| 维度 | 名称 | 在工程图中的对应 |
|---|---|---|
| 能指 (Sign) | 图形本身 | 一个三角形、一个箭头、一段文字 |
| 所指 (Object) | 被指代的真实对象 | 某根钢筋、某个标高、某条焊缝 |
| 解释项 (Interpretant) | 阅读者头脑中的理解 | "这是 ⌀14 钢筋，间距 200" |

工程注释的核心问题不是画得漂亮，而是 **三条对应关系不丢失**：

- 能指 → 所指：靠 **Anchor（锚定）**
- 能指 → 解释项：靠 **Style + 标准代号**
- 所指 → 解释项：靠 **Property（属性）**

任何一根线断了，注释就废了。

## 4. 三类符号：Icon / Index / Symbol（重要！）

| 类型 | 特征 | 工程图实例 | 实现机制 |
|---|---|---|---|
| **图像 Icon** | 形似——直接复刻外形 | 构件投影、剖面图、轴测图 | 纯几何复制，无需绑定 |
| **索引 Index** | 关联——通过物理或因果指向 | 引线、剖切箭头、详图索引、标高引线 | **必须维持源-靶绑定（Anchor）**，源动靶动 |
| **象征 Symbol** | 约定——纯靠标准与规则约定 | 焊缝符号、粗糙度符号、地形等高线、电气符号 | **必须可参数化、可标准化**（ISO/GB 编码） |

**关键洞察**：HyCADTool 的符号库不能只支持「画图块」（Icon），还要分别支持 Index 和 Symbol。这三类符号的实现机制完全不同，**绝不能用同一种 Block 抽象套全部**。

## 5. 视觉语言的法则

注释为什么"看得懂"？因为它遵守了三套法则。

### 5.1 Gestalt 心理学（人为什么"自动分组"）

| 法则 | 工程图应用 |
|---|---|
| 接近律 | 注释靠近被注释对象 |
| 相似律 | 同类构件用同色编号 |
| 闭合律 | 剖面线、详图边界 |
| 连续律 | 引线、尺寸界线 |
| 共同命运律 | 注释比例随视图缩放 |

### 5.2 Tufte 信息可视化原则

- **数据-墨水比最大化**：删掉一切不传递信息的"墨水"
- **避免 Chartjunk**：花哨的渐变、阴影、3D 边框是负担
- **小型化重复（Small Multiples）**：同类信息用相同模板，让差异自动凸显
- **直接标注 > 图例**：能在对象旁标注的不要丢到图例

### 5.3 工程制图传统：视觉重量层级（VISIBLE LINEWORK HIERARCHY）

| 级别 | 线宽 | 用途 |
|---|---|---|
| 粗线（0.50–1.00 mm） | 主轮廓、剖切轮廓 | 第一眼焦点 |
| 中线（0.25–0.35 mm） | 次要轮廓、可见线 | 形状信息 |
| 细线（0.13–0.18 mm） | 尺寸、引线、剖面线、辅助线 | 注释信息 |
| 虚线 | 不可见轮廓 | 隐藏信息 |
| 点划线 | 中心线、对称线、轴线 | 几何参考 |

**铁律**：注释永远不能比主轮廓更"重"。HyCADTool 的注释样式必须严格遵守。

## 6. 跨建模软件的"符号原子"对比（01 没碰的层级）

01 给了**软件族**对比，本节细化到**符号原子**——即"尺寸的界线/尺寸线/数值"这种最小语义单元。

### 6.1 尺寸标注三要素

| 软件 | 界线 (Witness) | 尺寸线 (Dimension) | 数值 (Text) | 是否参数化 |
|---|---|---|---|---|
| AutoCAD | 显式实线 + 偏移 | 端部带箭头 | DimStyle 控制 | 关联标注（半参数） |
| Revit | 视图驱动，自动锚定 | 同 | 类型属性 | 全参数 |
| SolidWorks | 草图驱动，双向参数 | 自动整理 | 链接到尺寸表达式 | **驱动式**（改尺寸即改几何） |
| Tekla | 自动生成，按规则批量 | 智能避让 | 自动取构件长度 | 全参数 |
| NX/CATIA | 同上 + GD&T | 同 | 链接到 PMI | 全参数 |
| Blender / Maya | **无原生尺寸概念** | - | - | - |
| ArcGIS | 比例尺 / 坐标格网代替 | - | - | - |

> **洞察**：尺寸标注只在「工程交付」语境下存在，纯视觉建模软件没有。HyCADTool 是工程软件，尺寸是核心；但要注意 SolidWorks 那种「**驱动式尺寸**」（改尺寸即改几何）目前还没碰过。

### 6.2 编号 / 引线 / 标签

| 软件 | 编号 | 引线 | 来源 |
|---|---|---|---|
| AutoCAD | 圆 + 文字块 | 多重引线 MLEADER | 用户手敲 |
| Revit | 详图气泡（视图驱动） | Tag with Leader | **从对象属性自动派生** |
| Tekla | 构件位号自动 | 智能引线 | **从构件 GUID 派生** |
| SolidWorks | 装配球（Balloon） | 注解引线 | **从 BOM 派生** |
| Unreal | Actor 名 + Outline | 调试 Gizmo | 运行时自动 |
| ArcGIS | 标注（Label）按字段 | 引出线 | **按属性字段** |

> **洞察**：现代软件中"编号"几乎都是**从属性自动派生**。HyCADTool 当前还是用户手敲为主，应优先做属性派生编号。

### 6.3 公差与基准（GD&T / PMI）

| 软件 | 公差 | 基准 | 标准支持 |
|---|---|---|---|
| AutoCAD | TOLERANCE 命令（弱） | 无原生 | ASME Y14.5 |
| SolidWorks | DimXpert/MBD（强） | 完整 | ISO 1101 + ASME Y14.5 |
| NX | PMI 模块（强） | 完整 | STEP AP242 |
| CATIA | FTA 模块（强） | 完整 | ASME Y14.41 |
| Revit / Tekla | **不支持** | - | - |

> **洞察**：建筑/结构 BIM 不做 GD&T，机械 CAD 必须做。HyCADTool 偏工程制图，**当前阶段不做 GD&T**，但数据模型应预留 `ToleranceFrame`、`DatumReference` 等字段。

### 6.4 物理符号（载荷 / 约束 / 流向 / 温度）

| 软件 | 载荷箭头 | 约束符号 | 结果云图 | 物理量标签 |
|---|---|---|---|---|
| AutoCAD | 无原生 | 无 | 无 | 无 |
| ANSYS / Abaqus | 自动彩色箭头 | 三角支座 / 铰 | 等高线 / 云图 | 探针 |
| ArcGIS | 流向箭头 | - | 分级渲染 | 字段标签 |
| HyCAD（建议） | 沉降箭头、地基反力 | 桩底铰、嵌固端 | 应力云图 | 沉降值 / 反力值 |

> **洞察**：HyCADTool 已经做沉降、筏板、地脚螺栓，物理量符号是**差异化机会**，但当前都是 ad-hoc 实现。需要统一抽象到 `PhysicalSymbol` 层。

### 6.5 表格与清单

| 软件 | 表格类型 | 数据来源 | 双向同步 |
|---|---|---|---|
| AutoCAD | TABLE | 字段（FIELD）或手填 | 半同步（字段单向） |
| Revit | 明细表 (Schedule) | 视图筛选 + 构件属性 | **全双向** |
| Tekla | 报告 (Report) | 构件 + 模板 | 单向（重新生成） |
| SolidWorks | BOM | 装配树 | 全双向 |
| ArcGIS | 属性表 | Feature Class | 全双向 |
| HyCAD（现状） | 直接 Table 实体 | 命令内部 ad-hoc | **不同步** |

> **洞察**：HyCADTool 的表格生成都是「一次性绘制」，没有任何同步机制。这是 L4 变更感知的缺口（见第 9 节）。

## 7. 2D 与 3D 注释的渲染管线差异

### 7.1 2D 注释（屏幕 = 纸面）

```
模型空间几何 → 视口变换 → 屏幕像素
注释跟随：     ✓        ✓
```

2D 注释的难点只有一个：**比例**。1:100 视图和 1:50 视图里，注释要保持纸面字高一致，所以注释自身得带「反向缩放因子」——这就是 AutoCAD 的 DIMSCALE / 注释比例机制。

### 7.2 3D 注释（屏幕 ≠ 纸面）

```
模型空间几何 → 透视投影 → 屏幕像素
                    ↓
注释面临选择：
  (a) 跟随对象旋转       → 在某些视角下背对相机不可读
  (b) Billboard 始终面向相机 → 失去空间感
  (c) 投影到屏幕空间锚点  → 失去深度
  (d) 半透明 + 深度排序   → 复杂度高
```

### 7.3 3D 注释的关键决策矩阵

| 维度 | 选项 A | 选项 B | 推荐 |
|---|---|---|---|
| 朝向 | 跟随对象法线 | 始终面向相机 | **混合**：标签 Billboard，尺寸跟随 |
| 缩放 | 模型空间固定（mm） | 屏幕空间固定（px） | **混合**：数值屏幕固定，引线模型固定 |
| 遮挡 | 参与深度测试 | 始终绘制在最前 | **可切换**：默认参与，用户可强制 |
| LOD | 远处不显示 | 远处缩小但不消失 | **按密度**：注释密集时远处自动隐藏 |
| 避让 | 不避让（重叠） | 自动错开 | **力导向布局**（参考 ArcGIS Maplex） |

### 7.4 HyCADTool 的现状（2026-02）

当前 HyCADTool 仍是**纯 2D AutoCAD 软件**，3D 注释**尚未涉及**。本框架为未来 3D 模块（如三维管廊、三维基础、BIM 协同）预留接口。

## 8. 注释的生命周期（Aggregate Root 视角）

```
[创建] → [活跃] → [脏 Dirty] → [校核] → [冲突] → [归档/失效]
   ↑                  ↓             ↓           ↓
   |   对象变更触发     |             |       注释指向的对象删除
   |                   |             |       
   └───────────────────┴─────────────┘
           手动编辑 / 规则重生成
```

| 阶段 | 触发 | 系统行为 |
|---|---|---|
| 创建 | 用户拾取 / 规则生成 | 写 XData，注册 Anchor |
| 活跃 | - | 渲染、参与打印 |
| 脏 | 目标对象 Modified 事件 | 标红 / 打问号，等待用户处理 |
| 校核 | 用户运行校核命令 | 标准核对、单位核对、冲突检测 |
| 冲突 | 多注释指向同一区域且语义矛盾 | 高亮、列入冲突报告 |
| 归档 | 图纸出版 | 锁定、版本号 |
| 失效 | 目标对象 Erased | 注释变孤儿，提示删除 / 重锚 |

**核心要求**：注释必须能**响应目标对象的变化**，不能"画完就脱钩"。AutoCAD 的关联标注（Associative Dimension）和 XData 持久化机制是基础，但还不够——需要在 Domain 层显式建模 Dirty 状态。

## 9. 注释自动化的 L0–L5 等级（参照自动驾驶概念）

| 等级 | 描述 | 用户工作量 | HyCAD 当前命令对照 |
|---|---|---|---|
| **L0 手动** | 完全手敲文字 | 100% | TEXT / MTEXT |
| **L1 模板** | 选择模板填空 | 70% | `DrawElevationCommand`（标高块） |
| **L2 拾取生成** | 拾取对象 → 自动生成 | 30% | `DimensionForReinforcementCommand`（拾取钢筋自动尺寸） |
| **L3 规则驱动** | 一次定义规则 → 全图批量 | 10% | **HyCAD 缺失** |
| **L4 变更感知** | 对象变 → 注释自动同步 | 接近 0 | **HyCAD 缺失** |
| **L5 智能注释** | AI 阅读图纸，建议 / 补全 / 校核 | 监督 | **HyCAD 缺失** |

> **洞察**：HyCAD 当前主要在 L1–L2，未来重点是 **L3（规则驱动）** 和 **L4（变更感知）**。这两级都依赖第 8 节的生命周期机制。L3→L4 是**从工具到平台**的分水岭。

## 10. 注释引擎的工程接口（Domain 层契约）

### 10.1 六个核心接口（建议在 `Domain/Annotations` 下定义）

| 接口 | 职责 |
|---|---|
| `IAnnotationAnchor` | 锚定到点 / 边 / 面 / 对象 / 视图坐标，提供变换矩阵 |
| `ISymbolFactory` | 输入参数（标准代号 + 尺寸 + 文本）→ 输出符号几何 |
| `IAnnotationRule` | 触发条件 + 生成器 + 失效器 |
| `IAnnotationStyle` | 字体、颜色、线宽、箭头、缩放策略 |
| `IAnnotationStore` | 持久化、查询、增量更新、版本 |
| `IAnnotationRenderer` | Domain 模型 → AutoCAD Entity / WPF Visual / SVG |

### 10.2 接口分层

```
Presentation：命令、面板、拾取交互
   ↓
Application：CreateAnnotationService, ValidateService, BatchService
   ↓
Domain：IAnnotationAnchor, ISymbolFactory, IAnnotationRule, ...
   ↓
Infrastructure：AutoCAD XData/Entity 转换, JSON 序列化, IFC 映射
```

### 10.3 一个具体的契约示例

```csharp
public interface IAnnotationAnchor
{
    AnchorKind Kind { get; }
    string TargetId { get; }
    Matrix3d TransformAt(ViewContext ctx);
    bool IsValid();
    event EventHandler Dirty;
}

public interface IAnnotationRule
{
    string RuleCode { get; }
    bool ShouldTrigger(AnnotationEvent e);
    IEnumerable<AnnotationEntity> Generate(IEnumerable<DrawingObject> targets);
    bool ShouldInvalidate(AnnotationEntity ann, AnnotationEvent e);
}
```

## 13. 数据持久化策略

| 信息 | 存储位置 | 理由 |
|---|---|---|
| 注释几何 | DWG Entity（Text/Mleader/Block） | 兼容 AutoCAD 原生工具链 |
| 锚定关系 | XData（每个 Anchor 写 TargetObjectId） | AutoCAD 原生持久化 |
| 注释语义（标准代号、单位、规则 ID） | XData 字典 + 项目级 JSON 镜像 | XData 用于绑定、JSON 用于查询 / 校审 |
| 样式 | DimStyle / TextStyle / Block + `SettingsPanelViewModel` | 复用 AutoCAD 原生样式系统 |
| 规则定义 | 项目级 JSON | 可版本化、可分享 |
| 失效 / 脏标记 | 临时（不持久化），靠 Modified 事件触发 | 避免 DWG 膨胀 |

## 15. 关键设计原则（与 01 不重复）

1. **三类符号需要三种实现机制**——Icon / Index / Symbol 不能用同一个 Block 抽象。
2. **视觉重量层级是底线**——注释永远不能比主轮廓粗。
3. **属性派生编号 > 手动编号**——能从对象属性算的不要让用户敲。
4. **L3 规则驱动是从工具到平台的分水岭**——HyCAD 当前在 L2，下一步重点突破 L3。
5. **3D 注释 ≠ 2D + 一维**——渲染管线、朝向、缩放、遮挡是全新问题。
6. **生命周期管理 > 一次性绘制**——Dirty / Validate / Archive / Stale 必须建模。
7. **接口先于实现**——先把 6 个 Domain 接口定下来，再让现有命令"对齐"。
8. **复用 AutoCAD 原生机制**（XData / DimStyle / Mleader）——不重复造轮子。
