# 08 - NewDDS 与 dds 命令对比：NewDDS 实施工作总结

> 本文与 06 / 07 互补：06 是诊断（What's wrong），07 是工单（What to build），**08 是验收（What was built）**。
> 老 `dds` / `ddss` 全程未动一个字符，作为金标对照保留；NewDDS 一系列命令（`ndds` / `nddss` / `nddsR` / `nddsT`）跑在 `Features/AcadDimension/` 新目录里。
> 文档面向后续维护者：让任何人能在 5 分钟内回答"NewDDS 比 dds 好在哪？为什么这么改？"

---

## 0. 一句话摘要

| 维度 | dds（老） | NewDDS（新） |
|---|---|---|
| **范式** | S1a 解析式直接派生 | **同为** S1a 解析式直接派生 |
| **架构** | 单 Service 1012 行，Domain / Infrastructure / Presentation 混层 | 5 层管线接口 + 9 个文件，Clean Architecture/DDD 落地 |
| **状态** | Service 持有 `_lineIntersectionsUpDown` / `_boundary` / `_step` 等字段，跨方法共享 | 无状态服务，所有运行态封进 `NewDdsContext` 上下文对象 |
| **稳健性** | bulge 段当直线、0 长度尺寸事后删除、固定步长 20 | bulge tessellate、0 长度根因消除、自适应步长检测 |
| **可观察** | 无中间产物、无 Q 评分 | `Phase X 链路`/`Source 分布`/`Q 诊断`/`几何诊断` 全链路打印 |
| **可回归** | 无（每次都得人眼比对 DWG） | 5 fixture 金标 + 7 字段 Snapshot + Comparer 浮点容差 |
| **回链** | 标注与源 Polyline 无任何关联 | XData 绑定 `SourcePolylineHandle + FeatureSignature + ConfigSnapshot` |
| **刷新** | 无 | `nddsR` 检测特征签名变化自动重生成 |

→ NewDDS **没有**改变范式（仍是 S1a），但把这条范式做"成"了：从一锅烩的脚本写法 → 可独立测试 / 可独立替换 / 可独立诊断的工程产品。

## 1. 范式定位：为什么仍是 S1a

引用 06 §5 / 07 §2：

| 范式 | 候选空间 | Q 角色 | 求解 |
|---|---|---|---|
| A 注释组合优化 | 离散有限 | 选择 | 贪心 / 退火 |
| B 模型布局优化 | 连续 ℝ² | 选择 | Lloyd 迭代 |
| **C 解析式直接派生 (S1a)** | **退化为单点** | **校核** | **几何特征 → 直接派生** |

NewDDS 严格守 S1a 三条铁律：
- 不引入候选枚举（每条标注由几何特征唯一确定）
- 不引入迭代收敛（一次性几何提取 → 派生 → 后处理）
- Quality 函数**只校核不选择**（Q 出问题只打 `Issues[]`，不会改写已经派生出来的标注）

→ 所有架构改造都在"S1a 实现质量"层面，不动算法范式定位。

## 2. 命令外观对比

| 项 | dds | NewDDS |
|---|---|---|
| 命令注册 | `dds`(单条) / `ddss`(批量) | `ndds`(单条) / `nddss`(批量) / `nddsR`(刷新) / `nddsT`(金标回归) |

## 3. 架构分层对比

### 3.1 dds（一锅烩）


## 4. 算法链路对比

### 4.1 dds：七步链路（06 §2 摘录）

```text
Polyline boundary
  ↓ ExplodePolyline + GetExtreme              [Step 1] 极值点
  ↓ GetAllSecantLinesHorizontal/Vertical      [Step 2] 双向割线扫描
  ↓ GetColumn(0) / GetColumn(cols-1)          [Step 3] 提取边界列
  ↓ SortLineSEPointForDim                     [Step 4] 起终点方向归一化
  ↓ GetDimensionPoints + CreateOutsideDim..   [Step 5] 外部派生（4 + 4 总）
  ↓ GetDimsByLines + CleanInsideDims          [Step 6] 内部派生 + 去重
  ↓ DeleteNearbyParallelDim → DimVsEqual..    [Step 7] 后处理
DWG Entity
```

### 4.2 NewDDS：Phase 化管线

```text
ObjectId polylineId
  ↓ Document.LockDocument + tr.StartTransaction              [Service 入口]
  ↓ AcadPolylineConverter.Convert (含 bulge tessellate)      [Infrastructure]
Polyline2D
  ↓ SweepLineFeatureExtractor.Extract                        [Phase 2]
BoundaryFeatures (HorizontalColumns / VerticalColumns)
  ↓ CompositeDimensionDeriver
  │   ├─ OutsideDimensionDeriver (含 CollapseSamePrimary)    [Phase 3a]
  │   └─ InsideDimensionDeriver                              [Phase 3b]
List<DerivedDimension> raw
  ↓ CompositeDimensionPostProcessor
  │   ├─ NearbyParallelMergePostProcessor                    [Phase 4-Merge]
  │   └─ EqualExtensionLengthPostProcessor                   [Phase 4-Equal]
List<DerivedDimension> clean
  ↓ FullQualityFunction.Evaluate                             [Phase 6]
QualityScoreCard (Cov/NoOv/InB/Con/Dir/Overall + Issues[])
  ↓ AcadDimensionRenderer.Render
  │   └─ ExtensionDictionaryService.Write(NewDdsDimensionBinding)  [Phase 5]
RotatedDimension[] + XData 回链
  ↓ NewDdsService.LogRun → 命令行打印
NewDdsRunOutcome
```

## 5. 稳健性改造逐项对比

### 5.1 Polyline bulge 段处理

| 维度 | dds | NewDDS |
|---|---|---|
| 处理方式 | 把 bulge 段当直线段处理（`ExplodePolyline` 直接拆为 `Line`） | `AcadPolylineConverter` 把 bulge 段按弧长 tessellate 成密集顶点 |
| 影响 | 弧形配筋区域的轮廓在割线扫描时丢失曲率特征，凸点不被识别 | 弧形顶点也参与拓扑变化检测，凸点完整 |

### 5.2 割线扫描步进策略

| 维度 | dds | NewDDS |
|---|---|---|
| 步长 | 硬编码 `_step = 20`（mm） | `Config.SweepStep` 默认 100，进 `NewDdsConfig`，按 bbox 自适应可调 |
| 推进规则 | `while countPri==countNext: y += _step`（拓扑不变就推进） | 同思路，但用 `HashSet<int>` 比对边索引集，能识别"边数没变但相交边换了"的隐性拓扑变化 |
| 兜底 | `safetyCounter < 1000` 死循环兜底 | 自适应迭代上限（按 bbox 高度 / step 估算），且 Context 记录"同拓扑跳过次数"用于诊断 |
| 求交 API | 同时使用 `Curve.IntersectWith` 与自家几何工具，技术债（06 §3.3） | 单一 `SegmentIntersectionService`（Domain 内纯 2D） |

### 5.3 0 长度标注

| 维度 | dds | NewDDS |
|---|---|---|
| 来源 | 同一组扫描点里有几乎相同 X（或 Y）的两个点投到同一边界，派生出 0 长度尺寸 | 同样会出现 |
| 处理 | 派生完后用 `DeleteDimensionZero` 暴力删（事后） | `OutsideDimensionDeriver.CollapseSamePrimary`：在派生**前**按主轴坐标差 < `CollapseTolerance=1mm` 归并相邻同主轴点（**根因消除**） |
| 用户原话 | "dds 老代码只是简单删除了" | "查找根本原因清除" |

### 5.4 平行近距合并

dds 的 `DeleteNearbyParallelDim`：
- 仅按 dim 行间距单一阈值合并
- 同时还会合并不同 Source 的尺寸（OutsideUp 和 OutsideTotalUp 也可能撞）

NewDDS 的 `NearbyParallelMergePostProcessor` 经历了多轮迭代（Phase 4 → Phase 4 修正）才稳定：

| 改进点 | 解决问题 |
|---|---|
| 按 `(Rotation, Source)` 分组而非全集合两两比对 | 分段尺寸不会与总尺寸误并 |
| `ParallelChainCoincidenceEpsilon = 1mm` 控制同链共线检测 | 同 dimLine 链内只看 ExtensionLine 重合，不看 dim 行间距 |
| 复合判据：**测量段重合** ∧ **见证轴坐标重合**（`SegmentMatchThreshold = 2mm`） | 远距同测量值（如两段相距 3m 但都是 1700 的凹槽）**不会**被误并 |
| 按 `MeasureSegment.Lo` 排序后再两两扫 | 合并次序稳定，结果可重现 |

→ 用户用例闭环：
- "为何 2 个 1700 都保留了？" → 真因是 `DimDistanceTolerance` 没覆盖到 1260mm 间距 → 加测量段重合判据
- "1700 距离已经很远，需要标注" → 反向修正：远距同测量不能合 → 增加见证轴判据

### 5.5 ExtensionLine 视觉对齐

| 维度 | dds | NewDDS |
|---|---|---|
| 实现 | `DimVsEqualLength`：把同侧尺寸的 ExtensionLine 端点拉到同一行/列 | `EqualExtensionLengthPostProcessor`：按 `(Rotation, dimLineKey)` 分组，把 ExtensionLine 末端投到组内最短长度 |
| 解耦 | 与具体方向硬编码混合 | 与方向无关，纯几何变换 |

## 6. 持久化绑定与刷新机制（NewDDS 独有）

### 6.1 dds：标注与源 Polyline 无关联

dds 写完 `RotatedDimension` 后，标注与 Polyline **没有任何持久关联**。Polyline 修改后，老标注变成"游魂"——
- 用户必须手工删掉老标注 → 重新选择 Polyline → 跑 dds
- 无法批量识别"哪些标注属于哪条多段线"

### 6.2 NewDDS Phase 5：XData 双向绑定

每条 NewDDS 派生的 `RotatedDimension` 在 `ExtensionDictionary` 写入 `HyCAD_NewDDS` 节点：

```json
{
  "SourcePolylineHandle": "1A2B",
  "FeatureSignature":      "<sha256>",
  "ConfigSnapshot": {
    "OffsetOutside": 420, "OffsetInside": 180,
    "OffsetWithDim": 180, "MergeDistance": 900,
    "SweepStep": 100, ...
  }
}
```

→ 三件事一次写完：
1. **回链**：标注知道它从哪条 Polyline 来
2. **变更检测**：`FeatureSignature` 是 Polyline 顶点（含 IsClosed）按 0.01mm 量化后的 SHA256，Polyline 改了签名就变
3. **配置审计**：跑这次标注时用了什么参数，永久落盘

### 6.3 NewDDS Phase 5+：`nddsR` 刷新命令

`NewDdsRefreshService` 流程：

```text
扫描 ModelSpace
  → 找 RotatedDimension 带 HyCAD_NewDDS XData
  → 按 SourcePolylineHandle 分组
对每组：
  → 取出当前 Polyline 的 FeatureSignature
  → 与 XData 中存的对比
  → 一致 → Skip（Unchanged++）
  → 不一致 → 删除老组，调用 NewDdsService.RunInTransaction 重新生成（Refreshed++）
  → Polyline 找不到（被删了） → 标记 Orphan（Orphans++）
打印汇总：ScannedDimensions / UniqueSources / Unchanged / Refreshed / Orphans / Errors
```

→ 老 dds 的工作流是"每次手工选 + 跑"；NewDDS 的工作流是"改完 Polyline → 一键 `nddsR` 全图同步"。

## 7. 质量校核体系（NewDDS Phase 6）

### 7.1 dds：无任何 Q 评估

dds 写完就走，没有任何"我标得对不对"的反馈。出问题只能靠用户在 DWG 上肉眼看。

### 7.2 NewDDS：5 条独立规则 + Issues 诊断

`FullQualityFunction` 实现 5 条规则，每条独立 0~1 评分，`Overall = 等权均值`：

| 规则 | 含义 | 实现思路 |
|---|---|---|
| **Coverage** | 顶点是否被分段尺寸覆盖 | **Phase 9 升级**：从"端点距 < 5mm"改为"顶点主轴坐标命中任一分段尺寸 ExtensionLine 端点 X/Y（容差 1mm）"，显式排除 OutsideTotal* 避免总尺寸误判 |
| **NoOverlap** | 同方向相邻 dimLine + 测量区间是否冲突 | dimLine 间距 < `OverlapDimLineGap` 且测量段相交则计 1 次 overlap |
| **WithinBounds** | dimLinePoint 是否在 polyline bbox 拓展范围内 | bbox + 200mm slack，外溢 dim 计 1 次 violation |
| **Consistency** | 同 Source 偏移距离 stddev | 按 Source 分组，stddev > 1mm 扣分 |
| **DirectionalCoverage** | 外四方向是否都有标注 | 沿用 M1 版逻辑 |

→ Q 仍是**校核器**而非**选择器**：评分低只在命令行打 `Issues[]`，不会自动改写已生成的标注。

### 7.3 命令行示例

```text
[NewDDS] Phase 6 链路：Polyline(原顶点=28 闭=True) → tessellated(顶点=28) | 配置(内=180 外=420 带尺寸=180 容差=900)
        | 步长=100.0 | 特征 H=9列/48段 V=13列/26段 | 派生=34 后处理=29 写入=29 | Q=1.00
[NewDDS] Source 分布(后处理后)：OL=3 OR=3 OU=10 OD=3 OTL=1 OTR=1 OTU=1 OTD=1 IL=6 IU=0 | 合计=29
[NewDDS] Q 诊断：Cov=1.00 NoOv=1.00 InB=1.00 Con=1.00 Dir=1.00 Overall=1.00
[NewDDS] 几何诊断：[Sweep-H] 列=9 同拓扑跳过=49 step=100.00 / [Sweep-V] 列=13 同拓扑跳过=191 step=100.00
```

→ 一行就能看清"输入几何复杂度 / 派生与后处理裁剪比例 / 各 Source 占比 / 5 条 Q 规则"。

## 8. 金标回归（NewDDS Phase 7）

### 8.1 dds：无回归保护

老 dds 修改后必须手工跑无数次 `dds` 命令在不同 DWG 上看效果，回归靠肉眼。

### 8.2 NewDDS：纯 Domain 金标

`NewDdsTestFixtures` 嵌入 5 个 fixture（无任何外部 DWG 依赖）：

| Fixture | 描述 | 顶点 |
|---|---|---|
| `01-rect` | 简单矩形 | 4 |
| `02-l-shape` | L 形 | 6 |
| `03-t-shape` | T 形 | 8 |
| `04-double-notch` | 双凹槽（含内尺寸） | 13 |
| `05-asymmetric` | 不对称多台阶 | 8 |

`nddsT`（金标命令）流程：
```text
对每个 fixture：
  → 跑完整管线（Extractor → Deriver → PostProcessor → Quality）—— 不需要 AutoCAD
  → 生成 NewDdsGoldenSnapshot（顶点数 / 列数 / 边数 / 派生数 / 清理后数 / Source 分布 / 5 条 Q）
  → 与 NewDdsGoldenBaseline.Map 比对
  → 输出 ToShortLine() 一行 + Comparer 差异列表
汇总：冻结一致=N 差异=N 未设基线=N
```

`NewDdsGoldenComparer` Phase 9 升级了 **Q 浮点比对**（容差 0.005，即两位小数舍入）：算法改了 → Q 变了 → DIFF 自动报出。

→ 修改一次 Domain 代码不用再开 AutoCAD：`nddsT` 一秒出结果。

## 9. 命令注册对比

| 命令 | dds | NewDDS |
|---|---|---|
| 入口 | `dds` / `ddss` 写在 `commands.json`（N1~N50 占位符方案） | `ndds` / `nddss` / `nddsR` / `nddsT` 通过 `CommandFacade.cs` 的 `[CommandMethod]` 直接注册 |
| 热重载 | C2 即可 | C2 即可（除非动 `CommandFacade.cs` 才需关 CAD + NETLOAD ReCall） |
| 直接命令名 | 即时可用 | 一次性 NETLOAD ReCall 后即时可用 |

→ NewDDS 选择直接 `[CommandMethod]` 注册是因为这 4 个命令是产品级常驻命令，而非临时占位，长期不需要 N 占位符表里再占 4 个槽位。
