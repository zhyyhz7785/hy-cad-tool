# 06 - dds 命令深度解析：解析式直接派生范式与算法稳健性优化

> 本文与 01~05 互补不重叠。
> 01 立项（What）；02 立柱（How / Why）；03 立尺（Optimal）；04 立路（Roadmap，注释域）；05 立梁（跨 Feature 优化引擎）。
> **06 立闸**：把 `dds` (`DimensionForReinforcementCommand`) 从一头到尾拆开，证明 03 / 04 / 05 默认的"多候选 + 评分 + 求解"三段式不是 HyCAD 的唯一范式——还有一类**纯解析式直接派生**的工作方式必须被显式承认，否则 §5 抽出的接口骨架会逼一个简单问题去走复杂路径。
>
> dds 是 HyCAD 已有的 `Features/DimensionForReinforcement` 命令：拾取一条多段线（配筋区域轮廓）→ 自动生成内部凹凸点尺寸 + 外部 4 方向边界尺寸 + 4 方向总尺寸。780 行 Service，关键算法是割线扫描法。

## 2. 算法骨架（七步链路）

```text
Polyline boundary
  ↓ ExplodePolyline + GetExtreme              [Step 1] 极值点 (xMin/xMax/yMin/yMax)
xMin / xMax / yMin / yMax
  ↓ GetAllSecantLinesHorizontal               [Step 2a] 水平割线扫描 (Y+ 方向)
  ↓ GetAllSecantLinesVertical                 [Step 2b] 垂直割线扫描 (X+ 方向)
Line[,] _lineIntersectionsUpDown / LeftRight
  ↓ GetColumn(0) / GetColumn(cols-1)          [Step 3] 提取边界列 (左/右 或 下/上)
  ↓ SortLineSEPointForDim                     [Step 4] 起终点方向归一化
boundary lines per side
  ↓ GetDimensionPoints                        [Step 5a] 外部：取边界点序列
  ↓ CreateOutsideDimensions                   [Step 5b] 4 方向相邻点对 + 总尺寸
  ↓ GetDimsByLines                            [Step 6a] 内部：按列对偏置朝向决策
  ↓ CleanInsideDims                           [Step 6b] 内部去重
RotatedDimension[6 组]
  ↓ DeleteNearbyParallelDim                   [Step 7a] 平行近距合并
  ↓ DimVsEqualLength + DeleteDimensionZero    [Step 7b] 视觉对齐 + 去零长
  ↓ ToSpace                                   [Step 7c] 写入模型空间
DWG Entity
```

## 3. 算法核心：割线扫描法（Sweep Line）

### 3.1 想法

把一条水平直线从 \(y_{\min}\) 自下而上推过整个图形，**每当它穿过的轮廓边数发生变化时**，说明刚刚跨过了一个拓扑特征点（凹凸顶点）。把每次变化时割线截到的边界线段提取出来，就拿到了"沿 Y 轴方向所有需要标注的特征 X 坐标"。

垂直方向同理，从 \(x_{\min}\) 向右推。

→ 这是 \(O(n \cdot m)\) 的扫描线算法（\(n\) 是高度方向步数，\(m\) 是边界顶点数），与计算几何里"事件驱动扫描线"是同一脉络。

### 3.2 具体推进规则（`GetNextHorizontalSecant`）

```csharp
while (countPri == countNext && y <= shortestIntersection.EndPoint.Y && safetyCounter < 1000)
{
    y += _step;             // _step = 20，硬编码
    next = CreateHorizontalSecant(y);
    countNext = GetIntersectionCountAcad(next, _boundary);
    safetyCounter++;
}
```

- `_step = 20`：固定步长
- `countPri == countNext`：交点数不变 → 没遇到特征点 → 继续推
- `safetyCounter < 1000`：死循环兜底
- `shortestIntersection.EndPoint.Y`：保证不越过当前列最短线段顶端，避免跳过特征

### 3.3 同时使用两套求交 API（隐性技术债）

| 用途 | API | 行为差异 |
|---|---|---|
| 数交点判断推进 | `Line.IntersectWith(Polyline, Intersect.ExtendThis)` | ACAD，含端点 / 切点 |
| 获取实际坐标 | `NetTopologySuite.GeometryFactory.CreateLineString.Intersection` | NTS，不含端点 |

→ 这是历史上为了规避**两套 API 各自精度坑**的折中方案，注释里写得很委婉（"避免 NTS 精度偏差导致的异常"）。但代价是：

- **同一段代码同时存在两套几何语义**
- **新人无法直接看出"为什么这两个 API 不能用同一个"**
- **任何一边升级 / 行为变化都可能让算法失稳**

### 3.4 二维数组对齐：FillArray 经验性策略（隐性几何假设）

`To2DArray` + `FillArray` 把不等长的"每条割线截到的线段数组"对齐成 `Line[行, 列]`：

```csharp
if (count % 2 == 0)
{
    for (int i = 0; i < count / 2; i++)
    {
        values[i] = source[i];                          // 前半段放头
        values[targetLength - 1 - i] = source[count - 1 - i]; // 后半段放尾
    }
}
```

**隐含假设**：对称凹凸图形——即"短行少出来的特征点对称分布在两端"。

| 适用图形 | 不适用图形 |
|---|---|
| 矩形 | 任意单凹形（特征点偏一侧） |
| 工字 | 不对称 L 形 |
| H 形 | T 形（顶宽 / 底窄） |
| 十字 | Z 形 / S 形 |
| 一般底板（左右对称） | 含倾斜段或非轴对齐凹凸的轮廓 |

→ **dds 的稳健性建立在工程图绝大多数为轴对齐 + 大致对称的经验观察上**。一旦遇到 Z / 不对称 L / 含旋转段的轮廓，二维对齐错位，标注会偏到错误位置。

## 4. 内部标注的朝向决策（被忽略的小聪明）

`GenerateInsideLeftRight` 第 287 行：

```csharp
DimensionFor side = (midLeftX - priRightX > nextLeftX - midRightX)
    ? DimensionFor.ForLeft
    : DimensionFor.ForRight;
```

**这条决策的工程含义**：当某列特征段在前后两列之间，比较"它到前一列右侧的距离"与"它到后一列左侧的距离"——**哪边空间大，标注就朝哪边伸**。

→ 这是 03 §6.5 提的"避让"在 dds 里的实际工作机制，但它**不是评分函数**，是一条 if/else 局部规则。这种范式在 03 §3.2 / 05 §6.1 抽象的 \(Q\) 函数里没有对应——它是**直接派生**的一部分。

→ **抓出这一行就抓住了第三种范式**。

## 5. dds 揭示的第三种范式：解析式直接派生

### 5.1 把 03 / 04 / 05 的范式表补全

| 范式 | 输入 | 候选 | 评分 | 求解 | HyCAD 实例 |
|---|---|---|---|---|---|
| **A 注释组合优化** | 已有点 | 8 方位 / 行列 | 显式 \(Q\) | 贪心 / 退火 | ClusterPanel（隐式 \(Q\)） |
| **B 模型布局优化** | 约束区域 | 连续 \(\mathbb{R}^2\) | 单元方差 | Lloyd 迭代 | PileVoronoi |
| **C 解析式直接派生** | 已建几何 | **无候选** | **不用来选，只用来校核** | **几何特征提取 → 直接派生** | **dds（本文）** |

### 5.2 范式 C 的特征

1. **输入决定输出**：给定多段线 → 标注几乎唯一确定（除"内部朝向"等少数局部规则有 2 选 1 决策）
2. **主要成本是"识别输入特征"**：割线扫描提取拓扑特征点是最贵的一步
3. **不存在多候选**：没有 8 方位、没有连续点位、没有迭代收敛
4. **Quality 角色变换**：不是用来选最优，是用来**校核生成结果是否合规**（漏标 / 重叠 / 超界）
5. **求解时间近似 \(O(n)\)**：与图形规模线性相关，无收敛性问题

### 5.3 范式 C 在 03 §5 阶梯里的位置

03 §5 把求解器分 S1~S4。其实 S1（规则系统）应进一步细分：

| 子档 | 名称 | 核心机制 | HyCAD 实例 |
|---|---|---|---|
| **S1a** | **解析式直接派生** | 几何特征提取 → 直接生成 | **dds**、`DrawElevationCommand`、AnchorBolt 编号自动派生 |
| **S1b** | 候选枚举 + 评分 | 8 方位候选 + 评分函数 | 03 §9 MVP 计划（钢筋编号气泡） |
| **S1c** | 网格反算 | 解析公式反推参数 | `PileLayoutService.Calculate` |

→ S1a / S1b / S1c 的工程难度排序：**S1a < S1c < S1b**。

→ HyCAD 当前 S1a 实例最多（dds、标高、轴号），S1c 次之（PileLayout），S1b 最少。说明**HyCAD 的强项是"已知特征→直接派生"**，而非"多候选打分"。这条认知会改变 03 §9 MVP 的选取方向。

## 6. dds 与 ClusterPanel / PileVoronoi 的同源性 / 异源性

### 6.1 同源（命题层）

都对应 03 §1 的：

\[
A^{*} = \arg\max_{A \in \mathcal{A}(M)} \; Q(A;\; M, C, U)
\]

### 6.2 异源（实现层）

| 维度 | ClusterPanel（A） | PileVoronoi（B） | **dds（C）** |
|---|---|---|---|
| \(\mathcal{A}\) 候选 | 离散有限 | 连续 \(\mathbb{R}^2\) | **退化为单点（无候选）** |
| \(Q\) 角色 | 选择 | 选择 | **校核** |
| 求解 | DBSCAN 长方形邻域 | Lloyd 迭代 4500 | **割线扫描 + 拓扑特征** |
| 求解时间 | \(O(n^2)\) 平方 | \(O(n \cdot k)\) 迭代 | \(O(n)\) 线性 |
| 唯一性 | 局部最优（依赖 \(\varepsilon\)） | 收敛局部最优（依赖初始） | **几何唯一确定** |

→ **范式 C 的 \(\mathcal{A}\) 是单点集合**——这是数学上的退化情况，但工程上恰恰是**最常见**的情况：大多数标注 / 编号 / 索引 / 标高确定后，就不存在"放哪好"的选择问题。

## 7. dds 的算法稳健性问题（10 项排查）

| # | 问题 | 位置 | 影响 | 严重度 |
|---|---|---|---|---|
| 1 | `_step = 20` 硬编码 | `SetProperties` 第 106 行 | 大图慢、小图错过特征 | 高 |
| 2 | `safetyCounter < 1000` 死循环兜底 | `GetNext*Secant` | 算法本身不稳定的反指标 | 中 |
| 3 | ACAD + NTS 两套求交 API 共存 | `GetIntersectionCountAcad` / `GetIntersectionPointsNTS` | 语义不统一，升级风险 | 中 |
| 4 | `FillArray` 假设几何对称 | `FillArray` 第 717 行 | 不对称图形对齐错位 | 中 |
| 5 | `SortLineSEPointForDim` 非竖线**无条件翻转** | 第 657 行 `result.Add(new Line(line.EndPoint, line.StartPoint))` | 旧代码原始逻辑保留，意图不明，可能埋雷 | 中 |
| 6 | `DeleteNearbyParallelDim` 删 `[i]` 不删 `[i+1]` | 第 865 行 | 可能保留短的丢长的（与 ClusterPanel `FilterDuplicateDimensions` 同病） | 中 |
| 7 | `DimVsEqualLength` 取最短界线长度 | 第 872 行 | 强制截短可能让某条标注界线短到无意义 | 低 |
| 8 | `_xMin/_xMax/_yMin/_yMax` 来源于 `ExplodePolyline` 后的所有顶点 | `SetProperties` | 仅顶点，**不含弧段中点**——如果多段线含 Bulge 段会漏 | 高 |
| 9 | `GenerateDimension` 没有失败回滚 | `WriteToSpace` 各组单独写 | 中途异常会留半成品 | 中 |
| 10 | 整个 Service 是 stateful 单实例 | 私有字段 `_xMin / _lineIntersections*` | 不可重入；批量命令 `ddss` 用同实例存在跨多段线状态污染风险 | 高 |

→ #1 / #8 / #10 是**工程上真出过问题**的一类（用户感知到"某些图标不对"），#2 / #3 是**架构债**，#4~#7 是**经验性策略的潜在边角**。

## 8. dds 的架构债（与 02 §8 / 05 §7 同病）

| # | 缺口 | 与其他 Feature 共性 | 修复阶段 |
|---|---|---|---|
| 1 | 没有 Domain 层（割线扫描 / 拓扑特征混在 Service 里耦合 AutoCAD `Polyline / Line / Point3d`） | 同 ClusterPanel | 05 §8 Phase 0 |
| 2 | 没有 XData 持久化（标注与源多段线脱钩） | 同 ClusterPanel + PileVoronoi | 05 §8 Phase 2 |
| 3 | 没有 Quality Score（删/留靠硬阈值不可解释） | 同 ClusterPanel + PileVoronoi | 05 §8 Phase 1 |
| 4 | 没有重生成（源多段线变更只能全删全画） | 同 ClusterPanel + PileVoronoi | 05 §8 Phase 2 |
| 5 | 没有可中断 / 进度反馈（虽然现在快） | 同 PileVoronoi | 05 §8 Phase 4 |
| 6 | 没有校核（漏标 / 重叠 / 超界都不报） | 同所有 Feature | 05 §8 Phase 5 |
| 7 | 服务有可变全局状态（线程不安全 / 不可重入） | dds 独有 | 立即修 |
| 8 | 配置入口分散（直接读 `SettingsPanelViewModel.Current`） | 同 ClusterPanel | 05 §8 Phase 3（Profile 化） |

→ **dds 的架构债与 ClusterPanel + PileVoronoi 高度同构**，证明 05 §5 抽出的统一接口能直接收编 dds。

## 9. dds 的真正价值（被它的封装藏起来了）

### 9.1 dds 内部真正可复用的能力

```text
┌─────────────────────────────────┐
│  BoundaryFeatureExtractor       │  ← 真正的核心，dds 之外可复用
│  - 输入：Polyline               │
│  - 输出：拓扑特征点 / 特征边     │
│  - 实现：割线扫描法              │
└─────────────────────────────────┘
           ↓
┌─────────────────────────────────┐
│  DimensionDeriver               │  ← dds 域专属
│  - 输入：特征点 / 边             │
│  - 输出：内外标注                │
└─────────────────────────────────┘
           ↓
┌─────────────────────────────────┐
│  DimensionPostProcessor         │  ← 与 ClusterPanel / 其他 Feature 重复
│  - DeleteDimensionZero          │
│  - DeleteNearbyParallelDim      │
│  - DimVsEqualLength             │
└─────────────────────────────────┘
```

### 9.2 三层各自的复用方向

| 层 | 已被复用 | 可被复用 |
|---|---|---|
| `BoundaryFeatureExtractor` | 仅 dds 内部 | 钢筋图（找配筋边界凹凸点）、设备基础（找台阶）、底板（找包络）、PileLayout（识别异形承台轮廓） |
| `DimensionDeriver` | 仅 dds 内部 | 同上业务标注 |
| `DimensionPostProcessor` | 仅 dds 内部 | **ClusterPanel 已有同病的 `FilterDuplicateDimensions`** —— 应共享 |

→ **dds 的最大遗憾不是它有架构债，而是它的核心算法（割线扫描 + 拓扑特征）被 1012 行单文件囚禁，没人能复用**。

## 12. 关于"为什么 dds 那么好用却没人意识到它特殊"

dds 现状的命令行体验：选一条多段线，秒出标注，效果通常正确。

→ 用户没意识到**它代表的范式很重要**，因为它"太普通了"，看起来就像"一个标注命令"。

但 dds 的真正贡献是证明了：

1. **不是所有"约束极强子领域"都需要 AI / 启发式 / 优化算法**——纯几何特征提取就够了
2. **HyCAD 的强项已经是"输入特征 → 直接派生"**——03 §3 / 04 §3 强调的"评分 / 求解"反而是它的弱项
3. **范式 C 是工程软件最值钱的范式**：可解释、可重现、性能稳定、不依赖参数调优、不依赖训练数据——**这些恰恰是 AI 时代工程软件的最大护城河**

→ **若要总结 HyCAD 应做什么**，与其追"AI 自动建模"或"全局优化器"，不如先把范式 C 做到极致：

- 抽 `BoundaryFeatureExtractor`，让钢筋 / 设备 / 底板 / 桩 都能复用
- 抽 `DimensionPostProcessor`，让 ClusterPanel + dds + 钢筋编号 共享后处理
- 抽 `FeatureSignature`，让 XData 持久化能够 hash 形状特征实现重生成 diff

这三件事都不需要 AI，都不需要 S2 以上的优化器，**但每一件都能把 HyCAD 的实际工程价值翻一倍**。

## 14. 关键设计原则（与 04 §15 / 05 §13 互补）

1. **承认范式 C 的存在**——03 / 04 / 05 都默认了"多候选 + 评分"三段式；dds 证明 HyCAD 已有的最强能力恰恰是"单候选直接派生"，必须显式承认这一类。
2. **Quality 角色双重**——范式 A / B 用 \(Q\) 选最优，范式 C 用 \(Q\) 校核生成结果；接口设计要兼容两种用法。
3. **\(\mathcal{A}\) 退化为单点不是缺陷而是优势**——可解释、可重现、性能稳定，是 AI 时代工程软件的真正护城河。
4. **核心算法与业务派生分离**——`BoundaryFeatureExtractor` 与 `DimensionDeriver` 必须可独立测试 / 独立复用。
5. **金标测试先于重构**——dds 1012 行的服务，没有金标就不能动；动了就回不来。
6. **状态封装到 Context**——立即消除 stateful Service 的隐患；这是所有 Service 类都该走的方向，不限于 dds。
7. **算法注释要写"范式编号"**——让任何读者一眼看出这段代码属于 S1a / S1b / S1c / S2 / S3 / S4，方便交叉对比。
