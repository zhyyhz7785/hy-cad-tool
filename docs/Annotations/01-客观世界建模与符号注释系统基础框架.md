# 客观世界建模与 2D/3D 符号注释系统基础框架

## 1. 目标

软件要表达客观世界，不能只画出“像什么”，还要记录“它是什么、为什么这样、如何被制造、施工、检测和维护”。几何形态解决可见外形，物理性质解决真实属性，符号与注释解决人类快速理解、协作和决策。

本框架用于为 HyCAD 后续完善 2D 与 3D 中的符号、标注、注释、属性说明、工程表达建立基础。它不是简单模仿某一个 CAD 或 BIM 软件，而是抽取主流建模软件的共同结构，形成可持续扩展的系统。

## 2. 基本判断

任何建模软件都同时处理三层信息：

| 层级 | 解决的问题 | 常见载体 |
|---|---|---|
| 几何层 | 对象在哪里、形状如何、尺寸如何 | 点、线、面、体、网格、曲线、曲面、实体 |
| 属性层 | 对象是什么、材料和物理参数是什么 | 图层、块属性、族参数、构件属性、Property Set、元数据 |
| 注释层 | 人如何快速理解、制造、施工、检查 | 尺寸、文字、引线、编号、符号、标签、PMI、表格、视图标记 |

注释不是几何的附属装饰，而是模型语义的一部分。低级注释只是一段文字或一条引线；高级注释应当知道自己指向哪个对象、表达什么规则、是否随对象变化而更新。

## 3. 建模软件与注释系统对标

“所有建模软件”无法逐一穷尽，但可以按软件族覆盖其注释系统的本质差异。

| 软件族 | 代表软件 | 主要建模对象 | 符号与注释特征 | 值得吸收的能力 |
|---|---|---|---|---|
| 2D CAD | AutoCAD、DraftSight、BricsCAD | 线、圆、块、图层、布局 | 尺寸、文字、引线、多重引线、块符号、表格、图层线型、图纸空间比例 | 轻量、自由、适合工程制图；注释比例和图层体系成熟 |
| BIM 建筑 | Revit、Archicad、Allplan、Vectorworks | 墙、梁、柱、板、门窗、房间、轴网 | 标高、轴号、房间标签、构件标签、剖面/立面符号、明细表 | 注释与构件绑定，视图驱动，参数化标签强 |
| 结构详图 | Tekla、Advance Steel、RebarCAD | 钢构件、钢筋、连接、节点 | 钢筋编号、焊缝符号、螺栓标注、节点索引、材料表 | 制造与施工导向，编号、清单、详图联动强 |
| 机械 CAD / PLM | SolidWorks、Inventor、Creo、NX、CATIA | 零件、装配、特征、曲面、实体 | 尺寸、公差、GD&T、基准、表面粗糙度、焊接符号、PMI/MBD | 3D 注释语义化，制造检测可读 |
| CAE / 仿真 | ANSYS、Abaqus、HyperMesh、COMSOL | 网格、边界条件、载荷、材料、结果场 | 载荷箭头、约束符号、云图图例、探针、结果标签 | 物理意义表达强，注释与计算条件/结果关联 |
| GIS / 城市模型 | ArcGIS、QGIS、CityEngine、Cesium | 地物、地块、道路、管网、城市对象 | 地名、图例、专题符号、颜色分级、比例尺、坐标网 | 符号系统、分类渲染、空间属性表达成熟 |
| DCC / 视觉建模 | Blender、Maya、3ds Max、Houdini、Cinema 4D | 网格、材质、动画、场景节点 | 对象名、集合、材质标签、骨骼控制器、节点注释 | 复杂场景组织、可视化层级、节点图注释 |
| 游戏 / 实时场景 | Unreal、Unity | Actor、Prefab、场景、组件 | Gizmo、调试标签、碰撞体显示、导航网格、运行时标记 | 交互式注释、运行时可视化、调试表达 |
| 点云 / 实景建模 | Leica Cyclone、RealityCapture、CloudCompare | 点云、照片、扫描站、重建网格 | 测点、站点、误差、剖切、测距、分类颜色 | 真实采集数据溯源、误差与置信度表达 |
| EDA / 专业工程 | Altium、KiCad、EPLAN | 电路、线缆、元器件、回路 | 元件编号、网络标签、端子号、接线表、规则检查标记 | 符号库、编号规则、连接关系表达严谨 |

结论：2D CAD 的优势是自由绘图和图纸表达；BIM 的优势是对象标签和参数明细；机械 MBD 的优势是 3D 语义化制造信息；GIS 的优势是分类符号；CAE 的优势是物理场与边界条件表达。HyCAD 的注释系统应吸收这些共同结构，而不是只停留在 AutoCAD 式文字和引线。

## 4. 标准体系

符号与注释系统必须尽量贴近公开标准，避免自创一套只有软件内部能理解的语言。

| 领域 | 标准/格式 | 关注点 |
|---|---|---|
| 工程制图 | ISO 128、ISO 129、GB/T 4457、GB/T 4458 | 线型、视图、尺寸标注、图样表达 |
| 几何公差 | ISO 1101、ASME Y14.5、GB/T 1182 | 形位公差、基准、位置度、平面度、垂直度等 |
| 3D 产品定义 | ISO 16792、STEP AP242 | 3D 模型中的 PMI、MBD、语义化制造信息 |
| 表面与焊接 | ISO 1302、ISO 2553、AWS A2.4、GB/T 131 | 表面粗糙度、焊缝符号、加工要求 |
| BIM | IFC、bSDD、OmniClass、Uniclass | 建筑构件分类、属性集、对象关系 |
| GIS | CityGML、GeoJSON、OGC 标准族 | 城市对象、地理坐标、空间语义 |
| 场景与可视化 | USD、glTF | 场景层级、材质、元数据、实时交换 |

HyCAD 初期不需要完整实现所有标准，但数据结构要预留标准映射字段，例如 `StandardCode`、`SymbolCode`、`PropertySetName`、`ClassificationCode`、`ExternalId`。

## 5. 注释对象的核心数据模型

一个可靠的注释对象至少应记录以下信息：

| 字段 | 含义 |
|---|---|
| `Id` | 注释自身唯一标识 |
| `Type` | 注释类型：尺寸、文字、引线、标签、符号、表格、PMI、图例等 |
| `TargetIds` | 被注释对象，可为一个或多个几何/构件 |
| `SemanticRole` | 语义角色：尺寸说明、施工要求、材料说明、检测要求、编号、警告等 |
| `Geometry` | 注释自身几何：文字位置、引线、箭头、符号边界、表格区域 |
| `Anchor` | 与目标对象的锚定方式：点、边、面、中心、包围盒、视图投影点 |
| `ViewContext` | 所属视图：模型空间、布局、剖面、立面、3D 视角、局部详图 |
| `ScalePolicy` | 比例策略：纸面固定、模型固定、随视图比例缩放 |
| `StyleId` | 样式：字体、颜色、线宽、箭头、符号模板 |
| `Payload` | 注释内容：文字、参数、公式、单位、标准号 |
| `Rule` | 更新规则：手动、随目标移动、随参数变化、随视图刷新 |
| `Source` | 来源：人工创建、规则生成、导入、检测结果、AI 生成 |
| `Status` | 状态：草稿、已校核、冲突、过期、锁定 |

关键原则：注释应尽量“绑定对象”，而不是只画在对象旁边。否则对象一变，注释就失真。

## 6. 2D 注释系统框架

2D 注释主要服务图纸阅读、施工表达和快速编辑。

| 模块 | 功能 |
|---|---|
| 尺寸系统 | 线性、对齐、半径、直径、角度、弧长、连续、基线、坐标标注 |
| 文字系统 | 单行文字、多行文字、富文本、字段、公式、自动编号 |
| 引线系统 | 普通引线、多重引线、气泡编号、材料说明、构造说明 |
| 符号系统 | 标高、轴号、剖切、详图索引、坡度、焊缝、粗糙度、钢筋、螺栓 |
| 标签系统 | 对象标签、构件编号、房间名、图层名、材料名、属性摘要 |
| 表格系统 | 材料表、工程量表、钢筋表、坐标表、设备表、检查表 |
| 图例系统 | 线型图例、填充图例、颜色图例、专业符号图例 |
| 样式系统 | 字高、箭头、线宽、颜色、图层、比例、文字样式、标注样式 |

2D 系统的重点是“图纸可读性”：遮挡处理、比例控制、对齐、批量更新、样式统一、打印一致。

## 7. 3D 注释系统框架

3D 注释不能照搬 2D 文本。它必须解决视角、遮挡、空间锚定和语义绑定。

| 模块 | 功能 |
|---|---|
| 3D 标注 | 点到点、边长、半径、角度、空间坐标、包围盒尺寸 |
| PMI / MBD | 公差、基准、表面、焊接、制造要求、检测要求 |
| 3D 标签 | 构件名称、编号、材料、规格、状态、施工阶段 |
| 视图注释 | 与某个视图、剖切面、局部详图、爆炸图绑定 |
| Billboard 标签 | 始终面向屏幕的标签，用于浏览和交互 |
| 剖切注释 | 剖面边界、切割面、内部构件说明 |
| 物理场注释 | 载荷、约束、位移、应力、温度、流向、结果图例 |
| 冲突/问题标记 | 碰撞点、错误点、待处理问题、审查批注 |

3D 注释的重点是“空间语义”：注释必须知道自己贴在哪个点、边、面或构件上，并能在不同视角下保持可读。

## 8. 统一抽象：注释不是一种对象，而是一组能力

HyCAD 可把注释系统拆成六个核心能力：

| 能力 | 说明 |
|---|---|
| Anchor 锚定 | 注释如何绑定几何、构件、视图、坐标、属性 |
| Symbol 符号 | 注释如何以标准化图形表达 |
| Text 文本 | 注释如何表达人类语言、字段、公式、单位 |
| Style 样式 | 注释如何统一视觉风格和打印效果 |
| Rule 规则 | 注释如何自动生成、自动更新、校验冲突 |
| Exchange 交换 | 注释如何导入导出到 CAD、BIM、STEP、IFC、JSON 等格式 |

推荐不要把“标高”“轴号”“钢筋编号”“焊缝符号”都写成互不相关的功能。它们底层都应复用 Anchor、Symbol、Text、Style、Rule、Exchange。

## 9. 建议的 HyCAD 分层架构

| 层 | 职责 | 示例 |
|---|---|---|
| Domain | 平台无关的注释模型、规则、标准代码 | `Annotation`, `AnnotationAnchor`, `SymbolDefinition`, `AnnotationRule` |
| Infrastructure | AutoCAD/WPF/文件格式适配 | DWG Entity 转换、XData、JSON、IFC/STEP 映射 |
| Application | 创建、更新、批量生成、校验服务 | 标注生成服务、符号库服务、注释同步服务 |
| Presentation | 命令、面板、交互、预览 | 拾取对象、编辑属性、选择样式、放置注释 |

核心对象建议：

| 对象 | 说明 |
|---|---|
| `AnnotationEntity` | 注释聚合根，记录类型、目标、内容、状态 |
| `AnnotationAnchor` | 绑定目标和锚点，支持 2D/3D |
| `AnnotationPayload` | 文字、数值、单位、字段、公式 |
| `SymbolDefinition` | 符号模板，如标高、轴号、焊缝、钢筋、螺栓 |
| `AnnotationStyle` | 字体、线型、箭头、颜色、比例 |
| `AnnotationViewContext` | 模型空间、布局、视图、剖面、相机 |
| `AnnotationRule` | 自动更新、冲突检测、生成规则 |
| `AnnotationSerializer` | DWG、JSON、IFC、STEP、glTF/USD 元数据映射 |

## 10. MVP 路线

第一阶段先做 2D 工程制图稳定内核：

1. 建立统一 `AnnotationEntity` 数据模型。
2. 抽象 `Anchor`，支持点、线、曲线、块、Polyline、对象中心、包围盒。
3. 建立符号库：标高、轴号、剖切、详图索引、坡度、钢筋、螺栓。
4. 建立样式库：文字、箭头、线宽、比例、图层、颜色。
5. 做对象绑定：对象移动或参数变化后，注释可提示过期或自动刷新。
6. 做表格输出：材料表、钢筋表、设备表、坐标表。

第二阶段扩展 3D 语义注释：

1. 支持 3D 点/边/面锚定。
2. 支持 Billboard 标签和视图绑定标签。
3. 支持剖切视图与局部详图注释。
4. 支持基础 PMI：尺寸、公差、基准、表面、焊接。
5. 支持模型检查问题标记：碰撞、缺失、超限、待审。

第三阶段做标准交换：

1. DWG/XData 内部保存注释语义。
2. JSON 作为 HyCAD 内部中间格式。
3. BIM 对象映射 IFC Property Set。
4. 机械制造信息预留 STEP AP242 / PMI 映射。
5. 场景可视化预留 glTF/USD extras 或 metadata。

## 11. 设计原则

1. 几何、属性、注释三者分离，但通过 ID 和 Anchor 关联。
2. 注释显示可以是 2D 图形，但底层必须尽量保留语义。
3. 注释样式与注释内容分离，避免每个命令各自写字体、颜色、箭头。
4. 注释要有视图上下文，同一个对象在平面图、剖面图、3D 视图中可有不同表达。
5. 自动生成的注释必须可追溯来源，避免用户不知道文字从哪里来。
6. 先保证工程图稳定，再扩展 3D PMI 和 BIM 语义。
7. 优先兼容行业标准符号，不轻易创造封闭符号语言。

## 13. 参考入口

- ISO 16792：Digital product definition data practices，用于 3D 模型注释和 MBD。
- ISO 1101 / ASME Y14.5：几何尺寸与公差体系。
- STEP AP242：支持 3D PMI 的产品模型交换。
- IFC：BIM 构件、属性集和关系交换。
- CityGML / OGC：城市与地理空间对象表达。
- USD / glTF：场景层级、材质、可视化和元数据交换。
