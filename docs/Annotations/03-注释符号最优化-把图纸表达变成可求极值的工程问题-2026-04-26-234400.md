# 03 - 模型已定 → 注释最优化：把图纸表达变成一个可求极值的工程问题

> 与 01、02 **互补不重叠**。
> 01 切「**What**」：软件族对标 + 数据字段清单。
> 02 切「**How / Why**」：符号学 + 视觉语言 + 生命周期 + L0–L5 自动化分级。
> 03 切「**Optimal**」：当模型已经被建好（输入冻结），把"画注释、放符号"重新定义为**多目标约束优化问题**，并给出可立即开工的核心计划。
> 三份合在一起：01 立项 → 02 立柱 → 03 立尺（可量化的目标函数）。

---

## 1. 起点：把您原话中的判断翻译成可形式化的工程命题

| 用户原话 | 工程翻译 | 数学翻译 |
|---|---|---|
| 未来模型构建会被 AI 大幅替代 | AI 处理"创造性 + 不确定性"问题 | 模型 \(M\) 进入未知/创意空间 |
| 模型自带设计属性、可以是未知的 | 模型空间 \(\mathcal{M}\) 高维、非凸、含隐性意图 | 不可形式化为闭式优化 |
| 注释、符号约束极强 | 注释空间 \(\mathcal{A}\) 受 ISO/GB/行业标准强约束 | 可形式化为有限组合优化 |
| 模型一旦完成 = 已有格式化数据 | 模型作为**输入冻结** | 优化问题的约束条件，非变量 |
| 用规则约束注释符号 | 规则系统给出可行域 \(\mathcal{A}(M)\) | 硬约束 + 软约束 |
| 不同客户、不同条件求极值 | 客户/介质 \(\to\) 不同目标函数 | 参数化目标函数 \(Q(\cdot; C, U)\) |
| 极值可求 | 这是个组合/连续混合优化问题 | 已有成熟算法族（Label Placement、ILP、Heuristic） |
| 难度不大、但没人做 | 工程整合问题，非算法突破问题 | 真正卡点是**评分函数**，不是求解器 |

**最关键的一步翻译**：

\[
A^{*} \;=\; \arg\max_{A \in \mathcal{A}(M)} \; Q\bigl(A;\; M,\; C,\; U\bigr)
\]

- \(M\)：已建好的模型（几何 + 属性，**冻结**）
- \(A\)：一份完整的注释方案（每条注释的位置 / 样式 / 内容 / 锚点）
- \(\mathcal{A}(M)\)：在模型 \(M\) 之上，由规则系统 \(R\) 派生的注释方案可行域
- \(C\)：客观条件（图幅、比例、打印介质、阅读距离、色彩可用性）
- \(U\)：客户/受众画像（行业、阅读习惯、招标/施工/竣工档位）
- \(Q\)：质量函数，**多目标加权和**

> **核心断言**：当 \(M\) 冻结、\(\mathcal{A}\) 有限、\(Q\) 可分解，问题就从"艺术"变成"工程"。这正是您说的"难度不应很大"的数学根据。

## 2. 为什么"目前没有人做"——市场缺口的真实原因

| 障碍 | 行业现状 | 为什么没被攻破 |
|---|---|---|
| AutoCAD 思维 | 注释 = 手工艺，每张图都是孤例 | 工具迭代 30 年没改这个心智模型 |
| BIM/SolidWorks 思维 | 注释 = 属性派生（L4 同步） | 解决了"准确"，**不在乎"最优"** |
| ArcGIS Maplex 是孤例 | 只做地图标注自动化，已商用 25 年 | 没人把它的算法迁到工程图（标准/比例/图框完全不同） |
| 学术界 Label Placement 文献丰富 | 30+ 年研究，算法成熟 | 研究者不懂 ISO/GB 工程制图标准，做 demo 不做产品 |
| 工程软件公司 | 优化算法 + 视觉感知 + CAD API 三栖人才几乎不存在 | 三个学科隔离，组织上不交叉 |
| 客户付费意愿 | "反正最后还要手调" | 没人给他们看过自动化的极限是什么样 |

→ **真正卡住的是"评分函数 \(Q\) 该怎么写"——不是求解器**。这恰好是 HyCADTool 的天然优势：长期接触一线工程图纸，知道"什么样的图被退、什么样的图被表扬"。

## 3. 问题分解：质量函数 \(Q\) 不是黑箱，而是六组可量化指标

把"好注释"拆成可计算的子项，每一项都能写成 0~1 评分：

### 3.1 完备性（Completeness）— 必标项是否都标了

- 漏标检测：必标对象集 \(\Omega(M)\) 已被标注的比例
- 标准合规：ISO/GB 必标项检查表的覆盖率
- 信息完整：单位、标准号、规格是否齐全

### 3.2 可读性（Readability）— 人眼能不能秒读

- 字符密度（字符数 / 单位图幅面积），超阈值惩罚
- 引线交叉数（越少越好）
- 文字与对象、文字与文字的最小净距
- 视觉重量倒挂率：注释比主轮廓粗的注释比例（02 §5.3 铁律）

### 3.3 几何整洁（Aesthetic Geometry）— 图整不整齐

- 同类注释的位置对齐方差（X / Y 方向）
- 引线长度的方差（统一好看）
- 注释包围盒在图幅内的分布均匀度
- 视觉重心平衡（左右、上下）

### 3.4 信息密度（Data-Ink Ratio，Tufte）— 墨水有没有浪费

- 单位墨水承载的信息量
- 冗余比（同一信息出现的次数）
- Chartjunk 检测（多余装饰、重复边框）

### 3.5 一致性（Consistency）— 同类同样

- 同类标签字体/字高/颜色的方差
- 同图层颜色一致性
- 编号规则的连续性与不冲突

### 3.6 受众适配（Audience Adaptation）— 看的人懂不懂

- 行业惯例命中率（结构 / 道路 / 机械 / GIS 用语和符号）
- 详简档对应（施工图 ≠ 招标图 ≠ 竣工图）
- 客户企业内部规范命中率（每个客户可定制）

\[
Q \;=\; \sum_{i=1}^{6} w_i \cdot q_i \quad,\quad q_i \in [0,1] \quad,\quad \sum w_i = 1
\]

- \(q_i\)：六组指标各自的归一化得分
- \(w_i\)：权重向量，**由客户/场景画像决定**
- \(Q \in [0,1]\)：单张图整体得分，可直接显示给用户

> **关键设计**：\(Q\) 不是一次写死的"最优定义"，而是**权重可配置的可适配函数**。这样"针对不同客户和客观条件下的极值"才有数学意义。

## 4. 约束系统：可行域 \(\mathcal{A}(M)\) 怎么定义

| 类别 | 硬约束（违反即非法） | 软约束（违反扣分） |
|---|---|---|
| 几何 | 注释不与对象主体重叠；引线不穿对象内部 | 远离对象边界、避开尖角 |
| 制图 | 比例 / 字高 / 视图 / 图层 | 美观对齐、规整方位 |
| 标准 | ISO 128/129、GB/T 4457/4458 必标项 | 标注顺序、习惯方位 |
| 物理 | 不脱离图幅、不超过打印边界 | 优先靠近被注对象 |
| 语义 | Anchor 必须有效；Type 必须合法 | 同类注释方向一致 |

硬约束 = 过滤器（不进可行域）；软约束 = 进入 \(Q\) 的扣分项。

## 5. 求解策略阶梯：从规则系统到学习增强

借自动驾驶 L0–L5 思路，注释最优化也是渐进的：

| 阶段 | 方法 | 适合场景 | 性能 | 可解释性 |
|---|---|---|---|---|
| **S1 规则系统** | 决策树 + 优先级 + 解析式位置候选 | 80% 标准场景 | 毫秒级 | 完全可解释 |
| **S2 启发式 + 局部搜索** | 模拟退火 / 遗传算法 / 力导向 | 密集场景的避让与排版 | 秒级 | 可解释 |
| **S3 全局优化** | ILP / CP-SAT / OR-Tools | 高难度全局最优 | 分钟级 | 可证明最优 |
| **S4 学习增强** | 模仿学习（专家图纸）+ RL（\(Q\) 当 Reward） | 修正权重、补规则缺口 | 训练慢、推理快 | 半可解释 |

**铁律**：**S4 不替代 S1**，而是修正 S1 的权重和补规则缺口。规则系统永远是底座，AI 只是上层修正。这是工程软件的安全要求。

> 参考工程：ArcGIS Maplex Label Engine（S2 启发式+力导向已商用 25 年）；OR-Tools 的 CP-SAT（S3）；近 5 年 Layout-RL 顶会论文（S4）。

## 6. 为什么"难度不应很大"——五条事实

1. **输入已结构化**：DWG XData / IFC Property / HyCAD `AnnotationEntity`（02 §10）已是格式化数据，不需要先做识别。
2. **输出是 2D 图形**：不需要 3D 物理仿真、不需要光照渲染。
3. **评分函数可分解**：每条注释独立评分 + 全局求和，并行友好。
4. **约束有限**：图幅、比例、字高、行业标准——都是有限离散集。
5. **类似问题已有公开算法**：Label Placement / Force-Directed / SAT-Solver 文献和库都成熟（Maplex、OR-Tools、NetworkX）。

剩下的工作是**整合**，不是**算法突破**。

## 8. 核心计划：六个阶段 + 一个一周内可见的 MVP

### Phase 0 — 基础设施（1~2 周）

> 只搭骨架，**不写实现**。

- [ ] `Domain/Annotations/Optimization` 目录
- [ ] 接口 `IAnnotationQualityFunction`：输入注释方案 + 上下文 → 输出 \(Q \in [0,1]\) 与子项明细
- [ ] 接口 `IAnnotationConstraintSet`：输入模型 → 输出硬/软约束
- [ ] 接口 `IAnnotationCandidateGenerator`：枚举候选位置（8 方位 / 16 方位 / 自由）
- [ ] 接口 `IAnnotationOptimizer`：S1 / S2 / S3 实现共享同一接口
- [ ] 数据结构 `AnnotationProblem` / `AnnotationCandidate` / `AnnotationScoreCard`
- [ ] 与 02 §10 六接口对齐：`IAnnotationAnchor` / `ISymbolFactory` / `IAnnotationStyle` 已存在

### Phase 1 — 单注释最优放置（2~4 周）

> 选最简单场景：**一条尺寸或一个引线编号的位置选择**。

- 8 方位 / 16 方位候选枚举
- 写最小 5 项评分（重叠 / 交叉 / 超界 / 字符密度 / 视觉重量倒挂）
- 在已有命令上落地：`MleaderReinCommand`、`DimensionForReinforcementCommand`（dds/ddss）
- 用户体验：先维持原命令，新增"自动放置"按钮，可对比 Before/After

### Phase 2 — 多注释联合避让（4~8 周）

> 当 N > 20 条注释时，单条最优 ≠ 全局最优。

- 模拟退火 / 遗传算法实现 S2
- 力导向布局（参考 Maplex）解决密集图纸交叉
- 性能阈值：N ≤ 50 用 S1；N > 50 自动切换 S2
- 测试场底板配筋图（已有 `BaseReinforcementService` 上下文）

### Phase 3 — 客户偏好建模（4 周）

> 引入 **Profile 概念**：同一份模型 \(M\)，针对不同客户出不同的图。

- Profile = 权重向量 + 软约束修正项 + 检查表
- 内置 5 个 Profile：结构 / 道路 / 机械 / 招标 / 施工
- 客户可在 BlenderUI 上调权重并保存（XData 或项目级 JSON）
- 一键切换：同一模型 → 不同 Profile → 不同 \(A^*\)

### Phase 4 — 规则编辑器面板（2~4 周）

> 让用户可见、可改，**不再是黑箱**。

- BlenderUI 上的规则 DSL 编辑器（YAML 或 JSON）
- 规则可视化：每条规则命中哪些对象、扣多少分
- 规则版本化：项目级 / 企业级 / 行业级三层

### Phase 5 — 质量评估面板（2 周，**杀手级功能**）

> 用户输入一张图，软件直接给评分卡。

- 给一张图打分 \(Q\) 与六项明细
- 自动列出：漏标 / 重叠 / 不规范 / 不一致清单
- 一键跳转到问题位置
- 对客户的卖点：**"你看你的图能从 0.62 提到 0.91"**

### Phase 6 — 反馈数据收集（持续，为 Phase 7 蓄力）

> 不打扰用户，被动收集。

- 用户接受自动布局 → 隐式正反馈
- 用户每次手调 → 隐式负反馈（位置差量、样式差量）
- 攒数据集，匿名化，本地保存
- 年度可导出供训练

### Phase 7 — 学习增强（年后视效果）

> 不是必选项；S1~S3 跑通后再决定是否启动。

- 基于专家图纸的模仿学习（IL）
- 以 \(Q\) 为 Reward 的强化学习（RL）
- **绝不替代规则系统**：只用于修正权重和补规则空白

## 12. 技术风险与对应

| 风险 | 应对 |
|---|---|
| \(Q\) 主观、各客户口味不同 | 通过 Profile 把主观性参数化；做 5 个内置 Profile 校准 |
| 优化太慢拖慢命令响应 | S1 规则系统兜底，启发式只在 N>50 启用；最坏 1 秒预算 |
| 用户不信任自动化 | 始终允许手动覆盖；自动化只产出"建议"；可回滚 |
| AutoCAD API 性能瓶颈 | 全部计算在内存，最后一次性写入；用 Transaction 批量提交 |
| 评分指标互相矛盾 | 权重向量从 5 个 Profile 起步；不追求一开始全局最优 |
| 评分函数本身写错 | Phase 5 评估面板首先用来给**自己开发的图**打分，自检 |
| 规则爆炸维护困难 | 规则 DSL 三层（项目/企业/行业），版本化 + 测试用例 |

## 15. 设计原则（与 01 §11、02 §15 互补）

1. **\(Q\) 必须可分解、可解释、可调权重**——否则没法适配客户。
2. **规则系统永远是底座，AI 只在权重层修正**——工程软件的安全底线。
3. **优化只新增"自动"按钮，不替换现有命令**——保留用户主权。
4. **MVP 先跑窄场景，证明命题**——不要一上来全栈搞。
5. **评分指标先少后多**——5 项足够 MVP，30 项是终态。
6. **Profile 是产品化关键**——同模型出多客户图，是杀手级卖点。
7. **每一步都要可度量**——\(Q\) 数字本身就是 KPI。
8. **\(Q\) 必须能给"已发布客户图"打分**——这是验证函数对不对最直接的方法。
