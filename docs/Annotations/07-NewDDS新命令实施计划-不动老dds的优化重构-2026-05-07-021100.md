# 07 - NewDDS 新命令实施计划：不动老 dds 的优化重构

> 本文是 06 文档（dds 命令深度解析）的实施篇。
> 06 给出了诊断与改造路线，07 给出**可直接开工的工单**。
> 落地位置：`src/HyCADTool/Features/AcadDimension/`（不在 `DimensionForReinforcement/`）。
> 老 dds / ddss 在整个实施过程中**保持不变**，作为金标对照。

---

## 1. 实施前提

### 1.1 不变项（铁律）

- **老 dds（`DimensionForReinforcementCommand`）** 不动一个字符
- **老 ddss（`DimensionForReinforcementBatchCommand`）** 不动一个字符
- `commands.json` 中 `dds` / `ddss` 两条注册保留
- 钢筋首选项面板（`SettingsPanelViewModel` 中 `DimensionDistanceInside/Outside/WithDim/DimDistanceTolerance`）字段、默认值、绑定全部不动
- 老命令的金标输出冻结为基线

### 1.2 历史背景（用户原话校正）

- dds 当年的设计意图是"断面 Polyline → **生成钢筋 + 标注**"复合命令，但实施只完成了标注那一半。
- 钢筋首选项面板（截图：内部尺寸距离 7 / 外部尺寸距离 10 / 带尺寸距离 14 / 引线距离 5 / 距离容差 1）现状是**为老 dds 服务**的——这是事实，不是问题。
- NewDDS 的目标**不是**接管钢筋绘制（那部分留给独立命令；本计划只做标注）。
- NewDDS 的目标**是**：把老 dds 的"标注那一半"按 06 §10 的 5 个 Phase 重做一遍，跑在新目录里，老命令完全不动。

### 1.3 NewDDS 与 `Features/AcadDimension/` 目录定位的协调

- AcadDimension README 当前定位："**通用** AutoCAD 尺寸标注的编辑能力，与配筋业务无关"。
- NewDDS 进来后定位**重新表述**为：通用 AutoCAD 尺寸标注的**编辑 + 派生**能力。
- 与配筋业务的耦合通过 `NewDdsConfigAdapter` 隔离——参数继续从钢筋面板取（兼容用户偏好），但 NewDDS 内部完全不感知"钢筋"语义。
- README 增补一节"NewDDS 与配筋业务的边界"，明确：NewDDS 不读钢筋几何、不识别钢筋图层、不绑钢筋编号。

## 2. 范式与命题定位

引用 06 §5 的范式表：

| 范式 | 候选空间 | Q 角色 | 求解 | NewDDS 选择 |
|---|---|---|---|---|
| A 注释组合优化 | 离散有限 | 选择 | 贪心 / 退火 | × |
| B 模型布局优化 | 连续 ℝ² | 选择 | Lloyd 迭代 | × |
| **C 解析式直接派生** | **退化为单点** | **校核** | **割线扫描 → 直接派生** | **✓** |

→ NewDDS 严格属于 **S1a 解析式直接派生**。Quality 函数**只用来校核生成结果**，不用来选最优。这条决策影响后面所有阶段：

- **不引入候选枚举层**——每条标注由几何特征唯一确定
- **不引入迭代收敛层**——一次性几何提取
- **不引入"避让搜索"** —— 仅保留 06 §4 局部规则（朝向决策）

## 3. 命名与命令注册

### 3.1 命名约定

| 项 | 命名 | 说明 |
|---|---|---|
| 命令键 | `ndds` / `nddss` | new dds / new dds-batch |
| 命令类 | `NewDdsCommand` / `NewDdsBatchCommand` | 命名空间 `HyCADTool.Features.AcadDimension.Commands` |
| 服务 | `NewDdsService` | 编排层 |
| Domain 层目录 | `Features/AcadDimension/Domain/` | 平台无关算法 |
| 配置类 | `NewDdsConfig` | NewDDS 自有配置（不直接耦合 SettingsPanelViewModel） |
| 适配器 | `NewDdsConfigAdapter` | SettingsPanelViewModel → NewDdsConfig |
| 上下文 | `NewDdsContext` | **无状态 Service 必备**——所有"老 dds 私有字段"封装到此 |
| 重生成命令 | `nddsR` | new dds refresh，可选 Phase 8 |

### 3.2 commands.json 新增

按 `hycad-new-command-registration` skill 流程：

| 占位 | 键 | 类 | category | displayName |
|---|---|---|---|---|
| N1 | `ndds` | `HyCADTool.Features.AcadDimension.Commands.NewDdsCommand` | 尺寸标注 | 智能断面标注（NewDDS） |
| N2 | `nddss` | `HyCADTool.Features.AcadDimension.Commands.NewDdsBatchCommand` | 尺寸标注 | 批量智能断面标注 |
| N3（可选） | `nddsR` | `HyCADTool.Features.AcadDimension.Commands.NewDdsRefreshCommand` | 尺寸标注 | 重生成 NewDDS 标注 |

注册时 `order` 紧跟在老 dds / ddss 后（11 / 21 / 22），保持 UI 列表上"老命令在前、新命令在后"——用户在过渡期能并排看到。

## 5. 分阶段实施计划

> **每个 Phase 完成后必须：C2 → C1 → ed.WriteMessage 极简日志确认通；并跑当前阶段对应的金标。**

### Phase 0 — 金标兜底 + 占位注册（半天）

**目标**：先把测试基础设施和命令占位搭起来，避免后续重构无回归保护。

- [ ] 用老 dds 跑 5 张代表图形（矩形 / 工字 / L / T / 含 Bulge），把输入 Polyline 顶点 + Bulge + 输出 RotatedDimension（起终点 + DimLinePoint + Rotation + Measurement）序列化到 JSON
- [ ] 5 张代表图先存进 `Tests/Fixtures/01~05.json`
- [ ] 在 `commands.json` 新增 `ndds` / `nddss` 占位（按 hycad-new-command-registration skill）
- [ ] 创建空目录骨架 + 各子目录 README 占位
- [ ] `NewDdsCommand.Execute` 写最小路径：拾取 Polyline → ed.WriteMessage("NewDDS 占位")，**不生成任何标注**
- [ ] C2 → C1 → 输入 ndds → 看到占位输出

**验收**：`ndds` 命令能跑，输出"占位"消息；`dds` / `ddss` 行为零变化。

### Phase 1 — Domain 层骨架（无业务逻辑）（1 天）

**目标**：先把所有数据类与接口定义齐，让后续阶段只需"实现"而无需"设计"。

- [ ] 写六个数据类：`BoundaryFeatures` / `NewDdsConfig` / `NewDdsContext` / `NewDdsResult` / `DerivedDimension` / `QualityScoreCard`
- [ ] 写五个接口：`IBoundaryFeatureExtractor` / `IDimensionDeriver` / `IDimensionPostProcessor` / `IQualityFunction` / `IRenderer<NewDdsResult>`
- [ ] `NewDdsService.Execute` 编排链路（暂时各步返回空数据）：
  ```
  拾取 → ConfigAdapter → Context.Init → Extractor → Deriver → PostProcessor → QualityFunction → Renderer
  ```
- [ ] `NewDdsConfigAdapter` 从 `SettingsPanelViewModel.Current` 读 4 个字段乘 Scale 写入 `NewDdsConfig`（与老 dds 完全一致）

**验收**：`ndds` 跑完整链路无异常；命令行打印各阶段产物个数（特征点 0 / 标注 0 / 评分卡空）。

### Phase 2 — 移植割线扫描 + 修 4 项稳健性缺口（4~5 天，最重）

**目标**：把老 dds 的核心算法移到 `SweepLineFeatureExtractor`，同时修复 06 §7 的 #1 / #2 / #3 / #8。

#### 2.1 移植 `GetAllSecantLinesHorizontal/Vertical`

- [ ] 输入：Domain `Polyline2D`（顶点 + Bulge）+ `NewDdsContext`
- [ ] 输出：`BoundaryFeatures`（特征点序列 + 边类型）
- [ ] 老 dds 的 `_lineIntersectionsUpDown / LeftRight` 进入 `Context`，不再是 Service 字段

#### 2.2 修 #1：步长自适应

- [ ] `NewDdsConfig.StepStrategy` 三选一：`Adaptive` / `Fixed(value)` / `Custom(func)`
- [ ] Adaptive 默认：步长 = clamp(短边 × 5%, 1mm, 100mm)
- [ ] 老 dds 用的 `_step = 20` 固定值改为 Fixed(20) 也能选

#### 2.3 修 #3：删除 ACAD IntersectWith 双 API 共存

- [ ] 全部交点求解走 NTS（`GeometryFactory + SnappingPrecisionModel(0.001)`）
- [ ] 端点容差处理：交点距端点 < 1e-3 视为同点（避免老 dds 用 ACAD 求数 + NTS 求坐标的折中）
- [ ] 用金标 5 张图对比 NTS-only 与原 ACAD/NTS 双 API 结果一致

#### 2.4 修 #8：Bulge 段处理

- [ ] 入口先 tessellate Bulge 段为折线（采样精度 = 步长 / 2）
- [ ] tessellate 在 Domain `Polyline2D` 构造时一次性完成，不修改源 AutoCAD `Polyline`
- [ ] 增加 fixture `08-with-bulge.json`（同时存 tessellated 后版本）

#### 2.5 修 #2：safetyCounter 改用日志 + 早退

- [ ] 命中阈值时记录诊断信息：顶点数 / Bulge 数 / 当前 step / 当前 y 或 x
- [ ] 早退而非死循环兜底；状态写入 `NewDdsResult.Diagnostics`
- [ ] 命令行打印警告

**验收**：`SweepLineFeatureExtractor` 单独可调；金标 5 张代表图特征点序列与老 dds 输出一致（差异在 1e-3 以内）；fixture 08 Bulge 图老 dds 漏特征而 NewDDS 找到。

### Phase 3 — 标注派生层（3~4 天）

**目标**：从 `BoundaryFeatures` 派生 `DerivedDimension[]`。

#### 3.1 OutsideDimensionDeriver

- [ ] 输入：`BoundaryFeatures` + `NewDdsConfig`
- [ ] 4 方向（Left / Right / Up / Down）逐对邻接特征点生成边界尺寸
- [ ] 总尺寸（左右 / 上下首末两特征点）跟随生成

#### 3.2 InsideDimensionDeriver + InteriorSideRule

- [ ] 内部凹凸尺寸（中间列特征段）
- [ ] `InteriorSideRule.PickSide(prevColRight, midColLeftRight, nextColLeft) → ForLeft | ForRight`：抽出 06 §4 的局部规则成命名类
- [ ] 单元测试覆盖 8 种相对位置

#### 3.3 修 #4：弃用 FillArray 的对称假设

- [ ] 不再用"前半段放头 / 后半段放尾 / 中间填 null"
- [ ] 改用按"特征段 X 中心"或"Y 中心"作为列索引，存 `Dictionary<double, FeatureSegment>` 而非 `Line[,]`
- [ ] 不对称图形（fixture 06 / 07）金标对比通过

#### 3.4 修 #5：SortLineSEPointForDim 语义重命名

- [ ] 老 dds 中"非竖线无条件翻转"行为重新审视
- [ ] 改写为 `EnsureCanonicalOrientation`，加注释说明意图（按"标注方向 → 起终点选择"）
- [ ] 可疑边角情况（含旋转段轮廓）写测试用例兜底

**验收**：金标 1~7 全过；新增 fixture 06 / 07 不对称形状老 dds 偏位置而 NewDDS 正确。

### Phase 4 — 后处理共用层（2 天）

**目标**：把老 dds 的三件后处理工具与 ClusterPanel 的 `FilterDuplicateDimensions` 合到统一接口。

- [ ] `DefaultDimensionPostProcessor` 实现：
  - `DeleteDimensionZero`（Measurement < 1mm 的删）
  - `RemoveNearbyParallel`（**修 #6：保留长的丢短的**——按 Measurement 降序，淘汰相邻偏置容差内的短者）
  - `EqualizeWitnessLines`（**修 #7：选总扣分最小的统一长度**——不强制取最短，按一组评分公式选 best 长度）
- [ ] 写文档说明本类**未来将给 ClusterPanel 的 `FilterDuplicateDimensions` 共用**——但本期不动 ClusterPanel
- [ ] 后处理作为 `IDimensionPostProcessor` 接口，可在 `NewDdsConfig` 里关闭单项

**验收**：金标全过；fixture 中"密集近平行标注"图形（人为构造）保留长的而非短的。

### Phase 5 — Render + XData 持久化（2 天）

**目标**：Domain 结果 → AutoCAD 实体 + 绑回源对象。

- [ ] `NewDdsRenderer.Render(NewDdsResult, RenderTarget)`：
  - DerivedDimension → RotatedDimension
  - 设当前图层 = `LayerSemanticIds.CommonDimOuter`
  - 用单 Transaction 写入；**修 #9：失败回滚整体**（Transaction.Abort）
- [ ] `NewDdsXDataStore.Store(RotatedDimension, NewDdsBinding)`：
  - SourcePolylineId（源多段线 ObjectId）
  - ConfigSnapshot（NewDdsConfig 序列化）
  - FeatureSignature（顶点 + Bulge 的 hash，便于 diff）
  - 用 RegApp `HyCAD_NewDDS`
- [ ] 命令行输出："已写入 N 条标注，绑定到源多段线 0xXXXX"

**验收**：金标全过；写入后用老 PROPERTIES 命令选标注 → 看到 XData；删除源多段线 → 标注成孤儿可被检测（Phase 6）。

### Phase 6 — Quality 校核（不当选择器）（2 天）

**目标**：实现 06 §5.2 强调的"Q 用来校核而非选择"。

- [ ] 5 条规则各实现 0~1 评分 + 详细问题清单：
  - `LeakDetectionRule`：BoundaryFeatures 中应被覆盖的特征点是否都对应至少一条标注
  - `OverlapRule`：同图层 RotatedDimension 包围盒重叠面积 / 总面积
  - `OutOfBoundsRule`：DimLinePoint 是否超出原 Polyline 包围盒 + 边距
  - `ConsistencyRule`：同方向标注的 DimLinePoint 偏置方差是否合理
  - `CoverageRule`：4 方向边界尺寸是否齐
- [ ] `DefaultQualityFunction.Evaluate(NewDdsResult) → QualityScoreCard`
- [ ] 命令行打印评分卡（5 项分数 + 问题清单 + 综合分）
- [ ] **不影响生成结果**——Q 不参与决策；只读

**验收**：金标全过；金标图形评分≥0.85；故意构造的"漏标"图形评分卡显式列出漏标点。

### Phase 7 — 金标回归 + 边角图形扩充（1 天）

**目标**：用 5 张额外边角图形证明 NewDDS 比老 dds 更稳健。

- [ ] 新增 5 张老 dds 出过问题的图形：
  - `06-asymmetric-l.json`（不对称 L）
  - `07-z-shape.json`（Z 形 / S 形）
  - `08-with-bulge.json`（含弧段）
  - `09-tiny.json`（边长 < 100mm 微图）
  - `10-huge.json`（边长 > 100m 超大图）
- [ ] 每张图记录：老 dds 问题描述（漏 / 错位 / 死循环 / 抛异常）+ NewDDS 期望输出
- [ ] 跑全部金标，对比 NewDDS vs 老 dds：
  - 1~5：必须一致（标注位置容差 1mm 内、数量一致、文字内容一致）
  - 6~10：**老 dds 故意失败**而 NewDDS 全过
- [ ] 不一致项：人工审视，决定"老 dds 错 / NewDDS 错"

**验收**：1~5 一致；6~10 NewDDS 全过、老 dds 失败案例如预期。

### Phase 8 — 重生成命令 nddsR（可选，2 天）

**目标**：兑现 06 §10 Phase 3 的"L4 变更感知"。

- [ ] `NewDdsRefreshCommand`：扫描所有带 `HyCAD_NewDDS` XData 的 RotatedDimension
- [ ] 对每条标注：
  - 读 SourcePolylineId 找回源多段线
  - 找不到 → 标记为 Orphan，命令行列出
  - 找回 → 重算 FeatureSignature，与 XData 中的对比
  - 一致 → 跳过
  - 不一致 → 删旧标注 → 重新跑 NewDdsService.Execute → 写入新标注 + 新 XData
- [ ] 单 Transaction，整体写入或全部撤销

**验收**：源多段线移动 / 改顶点 → nddsR 后标注跟着更新；删除源多段线 → 标注被标 Orphan 而非默默错位。

### Phase 9 — UI 集成 + 文档（1 天）

- [ ] 钢筋首选项面板顶部加一行注释："这些参数同时为老 dds 与 NewDDS 服务"
- [ ] AcadDimension README 增补"NewDDS 与配筋业务的边界"
- [ ] 在 06 文档加 v1.1 修订段：NewDDS 实施计划（07）已落地

## 7. 关键技术决策点

| 决策 | 选择 | 理由 |
|---|---|---|
| NewDdsConfig 数据来源 | 一阶段从 SettingsPanelViewModel；Adapter 隔离 | 兼容用户偏好；二阶段（年后）可独立化 |
| 几何精度 | NTS `SnappingPrecisionModel(0.001)` 全局统一 | 避免老 dds 双 API 折中 |
| Bulge 处理 | 入口 tessellate；不修改源图元 | 干净分层 |
| 步长策略 | `Adaptive` 默认；保留 `Fixed(20)` 兼容 | 既现代又向后兼容 |
| Service 状态 | 全部封装到 `NewDdsContext`，Service stateless | 修老 dds #10 跨多段线污染 |
| 金标格式 | JSON；含输入顶点 + Bulge + 期望标注 | 可版本化 / 可比对 |
| 命令注册 | 用 hycad-new-command-registration skill 走 N1~N50 占位 | 标准流程 |
| 与 ClusterPanel 后处理器共用 | 本期**不共用**；Phase 4 写"未来共用"标记 | 避免本期跨 Feature 改动 |
| 钢筋绘制部分 | **本期不做** | dds 设计初心的另一半留独立命令 |

## 11. 关键设计原则（与 06 §14 互补）

1. **金标先于重构**——Phase 0 的 5 张图先行；没有金标就不能动算法。
2. **接口先于实现**——Phase 1 把 Domain 数据 + 接口定齐；Phase 2~6 只填充。
3. **Service stateless**——所有可变状态进 `NewDdsContext`。
4. **范式一致**——严格 S1a 解析式直接派生；不引入候选枚举或迭代收敛。
5. **Q 仅校核不选择**——评分卡只读，不影响生成结果。
6. **配置解耦但兼容**——Adapter 模式：内部用 NewDdsConfig，外部仍读钢筋面板。
7. **绑回源对象**——XData 写 SourcePolylineId / FeatureSignature / ConfigSnapshot 三件套。
8. **失败整体回滚**——单 Transaction 写入；任何阶段抛异常 Abort。
9. **诊断日志先行**——safetyCounter 等"代码味道"位置全部加诊断输出。
10. **不破坏老命令**——老 dds / ddss 完全不动是铁律。
