## 1. 先分清三个名字

| 名称 | 是什么 | 典型入口 |
|------|--------|----------|
| **Cursor Agent** | Cursor IDE 内置的 AI 编程助手（Chat / Agent 模式） | 侧边栏 Agent、`Ctrl+L`、Composer |
| **Claude Code** | Anthropic 出品的终端/IDE 插件 AI 编程工具 | `claude` CLI、VS Code 插件 |
| **Claudeception** | 本仓库自定义的「任务完成后自动提炼 Skill」机制 | `.cursor/rules/03-claudeception.mdc` |

三者**不是同一个程序**，但可以通过 **AGENTS.md / CLAUDE.md / Skills 开放标准** 共享大部分项目级配置。

**本文重点**：在 Cursor 中如何通过 **Rules + Skills** 定制 Agent；以及如何与 Claude Code 共用同一套仓库配置。

## 2. 在 Cursor 里怎么用 AI 写代码

### 2.1 主要模式

| 模式 | 用途 | 是否改文件 |
|------|------|------------|
| **Ask / 问答** | 解释代码、查文档、只读分析 | 否 |
| **Agent** | 多步任务：改码、编译、跑命令、写文档 | 是 |
| **Composer** | 大范围编辑、跨文件重构 | 是 |
| **Inline Edit** | 选中代码块局部修改 | 是 |

### 2.2 Agent 启动时自动加载的内容（由近到远）

```
内置系统提示（不可改）
  ↓
Team Rules（团队/企业，若有）
  ↓
Project Rules（.cursor/rules/*.mdc）
  ↓
User Rules（Cursor Settings → Rules）
  ↓
AGENTS.md / CLAUDE.md（项目根，始终生效）
  ↓
Skills 摘要列表（按 description 供 Agent 选择；完整正文按需加载）
  ↓
当前对话 + @ 引用的文件/规则/Skill
```

### 2.3 手动附加上下文

| 操作 | 效果 |
|------|------|
| `@文件名` | 把文件内容拉进上下文 |
| `@Codebase` | 语义搜索整个仓库 |
| `@Docs` | 引用已索引的外部文档 |
| `@规则名` | 强制加载某条 Project Rule |
| `@skill-name` | 强制加载某个 Skill 全文 |
| `/skill-name` | 以 Skill 工作流启动（斜杠命令） |
| `/create-rule` | 让 Agent 生成 `.mdc` 规则 |
| `/create-skill` | 让 Agent 生成 Skill 目录 |
| `/migrate-to-skills` | 把符合条件的 Rule/Command 批量迁为 Skill |

## 3. 配置体系全景图

```
┌─────────────────────────────────────────────────────────────┐
│                    Cursor 配置层级                           │
├─────────────────────────────────────────────────────────────┤
│ ① Team Rules        │ Cursor 云端/dashboard │ 全员/可选      │
│ ② Project Rules     │ .cursor/rules/*.mdc   │ Git 共享 ✅    │
│ ③ User Rules        │ Settings → Rules      │ 本机私有 ❌    │
│ ④ AGENTS.md         │ 项目根                │ Git 共享 ✅    │
│ ⑤ CLAUDE.md         │ 项目根（Claude 主读） │ Git 共享 ✅    │
│ ⑥ Legacy            │ .cursorrules          │ 已弃用         │
├─────────────────────────────────────────────────────────────┤
│ Skills（按需加载，非「始终全文」）                             │
│  • 项目：.cursor/skills/<name>/SKILL.md                     │
│  • 全局：~/.cursor/skills/<name>/SKILL.md                    │
│  • 兼容：.claude/skills/、~/.claude/skills/、.codex/skills/ │
│  • 内置：~/.cursor/skills-cursor/  （Cursor 系统自带，勿改）  │
└─────────────────────────────────────────────────────────────┘
```

**冲突优先级（Rules）**：

```
Team Rules  >  Project Rules  >  User Rules  >  Legacy .cursorrules
```

多条 Rule **会合并**；冲突时优先级高的覆盖低的。

## 4. Rules（规则）详解

### 4.1 是什么

Rules 是**短而硬的约束**：编码规范、禁止事项、项目约定、输出格式。适合「每次（或匹配文件时）都要遵守」的内容。

### 4.2 存放位置

| 类型 | 路径 | 格式 |
|------|------|------|
| 项目规则 | `<repo>/.cursor/rules/*.mdc` | 必须 `.mdc` + YAML frontmatter |
| 用户规则 | Cursor → **Settings → Rules → User Rules** | 纯文本，无文件 |
| 团队规则 | Cursor Dashboard（Team/Enterprise） | 云端下发 |
| 简易替代 | `<repo>/AGENTS.md` | 纯 Markdown，始终生效 |
| Claude 兼容 | `<repo>/CLAUDE.md` | Claude Code 主读；Cursor 也会加载 |

> **注意**：`.cursor/rules/` 下的 plain `.md` **没有 frontmatter 时会被 Rules 系统忽略**。需要条件激活请用 `.mdc`。

### 4.3 `.mdc` 文件结构

```markdown
---
description: 简短说明（供 Agent 判断是否加载）
globs: src/**/*.cs          # 可选：文件匹配时才自动附加
alwaysApply: true           # true = 每条对话都加载
---

# 规则标题

正文：约束、清单、示例……
```

### 4.4 四种激活方式

| alwaysApply | globs | description | 行为 |
|:-----------:|:-----:|:-----------:|------|
| `true` | — | — | **始终加载**（globs/description 被忽略） |
| `false` | 有 | — | 上下文含匹配文件时**自动附加** |
| `false` | 无 | 有 | Agent 根据 description **智能选用** |
| `false` | 无 | 无 | **仅** `@规则名` 手动引用时加载 |

### 4.5 创建与维护

**方式 A — 对话生成**

```
/create-rule
请写一条规则：WPF XAML 禁止 StaticResource 跨字典引用
```

**方式 B — UI**

`Customize`（侧边栏）→ `Rules` → `Add Rule`

**方式 C — 手写**

直接在 `.cursor/rules/` 新建 `xx-主题.mdc`。

### 4.6 最佳实践

- **单条规则单一主题**，建议正文 ≤ 500 行，理想 ≤ 50 行
- **alwaysApply: true 要克制**：每条都占上下文 token；只放「全项目强制」项
- **长流程不要写进 Rule**：迁到 Skill，Rule 只留一句指针（见本仓库 `06-新命令注册流程.mdc`）
- **编号命名**：如 `00-`、`01-` 便于排序与 @ 引用

## 5. Skills（技能）详解

### 5.1 是什么

Skills 是**可复用的多步骤工作流**：部署、代码审查、新命令注册、产品调研、陷阱清单等。比 Rule 更长、更 procedural，**按需加载**以节省上下文。

### 5.2 目录结构

```
.cursor/skills/
  hycad-new-command-registration/
    SKILL.md              ← 必需入口
    reference.md          ← 可选
    examples.md           ← 可选
    scripts/              ← 可选，可执行脚本
      validate.ps1
```

**Skill 名称** = 包含 `SKILL.md` 的那一层文件夹名（不是上层分类文件夹名）。

### 5.3 `SKILL.md` 结构

```markdown
---
name: my-skill-name          # 小写+连字符，≤64 字符
description: |
  第三人称描述：(1) 做什么 (2) 何时触发 (3) 技术栈关键词
  Agent 靠 description 决定是否自动加载。
paths:                       # 可选：仅匹配文件时 surfaced
  - "src/**/*.cs"
disable-model-invocation: true   # 可选：仅 / 或 @ 显式调用时加载
---

# Skill 标题

## 步骤 1 …
## 步骤 2 …
```

| 字段 | 作用 |
|------|------|
| `name` | 斜杠命令名、`@` 引用名 |
| `description` | **最关键**：写清 WHAT + WHEN + 触发关键词 |
| `paths` | glob 限定作用域（monorepo 子目录 Skill 也支持物理路径隔离） |
| `disable-model-invocation` | 为 `true` 时禁止 Agent 自动选用，只能手动 `/name` 或 `@name` |

### 5.4 发现路径（Cursor 会自动扫描）

| 作用域 | 路径 |
|--------|------|
| 项目 | `.cursor/skills/`、`.agents/skills/` |
| 全局 | `~/.cursor/skills/`、`~/.agents/skills/` |
| Claude 兼容 | `.claude/skills/`、`~/.claude/skills/` |
| Codex 兼容 | `.codex/skills/`、`~/.codex/skills/` |
| Monorepo 子项目 | `apps/web/.cursor/skills/` → 仅 `apps/web/**` 文件时 surfaced |
| **禁止写入** | `~/.cursor/skills-cursor/` ← Cursor 内置，勿手动创建 Skill |

### 5.5 使用方式

| 方式 | 示例 | 说明 |
|------|------|------|
| 斜杠调用 | `/hycad-new-command-registration` | 显式跑完整工作流 |
| @ 附加 | `@hycad-project-pitfalls` | 把 Skill 全文拉进上下文 |
| 自然语言触发 | 「帮我注册新命令 N12」 | Agent 读 description 自动选 Skill |
| 对话生成 | `/create-skill` | 交互式创建 |
| 批量迁移 | `/migrate-to-skills` | 把「动态 Rule」和 slash command 迁成 Skill |

### 5.6 最佳实践

- `description` 用**第三人称**，含错误信息/命令名等触发词
- 正文 ≤ 500 行；细节放 `reference.md`，Skill 只保留步骤骨架
- **一条 Skill 一个工作流**，不要与 Rule 重复同一套禁令
- 验证过的项目陷阱、排障链 → Skill（本仓库 `hycad-project-pitfalls` 即范例）

## 6. Rules 与 Skills 怎么选、会不会混淆

### 6.1 对照表

| 维度 | Rules | Skills |
|------|-------|--------|
| **目的** | 始终遵守的约束 / 风格 / 禁止项 | 多步骤可重复工作流 |
| **长度** | 短（几行～几百行） | 长（步骤、清单、脚本） |
| **加载** | 按 alwaysApply / globs / 智能 / @ | 按 relevance 或 `/` `@` 显式 |
| **上下文成本** | alwaysApply 的每条常驻 | 摘要常驻，全文按需 |
| **适合** | 「禁止」「必须」「默认语言」 | 「注册命令四步」「代码审查流程」 |
| **文件** | 单文件 `.mdc` | 目录 + `SKILL.md` (+ 附件) |
| **frontmatter** | `alwaysApply` / `globs` / `description` | `name` / `description` / `paths` |

### 6.2 会不会混淆？

**会，主要在三种情况：**

1. **同一指令写两份**（Rule 和 Skill 各一份）→ 浪费 token；若表述不一致，**Rule 优先于 Skill 的软性指导**
2. **把长流程塞进 alwaysApply Rule** → 每条对话都占上下文，应拆成 Skill + 短 Rule 指针
3. **目录放错** → 例如 Skill 写到 `~/.cursor/skills-cursor/` 会被系统覆盖；Rule 写成 plain `.md` 无 frontmatter 则不生效

### 6.3 推荐组合模式（本仓库已采用）

```
Rule（alwaysApply: false + 短 description）
  └── 「完整步骤见 @hycad-new-command-registration」

Skill（SKILL.md 含完整流程、模板、排障）
```

示例：`.cursor/rules/06-新命令注册流程.mdc` 仅 10 行指针 → Skill 132 行细节。

### 6.4 Claudeception：Rule 驱动 Skill 产出

`.cursor/rules/03-claudeception.mdc`（alwaysApply: true）规定：

- 任务完成后评估是否值得提炼经验
- 值得 → 写入 `.cursor/skills/<新名>/SKILL.md`
- 这是 **「用 Rule 规范 Skill 的创建」**，不是第三种配置类型

## 7. 目录对照表：放哪里、谁读、能否 Git 共享

| 路径 | 类型 | Cursor | Claude Code | Git 提交 | 说明 |
|------|------|:------:|:-----------:|:--------:|------|
| `.cursor/rules/*.mdc` | Project Rule | ✅ | 部分兼容 | ✅ | 团队共享的主规则位 |
| `.cursor/skills/*/SKILL.md` | Project Skill | ✅ | ✅（或通过 symlink） | ✅ | 工作流共享 |
| `.cursor/settings.json` | 插件/扩展配置 | ✅ | — | ✅ | 本仓库仅 Figma 插件开关 |
| `AGENTS.md` | 项目说明 | ✅ 始终 | ✅ | ✅ | 跨工具开放标准 |
| `CLAUDE.md` | 项目说明 | ✅ | ✅ 主读 | ✅ | 可与 AGENTS.md symlink |
| `.cursorrules` | Legacy Rule | ✅ | — | ✅ | **弃用**，请迁移 |
| `Settings → User Rules` | User Rule | ✅ | — | ❌ | 本机私有，换机需手抄 |
| `~/.cursor/skills/` | Global Skill | ✅ | — | ❌ | 个人跨项目 Skill |
| `~/.claude/skills/` | Global Skill | ✅ 兼容读 | ✅ | ❌ | Claude 全局 Skill |
| `~/.cursor/skills-cursor/` | 内置 Skill | ✅ | — | ❌ | **禁止用户写入** |
| `docs/rules/*.md` | 人类文档镜像 | ❌ 不自动读 | ❌ | ✅ | 仅文档，非 Agent 配置 |

> **`docs/rules/` 与 `.cursor/rules/` 不是同一东西**：前者是本仓库早期文档归档；Agent 只认后者。

## 8. 团队协作：共享什么、各自保留什么

### 8.1 应提交 Git 的（团队一致）

```
.cursor/rules/
.cursor/skills/
.cursor/settings.json          # 若含团队统一插件配置
AGENTS.md                      # 推荐作为跨工具入口
CLAUDE.md                      # 若团队也用 Claude Code
```

### 8.2 不应依赖 Git 的（个人偏好）

| 配置 | 原因 | 协作做法 |
|------|------|----------|
| User Rules | 存在 Cursor 本地数据库，不导出 | 重要约束写成 Project Rule |
| `~/.cursor/skills/` | 用户主目录 | 迁到项目 `.cursor/skills/` |
| 模型/API 密钥 | Settings → Models | 各自配置，不入库 |

### 8.3 Team Rules（Team / Enterprise）

- 管理员在 Cursor Dashboard 创建
- 可设 **Enforced（强制）** 或 **Optional（可关）**
- 支持 `globs` 按文件类型下发
- 优先级高于 Project Rules

### 8.4 Remote Rules（GitHub 导入）

`Settings → Rules → Add Rule → Remote Rule (GitHub)`

- 适合多仓库共用一套规则源
- Agent **可以**编辑项目内 `.mdc`；**不能**直接改 User Rules（无文件）

### 8.5 协作约定建议（HyCADTool）

1. **强制流程** → `alwaysApply: true` 的 Project Rule（如 `00-AI 工作规则.mdc`）
2. **领域工作流** → Skill + 短 Rule 指针
3. **个人习惯**（如「Always respond in Chinese」）→ User Rules 或写入 `00` 号 Project Rule 统一
4. **新成员 onboarding**：读本文 + `@01-AI热启动模式` Rule + `@hycad-project-pitfalls` Skill

## 9. Cursor 与 Claude Code 双工具共存

### 9.1 文件映射

| Claude Code | Cursor | 操作 |
|-------------|--------|------|
| `CLAUDE.md` | `AGENTS.md` | 内容相同；可 `AGENTS.md` 为主，`CLAUDE.md` symlink |
| `.claude/skills/` | `.cursor/skills/` | Skill 格式相同；可 symlink 一份 |
| `.claude/commands/` | `.cursor/commands/` | 需去掉 CC 专有 frontmatter |
| 全局 `~/.claude/CLAUDE.md` | User Rules | **需手动复制**到 Cursor Settings |

### 9.2 Windows  symlink 示例（PowerShell 管理员）

```powershell
# 项目根：让 Claude Code 与 Cursor 共用 AGENTS.md
cd E:\path\to\hy-cad-tool
New-Item -ItemType SymbolicLink -Path AGENTS.md -Target CLAUDE.md

# Skills 共用（二选一为主目录）
New-Item -ItemType SymbolicLink -Path .cursor\skills -Target ..\.claude\skills
```

### 9.3 Skill frontmatter 兼容性

- Cursor Skill 推荐带 YAML frontmatter（`name`、`description`、`paths`）
- Claude Code 读 Skill 时**主要读 Markdown 正文**，frontmatter 通常可共存
- **以 Cursor 格式为准**写一份，两边都能用

## 12. 排障与反模式

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| Rule 不生效 | 文件是 `.md` 且无 frontmatter | 改 `.mdc` 并加 YAML |
| Skill 找不到 | 目录名与 `name` 不一致；放错 `skills-cursor` | 检查路径与 `SKILL.md` 位置 |
| Agent 不遵守规范 | 约束只在 User Rules，队友没有 | 提升到 Project Rule |
| 上下文爆炸 | 过多 `alwaysApply: true` | 改为 globs 或 Skill |
| Rule 与 Skill 冲突 | 两处表述不同 | 删重复；Rule 写硬性，Skill 写流程 |
| 换电脑丢失偏好 | User Rules 不随 profile 导出 | 写入 Project Rule 或 AGENTS.md |
| Claude Code 读不到 Cursor 规则 | 只有 `.cursor/rules` 没有 AGENTS.md | 补 AGENTS.md 或 symlink |
| Agent 改不了全局规则 | User Rules 不在磁盘 | 让 Agent 写 `.cursor/rules/` |

### 反模式清单

- ❌ 同一禁令同时写 Rule + Skill 全文
- ❌ 10 条 alwaysApply 各 200 行
- ❌ 在 `~/.cursor/skills-cursor/` 手建 Skill
- ❌ 把 `docs/rules/` 当 Agent 配置（Agent 不读）
- ❌ 用 `.cursorrules` 新项目（应迁移 `.mdc`）
