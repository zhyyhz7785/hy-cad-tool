本文档回答当前最现实的问题:

1. **HYFEA 是否应该和 HyCADTool 彻底分开?**
2. **第一步到底建什么目录、哪些模块、哪些暂时不建?**
3. **在只有本人 + AI 协助的阶段,评估流程如何足够可靠但不过度工程化?**
4. **怎样保留未来扩充空间,但不把未来多人协作的复杂机制提前压到 P0?**

***

## 0. 结论先行

### 0.1 HYFEA 不应和 HyCADTool 仓库彻底分开,但必须和 AutoCAD/WPF/ReCall 依赖彻底分开

推荐方案是:

> **同仓库、独立项目、单向依赖。**

也就是:

```text
hy-cad-tool 仓库
├── src/HYFEA/                         # 新增:纯有限元内核,不引用 AutoCAD
│   ├── HYFEA.Core/
│   ├── HYFEA.Tests/
│   └── HYFEA.Examples/
└── src/HyCADTool/                     # 既有:AutoCAD 插件、面板、命令
    └── Features/Fem/                  # 只做 HYFEA 与 HyCADTool 的适配
```

依赖方向只允许:

```text
HyCADTool.Features.Fem  -->  HYFEA.Core
HYFEA.Core              -X-> HyCADTool
HYFEA.Core              -X-> AutoCAD API
HYFEA.Core              -X-> WPF / PaletteSet / ReCall
```

这比“完全放在 `src/HyCADTool/Features/Fem/Core` 里”更干净,也比“一开始另开仓库”更轻。

### 0.2 为什么不是现在就彻底分仓

当前只有本人主导 + AI 协助,最重要的是**快速形成可运行闭环**。如果现在单独建仓库,会立刻增加这些负担:

| 负担                                      | 当前是否值得 |
| --------------------------------------- | ------ |
| 单独 solution / build / package / version | 暂不值得   |
| NuGet 打包与本地源管理                          | 暂不值得   |
| 跨仓库 issue / commit / 文档同步               | 暂不值得   |
| HyCADTool 与 HYFEA 版本兼容矩阵                | 暂不值得   |

但是 HYFEA 必须从第一天就做到**源码边界可分离**。后期要分仓时,只需要把 `src/HYFEA/` 整体搬走,HyCADTool 改成引用 NuGet 或 project package。

### 0.3 004 的“双轨机制”在 P0 阶段降级

004 的完整机制面向长期扩展,包含 Track A/B、Fitness、自动晋升、贡献者流程、Leaderboard。当前阶段不要全做。

P0 只保留三件事:

1. **统一接口**:每个核心模块先有清晰输入输出。
2. **金标准算例**:少量但严格,用于判断是否写对。
3. **个人评估记录**:本人拍板,AI 辅助整理证据。

暂不做:

| 机制                  | P0 处理      |
| ------------------- | ---------- |
| 自动晋升 PR             | 不做         |
| 每周 CI 评估            | 不做         |
| ContributorPipeline | 不做         |
| Leaderboard         | 不做         |
| 11 维复杂 Fitness      | 降为 5 维手工评分 |

## 一、HYFEA 与 HyCADTool 的关系

### 1.1 名称定位

| 名称            | 定位             | 应该包含                        | 不应该包含                                   |
| ------------- | -------------- | --------------------------- | --------------------------------------- |
| **HYFEA**     | 有限元内核与计算底座     | FEM 模型、网格、单元、材料、装配、求解、结果、验证 | AutoCAD 命令、WPF 面板、DWG、PaletteSet、ReCall |
| **HyCADTool** | AutoCAD 工程插件产品 | CAD 选择、几何读取、图层标签、面板交互、结果出图  | FEM 数值内核细节                              |

HYFEA 是“发动机”,HyCADTool 是“驾驶舱 + 车身 + 施工图工作流”。

### 1.2 三种拆分方案对比

| 方案                                    | 结构        | 优点             | 缺点                      | 结论     |
| ------------------------------------- | --------- | -------------- | ----------------------- | ------ |
| A. 完全放进 `HyCADTool/Features/Fem/Core` | 一个项目内完成   | 最快             | 很容易把 AutoCAD/WPF 依赖漏进内核 | 不推荐    |
| B. 现在就单独仓库 `hyfea`                    | 完全独立      | 边界最干净          | 当前构建、调试、版本、文档成本过高       | 暂缓     |
| C. 同仓库独立项目 `src/HYFEA`                | 仓库同源、项目独立 | 边界清晰,迁移简单,调试方便 | 需要守住依赖方向                | **推荐** |

### 1.3 不可破坏的依赖规则

HYFEA P0 开始就写入工程约束:

```text
HYFEA.Core 可以引用:
- System.*
- Microsoft.Extensions.* 中与宿主无关的基础包
- 轻量数值库,如 CSparse.NET 或 Math.NET Numerics

HYFEA.Core 禁止引用:
- Autodesk.AutoCAD.*
- AdWindows
- PresentationFramework / WPF
- HyCADTool.Shell
- HyCADTool.App
- ReCall
```

如果某个功能需要 AutoCAD,它就不属于 HYFEA.Core,而属于:

```text
src/HyCADTool/Features/Fem/Integration/
```

## 二、第一步的真实目标

### 2.1 P0 不做“通用有限元软件”,只做“最小可信 FEM 闭环”

第一步的目标不是 ANSYS、ABAQUS、CalculiX 的缩小版,而是:

> **用最少代码跑通一条可验证的 FEM 链路:建模 → 自由度编号 → 装配 → 约束 → 求解 → 结果 → 金标准对比。**

P0 成功的判断不是功能多,而是这条链路可信。

### 2.2 P0 的第一个可运行目标

推荐第一个目标:

```text
HYFEA P0.v0.1:
2D Truss / Spring / Beam 最小线弹性静力分析
```

原因:

| 原因       | 说明                                           |
| -------- | -------------------------------------------- |
| 数学简单     | 刚度矩阵可手算,适合第一批金标准                             |
| 能覆盖核心流水线 | 节点、自由度、单元、材料、荷载、约束、装配、求解全部会出现                |
| 不需要网格生成  | 避免一开始陷入 Gmsh / Triangle.NET                  |
| 不需要复杂材料  | 先验证系统架构,不是验证土塑性                              |
| 能自然升级    | 下一步可接 Beam2D、Quad4、PlaneStrain、RetainingWall |

### 2.3 P0 的非目标

以下内容明确不进入第一步:

| 非目标                     | 推迟原因                    |
| ----------------------- | ----------------------- |
| 3D 实体单元                 | 太早,会把 L3 复杂度提前拉满        |
| Mohr-Coulomb / Cam-Clay | 先等线弹性流水线稳定              |
| 接触                      | L3 最大坑之一,绝不作为 P0        |
| MUMPS / PETSc / HYPRE   | 00L4 已说明重要,但 P0 用轻量求解即可 |
| Gmsh / CalculiX 子进程     | P1/P2 再接                |
| WPF 面板                  | P0 先命令行 / 测试工程跑通        |
| AutoCAD 选图建模            | 等 HYFEA.Core 自己证明正确后再接  |

## 五、P0 目录内各模块职责细化

### 5.1 `Model/`

职责:

* 定义 `FemProblem` 作为唯一输入 IR。

* 定义 `FemNode`、`FemElementDefinition`、`MaterialDefinition`。

* 使用稳定 ID,不要直接用数组下标作为外部身份。

P0 原则:

```text
外部身份:NodeId / ElementId / MaterialId
内部求解:连续 int index
```

### 5.2 `Dofs/`

职责:

* 把节点自由度映射到全局方程编号。

* 管理约束自由度与自由自由度。

* 生成装配所需的 element dof map。

P0 只支持:

```text
Truss2D:UX, UY
Spring1D:UX
```

P1 再支持:

```text
Beam2D:UX, UY, RZ
Plane2D:UX, UY
```

### 5.3 `Elements/`

职责:

* 每个单元只负责本单元刚度、等效荷载、单元结果。

* 单元不关心全局矩阵、不关心求解器、不关心 CAD。

P0 第一单元:

```text
Truss2D:
输入:两个节点坐标、E、A
输出:4x4 全局坐标刚度矩阵
```

### 5.4 `Assembly/`

职责:

* 遍历元素。

* 调用单元刚度。

* 通过 DOF map 写入全局矩阵。

* 应用边界条件。

P0 可以先用 Dense matrix,但接口要允许后续换 COO/CSR。

推荐顺序:

```text
DenseAssemblyResult
-> CooAssemblyResult
-> CsrAssemblyResult
```

### 5.5 `Solvers/`

职责:

* 接收已装配线性系统。

* 返回位移、反力、诊断。

P0 默认:

```text
DenseLinearSolver
```

P1 替换或并行:

```text
CSparseLinearSolver
```

注意:00L4 的 MUMPS/PARDISO/HYPRE/PETSc 先不进入 P0。P0 需要的是正确性闭环,不是性能天花板。

### 5.6 `Validation/`

职责:

* 定义 golden case。

* 运行分析。

* 对比期望位移/反力/单元力。

* 输出 `ValidationReport`。

这是 P0 最重要的模块之一。没有验证,HYFEA 只是“能跑”,不是“可信”。

## 六、个人评估流程

### 6.1 P0 评估原则

当前阶段不需要多人评审、不需要自动晋升、不需要复杂 CI。评估由本人拍板,AI 协助做:

1. 整理候选方案。
2. 生成对比表。
3. 跑/记录 golden case。
4. 检查接口是否变复杂。
5. 形成评估记录。

### 6.2 5 维手工评分

每次评估一个模块或方案,只打 5 维:

| 维度   | 权重  | 问题                        |
| ---- | --- | ------------------------- |
| 正确性  | 40% | golden case 是否通过?误差是否可解释? |
| 简洁性  | 25% | 代码是否能在 30 分钟内读懂主流程?       |
| 可扩展性 | 15% | 下一步加 Beam2D/Quad4 是否要推翻?  |
| 可诊断性 | 10% | 错了能否知道错在哪里?               |
| 性能余量 | 10% | 对 P0 规模是否足够?有没有明显灾难?      |

P0 不做 11 维 Fitness。11 维属于后期模块候选多起来后的升级版。

### 6.3 个人评估记录模板

每次关键选择写一份简短记录即可:

```markdown
## HYFEA 个人评估记录

日期:
评估对象:
候选方案:

### 结论

采用:
暂缓:
放弃:

### 评分

| 方案 | 正确性40 | 简洁性25 | 可扩展15 | 可诊断10 | 性能10 | 总分 |
|------|----------|----------|----------|----------|--------|------|

### 证据
```

## 七、P0 金标准算例

### 7.1 第一批 5 个 golden case

| 编号  | 案例          | 目的           | 期望结果来源             |
| --- | ----------- | ------------ | ------------------ |
| G01 | 单弹簧一端固定一端受力 | 验证约束、求解、反力   | 手算 `u=F/k`         |
| G02 | 两弹簧串联       | 验证装配与等效刚度    | 手算 `1/k=1/k1+1/k2` |
| G03 | 两杆 2D 桁架    | 验证方向余弦、坐标变换  | 教材例题/手算            |
| G04 | 对称桁架竖向荷载    | 验证对称性与反力平衡   | 结构力学手算             |
| G05 | 悬臂梁端部集中力    | 验证 Beam2D 阶段 | `δ=PL^3/(3EI)`     |

P0.v0.1 只要求 G01-G04。G05 等 `EulerBeam2D` 加入后再启用。

### 7.2 验收容差

| 数据       | P0 容差                         |
| -------- | ----------------------------- |
| 位移       | 相对误差 `1e-9` 或绝对误差 `1e-12`     |

| 单元轴力     | 相对误差 `< 1e-8`                 |
| 对称案例左右结果 | 差值 `< 1e-10`                  |

P0 模型很小,容差可以严格。后期接稀疏/迭代求解再放宽。

## 十、编码风格与边界约束

### 10.1 P0 编码原则

| 原则          | 说明                     |
| ----------- | ---------------------- |
| 小 record 优先 | FEM 数据天然适合不可变输入        |
| 错误结构化返回     | 求解失败、约束错误、奇异矩阵不要只抛普通异常 |
| 先可读,后性能     | P0 矩阵很小,可读性优先          |
| 单元不碰全局      | 单元只返回局部贡献              |
| 求解器不懂单元     | 求解器只看矩阵和向量             |
| 测试就是文档      | 每个 golden case 都是最小教程  |

### 10.2 禁止事项

P0 代码中禁止:

```text
Autodesk.AutoCAD.*
System.Windows.*
PaletteSet
ReCall
反射调用 HyCADTool
为了未来功能提前写空壳大框架
```

### 10.3 允许的简化

P0 可以接受:

| 简化                | 原因          |
| ----------------- | ----------- |
| Dense matrix      | 模型小,便于调试    |
| 手写网格              | 避免网格生成拖慢第一步 |
| 只支持 SI/mm 单位约定文档化 | 不先做单位系统     |
| 只支持线弹性            | 先验证流水线      |
| 只支持单工况            | 组合/阶段后续再加   |

## 十一、最终判断

HYFEA 与 HyCADTool 的关系应该是:

> **产品不分家,内核必须分层。**

当前不需要单独仓库,也不应该把 HYFEA 写成 HyCADTool 的一个普通 Feature 子文件夹。最佳第一步是在同一仓库中新增 `src/HYFEA/`,用独立 `.csproj` 建纯 FEM 内核。HyCADTool 以后只通过适配层消费它。

第一阶段不要被 00L4 的完整求解器后端、004 的完整双轨机制、L3 的单元材料大山吓住。P0 只做一件事:

> **把一个极小线弹性结构问题从** **`FemProblem`** **稳定算到** **`FemResult`,并用 golden case 证明它是对的。**

只要这条链路成立,后面的 Beam2D、Quad4、CSparse、CalculiX、HyCADTool 面板接入,都会有清晰的落点。
