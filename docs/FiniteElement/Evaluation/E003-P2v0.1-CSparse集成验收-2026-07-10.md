## §4 技术实现亮点

### §4.1 稀疏三元组装配

**设计决策**: 使用 `List<SparseTriplet>` 而非 `Dictionary`
- **优点**: 自动累加重复索引（CSparse.NET 会处理）
- **性能**: O(1) 添加，无哈希开销
- **容量**: 预分配 `7 × elementCount`（典型单元 7 非零元）

**代码示例**:
```csharp
var triplets = new List<SparseTriplet>(7 * problem.Elements.Count);
foreach (var elem in problem.Elements)
{
    var contrib = registry.Get(elem.Type);
    var Ke = contrib.ComputeStiffness(elem, ...);
    var dofMap = layout.GetElementDofIndices(elem);
    
    for (int i = 0; i < Ke.Rows; i++)
        for (int j = 0; j < Ke.Cols; j++)
            if (Math.Abs(Ke[i, j]) > 1e-14)
                triplets.Add(new SparseTriplet(dofMap[i], dofMap[j], Ke[i, j]));
}
```

### §4.2 CSparse.NET 集成

**关键 API**:
1. `CoordinateStorage<double>` - 三元组格式（COO）
2. `CompressedColumnStorage<double>.OfIndexed()` - COO → CSC 转换
3. `SolveCholesky()` - 对称正定求解器

**错误处理**:
```csharp
try
{
    var x = A.SolveCholesky(b);
    if (x == null || x.Any(double.IsNaN))
        return new SolveResult(false, ...);
}
catch (Exception ex)
{
    return new SolveResult(false, new FemError(..., ex.Message), null);
}
```

### §4.3 分析流程统一

**稀疏分析** (`SparseLinearStaticAnalysis`) 与 **稠密分析** (`LinearStaticAnalysis`) 共享:
- `DofLayout` 构建逻辑
- 单元贡献计算（通过 `IElementContribution`）
- 位移扩展和反力计算算法
- 单元内力恢复逻辑

**差异点**:
- 装配器: `SparseAssembler` vs `Assembler`
- 求解器: `CSparseLinearSolver` vs `DenseLinearSolver`
- 数据结构: `List<SparseTriplet>` vs `DenseMatrix`

## §6 遗留问题与改进方向

### §6.1 已知限制

1. **仅支持对称正定系统**
   - Cholesky 求解器要求矩阵对称正定
   - 非对称问题（如对流-扩散）需 LU 分解
   - **影响**: 当前结构分析均满足，非问题

2. **缺乏求解器选择机制**
   - 稀疏/稠密求解器需手动选择类
   - 无统一 `ILinearSolver` 接口
   - **计划**: P2.v0.2 实现 `ILinearSystemSolver` 接口

3. **无性能监控**
   - 缺乏装配/求解时间分解
   - 无内存占用追踪
   - **计划**: P2.v0.3 添加 `SolveDiagnostics`

### §6.2 代码质量改进

1. **重复代码**
   - `SparseLinearStaticAnalysis` 与 `LinearStaticAnalysis` 80% 代码重复
   - **建议**: P2.v0.2 提取公共逻辑到 `AnalysisCore`

2. **测试覆盖**
   - 缺乏奇异矩阵测试
   - 缺乏非对称矩阵错误处理测试
   - **建议**: 补充单元测试
