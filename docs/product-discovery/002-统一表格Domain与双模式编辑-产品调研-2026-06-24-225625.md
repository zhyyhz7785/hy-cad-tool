## 1. 产品愿景（完善你的 5 点思路）

### 1.1 总体公式

```
复杂表格产品 = 结构层（像 Word 做版式） + 数据层（像 Excel 填值） + 多端渲染（MD / CAD / XLSX）
```

### 1.2 对你 5 点的正式表述

| # | 你的思路 | 完善后的产品语言 | 关键约束 |
|---|---|---|---|
| **1** | Word 一样做复杂表 + Excel 基本功能 | **结构编辑**负责网格/合并/斜线/边框/竖排；**填值编辑**负责文本/数字/公式/复制填充 | 两种模式 UI 分离，Domain 合一 |
| **2** | 先做 Domain，用于 MD / CAD / Excel | **`GridTableDocument`** 为唯一真相源；各端为 **Adapter（适配器）** | Domain 层零 AutoCAD/Markdown 依赖 |
| **3** | 基础单元可斜线分成两格；可 merge/split | **原子格（AtomicCell）** 不可删除，只能 **隐藏边界** 或 **斜线二分** | 斜线分割产生 **子格 ID**，仍挂在原子格下 |
| **4** | 合并后底层仍是原格；显示合一；值可多个相同 | **MergeSpan** 仅为视图分组；存储用 **主格（Anchor）+ 镜像格（Mirror）** 策略 | 见 §2.3 |
| **5** | CAD 开编辑模式画线成表；关模式像 Table | **结构模式 ON**：线框编辑 + 拓扑识别 → 更新 Domain；**定稿模式 OFF**：渲染为原生 Table / Block | 定稿后默认锁定结构，仅填值 |

### 1.3 能力边界（Excel / Word / AutoCAD 对照）

| 能力 | Word | Excel | AutoCAD TABLE | **本方案目标** |
|---|---|---|---|---|
| 任意 merge/unmerge | ✔ | ✔（丢数据风险） | ✔（有 Title 暗坑） | ✔ 基于原子格，unmerge 可恢复 |
| 斜线表头（单元格对角分割） | ✔ | △ 近似 | △ 需自绘 | ✔ Domain 一级支持 |
| 竖排侧栏（一字一行） | ✔ | △ | △ | ✔ 作为 TextFlow 样式 |
| 公式 / 填充柄 | △ | ✔ | △ 弱公式 | ✔ 填值模式：基础公式 + 复制 |
| 从线段自动生成表格 | ✗ | ✗ | ✗ | ✔ **CAD 结构模式** |
| Markdown 表格 | △ 导出 | △ | ✗ | ✔ 简单表可导出 GFM |
| 原生 CAD 打印实体 | △ OLE | ✗ | ✔ | ✔ 定稿模式输出 Table |

**Excel 基本功能（填值模式 MVP 范围）**：文本/数字、Tab 跳格、复制粘贴矩形选区、插入/删除行列（结构联动）、简单公式（`SUM/AVERAGE/COUNT`）、对齐/数字格式。  
**不在 MVP**：数据透视、条件格式、宏、数据验证下拉（V2 可选）。

## 2. Domain 核心模型

> 建议程序集：`HyCADTool.Shared.Tables` 或 `HyCADTool/Features/Tables/Domain/`（平台无关，不引用 AutoCAD/Markdig）。

### 2.1 对象一览

```
GridTableDocument          // 文档：可含多表（对应样表 Table1 + Table2）
├── GridTable              // 单张表
│   ├── GridTopology       // 行列尺寸、线宽、表级样式
│   ├── AtomicCell[,]      // 原子网格（不可压缩）
│   ├── MergeSpan[]        // 合并视图
│   ├── DiagonalSplit[]    // 斜线分割
│   └── BorderSpec[]       // 可选：单边线型/线宽 override
└── TableMetadata          // 模板 ID、版本、来源 CAD handle 等
```

### 2.2 原子格 `AtomicCell`（基础单位）

每个原子格是 **永久存在** 的最小存储单元，对应拓扑上的一个 `(row, col)`。

```csharp
// 概念模型（示意，非最终实现）
class AtomicCell
{
    CellId Id;                    // 稳定 GUID，不随 merge 改变
    int Row, Col;                 // 在原子网格中的坐标
    CellRole Role;                // Label | Value | Header | Spacer | PhotoSlot ...
    CellContent Content;          // 见下
    CellStyle Style;              // 字体/对齐/边距/竖排
    Visibility Visibility;        // Visible | HiddenByMerge | HiddenBySplitParent
}

class CellContent
{
    ContentKind Kind;             // Empty | Text | Number | Formula | ImageRef | BlockRef
    string RawText;
    string? Formula;              // "=SUM(A1:A5)" 存 R1C1 或结构化 AST
    IReadOnlyList<TextRun> Runs;  // 富文本：仿宋 14pt 等
}
```

**要点**
- **插入/删除行列** = 对原子网格做线性代数式扩展，旧 `CellId` 尽量保留（可通过 `StableIdMap` 映射）。
- **PhotoSlot**：样表照片格 → `Role=PhotoSlot`，渲染到 CAD 时可插入占位 Block 或 OLE。

### 2.3 合并 `MergeSpan` —— 落实你的第 4 点

合并 **不删除** 原子格，只改变 **显示分组** 与 **读写策略**。

```
MergeSpan {
    AnchorCellId    // 主格：唯一权威读写入口
    MemberCellIds[] // 包含矩形区域内全部原子格 ID
    DisplayText     // 可选：合并后的显示文本（缓存）
}
```

**值的存储策略（推荐默认：Anchor + Mirror）**

| 策略 | 行为 | 适用 |
|---|---|---|
| **Anchor + Mirror（默认）** | 写入 Anchor 时，Member 格自动同步相同值；读取合并区返回 Anchor | 填值模式、Excel 导出 |
| **Anchor Only** | Member 格保持 Empty，仅 Anchor 有值 | 纯 label 合并 |
| **MultiValue Allowed** | Member 可存不同值；UI 显示冲突提示 | 高级场景 |

**Unmerge**：删除 `MergeSpan`，Member 格 `Visibility → Visible`，保留各自 Content（Mirror 策略下本相同，无需恢复）。

与 Excel 差异：Excel merge 常丢非左上格数据；本 Domain **显式保留** 所有原子格，unmerge 可逆。

### 2.4 斜线分割 `DiagonalSplit` —— 落实你的第 3 点

在 **一个原子格内部** 用对角线分成两个 **子格（SubCell）**，各自独立填值。

```
DiagonalSplit {
    ParentCellId: CellId
    Orientation: ForwardSlash | BackSlash   // / 或 \
    SubCellA: SubCellSpec   // 例如左上三角
    SubCellB: SubCellSpec   // 例如右下三角
}

SubCellSpec {
    SubCellId: Guid
    Label?: string          // 如「学历」
    Content: CellContent
    TextAnchor: NormalizedPoint  // 0..1 相对父格，控制文字位置
}
```

**样表映射**：「学历 / 学位」当前是同一格两行文字；斜线版应为：

```
┌─────────┐
│ 学历 ╲  │
│      ╲ 学位│
└─────────┘
```

→ 两个 SubCell 独立存储；渲染时在 CAD 画对角线 + 两段文字。

**限制（MVP）**
- 每个原子格 **最多 1 条** 对角线（两子格）。
- 已被 Merge 的 Member 格 **不能再** DiagonalSplit（先 split 再 merge，或仅允许 Anchor 上 split）。
- Markdown 导出：斜线表 **降级** 为多行 label 或 HTML table（GFM 不支持斜线）。

### 2.5 网格拓扑 `GridTopology`

```csharp
class GridTopology
{
    IReadOnlyList<GridTrack> RowTracks;   // 高度：pt/mm/权重
    IReadOnlyList<GridTrack> ColTracks;
    TableDirection Direction;             // Down | Up（TrueTable 倒置）
    GridLineDefaults DefaultBorder;
}
```

**CAD 结构模式反推**时：线段交点 → 推断 RowTracks/ColTracks → 生成等尺寸原子网格。

### 2.6 文档 `GridTableDocument`

- 支持 **多表**（样表 = 2 个 `GridTable`）。
- 表间可分页符 / CAD 布局分片（继承 001 长表分片思路）。
- 序列化：**JSON**（主格式，便于 diff）+ 可选压缩。

## 3. 双模式工作流 —— 落实你的第 5 点

### 3.1 模式定义

| 模式 | 用户做什么 | 系统做什么 | 对应 UI |
|---|---|---|---|
| **结构编辑模式** | 画/改网格线、merge/split、斜线、边框、插删行列 | 更新 `GridTopology` + `MergeSpan` + `DiagonalSplit` | CAD 内操作线+面板；或 WPF 结构器 |
| **填值编辑模式** | 输入文本/数字/公式；Tab 跳格；粘贴矩形 | 只改 `AtomicCell.Content`（及 SubCell） | WPF 类 Excel 网格（001 MVP） |

**原则**：结构模式 **不强制** 在 CAD 里填值；填值模式 **默认锁定** merge/split（防误触）。

### 3.2 AutoCAD 专属：结构模式 ON / 定稿 OFF

```
┌─────────────────────────────────────────────────────────────┐
│  结构编辑模式 ON（TableEditMode）                              │
│  · 用户在模型空间画 LINE/LWPOLYLINE 作为网格线               │
│  · 允许 snap、offset、trim 等基础 CAD 编辑                    │
│  · 命令：TET_INFER 从选中线框识别拓扑 → 写入 Domain          │
│  · 预览：半透明填充显示识别出的原子格                         │
│  · 不写 AutoCAD Table 实体（或写临时 Preview 层，可删）       │
└─────────────────────────────────────────────────────────────┘
                              │ 用户确认「定稿」
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  定稿模式 OFF（TablePublishMode）                             │
│  · Domain → TableWriter → 原生 Table（或 Block+Attribute）    │
│  · 线框可删除或放 _TABLE_FRAME 层仅作参考                     │
│  · 行为接近原生 Table：打印、选择、夹点改宽高（可选）          │
│  · 填值：拉回 WPF 面板编辑，或双击单元格（V2）                │
└─────────────────────────────────────────────────────────────┘
```

**线框识别算法（V1 最小可行）**

1. 选中一组水平/竖直线（容差 θ≈2°，端点 snap ε≈1mm）。
2. 求交点网格 → 行列坐标排序 → 生成 `RowTracks/ColTracks`。
3. 线缺失处 = 无边框；外框闭合 = 表边界。
4. 与 `mpTableFromEntities` 类似，但输出 **Domain** 而非直接 Table（参考 [modplus.org](https://modplus.org/en/autocadplugins/mptablefromentities)）。

**定稿后**：XData 存 `GridTableDocument` JSON 的 hash + templateId，便于「拾取 → 面板 → 重生成」。

### 3.3 样表工作流示例

| 步骤 | 模式 | 动作 |
|---|---|---|
| 1 | 结构 | 导入 Word 样表 → WordAdapter 解析 merge/竖排 → Domain |
| 2 | 填值 | 面板填写姓名、学历等 Value 格 |
| 3 | 结构（可选） | CAD 中微调列宽线框 → 重新 Infer → 更新 Topology |
| 4 | 定稿 | Publish → 生成原生 Table，打印归档 |
| 5 | 导出 | Domain → Markdown 章节插入设计说明；Domain → xlsx |

## 4. 多目标 Adapter（MD / AutoCAD / Excel）

Domain 居中，Adapter 只做 **有损/无损映射** 声明。

```
                    GridTableDocument
                           │
     ┌─────────────┬───────┴───────┬─────────────┐
     ▼             ▼               ▼             ▼
 MarkdownAdapter  AutoCadTable   ExcelAdapter  WordAdapter
 Adapter          Writer         (NPOI)        (V2, 可选)
     │             │               │             │
     ▼             ▼               ▼             ▼
  .md /           Table 实体      .xlsx         .docx
  DesignSpec      或 Block
```

| Adapter | 支持度 | 有损点 |
|---|---|---|
| **Markdown** | 简单 merge 表 → GFM；复杂 merge → HTML `<table>` 嵌入 MD | 斜线、竖排、线宽 |
| **AutoCAD Table** | merge → `MergeCells`；文本 → `TextString` | 斜线需 **自绘 Line** 盖在 Table 上；竖排用 `\U+XXXX` 或多行近似 |
| **Excel (NPOI)** | merge、基础样式、公式 | 竖排/斜线表头部分降级 |
| **Word** | V2 可选 OpenXML | 反向导入 merge 结构 |

**与现有代码衔接**

| 现有模块 | 演进方向 |
|---|---|
| `MarkdownTableExtractor` / `DesignSpecService` | 单向 **MD → Domain**；替换当前 `List<List<string>>` 中间态 |
| `Page53AnchorTableBuilder` | **Domain 模板** + `AutoCadTableWriter`；G16 数据注入 Value 格 |
| `SettlementTableService` | 迁移到 Writer；Unmerge 逻辑收到 Writer 内 |
| pitfalls **A5 Title 吞列** | Writer 统一 `UnmergeAllAfterSetSize` |

### 6.3 关键风险

| 风险 | 对策 |
|---|---|
| AutoCAD Table **不支持** 单元格内斜线 | 定稿层：`Table` + 上层 `Line` 子实体组；或 Block 封装 |
| 竖排侧栏（样表表2） | Domain 存 `TextFlow.Vertical`；Writer 用多行 `\n` 或 CAD 竖排属性 |
| merge 后 Infer 重复识别 | 结构模式只认 **框线层**；Publish 后框线可选删除 |
| Word `.doc` 二进制 | 导入走 Word COM / 另存 docx 再用 OpenXML（M3 实现细节） |
| Domain 与原生 Table 双向同步 drift | 定稿后以 Domain 为准；Reader 只用于 **初次拉取** |

## 8. 结论

- **002 相对 001 的核心升级**：从「做一个 CAD 表格面板」升级为 **「统一 GridTable Domain + 结构/填值双模式 + 多端 Adapter」**。
- **你的 5 点思路**在 Domain 层落为：**AtomicCell + MergeSpan + DiagonalSplit + 双模式状态机 + Adapter 矩阵**；其中第 4 点（合并保留底层格）是避免 Excel/AutoCAD 式 unmerge 丢数据的 **关键设计**。
- **样表**证明 MVP 必须支持：**多表、rowspan/colspan、侧栏竖排、不等高行**；斜线表头列为 M5。
- **第一步（M0）**：实现 Domain 与 JSON round-trip，用 **表2（家庭成员）** 做首个端到端样例；并行启动 **WordAdapter  spike** 验证样表导入。

## 附录 A：样表 Table1 逻辑网格（简化）

```
行1: [姓名|值|性别|值|出生年月|值|照片(跨3行)]
```
