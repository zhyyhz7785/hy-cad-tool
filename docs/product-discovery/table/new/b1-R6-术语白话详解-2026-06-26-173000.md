## 1. 三十秒大图景：HyCAD 表格在干什么

HyCAD 要做的不是「在 CAD 里画一个 Excel」，而是：

1. **在内存里维护一张「智能表」**（`TableGrid`）—— 知道哪格是「姓名标签」、哪格是「张三」、哪格绑定了字段名 `name`。
2. **用编辑器改这张表**（Univer 网页网格 或 320px 填值面板）。
3. **定稿时画到 CAD 图面上**（线 + 文字），并把表的结构存进 DWG（XData），以后能 **拾取 → 再编辑 → 再落图**。

```text
  用户看到的 Excel 式网格          程序内部的「真相」              图面上的结果
 ┌─────────────────┐         ┌─────────────────┐         ┌─────────────────┐
 │ 姓名 │ 张三 │ … │  ←→    │ TableGrid       │  ──→    │ CAD 线+文字     │
 │ (锁) │(可改)│   │         │ Role + FieldKey │         │ + XData 备份    │
 └─────────────────┘         └─────────────────┘         └─────────────────┘
        Univer 视图                 Domain 层                  落图 / 拾取
```

**R6** 就是中间这一步的「工程语义」：**给格子贴标签（Role）+ 给重要数据格起稳定名字（FieldKey）**。

## 3. 表格基础：格子与结构

### 3.1 Domain（领域层）是什么？

**Domain** = 不依赖 AutoCAD、不依赖网页 UI 的 **纯 C# 数据模型**。

- 程序集：[`HyCAD.Tables`](../../../src/HyCAD.Tables/)
- 好处：同一套数据可以 → 画 CAD、导出 HTML、给 Univer 显示、写进 DWG
- **类比**：Domain 像 Word 文档的 `.docx` 内部 XML；CAD / Univer 只是不同的「阅读器/编辑器」

### 3.2 格子坐标：CellAddr、Anchor、Merge、Hidden

#### CellAddr（单元格地址）

- 格式：`(行, 列)`，**从 0 开始**
- 例：人员表「张三」在 `(1, 1)` — 第 2 行、第 2 列

#### Merge（合并）

- 多个格子 **看起来** 合成一个大格
- 例：表题「人员基本情况表」占 `(0,0)` 到 `(0,6)` 共 7 列 → `merge 1×7`

#### Anchor 格（锚点格）

- 合并区域里 **唯一负责存数据、存 Role、存 FieldKey** 的那一格
- **规则**：FieldKey 只能绑在 Anchor 上，不能绑在被 merge 「吃掉」的从属格
- **类比**：合并像把 7 个房间打通成一个大厅，**Anchor** 是挂门牌号的那一间；其余房间（hidden 格）在数据里还在，但 UI 不单独显示

#### Hidden 格（隐藏格）

- 被 merge 覆盖、界面上不单独画出来的格
- 读值时：点合并区任意位置，都读 **Anchor** 里的内容

```text
合并前:  [A][B][C]     合并后显示:  [  ABC  ]
         只有 A 是 Anchor；B、C 是 hidden
```

### 3.3 TableGrid：一张表的完整数据

一张表在 Domain 里叫 **`TableGrid`**，分两大块：

| 部分 | 存什么 | 类比 |
|---|---|---|
| **GridStructure**（结构层） | 行列尺寸、合并、Role、FieldKey、边框样式、竖排 | 表格的「模板 / 版式」 |
| **GridData**（数据层） | 每格文字：「张三」「男」 | 表格里填的内容 |

**Structure 像表单设计**（哪里是标签、哪里是输入框）；**Data 像用户填写的答案**。

### 3.4 GridStructure 里和 R6 相关的两个字典

```text
GridStructure
├── Roles      : (1,0) → Label     「这格是标签」
├── FieldIndex : "name" → (1,1)    「name 字段在第 (1,1) 格」
├── Merges     : …
├── Styles     : …
└── …
```

### 3.5 真相源（Truth Source）与 OpLog

#### 真相源

- **最终以 `TableGrid`（Domain）为准**，不是 Univer 内存、不是 CAD 上某行文字单独为准
- Univer 只是 **视图**；用户改格子 → 必须回写到 `TableGrid`

#### OpLog（操作日志）

- 每次改表记录一条操作：`SetValue`、`SetFieldKey`、`Merge`…
- 用于 **撤销 / 重做**，也用于审计「谁改了什么」
- **类比**：Git 的 commit 历史，但粒度是「改了一个字段」

#### SetValueByField 为什么重要

- 普通改值：`SetValue(地址, "李四")` — 插行后地址可能变
- 按字段改值：`SetValueByField("name", "李四")` — **永远改绑了 name 的那格**
- OpLog 里记 FieldKey 比记坐标更稳定

## 4. CellRole（角色）：六种「格子的身份」

**Role** 回答：**「这一格在表里是干什么的？」** — 不是文字内容，是 **身份**。

### 4.1 为什么 Excel 不够，需要 Role？

Excel 里所有格默认都能改。工程表常是 **表单式**：

```text
| 姓名 | 张三 | 性别 | 男 |
  ↑      ↑
 Label  Value  ← 左边不应被填值模式误改，右边才填
```

HyCAD 用 **Role** 告诉程序：填值模式下 **锁 Label，放开 Value**。

### 4.2 Title（表题）

| 项 | 说明 |
|---|---|
| **含义** | 整张表最上面的大标题 |
| **样例** | 「人员基本情况表」，`(0,0)` merge 整行 |
| **填值模式** | 不可改 |
| **样式** | 字更大、居中 |
| **别和 Header 混** | Title = 整张表的名字；Header = 表内部的小标题/列名 |

### 4.3 Header（表头 / 分区标题）

| 项 | 说明 |
|---|---|
| **含义** | 列标题，或侧栏分区标题 |
| **样例 1** | 家庭成员表第 0 行：「称谓」「姓名」「年龄」… |
| **样例 2** | 人员表 `(4,0)` 竖排「家庭主要成员及重要社会关系」— 仍是 Header，只是 **竖排显示** |
| **填值模式** | 不可改 |
| **别和 Label 混** | Header = 一批数据的 **列名/区块名**；Label = 某一行的 **字段名**（姓名、性别） |

### 4.4 Label（标签）

| 项 | 说明 |
|---|---|
| **含义** | 表单左侧那种 **字段名** |
| **样例** | `(1,0)`「姓名」、`(1,2)`「性别」、`(3,0)`「籍贯」 |
| **填值模式** | **锁定** — 防止用户把「姓名」改成「张三」 |
| **通常无 FieldKey** | 标签文字一般固定，不需要程序按名查找 |

### 4.5 Value（值）

| 项 | 说明 |
|---|---|
| **含义** | 用户填的 **实际内容** |
| **样例** | `(1,1)`「张三」、`(1,3)`「男」 |
| **填值模式** | **可编辑** |
| **可有可无 FieldKey** | 有 key → 程序能 `SetValueByField`；无 key → 只能人在网格里改 |

### 4.6 PhotoSlot / Spacer

| Role | 含义 | 样例 |
|---|---|---|
| **PhotoSlot** | 贴照片的空位 | 人员表右侧 `(1,6)` merge 3 行，CAD 画虚线框 +「照片」 |
| **Spacer** | 纯占位，无业务含义 | 空白装饰格，一般不写字 |

### 4.7 FieldKey 与 FieldIndex（字段名体系）

#### FieldKey（字段键）

- 给 **某一格数据** 起的 **稳定英文/id 名字**
- 例：`name` 表示「姓名那一格的值」
- **不是** 格子里显示的文字；显示文字在 GridData 里

#### FieldIndex（字段索引表）

- 一张 **登记表**：`FieldKey → 当前在哪个 CellAddr`
- 例：`"name" → (1, 1)`，`"member0_name" → (1, 1)`（家庭表第 1 行）

#### 生活类比

| 概念 | 类比 |
|---|---|
| CellAddr `(1,1)` | 学生座位号「第 2 排第 2 列」— 调座位会变 |
| FieldKey `name` | 学号 — 人不变，座位变了学号还对 |
| FieldIndex | 教务系统：学号 → 当前座位 |
| SetValueByField | 「把学号 2024001 的成绩改成 90」— 不用记座位 |

#### 典型命名

| 场景 | FieldKey 示例 |
|---|---|
| 人员姓名 | `name` |
| 家庭成员第 i 行姓名 | `member0_name` … `member5_name` |
| 斜线格「学历」子格 | 可选独立 key（高级用法） |

### 4.8 不变量（Invariant）— 不能违反的规则

**不变量** = 数据必须始终满足的条件，否则校验报错。

| 规则 | 违反时 | 白话 |
|---|---|---|
| FieldKey 全表唯一 | `DuplicateFieldKey` | 不能两个格都叫 `name` |
| FieldKey 只能在 Anchor | `FieldKeyNotOnAnchor` | 不能把 key 绑在 merge 从属格上 |
| 一格最多一个 FieldKey | API 拒绝 | 换名字要先解绑旧的 |

### 4.9 Role 与 FieldKey 的「正交」是什么意思？

**正交** = 两件 **独立** 的事，可以任意组合：

| 组合 | 可能吗 | 例子 |
|---|---|---|
| Value + 有 FieldKey | ✓ | `(1,1)` 张三，Role=Value，key=`name` |
| Value + 无 FieldKey | ✓ | `(1,3)` 男，Role=Value，无 key |
| 无 Role + 有 FieldKey | ✓ | 家庭表 `(row,1)` 有 key，未写 Role |
| Label + 有 FieldKey | 少见 | 一般 Label 不设 key |

- **Role** 管：能不能在填值模式改、怎么画样式  
- **FieldKey** 管：程序/API 怎么找到这格

## 5. 编辑模式与 UI 术语

### 5.1 结构模式 vs 填值模式

HyCAD 表格编辑分两种 **模式**（015 / 002）：

| | **结构模式** | **填值模式** |
|---|---|---|
| **干什么** | 改表格 **长什么样** | 只改 **里面的数/字** |
| **能做什么** | 合并、插删行列、改 Role | 改 Value 格内容 |
| **不能做什么** | — | 不能改 Label/Header 文字；不能 merge |
| **类比** | 装修：改房间隔断 | 入住：往柜子里放东西 |
| **UI** | 布局 Tab「结构｜填值」Toggle 切到结构 | Toggle 切到填值 |

### 5.2 Toggle（切换开关）

- 界面上的 **二选一开关**，如 `[结构 | 填值]`
- 切换后通过 `setEditMode` 消息通知 Univer 前端改锁定策略

### 5.3 editable（可编辑）

- 布尔值：**这一格当前能不能改文字**
- 由 Role + FieldKey + 当前模式共同决定
- **权威规则**：[`TableFillGridAdapter.IsCellEditable`](../../../src/HyCADTool/Features/Tables/Presentation/TableFillGridAdapter.cs)

简化记忆：

```text
填值模式:
  Label / Header / Title / PhotoSlot / Spacer → 不可编辑
  Value → 可编辑
  有 FieldKey 的格 → 可编辑（即使没写 Role）
  其它 → 不可编辑
```

### 5.4 Inspector（检查器 / 属性栏）

- 编辑器 **右侧小面板**，显示当前选中格的信息
- R6 相关：显示 **Role**、**FieldKey**（P3 目标：至少只读展示）
- **类比**：Photoshop 右侧「图层属性」、AutoCAD「特性」面板

### 5.5 320px 填值面板（AC11）

- HyBlender 里 **窄条表格 Tab**，专门 **填值模式** 用 DataGrid 列表改 FieldKey 格
- **不在 Univer 替换范围内**（new/001 红线）
- 与 Univer 大窗 **共用同一 Domain**

## 6. 架构、路线与验收术语

### 6.1 R6 是什么？

- **R** = Requirement（需求条目）
- **R6** = [new/001 §3](001-Univer路线-原需求最优落地总纲-2026-06-26-163000.md) 第 6 条：**单元格 Role + FieldKey**
- 优先级：**Must**（必须做）

### 6.2 P0–P5 路线图

| 阶段 | 大致内容 |
|---|---|
| P0 | 基线：文本 + merge 能 round-trip |
| P1 | 富快照：对齐、边框、字高 |
| P2 | 三 Tab Ribbon |
| **P3** | **工程语义：竖排 + Role/FieldKey + 纸张** ← R6 主要落在这里 |
| P4 | 斜线、PhotoSlot 编辑器预览 |
| P5 | 公式、xlsx、图形取数 |

### 6.3 Univer 相关

| 术语 | 解释 |
|---|---|
| **Univer** | 开源网页 spreadsheet 组件，在 WebView2 里跑，长得像 Excel |
| **快照 Snapshot** | 把 `TableGrid` 转成 JSON 发给前端 **一次性加载** 的数据包 |
| **v1 快照** | 只有文字、merge、尺寸、`editable`；**没有** role/fieldKey 字段名 |
| **v2 快照** | 每格增加 `role`、`fieldKey` — R6 要补的 |
| **loadSnapshot** | C# → JS：把表加载进 Univer |
| **exportSnapshot** | JS → C#：导出当前 Univer 状态（主要用于文本/结构） |
| **cellChanged** | 用户改了一格 → 通知 C# 写 OpLog |
| **setEditMode** | C# → JS：切换结构/填值模式的保护策略 |
| **fixture** | 测试用固定 JSON 样例，如 `personnel-snapshot.json` |
| **bridge / 桥** | C# 与 JS 之间 `postMessage` 传 JSON 的通道 |

### 6.4 DoD（Definition of Done）

- **完成定义** = 怎样算「这个功能做完了」的 **勾选清单**
- a1 §1.2 列了 R6 / P3 的 DoD；全勾上才算交付

### 6.5 round-trip、XData、落图、拾取

| 术语 | 解释 |
|---|---|
| **落图 / Publish** | 把 `TableGrid` 画成 CAD 上的线+文字 |
| **拾取 / Pick** | 在 CAD 里点选已有表，读回 `TableGrid` |
| **round-trip** | 编辑 → 落图 → 拾取 → 再编辑，**Role/FieldKey/合并不丢** |
| **XData** | AutoCAD 实体附带的扩展数据；HyTable 把表 ID + JSON 存在载体上 |
| **AC3** | 里程碑：XData 真相源 + round-trip 验收 |

### 6.6 AC 编号（AC1–AC11…）

- **AC** = Acceptance Criteria / 分阶段交付（旧 008 系列）
- 和 R6 常一起出现的：
  - **AC5**：竖排、斜线、Role 样式渲染
  - **AC7**：拾取表摘要（含 FieldKey 数量）
  - **AC9**：从 CAD 线框 **识别** 表格（V1 **不推断** FieldKey）
  - **AC10**：编辑模式散开线框再识别（**保留** Sidecar 里 FieldKey）
  - **AC11**：320px WPF 填值面板

### 6.7 其它 a1 里出现的技术词

| 术语 | 解释 |
|---|---|
| **WYSIWYG** | What You See Is What You Get — 编辑器里看到的样式和落图一致 |
| **DTO** | Data Transfer Object — 跨 C#/JS 传的纯数据类，如 `UniverGridSnapshot` |
| **Mapper** | 把 `TableGrid` 转成 DTO 的转换代码 |
| **VM / ViewModel** | WPF 界面与 Domain 之间的编排层，`TableEditorViewModel` |
| **SubCell** | 斜线把一格分成两个三角区，每区独立文字（如「学历｜学位」） |
| **VerticalStacked** | 竖排堆字：一字一行往下排，不是整句旋转 90° |
| **MergeValuePolicy.AnchorOnly** | 合并时只有 Anchor 存值，从属格为空 — Domain 默认策略 |
| **Sidecar** | 编辑模式备份的 JSON，与 CAD 线框并行保存 FieldKey |
| **Degraded** | 某能力在 CAD/HTML 里是简化实现，非像素级一致 |

## 7. 常见混淆对照（FAQ）

### Q1：Role 和 FieldKey 有什么区别？

| | Role | FieldKey |
|---|---|---|
| 回答的问题 | 这格 **是什么类型**？ | 这格 **程序里叫什么**？ |
| 例子 | Label / Value | `name` |
| 影响填值锁定 | 是 | 间接（有 key 通常可编辑） |
| 类比 | 表单上的「标签控件 / 输入框」 | 数据库字段名 |

### Q2：Label 和 Header 有什么区别？

| | Label | Header |
|---|---|---|
| 位置感 | 某一行的字段名 | 列名行，或大块分区标题 |
| 样例 | 「姓名」「性别」 | 「称谓」「姓名」列头；竖排侧栏 |
| 人员表 | `(1,0)` | `(4,0)` 竖排区 |

### Q3：有 FieldKey 一定是 Value 吗？

**不一定。** FieldKey 只表示「这格数据可被程序寻址」；Role 仍建议标 Value，但 Domain 允许「有 key 无 Role」。

### Q4：为什么 `(1,3)`「男」没有 FieldKey？

- 人要能在网格里改「男/女」
- 但没有外部系统按 `"gender"` 自动灌数据 → **不必** 设 FieldKey
- 有 Role=Value 就够了

### Q5：editable 和 Role 是一回事吗？

**不是。** `editable` 是 UI 层的 **结果**（能不能改）；Role 是 **原因** 之一。v1 快照只有 `editable` 布尔，**丢失** Role 名字 — 这是 R6 要修的核心问题。

### Q6：Univer 能改 Role 吗？

- P3 设计：Role/FieldKey **结构语义** 走 C# OpLog（`SetRoleOp`），**不**从 Univer export 反推
- 用户在 Univer 里主要改 **Value 文字**；Role 在 Inspector 或结构模式下改

### Q7：「正交」「稀疏字典」是什么？

| 词 | 白话 |
|---|---|
| **正交** | 两套属性互不捆绑，独立设置 |
| **稀疏字典** | 只有 **特殊** 的格才 записи；普通格不在 Roles 里 |
