**两处关键合并决策（与单一来源不同）：**

- **稳定身份（✅ 已确认）**：放弃 002 的 per-cell GUID（`CellId`/`StableIdMap`）。MVP 三层：**`CellAddr` 作主键** + **`FieldKey` 作语义稳定引用** + **顺序操作日志 OpLog**（Undo/历史/审计；结构类操作回放时重映射坐标与 FieldIndex）。GUID 仅当无名格跨系统长期 opaque 引用时再议（V2）。详见 §4.4。

## 1. 第一性原理：表格为何必须是「对象」，不是「文本」

> 这一节回答「为什么 Domain 必须先行、为什么不能把 Markdown 当核心」。

### 1.1 任何文档都有四层

```text
文档(Document)
├── 内容(Content)        例：今天下雨
├── 结构(Structure)      标题 / 正文 / 列表 / 引用
├── 表现(Presentation)   字体 / 颜色 / 边框 / 单元格
└── 交互(Interaction)    折叠 / 排序 / 过滤 / 公式 / 拖动
```

Markdown **只负责前两层（内容 + 结构）**，并**故意舍弃**表现与交互——作者的设计目标是「源码即可读（Make it readable）」。这是**设计取舍，不是缺陷**。一旦允许 rowspan/合并/底色/竖排，源码立刻退化成 HTML。

### 1.2 复杂表格不是文本，是二维布局（2D Layout）

```text
┌──────┬──────────────┐
│姓名   │ 成绩          │
├──────┼─────┬────────┤
│Tom    │数学 │100      │
│       ├─────┼────────┤
│       │英语 │98       │
└──────┴─────┴────────┘
```

这里出现 rowspan / colspan / cell merge / layout——属于 **Layout Engine**，而非 Markdown 的 **Line Parser**。各系统真正的「真相源」都是对象模型，不是文本：

| 系统 | 真相源（对象模型） |
|---|---|
| Word | Table Object |
| Excel | Grid Model |
| HTML | DOM Tree |
| Blender | Node Tree |
| AutoCAD | Entity Tree |
| **Markdown** | **Line Parser（无二维对象）** |

Markdown 缺的不是「复杂表格语法」，而是**布局描述能力（Cell / Row / Column / Merge / Constraint）**。所以：

> **结论：本项目的真相源必须是 Domain 对象模型；Markdown / HTML / CAD / Excel 都只是导出目标。** 这正是 002/003/004 的共同判断，005 把它确立为不可动摇的第一性原理。

## 2. 战略定位：Table Domain 是 UDOM（Hy Document）的第一块基石

### 2.1 为什么不止步于「表格 Domain」

结合本项目方向（**CAD + Blender + AI**），表格只是更大蓝图的一个节点。真正值得投资的是**统一文档对象模型（UDOM, Unified Document Object Model）**——暂命名 **Hy Document**：

```text
Hy Document（UDOM）
└── Document
     ├── Text          文本
     ├── Table         表格      ← 本期落地
     ├── Formula       公式
     ├── Geometry      几何（Line / Arc / Polyline / Mesh）
     ├── Image         图像
     ├── Symbol        符号
     ├── Annotation    标注（Text / Leader / Dimension / Table）
     ├── Reference     引用
     └── Metadata      元数据
```

价值：
- **AI 直接操作对象**（表格、几何、标注），而不是解析/正则文本——与「AI 辅助设计」天然契合。
- **Markdown / HTML / PDF / Word / Excel / CAD 图纸都降为导出目标**，互不绑架。
- 与已有 `Shared.Geometry`、CAD 标注体系同构，未来可收口到同一对象树。

### 2.2 本期的克制边界（避免过度工程化）

> 本期**只落地 Table 节点**。UDOM 其余节点（Geometry/Annotation/…）**不实现**，仅预留一个极薄的节点身份接缝 `IDocumentNode`（§3.1），让 `TableDocument/TableGrid` 将来能并入 Hy Document，不为此付出当下成本。

### 2.3 Markdown 的正确角色

不要去「增强 Markdown 本体」。Markdown 在本架构里只承担两件事：

1. **轻量输入/导出格式**之一（简单表 → GFM；复杂表 → 见 §6.2 降级）。
2. 若要在 MD 里承载复杂表，用 **Rich Table Block（富表格块）**——不改 Markdown 语法，新增一个围栏块挂 Domain JSON，Notion/Logseq 同思路：

````md
# 钢筋表

```table
{ "ref": "udom://table/家庭成员表", "fallback": "html" }
```
````

> Markdown 负责文本，`table` 块负责二维布局，互不污染。

## 3. 统一 Domain 模型（定稿类型草图 = 设计规格）

> 建议程序集：**`HyCADTool.Shared.Tables`**（零 AutoCAD / 零 Markdig / 零 NPOI / 零 UI 依赖，可单测、可被 `MarkdownEditor` 复用；将来可并入 `HyCADTool.Shared.Documents` 的 UDOM 程序集）。命名空间 `HyCADTool.Shared.Tables`。

### 3.1 节点身份（UDOM 接缝，本期仅 Table 用）

```csharp
namespace HyCADTool.Shared.Tables;

// UDOM 接缝：本期仅 Table 落地，其余 NodeKind 预留不实现
public interface IDocumentNode
{
    Guid Id { get; }
    NodeKind Kind { get; }
    IReadOnlyDictionary<string, string> Metadata { get; }
}

public enum NodeKind
{
    Table
    // 预留：Text, Formula, Geometry, Image, Symbol, Annotation, Reference
}
```

### 3.2 顶层：文档与单表（结构/数据分离）

```csharp
// 文档：可含多表（黄金用例 = 人员基本情况表 + 家庭成员表）
public sealed class TableDocument : IDocumentNode
{
    public Guid Id { get; }
    public NodeKind Kind => NodeKind.Table;
    public string Name { get; }
    public IReadOnlyList<TableGrid> Tables { get; }
    public TableSourceInfo Source { get; }            // 来源：Word 路径 / CAD handle / Excel 文件
    public IReadOnlyDictionary<string, string> Metadata { get; }
}

// 单表 = 结构（模板，可独立复用） + 数据（填值，可换数据）
public sealed class TableGrid : IDocumentNode
{
    public Guid Id { get; }
    public NodeKind Kind => NodeKind.Table;
    public GridStructure Structure { get; }           // 版式：拓扑/合并/斜线/样式/角色
    public GridData Data { get; }                     // 填值：CellAddr → CellValue
    public IReadOnlyDictionary<string, string> Metadata { get; }
}
```

> **结构/数据分离的收益（采纳 003）**：一个「人员基本情况表」结构模板（`*.tabletpl`），可反复填不同人的 `GridData`，直接支撑模板复用、批量出表、从对象/Excel/图元填值。

### 3.3 结构层 GridStructure（= 模板）

```csharp
public sealed class GridStructure
{
    public GridTopology Topology { get; }                                   // 行列数 + 行高列宽 + 方向 + 默认边框
    public IReadOnlyList<MergeRegion> Merges { get; }                       // 矩形合并覆盖层（§3.6）
    public IReadOnlyDictionary<CellAddr, DiagonalSplit> Diagonals { get; }  // 斜线（§3.7），稀疏
    public IReadOnlyDictionary<CellAddr, CellStyle> Styles { get; }         // 稀疏：默认样式不入表
    public IReadOnlyDictionary<CellAddr, CellRole> Roles { get; }           // 稀疏：默认 Value
    public IReadOnlyDictionary<string, CellAddr> FieldIndex { get; }        // FieldKey → 格（稳定引用 / 模板填值 / 绑定）
}

public sealed class GridTopology
{
    public IReadOnlyList<GridTrack> Rows { get; }      // 每行轨道（高度）
    public IReadOnlyList<GridTrack> Cols { get; }      // 每列轨道（宽度）
    public GrowDirection Direction { get; }            // Down | Up（CAD 倒置表）
    public BorderSet DefaultBorder { get; }
    public int RowCount => Rows.Count;
    public int ColCount => Cols.Count;
}

public sealed class GridTrack
{
    public double Size { get; }            // 高/宽（mm，模型空间 1:1）
    public TrackSizeMode Mode { get; }     // Fixed | Auto | Weight
}

public readonly struct CellAddr
{
    public int Row { get; }
    public int Col { get; }
}

public enum GrowDirection { Down, Up }
public enum TrackSizeMode { Fixed, Auto, Weight }
```

### 3.4 数据层 GridData（= 填值）

```csharp
public sealed class GridData
{
    public IReadOnlyDictionary<CellAddr, CellValue> Cells { get; }  // 稀疏：空格不入表
}

public sealed class CellValue
{
    public string Text { get; }                        // 显示文本（公式结果亦缓存于此）
    public CellValueKind Kind { get; }                 // Static | Formula | Bound
    public string? Formula { get; }                    // Kind=Formula：R1C1 或结构化 AST
    public string? BindingExpr { get; }                // Kind=Bound：Excel 地址 / 图元取数表达式
    public IReadOnlyList<TextRun>? Runs { get; }       // 可选富文本（仿宋 14pt 等）
}

public enum CellValueKind { Static, Formula, Bound }
```

### 3.5 基础格 BaseCell（概念）与可见性（派生）

- **BaseCell 不是一个独立持久化对象**，而是「某个 `CellAddr` 上聚合 样式+角色+值+合并归属+斜线 的视图」。底座是 `RowCount×ColCount` 个 BaseCell，**永久存在、永不因合并删除**；但存储**稀疏**（默认值的格不进任何字典），内存友好。
- **可见性派生（不持久化）**：

```text
IsHidden(addr) ≡ 存在 MergeRegion 覆盖 addr 且 addr ≠ 该区 Anchor
IsCovered(addr) ≡ 存在 MergeRegion 覆盖 addr（含 Anchor）
```

> 这样 `MergeRegion` 是合并的唯一真相，不会与「存在格上的 Visibility 标志」漂移（修正 002）。

### 3.6 合并 MergeRegion（矩形覆盖，不删底格）

```csharp
public sealed class MergeRegion
{
    public CellAddr TopLeft { get; }       // = Anchor（主格：唯一权威读写入口）
    public int RowSpan { get; }
    public int ColSpan { get; }
    public MergeValuePolicy ValuePolicy { get; }
}

public enum MergeValuePolicy
{
    AnchorOnly,    // 仅 Anchor 有值，其余空（Excel 默认行为）
    SameValue,     // 全体镜像 Anchor 值（= 002 的 Anchor+Mirror；拆分后内容不丢）
    PreserveEach,  // 各格保留原值，仅显示 Anchor（复杂数据保真）
    Composite      // 显示时组合多格值（人事 / 说明表）
}
```

- **合并 = 加一个矩形覆盖层，绝不删除任何 BaseCell**（002/003/004 共识）；拆分 = 删掉 `MergeRegion`，底格原样复现，**天然可逆零丢失**。
- MVP 先支持 `AnchorOnly` + `SameValue`；`PreserveEach`/`Composite` 后置（采纳 004）。

### 3.7 斜线 DiagonalSplit（单元内子格，不破坏网格）

```csharp
public sealed class DiagonalSplit
{
    public DiagonalDirection Direction { get; }    // BackSlashTLBR(↘) | SlashBLTR(↗)
    public IReadOnlyList<SubCell> Parts { get; }   // MVP = 2 分；预留 4 分双斜线
}

public sealed class SubCell
{
    public string? FieldKey { get; }
    public CellValue Value { get; }
    public NormalizedPoint TextAnchor { get; }     // 0..1 相对父格，控制文字位置
    public TextAlign Align { get; }
}

public enum DiagonalDirection { BackSlashTLBR, SlashBLTR }
```

- 斜线**不真把 1 格切成 2 格**，而是给该 `CellAddr` 挂一个 `DiagonalSplit`，两个 `SubCell` 各自独立填值（如「学历 ╲ 学位」）。底层仍是 1 个 BaseCell，便于 Excel/MD 降级。

### 3.8 样式 CellStyle 与角色 CellRole（平台无关，落端翻译）

```csharp
public sealed class CellStyle
{
    public TextOrientation Orientation { get; }    // Horizontal | VerticalStacked（竖排堆字）
    public TextAlign HAlign { get; }
    public TextAlign VAlign { get; }
    public double TextHeight { get; }              // mm
    public string FontKey { get; }                 // 抽象字体键（如 "hei_bigfont"）→ 各端映射
    public BorderSet Borders { get; }
    public string? BackColor { get; }              // 底色，可空
}

public enum CellRole { Title, Header, Label, Value, PhotoSlot, Spacer }
public enum TextOrientation { Horizontal, VerticalStacked }
public enum TextAlign { Start, Center, End }
```

- **竖排堆字**（样表「家庭主要成员及重要社会关系」一字一行）是 `Orientation = VerticalStacked`，**不是手动换行**——各端各自翻译（CAD 逐字堆叠 / Excel 文字方向 / MD 降级）。
- **字体抽象**：Domain 只存 `FontKey`；AutoCAD 适配器映射到大字体 `gbcbig.shx`（解决中文问号），Excel 映射具体字体名。

### 3.9 对象总览

```text
TableDocument (IDocumentNode)
├── Source / Metadata
└── Tables[]
     └── TableGrid (IDocumentNode)
          ├── GridStructure（模板）
          │    ├── GridTopology { Rows[], Cols[], Direction, DefaultBorder }
          │    ├── Merges[]      : MergeRegion(+MergeValuePolicy)
          │    ├── Diagonals{}   : CellAddr → DiagonalSplit(→ SubCell[])
          │    ├── Styles{}      : CellAddr → CellStyle
          │    ├── Roles{}       : CellAddr → CellRole
          │    └── FieldIndex{}  : FieldKey → CellAddr
          └── GridData（填值）
               └── Cells{}       : CellAddr → CellValue
```

## 4. Domain 行为规格（不变量 + 操作语义，不写实现）

### 4.1 不变量（构造与每次操作后必须成立）

1. **底座完整**：逻辑上恒有 `RowCount×ColCount` 个 BaseCell；任何复杂性都是覆盖层，不删格。
2. **合并矩形且不重叠不越界**：每个 `MergeRegion` 是合法矩形，两两不相交，不超出网格。
3. **斜线唯一且不落被覆盖格**：每格至多 1 个 `DiagonalSplit`；被某 `MergeRegion` 覆盖的**非 Anchor 格**不得有斜线（如需斜线挂在 Anchor 上）。
4. **FieldKey 全表唯一**。
5. **值种类一致**：`Kind=Formula ⇒ Formula 非空`；`Kind=Bound ⇒ BindingExpr 非空`。

### 4.2 操作语义

| 操作 | 语义 | 关键点 |
|---|---|---|
| `Merge(rect, policy)` | 新增 `MergeRegion`，按 `policy` 处理底格值 | 校验矩形/不重叠 |
| `Unmerge(anchor)` | 删 `MergeRegion`，按 `policy` 复现底格值 | `SameValue/PreserveEach/AnchorOnly` 均无损可逆 |
| `SplitDiagonal(addr, dir)` / `ClearDiagonal(addr)` | 挂/清 `DiagonalSplit` | 校验不变量 3 |
| `InsertRow/InsertCol/DeleteRow/DeleteCol` | 改 `GridTopology` + **重映射所有 CellAddr 键**（Merges/Diagonals/Styles/Roles/FieldIndex/Data） | 覆盖层坐标随网格平移；删除时落在删除带内的覆盖层做收缩或剔除 |
| `SetValue(addr, value)` | 写入 | 若 `addr` 在某合并区且 `policy=SameValue`，镜像到全体 Member；读取合并区一律返回 Anchor 值 |

### 4.3 可逆性结论

合并→拆分在四种策略下都不丢底格结构与值（`AnchorOnly` 下底格本就空）。这正是相对 Excel/AutoCAD「merge 丢非左上格数据」的核心差异点（002/003/004 一致强调）。

### 4.4 操作日志 OpLog（✅ D2 定稿：与 FieldKey 分工）

**不替代 GUID，而是与 FieldKey 分工**：FieldKey 解决「指谁」；OpLog 解决「怎么变、怎么回退、改了什么」。

```text
Layer 1  状态（真相源）   TableGrid：CellAddr 主键 + FieldIndex 稳定引用
Layer 2  操作（变更记录） 顺序 OpLog：结构/填值命令序列
Layer 3  快照（可选）     周期性 full JSON + 之后只追加 op（加速加载）
```

**MVP 操作类型（最小集）**

| 类别 | 操作 | 回放要点 |
|---|---|---|
| 结构 | `InsertRow/DeleteRow/InsertCol/DeleteCol` | 重映射全部 CellAddr 键 + 更新 FieldIndex |
| 结构 | `Merge/Unmerge` | 更新 Merges；按 ValuePolicy 处理值 |
| 结构 | `SetFieldKey(addr, key?)` | 维护 FieldIndex 唯一性 |
| 填值 | **`SetValueByField(fieldKey, value)`** | **日志只记 FieldKey，不记坐标**——插行后仍正确 |
| 填值 | `SetValue(addr, value)` | 无名格；会话内有效 |

**规则**

1. 凡有 FieldKey 的格，外部绑定 / G16 注入 / AI 改值 → 优先 `SetValueByField`。
2. 结构类操作执行时，Domain 同步重映射 `FieldIndex`（FieldKey → 新 CellAddr）。
3. MVP OpLog 可先**内存 Undo 栈**；持久化 `.ops.json` 或 snapshot+op 为阶段 A 可选（A2+）。
4. per-cell GUID **不做 MVP**；触发条件见 §8 D2。

## 5. 序列化与真相源

- **主格式 JSON**：稀疏字典天然紧凑、可 diff、**便于 AI 直接生成/修改对象**（呼应 §2.1）。可选压缩。
- **真相源载体**：
  - **AutoCAD**：`TableDocument` JSON（或其 hash + templateId）存进表实体的 **XData / 扩展字典**，随实体复制迁移（采纳 003 建议「随实体走」）。
  - **Markdown**：旁挂 `.json` 真相源 + 文档内 Rich Table Block / HTML 仅作展示（§2.3 / §6.2）。
- **状态 JSON**：合并区镜像值见 §8 D1（建议只存 Anchor）。
- **OpLog（可选持久化）**：与状态 JSON 分离；MVP 可仅内存。若持久化，推荐「snapshot JSON + 增量 op 列表」，便于 Undo 与变更审计。

### 6.3 AutoCAD 双模式（采纳 002/003/004）

`编辑模式 ON`（散开为线+文字，用原生命令自由画）→ 退出时**线框识别器**反推 `TableGrid`；`定稿模式 OFF`（渲染为原生 Table / 线+文字组合）。MVP 落地优先「线+文字组合 + XData 元数据」，不急转原生 Table（004 结论）。识别为最高技术风险，规整网格+矩形合并先行，斜线/竖排识别 V2。

## 9. 附录

### 9.1 黄金用例映射（人员基本情况表 → 005 模型）

| 表中元素 | 落到模型 |
|---|---|
| 标题「人员基本情况表」跨整行 | `MergeRegion`(整行) + `CellRole.Title` |
| 「姓名/性别/出生年月」一行多组 label-value | 同行多个 `Label`+`Value` 交替 `BaseCell` |
| 右侧「照片」跨 3 行 | `MergeRegion`(竖向 RowSpan) + `CellRole.PhotoSlot` |
| 「籍贯」值跨 3 列、「学习和工作简历」跨 6 列 | `MergeRegion`(横向 ColSpan) |
| 「学历/学位」叠放 | MVP：`Composite` 或两行；M5：`DiagonalSplit`(2 子格) |
| 「家庭主要成员及重要社会关系」侧栏一字一行 | `MergeRegion`(大块) + `CellStyle.Orientation=VerticalStacked` |
| 「称谓/姓名/年龄/政治面貌/工作单位及职务」子表 | 普通多行多列 + 表头行 `CellRole.Header` |

> 结论：**基础网格 + 矩形合并 + 竖排 + 角色** 即可无损表达此复杂表；斜线本例可选。模型对「Word 级复杂表」充分。
