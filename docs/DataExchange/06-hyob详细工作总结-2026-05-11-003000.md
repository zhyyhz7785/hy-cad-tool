## 一、项目背景与设计动机

### 1.1 起点问题
AutoCAD DWG 是闭源二进制；DXF 是文本但单文件膨胀严重（一次保存 10MB+）；
USD 偏向场景描述、不适合工程图。需要一套：
- **AutoCAD 平行存储**（不修改 DWG 本体）
- **Git-like 版本控制**（commit / branch / merge / diff）
- **二进制紧凑 + content-addressable**（去重 + 校验）
- **AI 友好导出**（结构化 JSON，类型语义清晰）

### 1.2 关键设计原则
| 原则 | 体现 |
|---|---|
| **Domain 纯净** | `Domain/` 不引用 `Autodesk.AutoCAD.*` |
| **typed + opaque 双轨** | 已建模类型走精确 schema；其它一律降级 OpaqueObject 不丢数据 |
| **content-addressable** | 每个对象 = SHA-256(payload) 寻址，自动跨 commit 去重 |
| **不破坏 DWG** | 反向 patch 严格白名单 + 单事务回滚 |
| **每里程碑 = 编译/自检边界** | 41 项 Domain 自检每次 hyobI 自动跑 |

### 2.1 物理布局

```
<dwg>.hyob/
  HEAD                      ref: refs/heads/main  或  detached <commit-hash>
  objects/
    ab/cdef…                loose 对象，按 hash 前 2 位分桶
    pack/
      pack-<idx>.pack       Deflate 压缩 pack 文件（M7）
  refs/
    heads/
      main                  分支 → tip commit hash
      feat/x                支持斜线层级
  exports/
    <commit>.hygeom.json    hyobES 输出（M12）
    <commit>.<filter>.hygeom.json
```

### 2.2 二进制对象格式

```
  +--------+--------+----------------+----------------+--------------+
  | type_id| schema | payload_len    | crc32          | payload      |
  | u16 LE | u8     | u32 LE         | u32 LE         | bytes...     |
  +--------+--------+----------------+----------------+--------------+
```
- `type_id`：见 `HyobObjectKind`（0x0001 ~ 0xFFFF）
- `schema_ver`：每种 type_id 自己版本号（v1 起步，向前兼容）
- `crc32`：标准 IEEE 802.3 多项式 0xEDB88320，用于检测磁盘腐蚀
- `payload`：变长，定义见每种 type 的 schema

### 2.3 Tree / Commit 模型

**Tree** = 排序后的 entries 列表：
```
struct HyobTreeEntry { string Name; HyobTreeEntryKind Kind; Hash Hash; }
// Kind ∈ { Object, Tree }
```
**root tree**（schema = `hyob.snapshot/v4`）：
```
root/
  entities/
    by-handle/
      <HEX>           → 主对象（Line / Polyline / ...）
      <HEX>.x         → XData 兄弟对象（可选）
      <HEX>.d         → ExtensionDictionary 兄弟对象（可选）
  tables/
    layers/      <name> → HyobLayerDef
    text_styles/ <name> → HyobTextStyleDef
    dim_styles/  <name> → HyobDimStyleDef
    blocks/      <name> → HyobBlockDef
```
**Commit**：parents[] + tree + author + email + time + message + cmd + meta{}

## 三、各里程碑完成详情

### M1：Domain 基础设施 + Repository + 命令骨架

| 子任务 | 产物 | 自检项 |
|---|---|---|
| M1-A Codec | `Crc32 / HyobBinary / HyobObjectHeader` | 5 项（CRC 标准向量、Hash 自一致、Header 一轮 round-trip） |
| M1-B Opaque + Store | `HyobOpaqueObject / HyobObjectStore` | 3 项 |
| M1-C Tree + Commit + RefStore | `HyobTree / HyobCommit / HyobRefStore` | 3 项（顺序无关、同名拒绝、mini-DAG） |
| M1-D 命令落地 | `hyobI / hyobS / hyobC / hyobL / hyobR` 5 命令 | 命令级集成测 |

**关键设计**：
- `Hash` 是 `readonly struct`（32 byte），`IsZero / FromHex / ToHex / OfPayload(byte[])` 工具方法
- ObjectStore 写入幂等 —— 同 hash 重复写无副作用
- Tree 内部排序按 Name；同名 entry 直接抛异常（防止哈希漂移）
- HEAD 支持两种状态：`ref: refs/heads/<name>` 或 detached `<commit-hash>`

### M2：基础几何 typed schema

| Type | type_id | 字段 |
|---|---|---|
| `HyobLine` | 0x0001 | layer, handle, sxyz, exyz |
| `HyobPolyline` | 0x0002 | layer, handle, flags(closed), elevation, normal, constWidth, vertices[] |
| `HyobArc` | 0x0003 | layer, handle, center, radius, startAng, endAng, normal |
| `HyobCircle` | 0x0004 | layer, handle, center, radius, normal |

**正向触发命中率**：实测 5815 实体 DWG 中，typed 命中 2107 个（36.2%），其中 Line 1334。

### M3：文字与块 typed schema

| Type | type_id | 字段 |
|---|---|---|
| `HyobDBText` | 0x0005 | textString, styleName, pos, height, rot, widthFactor, oblique, thickness, normal, hMode, vMode, alignPt, flags |
| `HyobMText` | 0x0006 | contents(含 RTF 控制码), styleName, loc, height, width, rot, normal, dir, attach, drawDir, lineSpacing*, bgFill, bgArgb, bgScale |
| `HyobBlockReference` | 0x0007 | blockName, pos, scale, rot, normal, attributes[]（内联） |

**关键决策 1：MText.DrawingDirection**
AutoCAD .NET API 实际不暴露 `MText.DrawingDirection` 属性（只有 `MText.LineSpacingStyle`），
schema 保留 `draw_direction` 字段写 0，避免破坏二进制布局。

**关键决策 2：BlockReference Attributes 内联**
属性条目嵌入 BlockReference 内（schema 内 `attributes[]`），而非独立对象。
理由：Attributes 与 BlockRef 强绑定，独立存储反而引入额外 ref 开销。

### M4：标注与填充

#### M4-A Dimension 统一 schema
AutoCAD 9 种 Dimension subtype（Aligned / Rotated / Radial / Diametric / Angular / Angular3Point /
Ordinate / ArcDimension / RadialLargeDimension）合并到 `HyobDimension`：

```
[ utf8 layer ]
[ utf8 handle_hex ]
[ byte sub_type ]                      ← AutoCAD subclass enum
[ utf8 block_name ]
[ utf8 dim_text ]
[ utf8 dim_style_name ]
[ double measurement ]
[ double text_pos_x/y/z ]
[ double normal_x/y/z ]
[ uint32 point_count ]                 ← 视 sub_type 而定
loop point_count: [ double x, y, z ]
[ uint32 extra_count ]                 ← 角度等额外属性
loop extra_count: [ utf8 key, double value ]
```
单一 schema 覆盖全部 9 subtype，反序列化按 `sub_type` 分派语义。

#### M4-B 引线 / 填充 / 遮罩
- `HyobMLeader`（语义级）：内容（MText 或 Block）+ leader 起止 + dogleg 长度。**不存** vertex 拓扑。
- `HyobHatch`（pattern-only）：pattern name / scale / angle / origin。**不存** boundary 几何。
- `HyobWipeout`：边界 polygon 完整保留（点数有限，可全存）

**理由**：MLeader / Hatch 的完整顶点拓扑在 AutoCAD 内部表示极复杂（loop 嵌套、edge 类型多种），
全存 schema 会膨胀 5 倍以上；语义/参数级足够支持 AI 理解，全保真留 Opaque 兜底。

### M5：XData / ExtensionDictionary 兄弟对象

**问题**：如果 XData 嵌入主 entity，则 `修改 XData → 主对象 hash 变 → 去重命中失败 → 几何相同的实体被多算一份`。

**解决**：独立成 `HyobXDataAttachment` (0x0120) / `HyobExtensionDictionary` (0x0121)，
通过 by-handle 树的 `<HEX>.x` / `<HEX>.d` entry 与主对象并列引用。

```
by-handle/
  19BAB           → HyobLine        hash=A
  19BAB.x         → HyobXDataAttachment hash=B
  19BAB.d         → HyobExtensionDictionary hash=C
```

**简化处理**：XData TypedValue 内的二进制内容统一 `ToString()` 后存 utf8 字符串。损失：精度（double 转字符串可能丢尾数）。
权衡：避免维护 13 种 DXF 数据类型（Real/Int16/Int32/Point2d/...）的子 codec。

### M6：表 / 字典系统（**计划调整**）

**原计划**：M6 = Hatch/Wipeout boundaries 完整存储
**实际执行**：评估发现完整存储 boundary 的 ROI 太低（M4-B 已用 pattern-only 解决 90% AI 用例），
转而实施"表系统"，价值更高。

| Type | type_id | 包含字段 |
|---|---|---|
| `HyobLayerDef` | 0x0100 | name, color, lt, lw, on/freeze/lock/plot/used, desc |
| `HyobTextStyleDef` | 0x0102 | name, fontFile, bigFontFile, height, widthFactor, oblique, isShape, isVertical |
| `HyobDimStyleDef` | 0x0103 | 14 项常用（dimscale / textColor / extLineColor / arrowSize / textHeight / etc.） + 引线 block name |
| `HyobBlockDef` | 0x0104 | name, isLayout, isAnonymous, origin, units, entityCount |

**Tree 布局**：
```
tables/
  layers/      <name> → HyobLayerDef
  text_styles/ <name> → HyobTextStyleDef
  dim_styles/  <name> → HyobDimStyleDef
  blocks/      <name> → HyobBlockDef
```

**实测**：5815 实体 DWG → Layer=86, TextStyle=7, DimStyle=12, BlockDef=443。
表对象给 AI 提供完整样式上下文（"3.5mm 高的标注文字"实际是哪个 dimstyle 的 dimtxt × dimscale）。

### M7：Pack 压缩

**问题**：5815 实体 DWG 产生 4639 个 loose 文件（≈1.4 MB），文件系统寻址慢、占 inode。

**实现**：
- `HyobPackFile` 二进制格式：`[u32 magic="HYPK"][u32 ver][u32 count][index 区][data 区(Deflate)]`
- index 每条：`[hash 32B][data_offset u64][compressed_size u32][orig_size u32]`
- `HyobPacker.Pack(store)`：收集 loose → Deflate → 写 pack → 验证 → 删原 loose
- `HyobObjectStore` 优先读 loose，未命中再扫所有 packs（顺序 O(packs × log(packs)) 因 index 内存中）

**实测**：4639 loose × 1.4 MB → 1 pack × 1.1 MB（压缩 76.4%），删除 4639 loose 后磁盘只剩 1 个文件。

**hyobG** 命令体验：
```
[hyob] hyobG: 打包完成
  pack    : pack-47a8bb196a8721b2.pack
  对象    : 4639 个
  尺寸    : 1.4 MB → 1.1 MB  (压缩 76.4%)
  已删 loose : 4639
  pack 总数 : 1
  自检    : ✓ commits=5 trees=28 objs=4606
```

### M8-A：分支与 Checkout

**`hyobB` 三种动作**：
- `list`：枚举所有分支，标记 HEAD 当前分支
- `new <name> <start-ref>`：创建分支
- `delete <name>`：删除分支（拒绝删当前 HEAD 分支）

**`hyobCo <ref>`**：
- 如果 ref 是分支名 → 写 attached HEAD（`ref: refs/heads/<name>`）
- 否则解析为 commit hash → 写 detached HEAD

**关键修复**：分支名带斜线（`feat/x`）需要：
1. `WriteBranchTip` 调 `Directory.CreateDirectory(parentDir)`
2. `EnumerateBranches` 用 `SearchOption.AllDirectories` + 路径分隔符规范化为 `/`
3. `DeleteBranch` 删除文件后递归清理空中间目录到 `refs/heads`

**重要约束**：`hyobCo` **不修改 AutoCAD Database** —— 只动 HEAD 指针。
反向 patch 由独立的 `hyobAp` 命令负责（M9-A 起逐步落地）。

### M8-B：三路合并

**算法**：
1. `MergeBaseFinder.TryFind(a, b)` ← BFS 双向遍历 parent DAG，找最近公共祖先 LCA
2. 三路合并条件：
   - `base == ours` → fast-forward（HEAD 直接前移到 theirs）
   - `base == theirs` → 已是最新（no-op）
   - 其它 → 真三路合并
3. `TreeMerger.Merge(baseTree, oursTree, theirsTree)` ← 递归对比 entries：
   - 双方相同 → 保留
   - 一方变更 → 取变更
   - 双方都变且不同 → 冲突
   - 双方是 Tree → 递归
4. 冲突类型：`ModifyModify / AddAdd / ModifyDelete / DeleteModify`
5. 无冲突 → 写新 merge commit（parents=[ours, theirs]，meta 含 `merge.base/ours/theirs/autoMerged`）；HEAD 推进
6. 有冲突 → 仅打印冲突表，**不写 commit、不动 ref、不动 Database**

**hyobM 实际输出**：
```
[hyob] hyobM: 准备合并
  ours   : abc123…  (main)
  theirs : def456…  (feat/x)
  base   : 789xyz…
[hyob] hyobM: 检测到 1 条冲突，已中止
  ◆ ModifyModify  entities/by-handle/19BAB
      base    : aaa…
      ours    : bbb…
      theirs  : ccc…
[hyob] 未写 commit，未推进 HEAD，未改 Database。
```

### M9：DWG 反向 Patch（**M9-A / M9-B / M9-C-1 已落地**）

#### M9-A：反向 Patch 框架 + Line/Circle/Arc

**三类操作**：
- **Add**：target 有 / DB 无 → 构造新 Entity 追加到 ModelSpace
- **Modify**：双方都有 / hash 不同 → 擦除旧 + 追加新（**M9-A 不保留 handle**）
- **Delete**：DB 有 / target 无 → Erase

**安全约束**：
- 单一 Transaction，过程异常 AutoCAD 自动回滚
- 不在白名单的 type 全部跳过计数（**绝不破坏 DWG**）
- 命令行 Yes/No 二次确认（默认 No）
- 不动 Layer / TextStyle / DimStyle / Block 表（M9-C 范畴）
- 不自动 hyobC，由用户复核后手动提交

**端到端验证**（acadiso.dwt 测试）：
```
[hyob] hyobAp: +1 ~0 -1
  Add  : Line=1
  未变 : 2
[hyob] hyobC: 已提交
[hyob] hyobD HEAD~1 → HEAD:
  - entities/by-handle/2F8 Line   ← 旧 handle 删
  + entities/by-handle/2F9 Line   ← 新 handle 增
```
对称变化符合预期。

#### M9-B：反向白名单扩到 Polyline / DBText / MText

`HyobToEntityConverter.TryBuild(blob, db, tx, out entity, out layer)` 签名扩展，
内部按名查 `TextStyleTable` 解析 `TextStyleId`，找不到回落默认。

**Polyline 重建**：`new Polyline(numVerts)` + `AddVertexAt(i, pt2d, bulge, 0, 0)` × n + closed/elevation/normal/constantWidth

**MText.Direction 退化保护**：极少数老 DWG 的 Direction 为 (0,0,0)，此时回落 (1,0,0) 避免崩溃。

#### M9-C-1：Layer 表反向同步

**策略**（保守 + 字段幂等）：
- target 有 / DB 无 → 创建 LayerTableRecord，拷贝完整字段
- target 有 / DB 有 / 字段不同 → 更新 color / linetype / lineweight / on/freeze/lock/plottable / description
- target 无 / DB 有 → **不删**（防止误删用户层）
- IsUsed 跳过（AutoCAD 只读，由实体引用计算）
- LinetypeName 缺失 → 回落 `Continuous`（DB 自带）

**LineWeight 双向转换**：
```csharp
// 正向：mm → 存储
double LineWeightToMm(LineWeight lw) {
    int v = (int)lw;
    return v < 0 ? v : v / 100.0;     // -3/-2/-1 保留；其它 ÷ 100
}
// 反向：存储 → enum
LineWeight MmToLineWeight(double mm) {
    if (mm < 0) {
        if (mm == -3) return LineWeight.ByLayer;
        if (mm == -2) return LineWeight.ByBlock;
        return LineWeight.ByLineWeightDefault;
    }
    int hundredths = (int)Math.Round(mm * 100.0);
    return (LineWeight)Math.Min(Math.Max(hundredths, 0), 211);
}
```

### M10：BlenderUI 历史面板

**`hyobP` 命令**弹出独立 PaletteSet：
- 顶部：仓库路径 + 分支名 + 状态摘要（commit 数 / object 数 / pack 数）
- 中间：DataGrid 显示 commit 历史（hash / time / cmd / ents / msg）
- 按钮：`刷新 / Diff 选定对 / Diff WIP↔HEAD / 自检 / 清除 Pin`
- 底部：DiffText 文本框显示当前 diff 报告
- 交互：`Ctrl+Click` DataGrid 行 → 把 commit pin 到 CompareLeft / CompareRight；左右都 pinned 时显示 diff

**关键修复**：所有 `Run.Text` 与 `DataGridTextColumn` 绑定都需要 `Mode=OneWay`，
因为 WPF 默认 TwoWay 会尝试写回只读属性 `ShortHash` 等，触发 `InvalidOperationException`。

**主题独立**：使用独立深灰主题，不依赖 BlenderUI ResourceDictionary，避免 PaletteSet 宿主主题问题。

### M11：Diff 算子

#### M11-A：commit↔commit hash 级 diff
- `RefResolver`：解析 `HEAD / HEAD~N / branch / hash 前缀` → commit hash
- `TreeDiffer`：递归对比两 root tree，按 path 分类 `Added / Modified / Deleted`
- 输出格式：
```
+ entities/by-handle/19BAA                      Line
~ tables/blocks/*Model_Space                    BlockDef
- entities/by-handle/2F8                        Line
总计   : +1 ~1 -1
分类   : Line=+1/~0/-1, BlockDef=+0/~1/-0
```

#### M11-B：字段级 diff
对 Modified 条目自动展开 schema 字段 `old → new`：
```
~ tables/blocks/*Model_Space                    BlockDef
    entity_count           949 → 950
```
`HyobFieldExtractor` 是 389 行的 codec —— 按 type_id 分派到对应 `Extract<Type>(blob)` 函数，
返回 `Dictionary<string, string>` 字段名→值字符串。

#### G/C/H 完成段（智能折叠 + 过滤 + log stat）
- 大批量改动 ≥30 条时智能折叠按 type 聚合：
```
共 2662 条变更（智能折叠：> 30 条按 type 聚合）：
+ BlockDef × 887
    示例: *D2607, *D2608, *D2609, *D2610, *D2611, ...
+ Dim × 743
+ XData × 743
~ Dim × 279
```
- `hyobL` 增 `+N ~M -K` stat 摘要 + 按 type 简略：
```
b576b2d713  2026-05-07 22:46  [hyobI]  ents=1702  init...
            +2382 ~280 -0  Dim=+743/~279, BlockDef=+887/~1, ...
```

#### M9-V1：WIP 模式
`hyobD WIP` 比较当前 Database 的 BuildSnapshot vs HEAD，预览未提交变更（≈git status）。
内容寻址保证反复 `BuildSnapshot` 不会重复写对象，无副作用。

### M12：Hygeom 导出（AI 友好 JSON）

**`hyobES` 命令**：
- 输入 ref（默认 HEAD）+ 可选 filter（`layer:钢筋` / `type:Dimension` / `handle:174E`）
- 输出 `.hyob/exports/<commit>[.<filter>].hygeom.json`

**JSON 结构**：
```json
{
  "schema": "hygeom.export/v1",
  "source": { "schema": "hyob.snapshot/v4", "commit": "...", "tree": "..." },
  "commit": { "author": "...", "time": "...", "message": "..." },
  "tables": { "layers": [...], "textStyles": [...], "dimStyles": [...] },
  "entities": [
    {
      "kind": "Line",
      "handle": "19BAA",
      "layer": "钢筋",
      "start": [0, 0, 0],
      "end": [100, 0, 0],
      "xdata": [...],         ← 合并自 .x 兄弟
      "extDict": [...]        ← 合并自 .d 兄弟
    },
    ...
  ]
}
```

**流式 JSON 写入**：用 `JsonTextWriter`，避免大 DWG（5000+ 实体）一次性 OOM。

**类型分派**：每种 type_id 一个 `WriteLineEntity / WriteCircleEntity / ...` 函数，
全程不 `Decode → Encode → JSON`，而是 `Decode → JSON 直接写`，省一次内存拷贝。

## 六、踩过的坑（详细）

### 6.1 AutoCAD .NET API 不一致
| 错误 | 表现 | 修复 |
|---|---|---|
| `MText.DrawingDirection` | CS1061 不存在 | schema 保留字段 + 写 0 |
| `TextStyleTableRecord.IsShape` | CS1061 不存在 | schema 保留字段 + 写 0 |
| `Color.ColorIndex` | 在 ByLayer/ByBlock 时返回特殊值 | LayerReverseMirror 用 `Color.FromColorIndex(ColorMethod.ByAci, idx)` |

### 6.2 路径与文件系统
| 错误 | 表现 | 修复 |
|---|---|---|
| 分支名带 `/`（如 `feat/x`） | `Could not find a part of the path 'refs\heads\feat\x'` | `Directory.CreateDirectory(parentDir)` + `SearchOption.AllDirectories` |
| `paths.Exists` | CS0023 方法当属性用 | 改为 `paths.Exists()` |

### 6.3 WPF 绑定
| 错误 | 表现 | 修复 |
|---|---|---|
| `HyobHistoryItem.ShortHash` 只读 | `InvalidOperationException: 无法对只读属性进行 TwoWay 绑定` | 所有 Run.Text / DataGridTextColumn 显式 `Mode=OneWay` |

### 6.4 Prompt 双重渲染
`PromptString` 同时手写 `<HEAD>` 又设 `UseDefaultValue=true`，AutoCAD 在 prompt 末尾自动追加 `<HEAD>` 第二次。
修复：手写 prompt 中去掉 `<{defaultValue}>`，只设 UseDefaultValue。

### 6.5 using 缺失
- `using System;` 漏导致 `Math.Max` 找不到（M4-B 触发）

### 6.6 字段提取与字符串转义
`HyobFieldExtractor.Q()` 给字符串值加引号；
`HygeomExporter.ExtractLayerSafe` 用于过滤时需主动剥离首尾引号，否则 `layer:钢筋` 永远 false。

### 6.7 Modify 操作 handle 不可保留
M9 反向 patch 的 Modify 操作走 erase + AppendEntity，AutoCAD 自动分配新 handle。
所以 hyobAp + hyobC 后 diff 显示为 `+ NEW - OLD` 对称变化，而非 `~ HANDLE` 修改。
**已通过文案警告用户**，并标记为 M9-D 待解决（需 `SetUnverifiedHandle` API）。

## 七、不足与已知限制

### 7.1 反向 Patch 类型覆盖不全（**最大短板**）

**当前 M9 白名单**（6/13 typed）：
- ✓ Line / Circle / Arc / Polyline / DBText / MText

**未实现反向**（7 种 typed + Opaque）：
- ✗ BlockReference：依赖 BlockDef 表反向同步（M9-C-2）
- ✗ Dimension：9 subtype 各自 .NET 类型，构造参数不同；DimStyle 表也需反向同步（M9-C-3）
- ✗ MLeader：语义级存储，无完整顶点拓扑，反向只能"近似"
- ✗ Hatch：pattern-only 存储，缺边界几何，反向不可完整复原
- ✗ Wipeout：正向当前未触发（统一走 Opaque），无对象反向
- ✗ XDataAttachment / ExtensionDictionary：反向需挂回主 entity 的 XData / ExtensionDictionary 槽位
- ✗ Opaque：黑盒，原则上不可反向（除非 DWG 类工厂支持 from-DXF-bytes 重建）

**影响**：用户在反向 patch 时，被反向的 entity 如果引用了 Dim/MLeader/Hatch/BlockRef，那些 entity 不会回滚 → DWG 状态与 commit 不一致。**目前的"不破坏"语义保护用户安全，但失去了完整的回滚能力**。

### 7.2 表反向同步只完成 1/4

| 表 | 反向状态 |
|---|---|
| Layer | ✓ M9-C-1 已落地 |
| Linetype | ✗ 未存正向，反向更无 |
| TextStyle | ✗ 未实现，缺失时 DBText/MText 回落默认 STANDARD |
| DimStyle | ✗ 未实现，影响 Dimension 反向 |
| Block | ✗ 未实现，BlockDef 不实例化 BlockReference 也无意义 |

### 7.3 Modify 操作 handle 不保留

当前 Modify = erase + 新建，AutoCAD 自动分配新 handle。
**用户体验**：hyobAp + hyobC 后 diff 显示 `+ NEW - OLD` 对称变化，看起来像"删 1 加 1"而非"修改"。
**修复路径**：用 `Database.SetUnverifiedHandle(entity, oldHandle)` 强制保留 handle，但需要先 `SetExtendedReadOnlyMode(false)`，
风险是冲突时 AutoCAD 可能拒绝。M9-D 待评估。

### 7.4 损失精度

| 数据 | 损失方式 | 影响 |
|---|---|---|
| XData TypedValue | 一律 `ToString()` 后存 utf8 | double 尾数精度 |
| Hatch boundary | 完全不存 | 反向无法复原 boundary |
| MLeader vertex | 仅存 leader 起止 | 反向无法复原中间转折 |
| MText backgroundFill | 仅存 ARGB，未存 fill type | 反向回落 ARGB 实色 |
| Polyline 各段不同线宽 | 仅存全局 ConstantWidth | 各段 startWidth/endWidth 丢失 |
| Polyline2d / Polyline3d | 走 Opaque | 完整保真但不可反向 |

## 十一、结语

hyob 子系统从 0 实施 4 天，落地 51 个 .cs 文件 / 10,500 行 / 13 命令 / 41 项自检 / 1 WPF 面板，
覆盖 04 计划 90% 的工作量。**核心能力**（content-addressable 二进制存储 + Git-like 增量 +
13 种 typed schema + 4 张表 + 反向 patch 框架 + 完整 Diff/Merge/Branch/Pack）已端到端可用。

**最大短板**是反向 patch 类型覆盖不全（6/13），目前只能保证"安全不破坏 DWG"，
不能保证"完整回滚"。这块是 M9-C-2/3/4 的工作，预估 3 周内可补齐到 11/13（除 MLeader / Hatch 因 schema 信息损失天然不可完整反向）。

整体设计哲学坚守"Domain 纯净 + 黑盒兜底 + 单事务回滚"三条不退让的底线，
为后续扩展（远端、delta 编码、增量 BuildSnapshot）留足了空间。
