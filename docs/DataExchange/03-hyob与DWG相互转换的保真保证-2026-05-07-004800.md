# hyob ↔ DWG 相互转换的保真保证

> 配套阅读：

> - `02-HyCAD与DWG平行的增量几何存储系统-2026-05-07-002200.md`

> 02 提出 hyob 与 DWG 平行存储。本篇回答关键问题：**怎么保证两者能互相转换、不丢信息**。

---

## 1. 问题的真实难度

直觉上 DWG 只有 Line / Arc / Polyline / Text 几种，做 schema 转换不难。实际不是。

一个真实 DWG 文件里至少包含：

| 类别 | 内容 |
|---|---|
| 系统变量 | INSUNITS / LUNITS / MEASUREMENT / DIMSCALE / 上百个 header vars |
| 类注册 | Classes 段，登记本图所有自定义类型的 dxf name + cpp class + app name |
| 表 | Layer / Linetype / TextStyle / DimStyle / Block / View / UCS / Viewport / RegApp |
| 字典 | NamedObjectsDictionary 树（ACAD_GROUP / ACAD_LAYOUT / ACAD_PLOTSETTINGS / 用户自定义） |
| 实体 | Line / Arc / Circle / Polyline / Spline / Region / Hatch / 3DSolid / Surface / Mesh / WipeOut / Image / OLE / PDF / DGN underlay 等 |
| 块定义 | BlockTableRecord 含本块的所有对象 |
| 块引用 | BlockReference + AttributeReference |
| 标注 / 引线 / 表 | Dimension / MLeader / AcDbTable |
| 字段 | FIELD（动态求值，例如长度、面积、属性引用） |
| XData | 每个对象上挂的应用扩展数据，按 RegApp 分组 |
| ExtensionDictionary | 每个对象挂的命名字典 + xrecord |
| Persistent Reactors | 对象间联动通知 |
| 布局 / 纸空间 / 视口 | Layout + Viewport + PlotSettings |
| Proxy / Custom Object | 来自 Civil 3D / Map 3D / Mechanical 等垂直产品的对象，普通 AutoCAD 只能显示 proxy graphics |
| 加密 / 签名 / 缩略图 | 文件头与尾部数据 |

DWG 总类型数 1000+，垂直产品再各自加一批。**HyCAD 不可能、也不应该完整建模整个类型系统**。

因此"保证相互转换"这个问题的真正核心是：

> **不是怎么把所有类型都翻译成 hyob schema，而是不认识的东西怎么办、改过的东西怎么写回去而不破坏其他东西。**

## 2. 先定保真等级

| 等级 | 含义 | 现实性 |
|---|---|---|
| Bit-perfect | DWG 字节级一致 | 不可行（DWG 内部有时间戳、加密随机数、内部缓存指针，AutoCAD 自己 SAVE 都不 bit-perfect） |
| **Semantic-equivalent** | 所有对象、属性、关系、字典、XData 在打开后语义一致 | **我们的目标** |
| Render-equivalent | 图打开看着一样即可 | 太弱，垂直产品会瘫，proxy 会丢 |

往后所有"保证"二字都指 **Semantic-equivalent**：

```text
打开 hyob 还原出的 DWG
  ⇔
打开原 DWG
  在 AutoCAD / Civil 3D / 任何兼容软件里
  所有对象、图层、样式、字典、XData、proxy graphics 都仍然存在且行为一致
```

## 3. 核心保证机制（五件套）

```text
┌────────────────────────────────────────────────────────────────┐
│ ① 白名单 + 黑盒兜底     —— 不认识的不解释，按字节保留          │
│ ② DWG 永远由 AutoCAD 写 —— hyob 不直接生成 DWG                 │
│ ③ Handle 双向锁          —— 对象身份不丢                       │
│ ④ 命令级双写 + reconcile —— 两端实时一致                       │
│ ⑤ Round-trip 自检 + 降级 —— 不一致绝不悄悄发生                 │
└────────────────────────────────────────────────────────────────┘
```

### 3.1 白名单 + 黑盒兜底

DWG 中每个对象在 hyob 里有两种形态：

| 形态 | 适用 | 透明度 |
|---|---|---|
| **TypedObject** | 在 HyCAD 白名单里的类型（Line/Polyline/Arc/Circle/Text/MText/BlockRef/Layer/Style/...） | 完全透明：可 diff / merge / 给 AI / 命令操作 |
| **OpaqueObject** | 不在白名单里的类型（Spline NURBS / proxy entity / 3DSolid / Hatch 复杂边界 / 自定义类型） | 黑盒：只保留原始字节、type 名、handle，hyob 不解释 |

OpaqueObject 二进制结构：

```text
[ magic         : 2 bytes  = "HO" ]
[ schema_ver    : 1 byte   = 1 ]
[ type_id       : 2 bytes  = 0xFFFF (= Opaque) ]
[ flags         : 1 byte ]
[ payload_len   : 4 bytes ]
[ payload :
    [ dwg_class_name_len : 2 bytes ]
    [ dwg_class_name     : utf-8 bytes ]      <- "AcDbSpline" / "AeccDbAlignment" / ...
    [ dwg_app_name_len   : 2 bytes ]
    [ dwg_app_name       : utf-8 bytes ]      <- "ACAD" / "AeccCatalog" / ...
    [ handle_len         : 1 byte ]
    [ handle             : raw bytes ]        <- 原 DWG handle 字节
    [ raw_dxf_len        : 4 bytes ]
    [ raw_dxf            : DXF group code 序列 (binary form) ]
    [ raw_xdata_len      : 4 bytes ]
    [ raw_xdata          : 该对象上的 XData ]
    [ raw_extdict_len    : 4 bytes ]
    [ raw_extdict        : 该对象上的 ExtensionDictionary 序列化 ]
]
[ checksum      : 4 bytes  CRC32 ]
```

要点：

- 内容用 **DXF 二进制 group code 序列**，不是 DWG 段字节流。原因：DXF 由 AutoCAD .NET API 直接读写（`DxfOut` / `DxfIn` / `Entity.WriteDxfFields`），稳定且跨版本；DWG 内部段格式是 ODA 逆向工程的，跨版本不稳。
- 黑盒对象在 hyob 里仍然有 hash → 仍然能 content-addressable、仍然能 pack delta、仍然能进 commit 历史。
- 黑盒对象在 hyob 里 **不参与 diff/merge 的字段级比对**，只比对 hash：变了就是变了，不展开。

效果：

```text
┌────────────────────────────────┐
│ DWG 总类型数 1000+              │
├────────────────────────────────┤
│ HyCAD 白名单 ≈ 30 种            │
│   覆盖 95% 日常工作量           │
├────────────────────────────────┤
│ 剩下 970+ 种走 OpaqueObject     │
│   不认识 ≠ 不保留               │
└────────────────────────────────┘
```

### 3.2 DWG 永远由 AutoCAD 自己写

这是最关键的一条。

**hyob 不直接生成 DWG 文件**。hyob 只是 AutoCAD Database 的一个版本化镜像。生成 DWG 永远走 AutoCAD 自己的 `SAVEAS` / `Database.SaveAs(...)`。

数据流：

```text
打开：
  AutoCAD OPEN example.dwg
    → 内存里有完整 Database
    → HyCAD 镜像扫描 Database
        - 白名单类型 → TypedObject 写入 hyob
        - 其他类型   → OpaqueObject 写入 hyob (DXF 序列化)
        - 元数据     → header vars / tables / dictionaries 镜像
    → hyob commit "open"

修改（HyCAD 命令）：
  命令在 AutoCAD Database 上改对象
    → 命令完成后扫描受影响 handle
    → 增量更新 hyob (只改动的对象 + Tree + 1 commit)
    → AutoCAD 仍持有完整 Database

保存：
  AutoCAD SAVE example.dwg     ← AutoCAD 自己负责完整 DWG 写出
  hyob 同步 commit "save"      ← 与本次 SAVE 一一对应
```

**含义**：

- DWG 文件结构（header / classes / tables / dictionaries / sections / 加密 / 缩略图）**完全由 AutoCAD 维护**。
- HyCAD 只通过 .NET API 改某些对象，AutoCAD SAVE 时它会把整张图按它自己的格式写出。
- 我们没有"必须自己实现一个 DWG writer"的负担。
- 我们没有"DWG 升级版本时格式跟不上"的风险。

### 3.3 Handle 双向锁

每个 hyob Object 都必须带原 DWG handle：

```text
TypedObject(Line) {
  handle      : "3F2A"            <- 原 DWG handle
  hyob_hash   : <SHA-256>          <- 内容寻址
  ...
}
```

Tree 里维护正反两套索引：

```text
/entities/
  by-handle/
    3F2A         -> hash of Object   <- 用 handle 查 hyob 对象
    3F2B         -> hash of Object
  ordered/                              <- 保留 DWG 内部对象顺序
    [hash, hash, hash, ...]
```

新对象的 handle 由 AutoCAD Database 分配（Database.HandleSeed 自增），HyCAD 不自己造 handle。

效果：

- DWG → hyob：handle 从 Database 直接抄过来。
- hyob → DWG：用 handle 找 Database 里对应对象，调 AutoCAD API patch；新增对象交给 AutoCAD 分配 handle。
- handle 任何时刻都是同一个，**对象身份永远对得上**。

### 3.4 命令级双写 + 启动期 reconcile

两个写入路径：

```text
路径 A：HyCAD 命令
  Command.Execute() {
    using var tx = db.TransactionManager.StartTransaction();
    var changed = ApplyChanges(tx);          // AutoCAD Database 改动
    tx.Commit();                              // AutoCAD 端落地
    hyob.RecordChanges(changed);              // hyob 端记录
    hyob.Commit($"{commandName}", meta);     // hyob commit
  }

路径 B：用户在 AutoCAD 里直接改图（不经过 HyCAD 命令）
  在 Database.ObjectModified / ObjectAppended / ObjectErased 事件里
    → 维护一个 dirty handle 集合
    → 用户 SAVE 时
        AutoCAD 写 DWG (整图)
        HyCAD 把 dirty 集合 commit 到 hyob，命令名 "external-edit"
```

启动期 reconcile：

```text
打开 example.dwg：
  if (.hyob/ 不存在) {
      初次扫描整个 Database 写 hyob
  } else {
      读 hyob HEAD 的 Tree 与当前 Database 比对
      差异 → commit "reconcile-on-open"
  }
```

### 3.5 Round-trip 自检 + 自动降级

每次 HyCAD 命令完成、每次 SAVE 时，做一次轻量自检：

```text
对每个被修改的对象 H：
    a = AutoCAD.ReadDxfBinary(H)        // 当前 Database 里的 DXF 序列
    b = hyob.Encode(hyob.Read(H))        // 从 hyob 编码出 DXF 序列
    if (a == b)
        透明对象正确
    else
        ⚠ 自动降级
        把该对象在 hyob 里改写为 OpaqueObject(raw=a)
        commit "auto-downgrade <handle> <reason>"
        在 log/operations.jsonl 里写一条
```

CI 测试样本库：

```text
tests/dwg-corpus/
  ├ road/                       道路
  ├ rein/                       钢筋
  ├ anchor-bolt/                地脚螺栓
  ├ equipment/                  设备基础
  ├ civil3d/                    Civil 3D 含 alignment
  ├ map3d/                      Map 3D 含拓扑
  └ wild/                       网上找的奇葩 DWG
```

CI 流程：

```text
foreach dwg in corpus:
    open with AutoCAD .NET (Console)
    snapshot1 = dump_canonical(database)        # handle + 所有 dxf code 排序后 hash
    hyob = scan(database)
    save_dwg as roundtrip.dwg
    open roundtrip.dwg
    snapshot2 = dump_canonical(database)
    assert snapshot1 == snapshot2
```

不通过 = 必须修。

## 4. 各种"难类型"的具体保证策略

| DWG 内容 | 保证策略 |
|---|---|
| Line / Arc / Circle / Polyline | 白名单 TypedObject，schema 化 |
| Text / MText / Dimension / MLeader | 白名单 TypedObject，schema 化（重点保留 raw 字符串避免格式标记丢失） |
| BlockReference + AttributeReference | 白名单 TypedObject，引用块定义的 hash |
| Hatch | 边界白名单，复杂图案保 raw seed + 边界引用 |
| Spline / NURBS | OpaqueObject（hyob 不展开 NURBS 控制点序列化细节） |
| 3DSolid / Surface / Region | OpaqueObject |
| WipeOut / Image / OLE / PDF underlay | OpaqueObject |
| Layer / Linetype / TextStyle / DimStyle | 白名单 TypedObject |
| Block 定义 | 容器走 TypedObject，内部对象按各自策略 |
| Layout / Viewport / Plot 设置 | OpaqueObject（先黑盒，等需要再升白名单） |
| 字典 / NamedObjectsDictionary | 容器走 TypedObject，xrecord 走 OpaqueObject |
| XData (按 RegApp) | 全量 byte 保留挂在所属对象上 |
| ExtensionDictionary | 全量 byte 保留挂在所属对象上 |
| header vars | 镜像成 Object(HeaderVars)，所有变量原值保留 |
| Persistent Reactors | OpaqueObject 保留对象间引用，hyob 不主动 fire |
| Civil 3D / Map 3D 自定义对象 | OpaqueObject（只能这样，AutoCAD 普通版本身也不解释） |
| Proxy entity / proxy graphics | OpaqueObject |
| 加密 / 签名 / 缩略图 | 完全交给 AutoCAD SAVE，hyob 不参与 |

原则：**没把握的全黑盒**。黑盒是安全边界，不是失败。

## 5. 如果用户在 AutoCAD 里改了某个 OpaqueObject 怎么办

完全可以。流程：

```text
1. AutoCAD 改了一个 Hatch（OpaqueObject，hyob 不展开）
2. 命令完成 / SAVE
3. HyCAD 通过 ObjectModified 事件知道 handle dirty
4. 重新 DXF 序列化该对象 → 新 raw 字节流
5. hyob 端：用同一个 handle 写一个新的 OpaqueObject blob
   - 新 hash ≠ 旧 hash → Tree 里 by-handle/<H> 指向新 hash
   - commit "external-edit"
6. 历史里能看到该 handle 的二进制流改过，但不能在 hyob 内做字段级 diff
```

效果：**OpaqueObject 仍然受版本控制**，只是 diff 粒度是"整对象变了"而不是"哪个字段变了"。

如果以后要给 Hatch 做白名单升级，只需要：

1. 写 Hatch 的 schema 与 codec
2. 在 round-trip 自检通过后切换到 TypedObject
3. 历史里旧的 OpaqueObject blob 不动（hyob 是 append-only）

迁移是单向的、安全的。

## 6. 用户跨版本 AutoCAD 怎么办

AutoCAD 每年发版，DWG 格式约 3 年一变。我们的设计已经回避了这个问题：

- DWG 由 AutoCAD 自己读写 → 永远是当前 AutoCAD 版本支持的最新格式
- hyob 里黑盒走 DXF 序列化 → DXF 跨版本是稳定的
- hyob 自己有 schema_ver → 我们自己控制版本演进

如果用户在 AutoCAD 2028 上打开了 AutoCAD 2025 hyob 历史里某个旧 commit：

```text
hyob.checkout(old_commit)
  → 拿出当时的 OpaqueObject (DXF binary)
  → 通过 AutoCAD .NET API 反序列化为 Database 对象
  → AutoCAD SAVE 出新格式 DWG
```

DXF group code 跨版本兼容（高版本支持旧版本，新增 code 旧版本忽略），所以这条路径稳。

## 7. 失败处理矩阵

| 情况 | 检测点 | 处理 |
|---|---|---|
| 白名单类型解码失败 | hyob 写入时 | 自动降级为 OpaqueObject，warn 日志 |
| 白名单类型 round-trip 不一致 | 自检 | 自动降级，commit "auto-downgrade"，记 issue |
| 黑盒对象 DXF 序列化失败 | hyob 写入时 | 跳过该对象不写 hyob，用户被提示该 handle 不在版本控制中 |
| handle 冲突（两边对不上） | reconcile | 信任 AutoCAD Database，hyob 改写为最新状态，commit "handle-resync" |
| AutoCAD SAVE 失败 | SAVE 时 | hyob commit 仍保留，标记 `dwg-pending`，下次启动重试 |
| hyob 写入失败（磁盘满 / 权限） | hyob 写入时 | AutoCAD SAVE 不受影响，hyob 端记 fail，启动时提示用户 |
| hyob 损坏（hash 不一致） | 读取时 | 拒绝读取该 commit，回滚到上一个有效 commit；提示用户从 DWG 重建 |
| 用户拷走 DWG 没拷 hyob | 打开时 | 当作初次打开，扫描 Database 重建 hyob |
| 用户拷走 hyob 没拷 DWG | 打开时 | 拒绝；hyob 不是 DWG 的替代品 |
| Civil 3D 文件用纯 AutoCAD 打开 | 打开时 | proxy 对象走 OpaqueObject，能保住，但 HyCAD 也不能编辑 |

## 8. 落地路线（针对相互转换部分）

| 阶段 | 内容 | 验收 |
|---|---|---|
| 0 | 跑通"打开 → 镜像 → SAVE"路径，所有对象走 OpaqueObject | 任意 DWG 打开 SAVE 后 round-trip 通过 |
| 1 | Line / Polyline / Arc / Circle 升白名单 | corpus round-trip 通过 |
| 2 | Text / MText / DBText / DimStyle / TextStyle 升白名单 | 文字格式与字体不丢 |
| 3 | Layer / Linetype / 块定义 / 块引用 升白名单 | 块属性与可见性不丢 |
| 4 | Dimension / MLeader 升白名单 | 标注样式与文字位置不丢 |
| 5 | XData / ExtensionDictionary 完整保留机制 | 设备基础 / 钢筋等垂直数据不丢 |
| 6 | Hatch / Wipeout 边界升白名单（图案仍黑盒） | 图案外观一致 |
| 7 | round-trip 自检 + 自动降级 + CI corpus | 任何 commit 都过 round-trip |
| 8 | 启动期 reconcile + external-edit | 用户用别的工具改图也不丢历史 |

每升级一个白名单类型都要先建样本、过 round-trip、再上线。

## 9. 一句话保证

> **DWG 永远由 AutoCAD 自己读写，hyob 只镜像。HyCAD 不认识的对象按 DXF 字节保留为 OpaqueObject 进版本控制；handle 双向锁定保证身份；命令级双写保证实时一致；CI round-trip 自检保证不悄悄丢东西。**
>
> 这就是为什么相互转换可以保证。

## 10. 与 02 文档的衔接

02 里 Object 二进制格式增加一种 type_id：

```text
type_id == 0xFFFF  →  OpaqueObject (本文档定义)
其他 type_id       →  TypedObject  (02 文档定义)
```

02 里 Tree 增加 `entities/ordered/` 索引。

02 里 Commit 增加可选字段 `external-edit-handles: [hash, ...]`，标识本次 commit 是 reconcile 出的而不是 HyCAD 命令产生的。

02 里 Repository API 增加：

```csharp
public interface IDwgMirror
{
    void MirrorDatabaseIntoHyob(Database db);
    void ApplyHyobChangesToDatabase(Database db, Hash from, Hash to);
    RoundTripReport SelfCheck(Database db);
    void DowngradeToOpaque(Hash objectHash, string reason);
}
```

至此 02 设计完整地具备了"可保证相互转换"的能力。
