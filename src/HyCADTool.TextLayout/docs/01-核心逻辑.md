# 核心逻辑

> 面向人类读者：这个软件在干什么、为难谁、给谁用、用什么办法、边界在哪。
> 模块与路径见 [02-项目架构](02-项目架构.md)；启动与命令见 [04-启动与测试](04-启动与测试.md)。

## 1. 一句话

HyCADTool.TextLayout（HyCAD 文字排版程序集）把 Markdown 设计说明切成顶层块、按图纸栏宽估高并流到下一栏/下一页，再输出 AutoCAD 可用的 MText 格式码；它不画图、不依赖 AutoCAD API（应用程序接口，此处指 CAD 实体读写）。

## 2. 解决什么困难

结论：真正卡住的是「网页里看着一栏、落到图纸又换行错位」，因为预览和出图若各算一套字宽/栏高，页就会对不齐。

| 困难 | 表现 |
|---|---|
| 中英混排宽度口径不统一 | 同一段在预览能放下，图纸上提前折行或留白过大 |
| 分栏分页规则分裂 | 编辑器一页两栏，图纸上块跑到另一栏或另一页 |
| 表格/代码被空行误拆 | 一张表被切成半截 MText，图纸上对不齐 |

**本软件不解决**：不提供编辑窗口、不创建 CAD 图元、不负责 HyMd（进程外说明编辑器，经命名管道把纸面坐标贴进图纸）的屏外分页几何。当前 `hymd` 贴图主路径以 HyMd 导出的毫米坐标为准。**已验证**。

## 3. 什么样的用户需要

| 适合 | 不太需要 |
|---|---|
| 要在插件里把说明原文排进图纸栏的开发者 | 只在 HyMd 里写字、不改排版算法的最终用户 |
| 需要同一套「字宽 / 栏宽 / 估高」口径的预览与导出 | 要精确 TrueType 字形测量或 PDF/Word 排版的场景 |

## 4. 用什么机制（不展开实现）

| 概念 | 是什么 | 起什么作用 |
|---|---|---|
| 顶层块 | 标题、段落、列表、引用、表格、代码、分隔线之一 | 分栏的最小搬运单位，避免表/代码被空行切开 |
| 显示宽度单位 | ASCII=1、CJK（中日韩汉字）/全角=2；空白不计 | 估行数与栏内容量的共用尺子 |
| 页面驱动栏宽 | 用纸宽减边距再均分栏（栏间距计入） | 栏宽跟图纸走，而不是死记「每栏 28 字」 |
| 流式分配 | 当前栏放不下就进下一栏，栏满则新页 | 决定每块落在哪一页哪一栏 |
| MText 格式码 | `\H` 字高、`\P` 换段、`\f` 字体等控制串 | 让 CAD 按同一套段距/缩进画出说明 |

**主流程**（调用方视角）：

1. 喂入 Markdown 原文 + 版式配置（纸张、栏数、字高、比例）。
2. 解析顶层块并标类型、估显示宽度。
3. 按栏宽估每块高度，从左栏往右、满则翻页。
4. 按每栏块下标回切原文，再把每栏 Markdown 转成 MText 字符串。
5. 调用方（设计说明功能）负责把字符串写成图纸实体。

当前产品有两条路：**已验证**。

- 旧路径：本库做分页分栏，再逐栏转 MText。
- 现行 `hymd` 贴图：HyMd 已带每块的 x/y/宽，本库侧主要仍被旧插入与解析表格块使用；MText 字符串由设计说明功能里更完整的一份渲染器生成，不是本库这一份。

## 5. 边界

默认管：Markdown 常见块的切分、估高、分栏分页、把一段 Markdown 编成 MText 控制码、多级列表编号样式。

明确不管：AutoCAD 事务与图层、图框绘制、HyMd 管道协议、真机字体度量、把 GFM 表画成 CAD Table（表格实体）。

行为边界：单块高于一栏时，若该栏还是空的，仍会塞进去（允许溢出），不会把一块拆成两栏。`IsBreakable`（块是否允许打断）只在解析时赋值，分配时未使用。**已验证**。

估高是「显示单位 ÷ 每行字数 × 行距」，不是字形轮廓。**推断**（读估高公式，未对照 CAD 实测）。

## 6. 记忆链 / 口诀（可选）

谁痛（预览和图纸两套尺子）→ 给谁（插件排版，不是最终用户窗口）→ 办法（切块 → 估高 → 流栏 → 出 MText 串）→ 边界（不算 CAD、不算 HyMd 贴图坐标）。

- 库 ≠ 贴图：`hymd` 主路径坐标来自 HyMd 导出。
- 尺子 ≠ 字形：CJK=2 是约定，不是字体文件。
- 块 ≠ 行：分栏搬的是顶层块，不是按空行切。
- 空栏可溢出：放不下且栏已有内容才换栏。
