# 纸面预览与 AutoCAD 文字对照夹具

> 为了选：把「预览看起来和图纸差太大」拆成可独立计量的尺子，给以后对齐做底板。不改贴图算法。

## 1. 一句话

对照面是 **纸面预览 ↔ AutoCAD MText**（AutoCAD 多行文字实体）。夹具同一批样张分别在预览 DOM、贴图屏外 dump 宿主、真 MText 上量字宽、折行 N、行距和块框，写出 JSON 和图面叠框。主编辑器长卷不进主矩阵。**建议**。

## 2. 解决什么困难

结论：差不是单一字体，而是三条尺子叠在一起；不拆开量，对齐会改错边。**推断**（读代码，夹具数字待第一轮实测）。

| 困难 | 表现 |
|---|---|
| 预览 ≠ dump 宿主 | 预览叠画廊排版（默认 github 字高 3.7 mm、行高绝对毫米）；dump 用主题 CSS、字高写死 3.5 mm |
| dump 框 ≠ MText 再折行 | 贴图只交块框+Markdown 切片；AutoCAD 按文字样式轮廓重新折行 |
| 西文走不同家族 | 预览字体栈西文先 Segoe UI；样式 T（说明槽 TrueType）整段走微软雅黑 |

**本文不解决**：不改 `InsertFromHyMdDump`、不改 ASCII=1/CJK=2 估宽、不对齐 TSSD（天正 SHX 形字体配对）与网页预览。

## 3. 什么样的用户需要

| 适合 | 不太需要 |
|---|---|
| 要把设计说明从 HyMd 纸面预览贴进图纸、并准备改尺子的人 | 只在长卷里写字、不贴 CAD 的人 |

## 4. 用什么机制（不展开实现）

| 概念 | 是什么 | 起什么作用 |
|---|---|---|
| recipe | 同一份 Markdown 的一种排版配方 | 拆开「预览 / dumpHost / 强制雅黑 / 强制宋体 / CAD 雅黑 / CAD 宋体 / CAD TSSD」 |
| 折行 N | 固定栏宽下仍保持一行的最大字符数 | 把「提前折行」变成一个整数差 |
| 叠框 | HyMd 块框洋红、MText 外接框青色 | 目视溢出，不必先信 JSON |

**主流程**：

1. HyMd 排版预览打开 `samples/cad-compare/` 样张，点「导出对照 JSON」，得到 `hymd-compare.json` / `hymd-preview.json` / `hymd-dump.json`。
2. AutoCAD 执行 `HYMDCOMPARE`（热重载可用 `N39`），样张目录指向同文件夹，点左上角。写出 `cad-mtext.json` 与 `compare-table.md`。
3. 无 AutoCAD 时：`node samples/cad-compare/join.mjs` 只拼已有 JSON；缺的一侧留空，标 **待验证**。

样张矩阵：G 字形、W 折行、V 竖直、F 字体、I 集成叠框。纸面固定 A4、1 栏、边距 `[25,20,25,20]`。

## 5. 边界

默认管：把差异收成数字和图面框。

明确不管：改插入、改字体白名单、用 GDI 冒充 AutoCAD、用 Node 假 DOM 冒充 WebView2。

| 边界 | 说明 | 证据 |
|---|---|---|
| 预览 CSS ≠ dump CSS | 预览始终 `THEMES.default` + 画廊变量；dump 跟 frontmatter 主题且不叠画廊 | **已验证**（读源码） |
| CAD 单倍行距约 1.66×字高 | AutoCAD 帮助如此写；本仓 `LineSpacingFactor=1.2` 且 Exactly | **待验证**（两行 ActualHeight） |
| 约定尺子 2.0 | 估宽仍 ASCII=1 CJK=2；真机 CJK/ASCII 宽比由夹具 glyphs 给出 | **待验证** |
| 第一轮数字 | 本机尚未跑 WebView2 导出 + AutoCAD `HYMDCOMPARE` | **待验证** |

## 6. 记忆链 / 口诀

谁痛（预览和图纸差太大）→ 给谁（要对齐的人）→ 办法（三面都量、一次动一个变量）→ 边界（先量后改，TSSD 不对齐网页）。

- 看见的 ≠ 送去的：预览和 dump 宿主不是同一套 CSS。
- 送去的框 ≠ 落笔：MText 会再折一次。
- 雅黑 = YaHei，宋体 = SimSun：别名不是第二种字。
- TSSD 只对照：网页画不出单线字。
