# 字体选型收口：只留 TSSD、微软雅黑、宋体

> 为了选：把原先下拉里的可选字体归档，并收成最小集合。不写实现细节。排版程序集本身按「显示单位」估宽，不读字体文件；图纸上真正画出来的仍是所选字体轮廓。

## 1. 一句话

以后只用三套字：**TSSD**（天正建筑常用的 SHX 形字体包，西文 `tssdeng.shx` + 中文大字体 `tssdchn.shx`，作用是让标注/引线/表格跟国内常见天正图面一致）、**微软雅黑**（Windows 中文无衬线 TrueType 家族，英文名 Microsoft YaHei，作用是说明标题与预览）、**宋体**（Windows 中文衬线 TrueType 家族，英文名 SimSun，作用是国标/互操作与「必须用宋体」的图面）。其余原可选字体全部退出候选。**建议**。

## 2. 解决什么困难

结论：字体家族一多，同一栏文字会在预览、估高、图纸三处各走一套轮廓，换行点对不齐。收口不是审美，是把「尺子」和「落笔」锁到同一小集合。

| 困难 | 表现 |
|---|---|
| 下拉过宽 | 设置里可点黑体、楷体、仿宋、Arial、Times、Calibri、Consolas 等，同一份说明里容易混族 |
| 粗体/代码切族 | 粗体曾切到黑体（SimHei），代码默认 Consolas；同一段 MText（AutoCAD 多行文字，用 `\f` 等格式码控制字体）中途换轮廓 |
| SHX 与 TrueType 混用 | 预览按微软雅黑画，插入却用 `tssdeng.shx` + 旧大字体 `hztxt.shx`，字宽与缺字都不一样 |
| 中英别名当两套字 | 「微软雅黑」与 `Microsoft YaHei`、「宋体」与 `SimSun` 本是同一家族，下拉里却并列，容易当成可混排的两种 |

**本文不解决**：不测量某台机上的真实字形宽度；不规定 AutoCAD 字体搜索路径；不替代纸张/栏宽/行距配置。

估高仍用 ASCII=1、CJK（中日韩汉字）/全角=2 的约定尺子，**不是**字体文件里的轮廓宽。字体再少，估高也不会变成 TrueType 度量。**已验证**（读排版口径）。轮廓不同仍会改变图纸上的实际折行，所以白名单仍然必要。**推断**。

## 3. 什么样的用户需要

| 适合 | 不太需要 |
|---|---|
| 设计说明要进 CAD 图框、要和天正图面放在一起 | 要在说明里当「字体展览」、按段换艺术字的场景 |
| 要预览和插入尽量同一家族、少缺字、少中途切 `\f` | 必须用仿宋/楷体做规范条文体、或必须用 Arial 对接外文模板的专项图 |

## 4. 用什么机制（不展开实现）

| 概念 | 是什么 | 起什么作用 |
|---|---|---|
| 文字样式双槽 | 样式 T = TrueType 说明；样式 S = SHX 标注 | 标题/说明走微软雅黑或宋体；标注/引线/表格走 TSSD 配对 |
| SHX + 大字体 | 西文形文件 + 中文大字体文件成对 | TSSD 必须 `tssdeng.shx` 配 `tssdchn.shx`，不要再配 `hztxt.shx` |
| 同族粗体 | 加粗仍留在当前家族内 | 避免为了粗体切到黑体或另一套 TrueType |
| 代码跟随正文 | 代码块不再切 Consolas | 少一个等宽族，换行更稳；代价是代码不再「编程字体」观感 |

**主流程**（选型，不是改码步骤）：

1. 从图纸角色选槽：说明/标题 → 微软雅黑（默认）或宋体；标注/引线/表格 → TSSD 配对。
2. 别名归一：微软雅黑 = Microsoft YaHei = msyh；宋体 = SimSun。界面只显示中文名。
3. 禁止第三套：黑体、楷体、仿宋、西文西文 UI 字、旧 SHX（simplex / romans / txt / hztxt / gbcbig 等）不进新下拉。
4. 粗体与代码：优先同族或跟随正文，不靠切字模拟。

### 4.2 收口后的白名单

| 角色 | 只准用 | 界面显示 | 禁止 |
|---|---|---|---|
| 说明 / 标题（样式 T） | 微软雅黑或宋体 | 微软雅黑、宋体 | 其它 TrueType |
| 标注 / 引线 / 表格（样式 S） | TSSD 配对 | `tssdeng.shx` + `tssdchn.shx` | 其它 SHX / 其它大字体 |
| 粗体 | 同族：微软雅黑保持微软雅黑；宋体保持宋体；SHX 用加宽模拟，不切黑体 | — | SimHei / 黑体 |
| 代码 | 跟随当前正文族 | 无独立字体项 | Consolas、Courier New |

设置里当前默认已接近收口：样式 T = 微软雅黑，样式 S = `tssdeng.shx` + `tssdchn.shx`。**已验证**。设计说明配置默认正文/粗体是 Microsoft YaHei，代码仍默认 Consolas；旧全局文字样式仍有 `tssdeng.shx` + `hztxt.shx`。**已验证**（读默认值，未改码）。

## 5. 边界

默认管：产品「可以选哪些字」、三套字各干什么、原清单如何归档。

明确不管：HyMd 网页里用户随便贴的字体名；某台电脑没装 TSSD 时的文件分发；把估高改成真机字形测量。

| 边界 | 说明 | 证据 |
|---|---|---|
| TSSD 要成对 | 西文 `tssdeng.shx` 必须配中文 `tssdchn.shx`；拆开或改配 `hztxt.shx` 会回到旧混用 | **建议** |
| 微软雅黑 ≠ 宋体 | 无衬线 vs 衬线，字宽与灰度不同；一份说明只选其中一个做样式 T，不要段内混 | **推断** |
| 白名单 ≠ 估高改成轮廓度量 | 收口后估高仍是 CJK=2 约定；一致性靠少切族，不靠量 TTF | **已验证**（尺子）+ **待验证**（收口后目视） |
| Consolas | 等宽有利于代码对齐，但会在说明里插入第四轮廓；按本次目标应去掉 | **建议** |
| 仿宋/楷体专项 | 若某类图纸强制仿宋，不塞回通用下拉，避免再次膨胀 | **建议** |

旧调研曾建议「预览与插入都用微软雅黑、代码用 Consolas」以求网页一致，或「工程 SHX 用 tssdeng + hztxt」。本次选择是第三条：**工程槽锁 TSSD，说明槽只留微软雅黑与宋体**，不再维持「常见西文 UI 字 + 多套国标 SHX」超市。与旧文不完全相同。**已验证**（对照旧调研结论）。

## 6. 记忆链 / 口诀

谁痛（下拉一长串、预览和图纸各一套字）→ 给谁（设计说明进天正图面）→ 办法（T 槽微软雅黑或宋体，S 槽 TSSD 一对，别名归一，禁止切族）→ 边界（不测真机轮廓、不发字体安装包）。

- 超市 ≠ 稳定：可选越多，`\f` 越容易中途换族。
- TSSD 成对：`tssdeng` 不配 `hztxt`。
- 微软雅黑 = YaHei，宋体 = SimSun：别名不是第二种字。
- 粗体不换家：不要为了粗切到黑体。
- 代码不单开族：对齐感让给稳定性。
