# 核心逻辑

> 面向人类读者：这个软件在干什么、为难谁、给谁用、用什么办法、边界在哪。
> 模块与路径见 [02-项目架构](02-项目架构.md)；启动与命令见 [04-启动与测试](04-启动与测试.md)。

## 1. 一句话

HyCADTool.UniverEditor（独立表格编辑器侧车）在 AutoCAD 旁打开一个「像 Excel」的窗口：用 Univer（开源表格引擎，负责网格与功能区）编辑工程表，再按纸面毫米落到图纸上。

## 2. 解决什么困难

结论：制图员卡在「CAD 原生表难改、通用表格软件又落不进图纸」。

| 困难 | 表现 |
|---|---|
| 原生 TABLE 难用 | AutoCAD 自带表格改合并、行高、字高费劲，不像日常表格软件 |
| 屏幕数字对不上图纸 | 编辑器里看到的尺寸、布局栏里填的毫米、图上量到的毫米三者容易各说各话 |
| 改结构与改文字搅在一起 | 插行、删列、合并一旦只改屏幕网格、不改领域模型，下次打开或拾取就丢 |

**本软件不解决**：不当通用 Excel；不把 Univer 工作簿文件当作图纸真相；不替换插件左侧填表面板；不把落图比例写进表对象长期保存。

## 3. 什么样的用户需要

| 适合 | 不太需要 |
|---|---|
| 要做人员表、图框表并插入 DWG（Drawing，AutoCAD 图纸文件）的制图员 | 只做数据分析、不做落图的表格用户 |
| 要按纸面毫米调行高列宽、再按比例放大到模型空间的模板维护者 | 只要 CAD 命令行填几个格子、不要独立窗口的人 |

## 4. 用什么机制（不展开实现）

| 概念 | 是什么 | 起什么作用 |
|---|---|---|
| TableGrid（表格网格领域模型） | 表的行列、合并、文字、纸面毫米尺寸的内存真相 | 所有结构与内容最终以它为准 |
| TableOpLog（表格操作日志） | 往 TableGrid 上记账的命令入口 | 插删行列、合并只走这里，禁止只改屏幕网格 |
| 快照 | 把 TableGrid 编成 JSON（JavaScript Object Notation，文本数据交换格式）交给 Univer | Univer 只当视图壳，不拥有长期数据 |
| 口径 B | 编辑与布局一律用纸面毫米；只有落图时乘 Scale（落图比例） | 让布局数字与图上量测可对齐 |
| WebView2 | 用 Edge 内核把网页嵌进 WPF（Windows Presentation Foundation，桌面窗口框架）窗口 | 表格 UI 用网页做，窗口壳用桌面做 |
| N38 | 打开本编辑器的 AutoCAD 命令 | 用户从 CAD 进入独立窗口 |

**主流程**（用户视角，编号步骤）：

1. 在 AutoCAD 输入 N38（或测试命令 C1，若当前指向本编辑器），打开独立窗口。
2. 新建空表、加载人员样表，或拾取图上已有表，屏幕网格显示当前快照。
3. 改文字直接在格子里改；改行高/列宽/插删/合并走「布局」功能区，数字是纸面毫米。
4. 点落图（或范围落图）后在图面指定插入点；图上几何 = 纸面毫米 × Scale。
5. 关掉窗口不保存 Scale；下次打开仍从 TableGrid / 图上读回的表开始。

```mermaid
flowchart LR
  cad[AutoCAD 图面]
  win[独立编辑窗口]
  grid[TableGrid 真相]
  cad -->|拾取| grid
  grid -->|快照| win
  win -->|改文字/布局| grid
  grid -->|落图 ×Scale| cad
```

## 5. 边界

默认管：独立窗口里的网格编辑、布局毫米、与主插件之间的拾取/落图/样表。

明确不管：Univer 官方云文档与付费 xlsx 通道；把 Scale 写入 DWG 表对象；用 Univer 内置插删当作结构真相。**已验证**（契约写在宿主回调与布局说明里）。

窗口标题仍带 PoC（Proof of Concept，概念验证）。**已验证**（窗口 XAML 标题）。

浏览器开发页能改 UI，但不能真正拾取/落图。**已验证**（开发宿主对 CAD 动作只提示）。

## 6. 记忆链 / 口诀（可选）

谁痛（CAD 表难用）→ 给谁（要落图的制图员）→ 办法（Univer 当视图 + TableGrid 当真相 + 口径 B）→ 边界（不持久化 Scale，不拿 Univer 文件当图纸）。

- 屏幕网格 ≠ 真相
- 纸面毫米 ≠ 模型毫米（差一个 Scale）
- 改结构走操作日志，不走 Univer 自带插删
- 库能编译 ≠ CAD 里已重载
