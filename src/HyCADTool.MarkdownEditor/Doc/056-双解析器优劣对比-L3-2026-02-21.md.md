## 双解析器深度对比分析

### 核心结论先说

你的直觉是对的。PreviewHtmlRenderer.cs 本质上是一个 手写的简化 Markdown 渲染引擎 + 手写的简化 CSS 主题 + 手写的简化 HTML→Markdown 逆转换器，它在三个维度上都弱于 Vditor 的成熟生态。走统一 Vditor 渲染方向是正确的。

但问题是：Vditor 不是为"分栏分页图纸模式"设计的，而 PreviewHtmlRenderer 的核心价值恰恰在分栏分页交互上，不在 Markdown 渲染上。所以真正需要做的不是二选一，而是分离职责。

\### 五、为什么不能直接在图纸面板用 Vditor？

你可能会想：直接在图纸面板也嵌一个 Vditor 实例不就完了？

| 问题 | 原因 |

|------|------|

| **Vditor 不支持分栏** | Vditor 是单列编辑器，你需要多栏多页 |

| **Vditor 不支持固定纸张尺寸** | Vditor 自适应容器宽度 |

| **多一个 WebView2 实例** | 已经有 2 个了，第 3 个内存压力更大 |

| **Vditor 不暴露 DOM 操作接口** | 你的统计/分栏逻辑需要直接操作 DOM |

| **光标管理冲突** | Vditor 自管光标 vs 你的分栏需要手动管光标 |

结论：**图纸面板的"容器"必须是自研的，但"内容渲染质量"可以对齐 Vditor。**
