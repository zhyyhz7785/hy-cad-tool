### 3. 依赖注入注册

**文件**：`Infrastructure/Configuration/AutofacModule.cs`

**注册方式**：
```csharp
// 面板注册（按需创建，非单例）
builder.RegisterType<HyCADTool.Refactored.Presentation.Views.ReinPanel>()
    .AsSelf()
    .InstancePerDependency();
```

**设计考虑**：
- **InstancePerDependency**（按需创建）vs **SingleInstance**（单例）
  - 面板使用 `InstancePerDependency`
  - 每次 `ShowPanel` 调用都创建新实例（但 PanelManager 内部缓存）
  - 符合 WPF 控件的生命周期管理
  
- **为什么不是单例？**
  - WPF UserControl 不应该在容器级别单例化
  - PanelManager 已经管理面板的单例性（每个类型只创建一次）
  - `InstancePerDependency` 给予 PanelManager 完全的生命周期控制权

### 4. 面板显示命令

**文件**：`Presentation/Commands/ShowPanelCommand.cs`

**新增命令**：
```csharp
[CommandMethod("HYREIN")]
public static void ShowReinPanel()
{
    var ed = AcApp.DocumentManager.MdiActiveDocument.Editor;
    try
    {
        var panelManager = ServiceLocator.Container.Resolve<PanelManager>();
        panelManager.TogglePanel<HyCADTool.Refactored.Presentation.Views.ReinPanel>(
            "钢筋配置", 
            new Guid("A1B2C3D4-E5F6-7890-ABCD-EF1234567890"));
        ed.WriteMessage("\n钢筋配置面板已切换");
    }
    catch (Exception ex)
    {
        ed.WriteMessage($"\n❌ 显示面板失败: {ex.Message}");
    }
}
```

**GUID 说明**：
- 每个面板有唯一的 GUID
- AutoCAD 使用 GUID 持久化面板位置和状态
- 用户调整面板位置后，下次打开会记住位置

**命令特性**：
- 使用 `TogglePanel` 方法：连续执行可显示/隐藏
- 异常处理：防止错误导致 AutoCAD 崩溃
- 友好的消息反馈

**注意事项**：
- `[CommandMethod]` 需要通过 `ExtensionApplication` 机制加载
- 热加载器（ReCall）不会加载这些命令
- 开发阶段使用 `Phase5_0TestCommand` 测试

## 💡 经验教训

### 1. 渐进式验证的重要性

**教训**：
- 不要一次性迁移全部功能
- 先验证框架，再实现业务
- 每个阶段都要有可验证的输出

**案例**：
- 如果一次性迁移 UI + 业务逻辑，出错时难以定位
- 分阶段迁移后，问题域清晰：
  - 面板不显示 → 基础设施问题
  - 面板显示但功能不对 → 业务逻辑问题

### 2. 占位符的价值

**教训**：
- 占位符不是"偷懒"，而是验证框架的有效手段
- 每个占位符都应该有输出反馈
- 清晰的 TODO 标记便于后续迁移

**案例**：
```csharp
private void DrawButton_Click(object sender, RoutedEventArgs e)

```
- 验证了按钮绑定正确
- 验证了参数读取正确
- 为真实实现预留接口

### 3. 用户反馈的重要性

**用户反馈**：
> "出现面板，但是功能没有重构"

**价值**：
- ✅ 确认了面板显示成功（核心目标达成）
- ✅ 明确了下一步工作方向（业务逻辑迁移）
- ✅ 验证了渐进式策略的正确性

**如果没有用户反馈**：
- 可能会花费大量时间实现功能
- 可能在错误的方向上投入精力
- 难以及时调整策略

### 4. 热加载器的限制

**问题**：
- `HYREIN` 命令（使用 `[CommandMethod]`）无法通过热加载器加载
- 用户执行命令时提示"未知命令"

**解决方案**：

- 通过 `C1P50` 自动显示面板
- 避免依赖 `ExtensionApplication` 机制

**经验**：
- 开发阶段，所有测试都应集成到热加载器支持的命令中
- 生产环境才使用 `[CommandMethod]` + `ExtensionApplication`
- 明确区分开发测试和生产部署
