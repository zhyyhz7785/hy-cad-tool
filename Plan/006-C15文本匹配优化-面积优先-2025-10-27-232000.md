# C15 文本匹配优化 - 面积优先算法

> **时间戳**: 2025-10-27-232000  
> **命令**: C15 (SurfaceBasedElevation3DCommand)  
> **目标**: 修复文本匹配到外轮廓而非内部多边形的问题

---

## 🎯 问题描述

### 用户场景
```
平面图：
┌─────────────────────────┐
│  L 型外轮廓（8顶点）     │
│    ┌────────┐            │
│    │  -3    │ (6顶点)    │
│    └────────┘            │
│                 ┌──────┐ │
│                 │ -2   │ │ (4顶点)
│                 └──────┘ │
└─────────────────────────┘

文本位置：
- "-2" 和 "-3" 都在 L 型外轮廓内部
- 但也在各自的内部多边形内部
```

### 实际问题（从调试输出）
```

  ✓ 匹配到多边形（顶点数=8），标高=-2.000m  ← 匹配到外轮廓！

[文本匹配] 文本="-3", 中心点=(459111.8, 117403.9)
  ✓ 匹配到多边形（顶点数=8），标高=-3.000m  ← 也匹配到外轮廓！

[多边形匹配结果]
  ✓ 多边形（顶点数=8, 中心≈(...)）匹配标高 -3.000  ← 只有外轮廓被匹配
  ✗ 多边形（顶点数=6, 中心≈(...)）未匹配标高 → 红色
  ✗ 多边形（顶点数=4, 中心≈(...)）未匹配标高 → 红色
```

**结果**：
- ❌ 两个文本都匹配到了同一个外轮廓（8顶点）
- ❌ 后面的文本 "-3" 覆盖了前面的 "-2"
- ❌ 实际的内部多边形（6顶点和4顶点）未匹配标高

---

## 🔧 解决方案

### 核心思路
**优先匹配面积最小的多边形**

当一个文本的中心点在**多个多边形内部**时：
- 旧逻辑：匹配**第一个**找到的多边形
- 新逻辑：匹配**面积最小**的多边形

### 原理
```
外轮廓面积 > 内部多边形面积

示例：
- L 型外轮廓（8顶点）：面积 = 50,000,000 mm²
- 左侧内部多边形（6顶点）：面积 = 15,000,000 mm²
- 右侧内部多边形（4顶点）：面积 = 10,000,000 mm²

文本 "-2"：
  - 在外轮廓内（面积 50,000,000）
  - 在右侧多边形内（面积 10,000,000）
  → 选择面积最小的：右侧多边形 ✓

文本 "-3"：
  - 在外轮廓内（面积 50,000,000）
  - 在左侧多边形内（面积 15,000,000）
  → 选择面积最小的：左侧多边形 ✓
```

## 📝 代码修改

### 旧逻辑（匹配第一个）
```csharp
foreach (var polyline in polygons)
{
    if (IsPointInsidePolyline(checkPoint, polyline))
    {
        // 找到第一个就停止
        result[polyline] = Elevation.FromMeters(elevationValueInMeters);
        break;  // ❌ 可能匹配到外轮廓
    }
}
```

### 新逻辑（匹配面积最小的）
```csharp
// 查找所有包含该文本的多边形，选择面积最小的
Polyline bestMatch = null;
double minArea = double.MaxValue;
int bestVertexCount = 0;

foreach (var polyline in polygons)
{
    if (IsPointInsidePolyline(checkPoint, polyline))
    {
        double area = polyline.Area;
        int vertexCount = polyline.NumberOfVertices;
        
        // ✅ 选择面积最小的多边形（内部多边形 < 外轮廓）
        if (area < minArea)
        {
            minArea = area;
            bestMatch = polyline;
            bestVertexCount = vertexCount;
        }
    }
}

if (bestMatch != null)
{
    result[bestMatch] = Elevation.FromMeters(elevationValueInMeters);
    ed.WriteMessage($"\n  ✓ 匹配到多边形（顶点数={bestVertexCount}, 面积={minArea:F0}），标高={elevationValueInMeters:F3}m");
}
```

## 📊 算法复杂度

### 时间复杂度
- **旧算法**：O(T × P)，T = 文本数，P = 多边形数
- **新算法**：O(T × P)（相同，只是遍历所有多边形而非第一个匹配就停止）

### 空间复杂度
- **旧算法**：O(1)
- **新算法**：O(1)（只增加了几个临时变量）

### 性能影响
- 对于 2-3 个文本 × 3-5 个多边形：**几乎无影响**
- 对于大型项目（100+ 文本 × 100+ 多边形）：**仍然可接受**（<1秒）
