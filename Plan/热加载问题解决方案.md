# 热加载问题解决方案

## 🔍 问题描述

**错误信息**：
```
无法将"E:\...\HyCADTool\bin\Debug\HyCADTool.dll"复制到"bin\Debug\HyCADTool.dll"。
超出了重试计数 10。失败。文件被"acad.exe"锁定。
```

**根本原因**：
- `HyCADTool.Refactored.csproj` 引用了 `HyCADTool.csproj`
- 默认情况下，MSBuild 会复制引用项目的 DLL 到输出目录
- AutoCAD 已加载 `HyCADTool.dll`，导致文件被锁定
- 编译时无法覆盖已锁定的 DLL

---

## ✅ 解决方案

### 核心修改：设置 `<Private>False</Private>`

**修改文件**：`HyCADTool.Refactored/HyCADTool.Refactored.csproj`

**修改前**：
```xml
<ItemGroup>
  <ProjectReference Include="..\HyCADTool\HyCADTool.csproj">
    <Project>{76EDAE9E-175E-4A23-94C4-B171F85C8F76}</Project>
    <Name>HyCADTool</Name>
  </ProjectReference>
</ItemGroup>
```

**修改后**：
```xml
<ItemGroup>
  <ProjectReference Include="..\HyCADTool\HyCADTool.csproj">
    <Project>{76EDAE9E-175E-4A23-94C4-B171F85C8F76}</Project>
    <Name>HyCADTool</Name>
    <!-- 关键设置：不复制到输出目录，避免热加载时被锁定 -->
    <Private>False</Private>
  </ProjectReference>
</ItemGroup>
```

### 作用解释

| 设置 | 含义 | 结果 |
|------|------|------|
| `<Private>True</Private>` （默认） | 复制引用的 DLL 到输出目录 | `HyCADTool.dll` 被复制到 `bin\Debug`，导致锁定错误 |
| `<Private>False</Private>` | 不复制引用的 DLL | `HyCADTool.dll` 不会被复制，避免锁定 |

## 🎯 为什么重构项目需要引用原项目？

### 设计架构：Adapter Pattern（适配器模式）

重构项目的核心设计是**作为原项目的适配层**，将原有系统的静态类封装为符合 Clean Architecture 的服务接口。

### 引用关系图

```
HyCADTool.Refactored (重构项目)
  ↓ 调用
HyCADTool (原项目)
  ├── BaseRein (静态类)
  ├── Reinforcement (静态类)
  └── BaseConfig (静态类)
```

### 关键引用示例

#### 1. `BaseReinforcementService.cs`
```csharp
using static HyCADTool.BaseRein;  // ← 引用原项目

public class BaseReinforcementService : IBaseReinforcementService
{
    public void CreateOptimizedBoundingPolygon(...)
    {
        // 调用原项目的静态方法
        CreateOptimizedBoundingPolygonFromPolygons(...);
    }
}
```

#### 2. `ReinService.cs`
```csharp
using HyCADTool.Commands;  // ← 引用原项目
using HyCADTool.Config;

public class ReinService : IReinService
{
    public void DrawReinforcement()
    {
        // 调用原项目的静态方法
        Reinforcement.Rein();
        BaseConfig.InitializeStyle();
    }
}
```

#### 3. `BaseReinforcementConfig.cs`
```csharp
using static HyCADTool.BaseRein;  // ← 引用原项目的枚举

public class BaseReinforcementConfig
{
    public RebarDirection MainReinforcementDirection { get; set; }
    public IntersectionsDirection IntersectionsDirection { get; set; }
}
```

## 🚀 热加载工作流程（修复后）

### 前提条件
1. AutoCAD 已启动
2. 已加载 `ReCall.dll`（一次性，不再修改）
3. **原项目 `HyCADTool.dll` 已加载**（通过 NETLOAD 或原有命令）

### 开发流程

```bash
# 步骤 1: 修改重构项目代码
# 编辑 HyCADTool.Refactored/ 下的文件

# 步骤 2: 编译（只编译重构项目）
MSBuild.exe HyCADtoolGpt.sln /t:HyCADTool_Refactored /p:Configuration=Debug

# 步骤 3: 在 AutoCAD 中重新加载
AutoCAD> C2

# 步骤 4: 运行测试
AutoCAD> C1
```

### 关键点
- ✅ **只重新加载** `HyCADTool.Refactored.dll`
- ✅ **不重新加载** `HyCADTool.dll`（避免重启 AutoCAD）
- ✅ 原项目 DLL 保持加载状态，重构项目可以正常调用

## 📖 技术细节

### MSBuild 的 `<Private>` 属性

| 属性值 | 别名 | 含义 |
|--------|------|------|
| `True` | `Copy Local` | 复制引用的 DLL 和 PDB 到输出目录 |
| `False` | `Don't Copy Local` | 不复制引用的 DLL（仅编译时引用） |

### 运行时依赖解析

```
运行时（AutoCAD）
  ├── HyCADTool.dll               ← 已加载（通过 NETLOAD）
  └── HyCADTool.Refactored.dll    ← 热加载（通过 C2）
       ↓ 依赖
     HyCADTool.dll                ← 从 AppDomain 中解析
```

**关键**：
- 重构项目运行时不需要从文件系统加载 `HyCADTool.dll`
- 而是从 **AppDomain** 中查找已加载的 `HyCADTool.dll`
- 因此 `<Private>False</Private>` 不会影响运行时
