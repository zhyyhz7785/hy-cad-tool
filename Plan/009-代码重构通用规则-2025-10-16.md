# 代码重构通用规则

> **生成日期**: 2025-10-16  
> **用途**: 后续代码编辑的通用规则，便于在重构中复用  
> **重要性**: ⭐⭐⭐⭐⭐ 核心规则

---

## 一、测试规则

### 1.1 C1 测试规则

**规则**: 所有命令必须通过 C1 命令进行测试

**实现方式**:
1. 在 `TestRunner.cs` 中添加专门的测试方法
2. 测试方法命名格式: `Test[CommandName]BasicFunctionality()`
3. 测试内容: 核心功能验证，不依赖用户交互
4. 测试输出: 简洁的 ✓/✗ 状态报告

**示例**:
```csharp
private void TestHYOVBasicFunctionality()
{
    _editor.WriteMessage("\n=== HYOV 基础功能测试 ===");
    
    var service = ServiceLocator.Resolve<LineOverKillService>();
    
    // 测试1：合并重叠线段
    TestMergeOverlappingLines(service);
    
    // 测试2：合并端点接触的共线线段
    TestMergeTouchingCollinearLines(service);
    
    _editor.WriteMessage("\n=== HYOV 基础功能测试完成 ===");
}
```

### 1.2 测试方法设计原则

- **独立性**: 每个测试方法独立，不依赖其他测试
- **简洁性**: 测试逻辑简单明了，易于理解
- **完整性**: 覆盖核心功能的所有关键场景
- **可重复性**: 测试结果稳定，不依赖外部状态

## 二、功能扩展规则

### 2.1 平行线删除规则

**适用场景**: 当两条直线平行且距离小于容差时

**判断条件**:
1. 两条线段平行（使用 `IsParallel` 方法）
2. 距离小于等于容差（使用 `CalculateParallelDistance` 方法）

**保留规则**: 保留端点连接性更好的线段
- 计算每条线段的端点连接性得分
- 选择得分更高的线段保留
- 删除得分较低的线段

**实现模式**:
```csharp
// 在 CheckAndMergeOverlap 中添加
if (line1.IsParallel(line2, tolerance))
{
    double distance = CalculateParallelDistance(line1, line2);
    if (distance <= tolerance)
    {
        return SelectBetterParallelLine(line1, line2, out merged);
    }
}
```

### 2.2 共线线段合并规则

**判断条件**:
1. 两条线段共线（使用 `IsCollinear` 方法）
2. 有重叠或端点接触（使用投影区间法）

**合并规则**:
- 取所有端点中投影距离最远的两点
- 合并为一条新线段
- 删除原有两条线段

**不合并条件**:
- 有间隙的共线线段（间隙 > 容差）

## 三、代码清理规则

### 3.1 无用代码删除原则

**删除标准**:
1. 未被当前功能使用的方法
2. 功能重复的方法
3. 过于复杂且不稳定的方法
4. 实验性功能（未完成或有问题）

**保留标准**:
1. 核心业务逻辑方法
2. 被其他方法调用的辅助方法
3. 经过充分测试的稳定方法
4. 符合当前设计目标的方法

### 3.2 代码组织原则

**文件结构**:
```
Service.cs
├── 公共方法（主要入口）
├── 核心业务逻辑方法
├── 辅助计算方法
└── 私有工具方法
```

**方法命名**:
- 公共方法: `Verb + Noun` (如 `CleanLines`, `MergeOverlappingLines`)
- 私有方法: `Check + Condition` (如 `CheckCollinearMerge`)
- 计算方法: `Calculate + What` (如 `CalculateParallelDistance`)
- 选择方法: `Select + Criteria` (如 `SelectBetterParallelLine`)

## 四、算法设计规则

### 4.1 几何算法原则

**容差处理**:
- 所有几何比较必须使用容差
- 容差值通过参数传入，不硬编码
- 默认容差: `1e-6`

**投影区间法**:
- 用于判断共线线段重叠
- 将线段投影到主轴方向
- 通过区间重叠判断是否有间隙

**距离计算**:
- 使用 `DistanceCalculator` 统一计算
- 支持点到线段距离、平行线距离等
- 避免重复实现距离算法

### 4.2 性能优化原则

**算法复杂度**:
- 避免 O(n²) 以上的算法
- 使用 HashSet 进行快速查找
- 预处理数据减少重复计算

**内存管理**:
- 及时释放不需要的对象
- 避免创建大量临时对象
- 使用 `using` 语句管理资源

## 五、错误处理规则

### 5.1 异常处理原则

**异常类型**:
- 参数错误: 抛出 `ArgumentException`
- 业务逻辑错误: 抛出 `InvalidOperationException`
- 系统错误: 抛出 `SystemException`

**异常信息**:
- 使用中文描述错误原因
- 提供具体的错误位置信息
- 包含可能的解决方案

### 5.2 边界条件处理

**输入验证**:
- 检查 null 值
- 检查空集合
- 检查无效参数

**边界情况**:
- 容差为 0 的情况
- 线段长度为 0 的情况
- 集合为空的情况

## 七、重构流程规则

### 7.1 重构步骤

1. **分析现有代码**
   - 识别核心功能
   - 找出无用代码
   - 确定重构目标

2. **设计新结构**
   - 定义清晰的接口
   - 设计算法流程
   - 确定测试方案

3. **逐步实现**
   - 先实现核心功能
   - 再添加辅助功能
   - 最后优化性能

4. **测试验证**
   - 单元测试验证
   - 集成测试验证
   - 用户测试验证

### 7.2 质量检查

**代码质量**:
- 编译无错误
- 通过所有测试
- 符合编码规范

**功能质量**:
- 功能完整
- 性能达标
- 用户体验良好

---

## 八、总结

这些规则旨在确保代码重构的一致性、可维护性和可扩展性。在后续的重构工作中，应严格遵循这些规则，并根据实际情况进行调整和完善。

**核心原则**:
1. **测试驱动**: 所有功能必须通过 C1 测试
2. **功能聚焦**: 只实现核心功能，删除无用代码
3. **算法稳定**: 使用经过验证的几何算法
4. **代码清晰**: 保持代码结构清晰，注释完整
5. **向后兼容**: 保持接口稳定，支持渐进式升级
