## 🐛 遇到的问题与解决

### 问题 1: `ref` 参数不能用于属性

**错误**:
```csharp
CS0206: 非引用返回属性或索引器不能用作 out 或 ref 值
```

**原因**: 尝试对 `_config.Property` 使用 `ref`，但它是另一个对象的属性。

**解决方案**:
```csharp
// ❌ 原方案
private void SetConfigValue<T>(ref T configField, T value)

// ✅ 最终方案（直接在 setter 中实现）
public double RebarDiameter
{
    get => _config.RebarDiameter;
    set 
    { 
        if (_config.RebarDiameter != value) 
        { 
            _config.RebarDiameter = value; 
            OnPropertyChanged(); 
        } 
    }
}
```

### 问题 2: 项目引用缺失

**错误**:
```csharp
CS0234: 命名空间"HyCADTool"中不存在类型或命名空间名"BaseRein"
```

**解决方案**:
在 `HyCADTool.Refactored.csproj` 中添加项目引用：
```xml
<ProjectReference Include="..\HyCADTool\HyCADTool.csproj">
  <Project>{76EDAE9E-175E-4A23-94C4-B171F85C8F76}</Project>
  <Name>HyCADTool</Name>
</ProjectReference>
```

### 问题 3: `IConfigService` vs `IConfigurationService`

**错误**: 使用了错误的接口名。

**解决方案**: 统一使用 `IConfigurationService`。

## 📚 技术亮点

### 1. 桥接模式（Bridge Pattern）

**目的**: 在不修改原有静态类的前提下，实现新架构。

**实现**:
```csharp
public class BaseReinforcementService : IBaseReinforcementService
{
    // 新架构接口
    public void DrawReinforcement(BaseReinforcementConfig config, bool dimAll)
    {
        // 桥接到旧代码
        ApplyConfigToStaticClass(config);
        BaseRein.DimAll = dimAll;
        
        var data = BaseRein.ReinforcementStepA();
        if (dimAll)
            BaseRein.ReinforcementAll(data);
        else
            BaseRein.ReinforcementStepB(data);
    }
}
```

**优势**:
- ✅ 保持原有代码稳定性
- ✅ 实现新架构的依赖注入
- ✅ 为后续逐步迁移提供基础

### 2. 双向绑定（Two-Way Binding）

**XAML**:
```xaml
<TextBox Text="{Binding Scale, UpdateSourceTrigger=PropertyChanged}" />
```

**ViewModel**:
```csharp
public double Scale
{
    get => _config.Scale;
    set 
    { 
        if (_config.Scale != value) 
        { 
            _config.Scale = value;
            OnPropertyChanged();
            SaveConfigToService(); // 自动保存
        } 
    }
}
```

**效果**:
- UI 改变 → ViewModel 更新 → 自动保存
- ViewModel 更新 → UI 自动刷新

3. **桥接模式价值**: 在重构大型遗留系统时，桥接模式是渐进式迁移的关键。
4. **MVVM 收益**: 初期投入略高（ViewModel 编写），但长期收益巨大（可测试性、可维护性）。
