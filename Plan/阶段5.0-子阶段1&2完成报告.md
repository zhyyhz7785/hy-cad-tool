## ✅ 子阶段 5.0.1：选择服务基础设施

### 目标
创建统一的选择服务，简化原有的多个选择工具为一个可复用的服务层。

### 实现内容

#### 1. 创建选择服务接口
**文件**：`Domain/Interfaces/ISelectionService.cs`

**设计思路**：
- 提供统一的实体选择接口
- 支持多种选择模式：提示选择、全选、类型化选择
- 支持多种过滤条件：图层、颜色、线型、线宽、类型
- 提供高亮/取消高亮功能
- 支持获取当前选择集

**核心方法**：
```csharp
ObjectId[] SelectEntities(string prompt, params DxfCode[] filters);
ObjectId[] SelectAll(params DxfCode[] filters);
List<T> SelectTypedEntities<T>(string prompt) where T : Entity;
ObjectId[] FilterByLayer(ObjectId[] baseIds, string layerName);
ObjectId[] FilterByColor(ObjectId[] baseIds, short colorIndex);
ObjectId[] FilterByLineType(ObjectId[] baseIds, string lineTypeName);
ObjectId[] FilterByLineWeight(ObjectId[] baseIds, LineWeight lineWeight);
ObjectId[] FilterByType(ObjectId[] baseIds, DxfCode dxfCode);
void HighlightEntities(ObjectId[] ids);
void UnhighlightEntities(ObjectId[] ids);
```

**关键实现细节**：
```csharp

// 实现 IValueConverter 接口
public class BoolToVisibilityConverter : IValueConverter
{
    public object Convert(object value, Type targetType, object parameter, CultureInfo culture)
    {
        return (value is bool boolValue && boolValue) 
            ? Visibility.Visible 
            : Visibility.Collapsed;
    }
    
    public object ConvertBack(object value, Type targetType, object parameter, CultureInfo culture)
    {
        return value is Visibility visibility && visibility == Visibility.Visible;
    }
}
```

**错误现象**：

```
命令: HYTEST_PANEL
未知命令"HYTEST_PANEL"。按 F1 查看帮助。
```

#### 问题 2：`PanelManager` 依赖注入失败

**错误信息**（第一次）：
```
❌ 测试 4 失败: An exception was thrown while activating HyCADTool.Refactored.Presentation.PanelManager.
堆栈跟踪:
   at Autofac.Core.Resolving.Middleware.ActivatorErrorHandlingMiddleware.Execute(...)
   ...
```

**原因分析**：
- `PanelManager` 构造函数需要 `IServiceProvider` 参数
- 初始注册方式：
  ```csharp
  builder.RegisterType<PanelManager>()
      .AsSelf()
      .SingleInstance();
  ```
- Autofac 无法自动解析 `IServiceProvider`

**第一次尝试修复**：使用 lambda 表达式注册
```csharp
builder.Register(c => new PanelManager(c.Resolve<IContainer>() as IServiceProvider))
    .AsSelf()
    .SingleInstance();
```

**编译错误**：
```
error CS1503: 参数 1: 无法从"Autofac.IContainer"转换为"System.IServiceProvider"
```

**第二次尝试修复**：添加显式转换
```csharp
builder.Register(c => new PanelManager(c.Resolve<IContainer>() as IServiceProvider))
    .AsSelf()
    .SingleInstance();
```

**编译错误**：
```
error CS0246: 未能找到类型或命名空间名"IServiceProvider"
```

**临时修复**：添加 using 指令
```csharp
using System;
```

**运行时错误**（第二次）：
```
❌ 测试 4 失败: An exception was thrown while activating λ:HyCADTool.Refactored.Presentation.PanelManager.
```

**根本原因分析**：
- Autofac 的 `IContainer` 虽然实现了 `IServiceProvider` 接口
- 但在 .NET Framework 4.8 环境下，`as` 转换可能失败
- 这是一个兼容性问题，而非设计问题

**最终解决方案**：改用 `IComponentContext`

1. **修改 PanelManager 构造函数**：
```csharp
// 从 IServiceProvider 改为 IComponentContext
private readonly IComponentContext _componentContext;

public PanelManager(IComponentContext componentContext)
{
    _componentContext = componentContext ?? throw new ArgumentNullException(nameof(componentContext));
    _paletteSets = new Dictionary<Type, PaletteSet>();
    _panelInstances = new Dictionary<Type, object>();
}
```

2. **修改面板解析逻辑**：
```csharp
// 使用 TryResolve 而不是 GetService
TPanel panelInstance;
if (_componentContext.TryResolve<TPanel>(out panelInstance))
{
    // 成功从容器解析
}
else
{
    // 如果 DI 容器中没有注册，尝试手动创建
    panelInstance = Activator.CreateInstance<TPanel>();
}
```

3. **简化 Autofac 注册**：
```csharp
// 回到最简单的注册方式
builder.RegisterType<PanelManager>()
    .AsSelf()
    .SingleInstance();
```

**为什么这个方案有效**：
- `IComponentContext` 是 Autofac 的核心接口
- Autofac 会自动将当前上下文注入到构造函数中
- 无需复杂的 lambda 表达式或类型转换
- 类型安全，编译时检查
- 符合 Autofac 的最佳实践

**经验总结**：
1. **优先使用框架原生接口**：
   - `IComponentContext` > `IServiceProvider`（在 Autofac 中）
   - 原生接口有更好的框架支持和类型安全

2. **避免过度抽象**：
   - 不要为了"平台无关"而强行使用通用接口
   - `PanelManager` 本身就是 AutoCAD 特定的（使用 `PaletteSet`）
   - 使用 Autofac 特定接口是合理的

3. **渐进式修复**：
   - 第一次尝试：lambda 表达式 + 转换
   - 第二次尝试：添加 using 指令
   - 最终方案：改用原生接口
   - 每次修复都接近正确答案

4. **关注堆栈跟踪**：
   - 错误发生在 "ActivatorErrorHandlingMiddleware"
   - 说明是依赖注入激活时的问题
   - 而非运行时逻辑问题

#### 问题 3：缺少 `WindowsFormsIntegration` 引用

**错误信息**：
```
error CS0234: 命名空间"System.Windows.Forms"中不存在类型或命名空间名"Integration"
```

**原因分析**：
- `ElementHost` 类位于 `System.Windows.Forms.Integration` 命名空间
- 需要引用 `WindowsFormsIntegration.dll` 程序集

**解决方案**：
在 `.csproj` 文件中添加引用：
```xml
<ItemGroup>
  <Reference Include="WindowsFormsIntegration" />
</ItemGroup>
```

**经验总结**：
- WPF 和 WinForms 互操作需要额外的程序集
- `ElementHost`（WinForms 中托管 WPF）需要 `WindowsFormsIntegration`
- 与之对应的 `WindowsFormsHost`（WPF 中托管 WinForms）在 `PresentationFramework` 中

## 🔧 技术要点

### 1. Autofac 依赖注入最佳实践

**推荐方式**：
```csharp
// ✅ 使用框架原生接口
public PanelManager(IComponentContext componentContext)
{
    _componentContext = componentContext;
}

// ✅ 简单注册
builder.RegisterType<PanelManager>()
    .AsSelf()
    .SingleInstance();
```

**避免方式**：
```csharp
// ❌ 不推荐：复杂的 lambda 表达式 + 类型转换
builder.Register(c => new PanelManager(c.Resolve<IContainer>() as IServiceProvider))
    .AsSelf()
    .SingleInstance();
```

### 2. WPF 资源字典组织

**推荐结构**：
```xaml
<ResourceDictionary>
    <!-- 1. 转换器资源 -->
    <converters:BoolToVisibilityConverter x:Key="..."/>
    
    <!-- 2. 颜色和画刷资源 -->
```

## 📚 经验教训

### 1. 渐进式问题解决
- 遇到复杂问题时，不要急于找"完美方案"
- 先尝试简单的修复，逐步接近正确答案
- 每次修复都积累对问题的理解

**案例**：PanelManager 依赖注入问题
1. 第一次尝试：lambda + 转换（遇到类型转换错误）
2. 第二次尝试：添加 using（遇到运行时错误）
3. 最终方案：改用原生接口（成功）

### 2. 优先使用框架原生接口
- 框架提供的原生接口通常有更好的支持
- 避免为了"抽象"而过度设计
- 在特定平台上使用特定接口是合理的

### 3. 关注错误堆栈的深层信息
- `ActivatorErrorHandlingMiddleware` → 依赖注入问题
- `CommandMethod not found` → 命令注册问题
- 堆栈跟踪比错误消息更有价值

### 4. 文档化复杂决策
- 为什么使用 `IComponentContext` 而不是 `IServiceProvider`？
- 为什么需要 `ElementHost`？
- 在代码注释中记录这些决策的原因
