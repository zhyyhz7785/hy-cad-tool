## 🎯 实施策略

### 策略选择：**适配器模式 + MVVM**

由于原代码是基于静态类（`Reinforcement`）实现，我们采用：
1. **保留原有业务逻辑** - 不重写复杂的钢筋生成算法
2. **创建 ViewModel** - 管理面板状态和参数
3. **通过适配器调用原逻辑** - ViewModel → 原静态类

**优点**：
- ✅ 快速实现（不需重写算法）
- ✅ 降低风险（复用已测试代码）
- ✅ 符合重构原则（逐步迁移）

## 🔍 关键挑战与解决方案

### 挑战 1: 原代码使用静态属性

**问题**：`Reinforcement` 类通过 `ReinPanel.ActivePanel` 获取参数。

**解决方案**：
1. **临时方案**：适配器中设置 `ReinPanel.ActivePanel`
2. **长期方案**：将 `Reinforcement` 重构为实例类

```csharp
// 临时适配方案
private void UpdateReinforcementProperties(ReinParameters parameters)
{
    // 创建临时 Panel（仅用于参数传递）
    var tempPanel = new HyCADTool.Views.ReinPanel();
    tempPanel.ScaleText.Text = parameters.Scale.ToString();
    // ... 设置其他参数
    HyCADTool.Views.ReinPanel.ActivePanel = tempPanel;
}
```

### 挑战 2: 复杂的标注逻辑

**问题**：`DimensionForReinforcement` 类包含 800+ 行复杂算法。

**解决方案**：
- **不重写**，直接通过适配器调用
- 后续可逐步重构为领域服务

### 挑战 3: 依赖原项目的工具类

**问题**：依赖 `ZTools`, `BaseConfig` 等原项目类。

**解决方案**：
- 通过项目引用访问（已存在）
- 后续逐步迁移核心工具类
