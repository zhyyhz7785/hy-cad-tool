# 阶段 5.0.4 - BaseReinPanel 重构计划

## 📊 现状分析

### 原始文件统计
- **XAML**: 487 行（复杂布局，4个Expander）
- **C#**: 318 行（大量直接操作静态类`BaseRein`）
- **参数数量**: 20+ 个配置参数
- **操作按钮**: 8 个业务操作

### 主要问题
1. ❌ **紧耦合**：直接操作静态类 `BaseRein`，无法单元测试
2. ❌ **代码重复**：大量重复的 `TextBox_TextChanged` 事件处理
3. ❌ **混乱的职责**：UI 逻辑、数据验证、业务逻辑混在一起
4. ❌ **硬编码**：默认值、验证逻辑硬编码在 UI 层
5. ❌ **缺少数据绑定**：使用事件而非 MVVM 绑定

---

## 🎯 重构目标

### 代码质量目标
- ✅ 从 **318 行** 简化到 **~150 行**（ViewModel）
- ✅ 完全采用 **MVVM 模式**，移除所有事件处理器
- ✅ 使用 **数据绑定** 替代手动赋值
- ✅ 通过 **DI** 注入服务，移除对静态类的依赖

### 架构目标
- ✅ **ViewModel** 管理所有 UI 状态和命令
- ✅ **配置服务** 负责参数持久化
- ✅ **业务服务** 执行实际的钢筋计算逻辑
- ✅ **清晰的职责边界**：UI ↔ ViewModel ↔ Service

## 📋 关键重构技术

### 1. 双向绑定替代事件处理

#### ❌ 旧方式（事件驱动）
```csharp
private void ScaleText_TextChanged(object sender, TextChangedEventArgs e)
{
    if (double.TryParse(ScaleText.Text, out double value))
    {
        BaseRein.Scale = value;
    }
}
```

#### ✅ 新方式（数据绑定）
```xaml
<TextBox Text="{Binding Scale, UpdateSourceTrigger=PropertyChanged}" />
```

```csharp
private double _scale = 100;
public double Scale
{
    get => _scale;
    set
    {
        if (SetProperty(ref _scale, value))
        {
            // 自动保存到配置
            SaveConfigToService();
        }
    }
}
```

---

### 2. 命令模式替代按钮事件

#### ❌ 旧方式
```csharp
private void StepOne_Click(object sender, RoutedEventArgs e)
{
    BaseRein.OptimizeBasemap();
}
```

#### ✅ 新方式
```xaml
<Button Content="整理底图" Command="{Binding StepOneCommand}" />
```

```csharp
public ICommand StepOneCommand { get; }

public BaseReinPanelViewModel(IBaseReinforcementService service)
{
    StepOneCommand = new RelayCommand(ExecuteStepOne, CanExecuteStepOne);
}

private void ExecuteStepOne()
{
    try
    {
        _reinforcementService.OptimizeBasemap();
        // 命令行反馈（通过 CAD 服务）
    }
    catch (Exception ex)
    {
        // 错误处理
    }
}

private bool CanExecuteStepOne() => true;
```

### 3. 枚举绑定

#### ❌ 旧方式
```csharp
private void DirectionComboBoxTry_SelectionChanged(object sender, SelectionChangedEventArgs e)
{
    if (DirectionComboBoxTry.SelectedItem != null)
    {
        var item = DirectionComboBoxTry.SelectedItem as ComboBoxItem;
        BaseRein.Direction = (RebarDirection)Enum.Parse(typeof(RebarDirection), item.Tag.ToString());
    }
}
```

#### ✅ 新方式
```xaml
<ComboBox SelectedItem="{Binding SelectedDirection}">
    <ComboBox.ItemsSource>
        <Binding Source="{x:Type local:RebarDirection}"

    </ComboBox.ItemsSource>
</ComboBox>
```

```csharp
public RebarDirection SelectedDirection
{
    get => _config.Direction;
```

## 🚨 风险与挑战

### 1. 业务逻辑迁移复杂性
**问题**：原代码直接调用 `BaseRein` 静态类的 20+ 个静态方法。

**解决方案**：
- 创建 `BaseReinforcementService` 作为静态类的适配器
- 逐步将静态方法迁移到服务中（后续阶段）
- 当前阶段：服务内部仍可调用静态方法（桥接模式）

---

### 2. 配置数据量大
**问题**：20+ 个参数需要管理和验证。

**解决方案**：
- 使用 `BaseReinforcementConfig` 封装所有参数
- 在 ViewModel 中使用辅助方法批量设置属性
- 使用 `INotifyPropertyChanged` 基类减少样板代码

---

### 3. ComboBox 枚举绑定
**问题**：原代码使用 `ComboBoxItem.Tag` 手动绑定枚举。

**解决方案**：
- 创建 `EnumToCollectionConverter`
- 或者在 ViewModel 中提供枚举值列表
- 使用 `SelectedValue` 绑定枚举属性
