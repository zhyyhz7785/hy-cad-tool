- ✅ **通用性**：支持所有重构阶段的测试需求

## 📦 核心组件

### 1. ReCall.dll（固定不变）

**文件**: `ReCall/Recall.cs`

#### 关键特性
- ✅ **单例加载**: 在 AutoCAD 中只需加载一次
- ✅ **动态重载**: 每次 C2 都重新加载目标 DLL
- ✅ **依赖解析**: 自动解析 Autofac、Newtonsoft.Json 等依赖
- ✅ **路径智能**: 自动计算解决方案根目录

#### 核心方法

```csharp
[CommandMethod("C2")]
public void Reload()
{
    // 1. 计算路径
    string rootDirectory = GetRootDirectory(adapterFileInfo, 3);
    var targetFilePath = Path.Combine(rootDirectory, 
        "HyCADTool.Refactored", "bin", "Debug", "HyCADTool.Refactored.dll");
    
    // 2. 加载 DLL
    var targetAssembly = Assembly.Load(File.ReadAllBytes(targetFilePath));
    
    // 3. 注册依赖解析器
    AppDomain.CurrentDomain.AssemblyResolve += ResolveAssembly;
    
    // 4. 获取 TestRunner
    var testRunnerType = targetAssembly.GetType(
        "HyCADTool.Refactored.Test.TestRunner");
    
    // 5. 创建委托
    _runAllTestsAction = () => runAllTestsMethod.Invoke(testRunnerInstance, null);
}

[CommandMethod("C1")]
public void ExecuteAllTests()
{
    _runAllTestsAction?.Invoke();
}
```

#### 依赖解析机制

```csharp
private static Assembly ResolveAssembly(
    ResolveEventArgs args, 
    string dependenciesPath, 
    string nugetPackagesPath)
{
    // 排除 .resources 文件
    if (args.Name.EndsWith(".resources")) return null;
    
    // 1. 在 bin\Debug 目录查找
    string localPath = Path.Combine(dependenciesPath, assemblyName);
    if (File.Exists(localPath))
        return Assembly.LoadFrom(localPath);
    
    // 2. 在 NuGet 包目录递归查找
    foreach (var dir in Directory.GetDirectories(nugetPackagesPath, packageName))
    {
        if (File.Exists(Path.Combine(dir, assemblyName)))
            return Assembly.LoadFrom(...);
    }
    
    return null;
}
```

## 🔧 关键技术实现

### 1. 热重启加载机制

**技术**: `Assembly.Load(byte[])` 而非 `Assembly.LoadFrom(string)`

**优势**:
- ✅ 不锁定文件，可以重新编译
- ✅ 每次加载都是新的程序集实例
- ✅ 支持无限次热重启

**限制**:
- ⚠️ `Assembly.Location` 返回空字符串
- ⚠️ 需要手动注册 AssemblyResolve 事件

### 2. 程序集依赖解析

**挑战**: 动态加载的程序集无法自动解析依赖

**解决方案**: 多级回退查找策略

```csharp
查找顺序：
1. bin\Debug\ 目录（与目标 DLL 同目录）
2. NuGet 包目录（~/.nuget/packages/）
   - 递归查找包名目录
   - 查找匹配的 DLL 文件
```

### 3. 反射调用机制

**技术**: 动态获取类型和方法，创建委托

```csharp
// 1. 获取类型
var testRunnerType = assembly.GetType(
    "HyCADTool.Refactored.Test.TestRunner");

// 2. 获取方法
var runAllTestsMethod = testRunnerType.GetMethod("RunAllTests");

// 3. 创建实例
var testRunnerInstance = Activator.CreateInstance(testRunnerType);

// 4. 创建委托（避免每次反射调用）
_runAllTestsAction = () => runAllTestsMethod.Invoke(testRunnerInstance, null);
```

**优势**:
- ✅ 解耦 ReCall 和测试逻辑
- ✅ 委托缓存提高性能
- ✅ 支持任意方法签名

### 4. 命令重复处理

**现象**: 热重启时命令名称重复

**AutoCAD 行为**:
- 保留第一次注册的命令
- 抛出 `eDuplicateKey` 异常

**处理策略**:
```csharp
try
{
    // 加载程序集，注册命令
    LoadPlugin(...);
}
catch (Exception ex)
{
    // 捕获但不影响流程
    // 命令仍然可用（指向新的实现）
}
```

**结果**: ⚠️ 警告可忽略，功能正常

## 🐛 问题与解决方案

### 问题 1: 路径计算错误

**现象**:
```
找不到目标文件: 
E:\BaiduSyncdisk\Code\CSharp\CursorProjects\HyCADTool.Refactored\...
```
（缺少 `hy-cad-tool` 目录）

**原因**: 向上查找级数错误（4级 → 应为3级）

**解决方案**:
```csharp
// 修复前
string rootDirectory = GetRootDirectory(adapterFileInfo, 4);

// 修复后
string rootDirectory = GetRootDirectory(adapterFileInfo, 3);
```

**效果**: ✅ 路径正确，DLL 成功加载

### 问题 2: NuGet 包运行时标识符错误

**现象**:
```
Your project file doesn't list 'win-x64' as a "RuntimeIdentifier"
```

**解决方案**:
```xml
<PropertyGroup>
  <RuntimeIdentifiers>win-x64;win-x86</RuntimeIdentifiers>
  <RestoreProjectStyle>PackageReference</RestoreProjectStyle>
</PropertyGroup>
```

**效果**: ✅ NuGet 包正确还原

### 问题 3: 命令重复警告

**现象**:
```
Autodesk.AutoCAD.Runtime.Exception: eDuplicateKey
```

**状态**: ⚠️ **已知特性，可忽略**

**原因**: 
- 热重启时，旧命令仍在 AutoCAD 中注册
- 新程序集尝试注册同名命令
- AutoCAD 拒绝重复注册

**影响**: 
- ❌ 不影响功能
- ❌ 不影响测试执行
- ✅ 命令仍然指向新的实现

**建议**: 直接忽略此警告

## 🎓 经验总结

### 技术亮点

1. **热重启机制**
   - 使用 `Assembly.Load(byte[])` 避免文件锁定
   - 委托缓存提高性能
   - 多级依赖解析确保稳定

2. **架构设计**
   - ReCall 和 TestRunner 解耦
   - 通过反射实现松耦合
   - 易于扩展的测试框架

3. **用户体验**
   - 秒级反馈（编译 → C2 → C1）
   - 清晰的测试输出格式
   - 详细的错误信息

### 设计原则

| 原则 | 应用 | 收益 |
|------|------|------|
| **单一职责** | ReCall 只负责加载<br>TestRunner 只负责测试 | ✅ 职责清晰 |
| **开闭原则** | ReCall 固定<br>通过扩展 TestRunner 增加功能 | ✅ 稳定可扩展 |
| **依赖倒置** | 通过反射解耦<br>不直接依赖测试类型 | ✅ 松耦合 |
| **里氏替换** | 委托可替换为任何测试方法 | ✅ 灵活性 |

### 最佳实践

1. **热重启场景特殊处理**
   - 文件路径不能依赖 `Assembly.Location`
   - 必须手动注册 AssemblyResolve
   - 命令重复警告可忽略

2. **测试组织方式**
   - 按阶段分组
   - 使用 `RunTest()` 包装统一处理异常
   - 提供清晰的输出格式

3. **开发流程优化**
   - 使用 Visual Studio 编译
   - 利用热重启快速迭代
   - 保持 ReCall 稳定不变
