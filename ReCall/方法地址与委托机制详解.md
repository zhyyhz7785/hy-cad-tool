# 方法地址与委托机制详解

> **问题**：为什么一般命令调用时内存地址会改变，而 C11-C19 命令的地址不变？  
> **生成日期**：2025-10-18  
> **关键**：理解"方法地址"的不同含义

---

## 🎯 核心要点（先理解这个）

### 关键误解的澄清

**您可能的理解**（需要纠正）：
```
❌ 错误理解：
    一般命令：HYOV → 地址会变
    C11 命令：C11 → 地址不变
```

**实际情况**：
```
✅ 正确理解：
    两者的"命令方法地址"都不会变！
    关键是"调用目标"不同：
    
    HYOV：固定调用 OverKillCommand.Execute_v1() ← 旧方法
    C11：固定调用 ExecuteC11()，但内部通过委托调用最新方法 ← 新方法
```

## 什么是"方法地址"

### .NET 中的方法表示

在 .NET 中，每个方法在内存中有两种"地址"：

#### 1. MethodInfo（方法元数据）

```csharp
// 通过反射获取方法
var method = typeof(OverKillCommand).GetMethod("Execute");

// MethodInfo 包含：
// - 方法名称
// - 参数列表
// - 返回类型
// - 所属类型
// - 方法体的 IL 代码位置

Console.WriteLine(method.MethodHandle);  // 打印方法句柄
```

**特点**：
- 每次编译后，MethodInfo 会变化（新的类型定义）
- 但在同一次运行期间，MethodInfo 是固定的

#### 2. 实际执行代码的地址（JIT 编译后）

```csharp
// JIT（Just-In-Time）编译流程：
IL 代码 → JIT 编译 → 机器码 → 内存中的可执行代码
                                    ↑
                                这才是真正的"方法地址"
```

**关键点**：
- 第一次调用方法时，JIT 编译 IL → 机器码
- 机器码存储在内存的某个地址（如 0x12345678）
- 后续调用都直接跳转到这个地址执行

## AutoCAD 命令注册的真相

### 命令注册时发生了什么？

```csharp
[CommandMethod("HYOV")]
public void Execute() { }

// AutoCAD 内部（伪代码）：
void RegisterCommand(string name, MethodInfo method)
{
    // 1. 存储方法信息
    var commandInfo = new CommandInfo
    {
        Name = "HYOV",
        Method = method,                    // ← 存储 MethodInfo
        DeclaringType = method.DeclaringType,
        Assembly = method.DeclaringType.Assembly
    };
    
    // 2. 注册到命令表
    _commandTable[name] = commandInfo;
}
```

### 命令执行时发生了什么？

```csharp
// 用户输入：HYOV
void ExecuteCommand(string name)
{
    // 1. 查找命令
    var commandInfo = _commandTable["HYOV"];
    
    // 2. 创建实例（如果需要）
    var instance = Activator.CreateInstance(commandInfo.DeclaringType);
    
    // 3. 调用方法
    commandInfo.Method.Invoke(instance, null);
    //              ↑
    //          这个 Method 是第一次注册时存储的 MethodInfo
}
```

### 关键问题

```
第一次 NETLOAD HyCADTool.Refactored.dll (v1)：
    Assembly_v1 加载
        ↓
    Type: OverKillCommand_v1
        ↓
    Method: Execute_v1
        ↓
    AutoCAD 注册：HYOV → Execute_v1 的 MethodInfo
    
第二次 NETLOAD HyCADTool.Refactored.dll (v2)：
    Assembly_v2 加载（新的程序集实例）
        ↓
    Type: OverKillCommand_v2（新的类型定义）
        ↓
    Method: Execute_v2（新的方法定义）
        ↓
    AutoCAD 尝试注册：HYOV → Execute_v2
        ↓
    ❌ 失败：HYOV 已存在，忽略
    
用户执行 HYOV：
    AutoCAD 查找命令表：HYOV → Execute_v1 的 MethodInfo
        ↓
    Invoke Execute_v1  ← 仍然是旧方法
```

## 为什么一般命令会"失效"

### 不是"地址改变"，而是"指向的对象不同"

```
正确理解：

时间线 T0（第一次 NETLOAD）：
    ┌─────────────────────────────────────┐
    │ 内存布局                            │
    ├─────────────────────────────────────┤
    │ Assembly_v1（地址 0x1000）          │
    │   ├── OverKillCommand_v1            │
    │   └── Execute_v1（MethodInfo）      │
    │       → IL 代码位于 0x1100          │
    └─────────────────────────────────────┘
    
    AutoCAD 命令表：
    HYOV → Execute_v1 (MethodInfo @ 0x1100)

时间线 T1（第二次 NETLOAD）：
    ┌─────────────────────────────────────┐
    │ 内存布局                            │
    ├─────────────────────────────────────┤
    │ Assembly_v1（地址 0x1000）← 仍在内存│
    │   ├── OverKillCommand_v1            │
    │   └── Execute_v1（MethodInfo）      │
    │       → IL 代码位于 0x1100          │
    │                                     │
    │ Assembly_v2（地址 0x2000）← 新加载  │
    │   ├── OverKillCommand_v2            │
    │   └── Execute_v2（MethodInfo）      │
    │       → IL 代码位于 0x2100          │
    └─────────────────────────────────────┘
    
    AutoCAD 命令表：
    HYOV → Execute_v1 (MethodInfo @ 0x1100) ← 未改变
    
    问题：
    - Execute_v2 @ 0x2100 被加载
    - 但 AutoCAD 不知道它的存在
    - HYOV 仍然指向 Execute_v1
```

### 为什么不能更新？

```
原因 1：命令表只在注册时写入一次
    _commandTable["HYOV"] = Execute_v1;  // T0 时刻
    // T1 时刻不会执行：
    // _commandTable["HYOV"] = Execute_v2;  ← 不会发生

原因 2：命令冲突保护
    if (_commandTable.ContainsKey("HYOV"))
        return;  // 已存在，忽略

原因 3：程序集无法卸载
    Assembly_v1 永久保留在内存
    Execute_v1 的 MethodInfo 仍然有效
    无法"替换"为 Execute_v2
```

## C11-C19 的巧妙之处

### 核心思想：间接调用

```
关键：ExecuteC11() 的地址永不改变，但它调用的目标可以改变！
```

### 内存布局对比

#### 一般命令（HYOV）

```
时间线 T0（第一次 NETLOAD）：
    ┌────────────────────────────────────────────┐
    │ HyCADTool.Refactored.dll (Assembly_v1)     │
    ├────────────────────────────────────────────┤
    │ OverKillCommand_v1 @ 0x1000                │
    │   └── Execute_v1() @ 0x1100                │
    │       方法体：{ /* v1 逻辑 */ }            │
    └────────────────────────────────────────────┘
    
    AutoCAD 命令表：
    HYOV → Execute_v1 @ 0x1100

时间线 T1（第二次 NETLOAD）：
    ┌────────────────────────────────────────────┐
    │ HyCADTool.Refactored.dll (Assembly_v2)     │
    ├────────────────────────────────────────────┤
    │ OverKillCommand_v2 @ 0x2000                │
    │   └── Execute_v2() @ 0x2100                │
    │       方法体：{ /* v2 新逻辑 */ }          │
    └────────────────────────────────────────────┘
    
    AutoCAD 命令表：
    HYOV → Execute_v1 @ 0x1100  ← 未改变！
    
    用户执行 HYOV：
    → 调用 0x1100（Execute_v1）
    → 执行旧逻辑 ❌
```

#### Recall 命令（C11）

```
时间线 T0（第一次 NETLOAD ReCall.dll）：
    ┌────────────────────────────────────────────┐
    │ ReCall.dll (Assembly_Recall)               │
    ├────────────────────────────────────────────┤
    │ ReCallClass @ 0x3000                       │
    │   ├── ExecuteC11() @ 0x3100                │
    │   │   方法体：{ ExecuteTestCommand("C11"); }│
    │   │   ↑                                    │
    │   │   这个方法地址永不改变！                │
    │   │                                        │
    │   └── _testCommandActions                  │
    │       Dictionary<string, Action>           │
    │       ["C11"] → null  ← 初始为空           │
    └────────────────────────────────────────────┘
    
    AutoCAD 命令表：
    C11 → ExecuteC11() @ 0x3100  ← 固定地址

时间线 T1（第一次加载 HyCADTool.Refactored.dll，执行 C2）：
    ┌────────────────────────────────────────────┐
    │ HyCADTool.Refactored.dll (Assembly_v1)     │
    ├────────────────────────────────────────────┤
    │ OverKillCommand_v1 @ 0x1000                │
    │   └── Execute_v1() @ 0x1100                │
    └────────────────────────────────────────────┘
    
    ┌────────────────────────────────────────────┐
    │ ReCall.dll                                 │
    ├────────────────────────────────────────────┤
    │ ReCallClass                                │
    │   ├── ExecuteC11() @ 0x3100 ← 地址不变     │
    │   │                                        │
    │   └── _testCommandActions                  │
    │       ["C11"] → Delegate @ 0x4000          │
    │                    ↓                       │
    │               Lambda: () =>                │
    │                 Execute_v1.Invoke(...)     │
    │                     ↓                      │
    │               指向 0x1100（Execute_v1）    │
    └────────────────────────────────────────────┘
    
    AutoCAD 命令表：
    C11 → ExecuteC11() @ 0x3100  ← 仍然是固定地址
    
    用户执行 C11：
    → 调用 0x3100（ExecuteC11）
    → ExecuteTestCommand("C11")
    → _testCommandActions["C11"].Invoke()
    → Delegate @ 0x4000
    → Lambda 调用 Execute_v1.Invoke()
    → 执行 0x1100（Execute_v1）✅

时间线 T2（第二次加载 HyCADTool.Refactored.dll，执行 C2）：
    ┌────────────────────────────────────────────┐
    │ HyCADTool.Refactored.dll (Assembly_v2)     │
    ├────────────────────────────────────────────┤
    │ OverKillCommand_v2 @ 0x2000                │
    │   └── Execute_v2() @ 0x2100                │
    └────────────────────────────────────────────┘
    
    ┌────────────────────────────────────────────┐
    │ ReCall.dll                                 │
    ├────────────────────────────────────────────┤
    │ ReCallClass                                │
    │   ├── ExecuteC11() @ 0x3100 ← 仍然不变     │
    │   │                                        │
    │   └── _testCommandActions                  │
    │       // C2 执行：                         │
    │       _testCommandActions.Clear();         │
    │       ["C11"] → NEW Delegate @ 0x5000      │
    │                    ↓                       │
    │               Lambda: () =>                │
    │                 Execute_v2.Invoke(...)     │
    │                     ↓                      │
    │               指向 0x2100（Execute_v2）✅  │
    └────────────────────────────────────────────┘
    
    AutoCAD 命令表：
    C11 → ExecuteC11() @ 0x3100  ← 仍然是固定地址
    
    用户执行 C11：
    → 调用 0x3100（ExecuteC11）← 这个地址永不改变
    → ExecuteTestCommand("C11")
    → _testCommandActions["C11"].Invoke()
    → NEW Delegate @ 0x5000  ← 新的委托！
    → Lambda 调用 Execute_v2.Invoke()
    → 执行 0x2100（Execute_v2）✅ 最新代码！
```

## 内存布局详解

### 关键数据结构

```
AutoCAD 进程内存布局：

┌──────────────────────────────────────────────────────┐
│ AutoCAD 核心（C++ 原生代码）                          │
├──────────────────────────────────────────────────────┤
│ 命令表（CommandTable）                               │
│   ├── "LINE" → 0x00010000（AutoCAD 内置命令）       │
│   ├── "HYOV" → 0x12345678（第一次注册的地址）       │
│   └── "C11"  → 0x3100（ReCallClass.ExecuteC11）     │
└──────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────┐
│ .NET AppDomain（托管堆）                             │
├──────────────────────────────────────────────────────┤
│ ReCall.dll (Assembly @ 0x3000)                       │
│   ├── ReCallClass                                    │
│   │   ├── ExecuteC11() @ 0x3100  ← 固定地址          │
│   │   └── _testCommandActions（字段）                │
│   │       └── Dictionary 对象 @ 0x3200               │
│   │           └── ["C11"] → Delegate @ 0x4000        │
│   │                           ↓                      │
│   │                       Lambda 闭包对象            │
│   │                         ↓                        │
│   │                   捕获的变量：                   │
│   │                     - method (MethodInfo)        │
│   │                     - instance (object)          │
│   └── ...                                            │
├──────────────────────────────────────────────────────┤
│ HyCADTool.Refactored.dll v1 (Assembly @ 0x1000)      │
│   ├── OverKillCommand_v1                             │
│   │   └── Execute_v1() @ 0x1100                      │
│   └── ...                                            │
├──────────────────────────────────────────────────────┤
│ HyCADTool.Refactored.dll v2 (Assembly @ 0x2000)      │
│   ├── OverKillCommand_v2                             │
│   │   └── Execute_v2() @ 0x2100                      │
│   └── ...                                            │
└──────────────────────────────────────────────────────┘
```

### 关键点对比

| 特性 | HYOV 命令 | C11 命令 |
|------|----------|---------|
| **注册的地址** | Execute_v1 @ 0x1100 | ExecuteC11 @ 0x3100 |
| **地址是否改变** | ❌ 不会（固定指向 0x1100） | ❌ 不会（固定指向 0x3100） |
| **调用的最终目标** | 始终是 Execute_v1 @ 0x1100 | 通过委托，可以是 Execute_v2 @ 0x2100 |
| **为什么不同** | 直接调用，无间接层 | 间接调用，通过委托查表 |

## 委托的魔法

### 委托是什么？

```csharp
// 委托的本质：方法引用 + 目标对象
public delegate void Action();

// 创建委托
Action myAction = () => Console.WriteLine("Hello");

// 委托的内部结构（简化）
class Delegate
{
    private object _target;        // 目标对象（如果是实例方法）
    private IntPtr _methodPtr;     // 方法指针
    private object[] _capturedVars; // 捕获的变量（Lambda）
    
    public void Invoke()
    {
        // 调用方法指针，传入目标对象
        CallMethod(_methodPtr, _target, _capturedVars);
    }
}
```

### Recall 中的委托使用

```csharp
// LoadTestCommands() 中创建委托
var method = commandType.GetMethod("Execute");      // Execute_v2 的 MethodInfo
var instance = Activator.CreateInstance(commandType); // OverKillCommand_v2 的实例

// 创建 Lambda 委托
_testCommandActions["C11"] = () => method.Invoke(instance, null);
//                           ↑
//                     捕获 method 和 instance 变量
```

**委托对象的内存结构**：

```
Delegate @ 0x4000（第一次 C2）
    ├── _target: null（Lambda 是静态的）
    ├── _methodPtr: 指向 Lambda 的机器码
    └── _capturedVars:
            ├── method: Execute_v1 的 MethodInfo @ 0x1100
            └── instance: OverKillCommand_v1 的实例 @ 0x1050

↓ 执行 C2（重新加载）

Delegate @ 0x5000（第二次 C2，新对象）
    ├── _target: null
    ├── _methodPtr: 指向 Lambda 的机器码（相同）
    └── _capturedVars:
            ├── method: Execute_v2 的 MethodInfo @ 0x2100  ← 新的！
            └── instance: OverKillCommand_v2 的实例 @ 0x2050  ← 新的！
```

### 为什么委托可以更新？

```
关键点：

1. ExecuteC11() 方法本身不变（地址 0x3100）
   
2. ExecuteC11() 内部查找委托：
   _testCommandActions["C11"]  ← 这是一个变量，可以改变
   
3. C2 时更新委托：
   _testCommandActions["C11"] = NEW Delegate @ 0x5000
   
4. 下次 C11 执行时：
   → ExecuteC11() @ 0x3100（固定）
   → 查找 _testCommandActions["C11"]
   → 获取 NEW Delegate @ 0x5000（最新）
   → 调用最新的 Execute_v2
```

## 完整调用链对比

### 一般命令（HYOV）

```
用户输入：HYOV

AutoCAD 命令表查找：
    CommandTable["HYOV"] → CommandInfo
                            ├── Method: Execute_v1 @ 0x1100
                            └── DeclaringType: OverKillCommand_v1

AutoCAD 执行（伪代码）：
    var commandInfo = CommandTable["HYOV"];
    var instance = Activator.CreateInstance(commandInfo.DeclaringType);
    commandInfo.Method.Invoke(instance, null);
                ↑
            Execute_v1 @ 0x1100（固定，永不改变）

调用链：
    HYOV → CommandTable → Execute_v1 @ 0x1100 → 执行旧逻辑

汇编层面（简化）：
    CALL 0x1100  ; 直接调用固定地址
    RET
```

### Recall 命令（C11）

```
用户输入：C11

AutoCAD 命令表查找：
    CommandTable["C11"] → CommandInfo
                           ├── Method: ExecuteC11 @ 0x3100
                           └── DeclaringType: ReCallClass

AutoCAD 执行（伪代码）：
    var commandInfo = CommandTable["C11"];
    var instance = reCallInstance;  // ReCallClass 的实例（固定）
    commandInfo.Method.Invoke(instance, null);
                ↑
            ExecuteC11 @ 0x3100（固定）

ExecuteC11() 内部：
    public void ExecuteC11()
    {
        ExecuteTestCommand("C11");
    }

ExecuteTestCommand("C11") 内部：
    private void ExecuteTestCommand(string commandName)
    {
        // 查找委托（这是关键！）
        var action = _testCommandActions["C11"];
                     ↑
                这是一个字段，C2 时会更新
        
        // 调用委托
        action.Invoke();
    }

委托 Invoke() 内部：
    // Lambda: () => method.Invoke(instance, null)
    method.Invoke(instance, null);
      ↑
    这里的 method 是 C2 时捕获的最新 MethodInfo
    可能是 Execute_v1 @ 0x1100（第一次）
    也可能是 Execute_v2 @ 0x2100（第二次）✅

调用链：
    C11 → CommandTable 
        → ExecuteC11 @ 0x3100（固定）
        → ExecuteTestCommand
        → _testCommandActions["C11"]（可变）
        → Delegate.Invoke()
        → method.Invoke()  ← method 可以是最新的
        → Execute_v2 @ 0x2100 ✅ 最新逻辑

汇编层面（简化）：
    CALL 0x3100        ; 调用 ExecuteC11（固定）
    ...
    MOV EAX, [0x3200]  ; 读取 _testCommandActions 字段
    MOV EAX, [EAX+8]   ; 获取 ["C11"] 的委托
    CALL [EAX]         ; 间接调用委托（地址动态）
    ...
    RET
```

## 核心总结

### 误解 vs 真相

| 误解 | 真相 |
|------|------|
| ❌ HYOV 的地址会变 | ✅ HYOV 指向的地址不会变（0x1100） |
| ❌ C11 的地址不变 | ✅ C11 指向的地址也不会变（0x3100） |
| ❌ 两者的区别在于地址 | ✅ 区别在于调用方式（直接 vs 间接） |

### 正确理解

```
HYOV（直接调用）：
    固定地址 0x1100 → Execute_v1() → 旧逻辑
    
    问题：0x1100 永远指向 Execute_v1，无法更新

C11（间接调用）：
    固定地址 0x3100 → ExecuteC11() → 查表 → 委托 → Execute_v2() → 新逻辑
                                        ↑
                                    这一层可以更新！
```

### 关键机制

1. **AutoCAD 命令表**：
   - 存储的是方法的 MethodInfo
   - 第一次注册后永不改变
   - HYOV 和 C11 都一样

2. **直接调用（HYOV）**：
   - CommandTable → Execute_v1
   - 没有间接层，无法更新

3. **间接调用（C11）**：
   - CommandTable → ExecuteC11（固定）
   - ExecuteC11 → 查找委托字典（可变）
   - 委托 → Execute_v2（最新）

4. **委托的魔法**：
   - 委托本身是一个对象，存储方法引用
   - C2 时创建新委托，指向新方法
   - C11 执行时调用最新的委托

## 类比理解

### 类比 1：电话簿

```
HYOV（直接拨号）：
    用户 → 拨号 12345678 → 接通 A 的手机 → A 接听
    
    问题：A 换了新手机，但你还是拨 12345678（旧号码）

C11（通过总机）：
    用户 → 拨号 3100（总机）→ 总机查询 "C11" → 转接到 B 的手机 → B 接听
    
    优势：B 换了新手机，只需更新总机的记录，用户仍然拨 3100
```

### 类比 2：快递配送

```
HYOV（固定地址）：
    快递 → 送到 "XX 街 100 号"（固定地址）→ 旧房子
    
    问题：你搬家了，但快递还是送到旧地址

C11（转发服务）：
    快递 → 送到 "转发中心"（固定地址）→ 转发中心查询 → 送到新地址
    
    优势：你搬家后，只需更新转发中心的记录
```

## 🎯 最终答案

### 您的问题：为什么一般命令调用时地址会改变，而 C11-C19 不变？

**答案**：

1. **两者的命令方法地址都不会改变**
   - HYOV → Execute_v1 @ 0x1100（固定）
   - C11 → ExecuteC11 @ 0x3100（固定）

2. **关键区别在于调用方式**
   - HYOV：直接调用 0x1100，永远执行旧代码
   - C11：调用 0x3100，内部通过委托间接调用最新代码

3. **不是"地址改变"，而是"间接调用"**
   - C11 的 ExecuteC11 地址不变（0x3100）
   - 但 ExecuteC11 内部查找的委托会变
   - 委托指向的最终方法会变（Execute_v1 → Execute_v2）

4. **委托是关键**
   - 委托对象可以更新（C2 时重新创建）
   - 委托捕获最新的 method 和 instance
   - 实现了"固定入口 + 动态目标"

---

**总结一句话**：

**C11 命令的地址（0x3100）永不改变，但它通过委托机制实现了间接调用，委托可以在 C2 时更新，指向最新的代码（0x2100），从而实现热重启！** 🎉
